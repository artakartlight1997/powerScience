# ユーザーマニュアル — Integral Prism PoC v2

**入力は社名だけ。** システムが自分で調べに行く。

Google Deep Research に社名を入れる感覚で使う。違いは、返ってくるものが
「読み物」ではなく **検証済みの台帳**であること — どの論点が独立証拠で固まっていて、
どこが薄く、どこが公開情報では取れないか(=コンサル/マネジメントに聞くべきことか)を
機械判定して返す。

## 0. 初回セットアップ(1回だけ)

```bash
cd poc2
cp .env.example .env      # OPENROUTER_API_KEY を記入
docker compose build
```

> 生成モデルと検証モデルは**別ベンダ**が必須(同一だと起動拒否)。
> 同じモデルに自分の答えを採点させないための構え。

## 1. 使う(これだけ)

```bash
docker compose run --rm prism research "株式会社サンプルテック" --industry ITサービス
```

- 業態(アーキタイプ)は**システムが外部情報から自動同定**する。
  間違っていたら `--archetype ses_jutaku` のように一言で差し替えればよい
  (差し替えは既存ケースにもう一度 `research` を実行すれば反映される)
- ケースIDは社名から自動生成される。自分で決めたければ `--case-id yamada2026`
  (半角英数小文字)。Web収集を使わず手元の資料だけで回すなら `--no-web`
- システムは: 固定の物差し(箱0〜10×業態ツリー)を実体化 → 未充足項目から検索クエリを
  機械生成 → Web検索 → ページ取得・**原文スナップショット保存** → 逐語引用の抽出 →
  原文照合(別ベンダのモデルで検証)→ カバレッジ判定 → を停止条件まで自動で繰り返す
- 停止条件(ラウンド上限/LLM上限/収穫逓減/公開経路の完了)で**必ず理由つきで**止まる。
  放置してよい

ティーザー段階で社名が伏せられているなら、業界名で回して業界パックを作る:

```bash
docker compose run --rm prism research "SES業界" --archetype ses_jutaku
```

## 2. (任意)手元に資料があれば置く

IM・コンサル報告・自分で拾ったレポートがあるなら、置けば突合に使われる。
**置かなくても動く。** これは補助入力である。

```
inbox/<ケースID>/
  seller/       ← ティーザー・IM(「売り手の主張」として扱われ、これ単独ではfilledにならない)
  consultant/   ← コンサル成果物(検収QCの対象)
  general/      ← 自分で拾った資料
```

- 対応形式: PDF / txt / md。ファイル名の先頭に `YYYY-MM-DD_`(その情報の入手時点)
- 置いたら `docker compose run --rm prism run <ケースID>` で再実行(追加分だけ反映される)

## 3. 成果物を読む(`out/<ケースID>/`)

| ファイル | 何か | いつ使うか |
|---|---|---|
| `sakusenban.md` | **作戦盤**: 箱×状態の全景、見張り台帳(論点依存度high)、未解消の矛盾 | 検討会の前に5分で眺める |
| `order_spec.md` | **発注仕様書**: 公開情報で埋まらなかった項目+取得経路。filled は「発注不要」リスト | コンサル発注・Mgmtインタビュー設計 |
| `qc.md` | **検収QC**: コンサル成果物のうち公開情報で再現できた割合 | 納品物の検収 |
| `ledger.md` | **証拠台帳**: 全証拠の出所・原文照合結果・独立性クラスタ | 数字の出典を確かめたいとき |
| `status.md` | 現況サマリと改竄検知の結果 | 途中経過の確認 |

### 状態の読み方

- ✅ **filled** — 独立2系統以上の証拠が原文照合を通過(売り手のみ・Web未取得は不可)
- 🟡 **thin** — 証拠はあるが、独立性不足/売り手のみ/矛盾が未解消
- 🔴 **missing** — 公開経路で取れるはずだが、まだ見つかっていない
- ⚫ **unknown** — 公開では到達不能。**取得手段つきで発注仕様書へ**(初期は多くて正常)

### システムの正直さについて

- 検索で「見つからなかった」は「無い」と報告されない(unknownのまま取得手段つきで残る)
- 矛盾(公式95% vs 記事80%)は平均せず並記され、確認タスクに変換される
- スナップショット(原文保存)に残っていないWeb情報は、証拠として一切使われない

## 4. その他のコマンド

```bash
docker compose run --rm prism run <ケースID>            # 続行・資料反映
docker compose run --rm prism run <ケースID> --no-web   # 置いた資料だけで監査
docker compose run --rm prism status <ケースID>
docker compose run --rm prism report <ケースID>
docker compose run --rm prism verify-chain <ケースID>   # 台帳の改竄検知
```

## 5. 不具合が起きたら

**何が起きたか説明する必要はない。** `data/logs/prism.log` を開発者に渡すだけでよい。
全処理・失敗・エラーの詳細が残る。資料の本文はログに記録されない(ID・URL・件数のみ)。

## 6. よくある質問

- **Q. Deep Research と何が違う?** → DRは読み物を返す。これは「固定の物差しに対して
  何が検証済みで何が欠けているか」の台帳と、次のアクション(発注仕様書)を返す。
  全ての数字は原文スナップショットまで遡れる
- **Q. 検索先を制限したい** → `templates/fund/standards.yaml` の `allowed_hosts`
- **Q. 新しい業態が来た** → `templates/archetypes/` に YAML を1枚追加(コード変更不要)
- **Q. Docker なし** → `pip install -e .` して `prism research "社名"`
