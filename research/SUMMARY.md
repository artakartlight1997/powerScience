## 1. 一枚で言うと（v2.0）

> **競合（Sakana Marlin / Google Deep Research）は「レポートを作る機械」を作っている。**
> **我々は「投資判断に対して、次に何を調べるべきかを選び続ける制御層」を作る
> — Decision-Centric Meta-Research Control Plane。**
>
> 投資プロの実益は「速く調べられた」ではなく、
> **「この投資仮説を殺しうる事実を、探したのに見つからなかった」という確信**にある。
> その確信は、**何を探し / 何が見つからず / なぜ止めたか**が記録に残るときだけ成立する。
> 効くのは DD の後（レポート）ではなく、**着手時（予算配分前）と DD の最中**。

> **【v2.0 note】** 外部から独立に作成された設計評価文書と統合した結果、
> 上記の直感は「Decision Compiler / Dual Loop / Epistemic Ledger / Action Router /
> Stop Rule / Outcome Calibration」という6要素の制御理論として厳密化された。
> 詳細は [discussion/17-integrated-design-v2.md](discussion/17-integrated-design-v2.md)。

## 4. 何を作るのか

### 中心はひとつ — **証拠グラフ**
```
Source / Evidence / Claim / Hypothesis / Question / ToolCall / Decision
＋ 追記専用・ハッシュ連鎖・as_of（時点）・trust_label（taint）
```
**この1構造が5つの要求を同時に満たす**: 引用の機械検証／規制の監査証跡／
セキュリティの taint 追跡／時点再現（リーク防止）／文脈圧縮しても壊れない `[S-128]`

### 作る（Class B/C: モデルが賢くなるほど価値が上がる or 独立）
証拠グラフ／接地検証（サブ質問分解）／数値エンジン／ACH 行列／
決定境界→EVPI→探索配分／確率層／二層LLM＋capability／停止条件／記憶（3層）

### 作らない（Class A: モデルに食われる）
汎用探索基盤／マルチモデル統率／探索アルゴリズム／モデル学習／OCR エンジン／
日本語品質／長文生成の作り込み／企業DB

## 5. 何を作り、いつ効かせるか（v2.0 — W1「IC メモ校閲」は却下・差し替え済み）

> **旧案（W1: 書き終えた IC メモへの事後ツッコミ）は却下された。**
> 理由: 手戻りが直せないタイミングで来る／書き手の仕事を否定する形で来る／
> そもそも知りたいのは書く前。詳細は [discussion/16](discussion/16-prism-proposal-vs-sakana.md)。

**一次商品: 案件着手時の「作戦盤」＋ DD 期間中の「生きた台帳」**（Decision Compiler の Phase 0 として発火）:
```
Phase 0（着手30分・予算配分の前）:
  ① この案件で判断を分ける論点（初期資料固有の引っかかりから検出。重要度順）
  ② 各論点の決着方法と値札（「VDR請求リストに足せばタダ」「商業DDの発注スコープに明記すべき」）
  ③ 人間が挙げなかった論点（差分のみ）

Phase 1（DD 期間中、常時更新）:
  ④ 資料間の食い違い（★平均も抑制もしない）        ← 矛盾検出
  ⑤ 次に調べる価値が最も高い1件と、その値札        ← EVPI
  ⑥ 「これ以上調べても判断は変わりません」の判定    ← 他社が出せない

Phase 2（IC 直前）: メモは校閲されるのではなく、検証済みの台帳から射影される
```

| 項目 | 決定 |
|---|---|
| **実益** | **V2 損失回避（1案件で数億〜数十億）＋ V4 説明責任**。V1 時間短縮では戦わない |
| **楔（v2）** | **Phase 0: 着手時の作戦盤**（W1「事後メモ校閲」は却下） |
| **効く時点** | DD の後（レポート）ではなく **着手時（予算配分前）と DD 最中** |
| **売り文句** | 「8時間考えます」ではなく **「これ以上調べても判断は変わりません」** |

**単価・原価・損益分岐（`discussion/11` の試算、外販モデルを想定した場合）**:
案件従量 ¥300,000–1,500,000 ＋ 薄いサブスク。機械原価は ¥6,000–18,000/案件（誤差）で、
支配的なのは人間 QA（自動ゲートの整備＝粗利施策）。損益分岐は顧客 3–25社。

> ✅ **【確定済み — [discussion/18](discussion/18-internal-build-and-zero-input.md)】**
> **売らない。自社ファンドの投資プロが使う内製システムである。**
> 内製の定義: フロンティアモデル・データベンダ・DR は契約して使う。契約しないのは
> **サカナ等の「リサーチシステムそのもの」**。内製するのは判断の層だけ。
> 根拠（補正2で改訂）: ①買えるものは競合も買える（差別化にならない）
> ③蓄積が自社に残る ④**用途固有性** — 深さの用途は「コンサルタントと対等に渡り合う知識武装」であり、
> カバレッジ台帳から出る3射影（対峙資料・発注仕様書・納品物QC）は Marlin 契約では手に入らない。
> ※旧根拠②（私有情報の取り込み）は撤回 — VDR の中身は外部コンサルが扱う。
> 上記の単価・買い手の試算（03/04/05/11章）は外販シナリオのアーカイブとして保持し、
> 11章の原価計算は「1案件あたりの運用コスト」として読み替える。
> **成功基準は「現行プロセス + DR に対する優位」、Kill criterion は「買った方がマシなら止める」。**

## 6. 討論の結論と、その評価

### 決着（A1–A12、すべて反証条件つき）
実益は V2/V4 ／ 一次商品は案D（IC レディネス核・レポートは副産物・モニタは第二波） ／
楔は W1 ／ 「8時間」を売らない ／ 証拠グラフは作る（M1 は最小） ／
**人間が先に死因を書き、差分を見せる** ／ **確率は内部で持ち、既定は非表示** ／
**記憶は3層**（案件層＝分離・**型層＝横断**・公開層＝横断） ／
検証の粒度は重要度で可変 ／ 承認型 UI を作らない ／ 一次成果物は1–3ページ

### 生き残った失敗仮説（＝真のリスク）
| | リスク | 対処 |
|---|---|---|
| **1位** | **F2: 較正された確率は使われない** | 拒否の5メカニズムを分解した結果、**R1–R4 は表示設計で解け、R5 だけが本質**。<br>→ **「確率」ではなく「判断が反転する条件」で出す**（案β）。3案モックで検証 |
| **2位** | **F4′: 使うが定着しない**（PE の scaling は 10–15%） | 1工程の正本化。記憶で「使わないと次で困る」構造 |
| 3位 | F5: 大手が降りてくる | 顧客データの蓄積を最速で開始 |

### ★討論そのものの評価
```
Decision Quality（6要素の最小値で評価）= 4/10

  DQ1 フレーム        7/10
  DQ2 選択肢の幅       6/10
  DQ3 情報の信頼性     5/10  ← ★顧客ヒアリングがゼロ。実務数値は全て推定
  DQ4 価値とトレードオフ 7/10
  DQ5 論理            8/10  ← ACH を自社に適用し、全決定に反証条件
  DQ6 実行へのコミット  4/10  ← ★担当・期限が未定

→ 論理は整ったが、外の情報がなく、実行に落ちていない。
→ これ以上「考える」ことでは DQ は上がらない。
```

**脆い決定 Top3**: A9（記憶の3層・**法務次第**）／ A2（一次商品・**証拠が推定のみ**）／ A4（価格枠）

**討論の穴（自己批判）**: 顧客セグメントの選択（PE本体 vs **DD ファーム**）と、
**「今のやり方（Excel と人力）」との定量比較**が抜けている。

## 9. このプロジェクトの賭け（一文ずつ）

1. **モデルはコモディティ化する**（推論単価は約1/300 になった）→ モデルに賭けない
2. **較正と検証はモデル層で解かれない**（評価が棄権を罰する構造）→ **ここに賭ける**
3. **投資領域では、モデルが賢くなるほどモデル由来の優位が速く消える** → 私有情報と処理の差に賭ける
4. **証拠グラフという1構造が、5つの要求を同時に満たす** → **ここに最初の工数を全部投じる**
5. **実益は「速さ」ではなく「探したのに見つからなかったという確信」にある** → ここが外れたら、事業は成立しない

**5番目が最大の賭けであり、文献では検証できない。顧客に聞くしかない。**
