# 00. 調査方法・スコープ・信頼度の扱い

## 1. 調査の目的

Integral Prism（PE / 投資プロ向けリサーチシステム）の **アーキテクチャ議論の前提を揃える**こと。
具体的には次の3問に、根拠つきで答えられる状態を作る。

1. **競合は実際に何をやっているか**（Sakana Marlin / Google Deep Research / その他）
2. **学術的に何が解けていて、何が未解決か**（探索・検証・記憶・評価）
3. **投資実務側の制約は何か**（データ、規制、ワークフロー、支払い意思）

## 2. スコープ

| 含む | 含まない（今回は） |
|---|---|
| Deep Research 型エージェントの設計 | 学習（事前学習・大規模 RL）そのもの |
| 推論時探索・検証・記憶 | インフラ/GPU 調達 |
| 投資リサーチ実務・データ源・規制 | 具体的な UI 実装 |
| 評価ベンチマークと評価設計 | 個別銘柄の投資判断 |
| 事業戦略（堀・単価・コモディティ化） | 資金調達計画 |

## 3. 調査方法と、その限界（重要）

本サーベイは **2026-08-22 時点** の Web 検索結果に基づく。
実行環境のエグレス制限により、**一次ソース（sakana.ai / arxiv.org / ai.google.dev 等）の本文を直接取得できなかった**。
したがって記述の多くは、検索エンジンが返した要約・二次記事・論文タイトル/アブストラクト断片に依拠している。

この制約を隠さずに扱うため、本サーベイでは主張ごとに **確度ラベル** を付ける。

| ラベル | 意味 | 扱い |
|---|---|---|
| `A: 確証` | 複数の独立ソース、または公式発表の一致 | そのまま設計前提にしてよい |
| `B: 有力` | 単一ソース／二次記事だが内容が具体的 | 設計前提にしてよいが、一次確認を宿題に積む |
| `C: 推定` | 公開情報からの合理的推定（内部構造など） | **設計前提にしない**。議論の仮説としてのみ使う |
| `D: 未確認` | 断片のみ | 宿題（`notes/open-questions.md`）へ |

> ⚠️ 特に **Marlin と Gemini Deep Research の内部アーキテクチャは、公開情報が薄い**。
> 本サーベイの該当箇所は原則 `B` か `C` である。「競合がこうしているから我々はこうする」という論法は、
> `C` ラベルの上に建てないこと。

## 4. 「実益」の定義（このプロジェクトでの操作的定義）

投資プロにとっての実益を、以下に分解して測る。単なる「良いレポート」は指標にしない。

1. **時間**: 一次スクリーニング〜IC 資料までのリードタイム短縮
2. **見落とし率**: 後から判明した重要事実を、事前に拾えていたか（recall of material facts）
3. **反証可能性**: 各主張が、何分で第三者に検証されうるか（出典到達コスト）
4. **判断の較正**: 提示された確度が実際の的中率と合っているか（Brier / ECE）
5. **再利用性**: 1件の案件で作った知識が、次の案件でどれだけ再利用されるか

この5軸は、後述の評価設計（08）と、差別化仮説（11）の土台になる。

## 5. 用語の統一

- **Deep Research（DR）**: 自律的に多段検索・推論し、引用つき長文レポートを出すエージェント類型。
- **Ultra Deep Research**: Sakana が Marlin に付したマーケティング用語。時間軸（数時間〜8時間）を強調する。`B`
- **投資プロ**: PE / VC / ヘッジファンド / IB / 事業会社の投資・経営企画担当。
- **本システム / IP**: Integral Prism（仮称）。
