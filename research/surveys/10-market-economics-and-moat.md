# 10. 市場・単価・コモディティ化と堀

## 1. コモディティ化は「起きるかも」ではなく「起きた」

- MMLU で GPT-3.5 相当の性能を出す推論単価： **2022/11 約 $20/M トークン → 2024/10 約 $0.07/M**（約 1/300）`[S-088]`
- オープンモデルが DR タスクでクローズドに肉薄（Tongyi DeepResearch 30B）`[S-030]`
- Deep Research は各フロンティアの **標準機能**として無料/低価格帯に降りてきている（Gemini DR API $2/task）`[S-020]`

→ **モデル層に価値を置く設計は、設計時点で減価する。**
→ ユーザの読み（フロンティア/オープンのコモディティ化）は正しい。Sakana のモデル非依存戦略も正しい。

## 2. では堀はどこにあるか

2026年の実務的コンセンサス `[S-086][S-087]`：

| 堀 | 内容 | IP での実装 |
|---|---|---|
| **ワークフローの深さ** | 業務の正本（system of record）になる | IC メモ・DD 台帳の**正本**を握る（→09） |
| **累積する自社データ** | 使うほど貯まり、他社が複製できない | ケースベース記憶＋反証結果（→06） |
| **流通/距離** | 顧客業務への埋め込み | 既存 VDR/CRM/Excel への接続 |
| **スイッチングコスト** | 抜けると痛い | 過去案件の証拠構造が中に溜まる |
| **規制の深さ** | 監査・準拠が参入障壁 | EU AI Act 準拠の監査証跡（→09） |
| **視点（point of view）** | 何を良しとするかの独自の型 | **反証・較正という評価軸そのものの定義** |

> 「最強の初期の堀は『より良い AI』ではなく、**より締まった成果と、より速く学習する系**」`[S-087]`

**IP にとっての結論**: 堀は3つだけ選ぶ。
1. **証拠構造の正本化**（ワークフロー＋スイッチングコスト）
2. **反証・較正という評価軸の所有**（point of view）
3. **監査可能性**（規制の深さ）

アルゴリズム（探索）は**堀ではない**。AB-MCTS は既にオープンソース（TreeQuest, Apache-2.0）`[S-009]`。

## 3. 単価構造の設計

### 参照点
| | 1実行あたり | 顧客 |
|---|---|---|
| Gemini DR API 標準 / Max | **$2 / $5** `[S-020]` | 開発者 |
| Sakana Marlin | **≒ ¥9,800**（100クレジット）／ 月額 ¥150,000〜 `[S-004]` | 金融・コンサル法人 |
| アナリスト1人日 | **¥50,000〜150,000** | — |
| 外部 DD ファーム（商業 DD 1本） | **¥5M〜30M** | — |

**空白**: Marlin の上、外部 DD ファームの下 に **1桁分の空白**がある。
`¥100,000〜¥1,000,000 / 案件` の帯域で、「外部 DD の一部を代替する」ポジションが取れる。`C`
ただしこれは **成果物がレポートではなく“検証済みの証拠構造”である**場合にのみ正当化できる。

### 原価側（設計制約）
- Gemini DR の実測で示された通り、**検索コストが LLM コストを超えうる**（1 run で $1.12〜$2.24 が検索）`[S-020]`
  → **クエリ予算の最適配分（=05 の EIG）は、品質問題であると同時に原価問題**
- キャッシュが効く（入力の 50〜70%）`[S-020]` → **案件内の文脈再利用設計がそのまま粗利になる**
- **モデルルーティング/カスケード**: 安いモデルで前段、必要時のみフロンティアへ昇格。
  RouteLLM は MT-Bench で **約85% コスト削減・GPT-4 品質の約95%維持、フロンティア呼び出しは約26%** `[S-089]`
  実務チームの報告は **40〜85% の請求削減** `[S-089]`
  → Marlin の「マルチモデル探索」は、**品質戦略であると同時にコスト戦略**である。ここは必ず踏襲する。

## 5. リスク

| リスク | 内容 | 緩和 |
|---|---|---|
| **フロンティアが降りてくる** | 「引用検証」機能を OpenAI/Google が標準搭載 | 検証は L0-L1 だけでは差がつかない。**L3 反証・L4 較正＋顧客データ**まで積む |
| **Marlin が金融特化を深める** | Sakana は EDINET-Bench を既に持つ `[S-016]` | 実務工程（IC/PMI）と顧客固有データで戦う。**汎用リサーチ品質では戦わない** |
| **エージェント多発の疲れ** | PE 側で PoC 疲れ（scaling は 10-15%）`[S-076]` | 「1業務の正本化」から入る。全社導入を狙わない |
| **精度事故** | 誤引用1件で信頼喪失 | 07 の Fact Check ループを**出荷ゲート**にする |
