# 01. Sakana Marlin

## 1. 事実関係（製品としての Marlin）

| 項目 | 内容 | 確度 |
|---|---|---|
| 発表 | 2026-06-15、Sakana AI 初の商用プロダクト `[S-001][S-002][S-004]` | A |
| 位置づけ | 自律型リサーチアシスタント。対外的には **"Virtual CSO"（仮想 CSO）** と称する `[S-005][S-006]` | A |
| カテゴリ名 | "Ultra Deep Research" — 既存 Deep Research との差を **実行時間** で定義 `[S-003]` | A |
| 実行時間 | **最大約8時間** の無人自律実行 `[S-001][S-003][S-004]` | A |
| 出力 | 数十〜**最大100ページ級**のテキストレポート ＋ プレゼン用スライド（画像生成 AI 併用） `[S-002][S-004]` | A |
| 前史 | 2026-04 からクローズドβ。**金融機関・コンサルティングファーム**に限定提供 `[S-002][S-004]` | A |
| 顧客 | 法人専用。金融機関 / コンサル / 事業会社の経営企画・事業開発 `[S-004]` | A |
| 価格 | Pay-per-use（1実行 = **100クレジット**、追加クレジット ¥98/個）＋ 月額プラン（**¥150,000〜**、Pro/Team/Enterprise） `[S-004][S-005]` | B |
| データ方針 | 顧客入力を学習・ファインチューンに使わない（明示的オプトイン時を除く）。外部 AI プロバイダにも同条件 `[S-005]` | B |

**単価の目安**: 1実行 ≒ 100クレジット × ¥98 ≒ **¥9,800/回**（pay-per-use 換算）。`C`
→ 後述の Google Deep Research API（$2〜$5/task ≒ ¥300〜¥800）と **1〜1.5桁違う**。
これは Marlin が「安いレポート量産機」ではなく「**高単価・低頻度・意思決定級**」を狙っていることを意味する。`B`

## 2. アーキテクチャ（公開情報＋推定）

Sakana 自身の説明では、Marlin は **2つの自社研究の製品化** である `[S-005][S-006]`：

1. **AB-MCTS**（Adaptive Branching Monte Carlo Tree Search, NeurIPS 2025 Spotlight）
   → 推論を「木探索」として扱う中核アルゴリズム。詳細は [02](02-sakana-lineage-abmcts.md)。
2. **The AI Scientist** 由来のワークフロー自動化基盤（Nature 掲載）
   → 仮説生成 → 実験/調査 → 執筆 → 自己レビュー、という**研究プロセスの自動化骨格**。

報じられている動作原理（`B`〜`C`）:

- 木の各ノードで、外部フィードバック信号に基づき **「広げる（新しい仮説を出す）」か「深める（既存候補を精緻化・監査する）」** を動的に選択 `[S-003]`
- さらに **第3の軸として「どのモデルを呼ぶか」を探索対象に含める** — フロンティア各社のモデルを
  プラグイン可能な「集合知ネットワーク」として扱う `[S-003]`
- 1セッションあたり **数百〜数千回の LLM 呼び出し**、計算資源を有望な枝に動的に配分 `[S-003]`
- 自律的に仮説を立て、情報を集め、**矛盾するデータを突き合わせて調停**し、成果物に統合 `[S-005]`

```
        ┌──────────── Marlin（推定される制御構造） ────────────┐
        │  ルート = リサーチ課題                                │
        │    │                                                 │
        │    ├─ 幅方向: 新規仮説/新規サブクエスチョンを生成      │  ← Thompson Sampling で
        │    ├─ 深さ方向: 既存の暫定回答を精緻化・監査          │     幅/深さを確率的に選択
        │    └─ モデル方向: どの LLM に任せるかを選択            │  ← マルチモデル集合知
        │                                                       │
        │  各ノードのスコア = 何らかの外部フィードバック（自己評価/検証） │ ← ここが公開されていない
        └───────────────────────────────────────────────────────┘
```

> **未公開の核心**: 木探索の**報酬（スコア）を何で与えているか**。
> コード生成や ARC-AGI では「テストが通る/通らない」という機械検証可能な報酬があるが、
> **ビジネスリサーチには自明な報酬がない**。ここを Marlin がどう埋めているかは公開されていない（`D`）。
> これは我々にとって最大の攻めどころでもある（→ [11](11-implications-for-integral-prism.md)）。

## 3. 戦略的評価 — 「Sakana の戦略は正しい」の中身

ユーザ仮説（サカナの戦略は正しい）を、構成要素に分解して検証する。

| Sakana の賭け | 内容 | 評価 |
|---|---|---|
| ① モデル非依存 | フロンティア/オープンモデルを差し替え可能な部品として扱う | **正しい**。モデル価格は 2022→2024 で MMLU 同等性能あたり $20/M → $0.07/M へ約 300 分の 1 `[S-088]`。モデルに賭けると価値が蒸発する |
| ② 推論時計算に賭ける | 学習ではなく推論時探索で性能を出す | **正しいが、他社も来る**。推論時スケーリングは公知領域で、検証器設計が勝負に移っている（→05） |
| ③ 時間軸で差別化 | 「8時間考える」を売る | **短期的に正しい、中期的に脆い**。時間は模倣可能な軸。Google DR も Max 版で検索回数を倍にしている `[S-020]` |
| ④ 高単価 B2B | 消費者向けを捨てる | **正しい**。DR 機能は各フロンティアの標準機能化＝コモディティ化しており、汎用は勝てない（→10） |
| ⑤ RSI（自己改善） | AI 開発プロセス自体を AI で最適化 `[S-007]` | 長期的な差別化としては合理的。ただし Marlin の顧客価値には**まだ直結していない** |

**結論**: ①②④は構造的に正しい。③は模倣容易。
つまり Sakana の堀は「AB-MCTS そのもの」ではなく、
**「探索を長時間安定に走らせるエンジニアリング資産」＋「金融/コンサルの初期顧客基盤」** にある。`C`

## 4. Marlin の弱点仮説（＝ Integral Prism の入り口）

以下は批判ではなく、**同じ土俵で戦わないための整理**である。

1. **報酬設計の穴**
   ビジネスリサーチには機械検証可能な正解がない。木探索は「良さそうに見える枝」を深掘りする傾向を持ち、
   **自己評価が報酬なら、確信度の高い誤りが最も深く掘られる**。
   実証的に、Deep Research 系はツール呼び出しを 2 → 150 に増やすと **引用の事実正確性が平均約42%低下**する `[S-057]`。
   「長く探索するほど良い」は自明ではない。

2. **成果物が「レポート」で終わっている**
   100ページのレポートは、投資委員会（IC）にとって**入力であって出力ではない**。
   PE の実務家が欲しいのは「読み物」ではなく、
   *この投資仮説を殺しうる事実は何か / それは今いくら確からしいか / 誰が次に何を確認すべきか* である（→09）。

3. **8時間の不可視性**
   途中で軌道修正できない長時間バッチは、実務では嫌われる。
   ユーザ調査では「リアルタイムに研究方向を操舵したい」という要求が繰り返し報告されている `[S-034]`。
   Sakana の設計は自律性に振り切っており、**mixed-initiative（協働）に弱い**可能性が高い。`C`

4. **監査可能性**
   数千回の LLM 呼び出しの結果として出た結論は、**なぜそう結論したかの経路が復元しにくい**。
   EU AI Act の高リスク要件（Art.12/13、2026-08-02 施行、10年保持のログ）を踏まえると、
   金融領域では「探索木そのものが監査証跡である」設計が要る（→09, 10）。`B`

5. **知識が案件をまたいで蓄積されない可能性**
   1実行 = 1レポートの課金モデルは、**知識の累積を製品価値にしない**構造を生みやすい。
   PE ファンドの真の資産は「過去100件の案件で何を見て、何を外したか」である。ここは空いている。`C`
