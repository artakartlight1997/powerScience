# 09. PE/VC 実務・データ・規制

## 1. 採用実態（2026）

| 指標 | 数値 | 出典 |
|---|---|---|
| 大手 PE のうち、投資ライフサイクルのいずれかで agentic AI を試験導入/拡大中 | **60%超**（McKinsey 推計） | `[S-076]` |
| 生成 AI を使うディールメーカー | **86%** | `[S-076]` |
| 取り組みが期待に一致/超過と回答したファンド | **95%** | `[S-076]` |
| **実際にスケールできている**ファンド | **10〜15%** | `[S-076]` |
| 文書抽出・スクリーニングの時間削減 | **70〜85%**、回収期間 9ヶ月未満 | `[S-076]` |
| DD 期間 | 「1週間 → 1日」の事例報告 | `[S-077]` |

**読み取り**: 関心ではなく **実行（scaling）がボトルネック**。
つまり市場が求めているのは「もっと賢いモデル」ではなく、
**既存ワークフローに接続でき、監査に耐え、繰り返し運用できるシステム**。

## 2. デューデリの工程と、AI の効きどころ

```
ソーシング → 初期スクリーニング → IOI/LOI → 本格 DD ─┬─ 財務 DD（QoE, 運転資本, 会計方針）
                                                     ├─ 商業 DD（市場規模, 競合, 顧客, チャネル）
                                                     ├─ 法務 DD（契約, 訴訟, 許認可, CoC条項）
                                                     ├─ 人事/組織 DD（キーマン, 離職, 報酬）
                                                     ├─ IT/セキュリティ DD
                                                     └─ ESG/規制 DD
   → IC メモ → 価格・条件交渉 → SPA → PMI/100日計画 → モニタリング → Exit
```

| 工程 | AI の現状 | IP の狙い |
|---|---|---|
| ソーシング/スクリーニング | 既に量産可能（コモディティ） | ここでは戦わない |
| 商業 DD | Marlin/DR の主戦場。**一次情報が薄いのが弱点** | 顧客インタビュー設計・専門家質問の**生成と優先順位付け** |
| 財務 DD | 数値抽出は成熟。**判断（正常化、質の評価）は未解決** | XBRL 再計算＋会計方針変更の検出＝**検証器の権限**（→05） |
| 法務 DD | 抽出は Hebbia 等が強い | 契約条項 → **バリュエーション/リスクへの影響伝播** |
| IC メモ | 生成は容易。**IC での質問に耐えるかは別** | **反証済みであることを保証する**（→07） |
| PMI/モニタリング | 手つかずに近い | **仮説の追跡（thesis tracking）**＝差別化の第二波 |

**最重要の洞察**: 商業 DD で PE が本当に買っているのは「市場レポート」ではなく、
**「この投資仮説を殺しうる事実が、探したのに見つからなかった」という確信**である。
これは *生成* ではなく *探索の網羅性の証明* の問題。**まさに 05/07 の設計が効く。**

## 3. データ源の地図

### 公開（機械可読）
- **日本**: EDINET（有報・四半期）、TDnet（適時開示）、J-Quants（株価）、官報、特許（J-PlatPat）、
  法人番号、登記、統計（e-Stat）
  - XBRL 構造化の実務課題が既知：**企業別タクソノミ拡張・表構造・注記の非定型性** `[S-078]`
  - 有報は **XBRL（構造化）＋ MD&A/リスク情報（非構造化）のハイブリッド** `[S-078]`
  - 2026年時点で「Claude Code で日本株データを分析する」等の実務ガイドが出回っている `[S-078]`
- **米国**: EDGAR/XBRL、8-K、S-1、13F、FTS

### 準公開・有償
求人（採用動向＝戦略の先行指標）、レビュー（Glassdoor/口コミ）、アプリ/Web トラフィック、
輸出入・物流、クレジットカード集計、衛星、業界誌、特許・論文、専門家ネットワーク（expert network）

### プライベート（ファンド内）
過去 IC メモ、DD レポート、VDR、ポートフォリオ実績、CRM、**外した案件の記録**

> **戦略的含意**: ①と②は誰でも買える（コモディティ）。**③がファンドの独自資産**。
> Integral Prism は ③を安全に取り込み、**外に漏らさずに**価値へ変換する構造が要る。
> ここは Marlin（汎用 SaaS）にも Google（分布勝負）にも真似しにくい。

## 4. 規制・コンプライアンス（設計制約であり、同時に堀）

- **EU AI Act**: 高リスク AI の義務が **2026-08-02 から完全適用**。制裁は最大 **€35M または全世界売上の7%** `[S-079]`
- **監査証跡**（Art.12/13）: タイムスタンプ付きログ、モデルバージョン追跡、人間レビュー記録、
  **展開後10年の保持**、**改竄検知可能な保存**（追記専用・暗号連鎖）`[S-079][S-080]`
- **人間による監督**: 異常時に介入・停止できる設計が必須 `[S-079]`
- 金融領域では ISO/IEC 42001 やプライベートネットワーク要件も絡む `[S-079]`

### 金融固有
- **MNPI（重要な未公開情報）**: エージェントが横断検索する構造は、**情報障壁（Chinese Wall）を壊しうる**。
  ケース単位のデータ隔離とアクセス統制が設計要件。
- **専門家ネットワーク**利用時のコンプライアンス（顧客企業の内部情報の取り扱い）
- 学習非利用の保証（Marlin も明示している `[S-005]`）は**最低ライン**であって差別化ではない

**含意（設計原則 #12）**:
**監査証跡を後付けしない。探索木・証拠・判断の系譜そのものを、改竄検知可能な形で一次記録にする。**
これは 07 の検証スタック L0 と同じものであり、**規制対応とプロダクト価値が同一の実装で満たされる**稀なケース。

## 5. 競合プロダクト（金融特化レイヤ）

| プロダクト | 強み | 弱み/空白 |
|---|---|---|
| **AlphaSense** | 14年、6,000社。市場・競合インテリジェンス、エキスパートコール書き起こし `[S-081]` | 汎用検索寄り。判断の較正は扱わない |
| **Hebbia (Matrix)** | 大規模文書横断の並列クエリ・構造化抽出 `[S-081]` | **抽出**が中心。仮説と反証の構造がない |
| **Rogo** | セルサイド IB ワークフロー（コンプス、CIM、ピッチ）`[S-081]` | 定型成果物の自動化。判断支援ではない |
| **BlueFlame AI (Amp)** | ディールサイクル全体のオーケストレーション、金融ネイティブ `[S-081]` | モデル/ツールの束ね。反証・較正は未対応 |
| **Sakana Marlin** | 長時間探索・レポート生成 | 09 の実務工程への接続が薄い（`C`） |

**空白の総括**: 誰も **「反証」と「較正」** を売っていない。
全員が **「速く・多く・きれいに作る」** を売っている。
