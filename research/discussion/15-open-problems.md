# 未解決の難問

**設計討論の最後に、「まだ解けていないこと」を正直に並べる。**
ここを隠すと、実装で必ず詰まる。

## 1. 技術的に解けていない

### O1: 定性主張の接地 ★最大の難問
```
「市場は年率12%成長する」    → 出典を当たれば検証できる（解ける）
「経営陣は優秀である」        → 何を照合すればよいのか（解けていない）
「この参入障壁は持続する」    → 同上
```
- FineVerify のサブ質問分解 `[S-102]` は**数値・事実主張には効く**が、定性は未検証（Q20/E4）
- **暫定案**: 定性主張は「検証」ではなく「**反証課題への変換**」に回す
  （「経営陣は優秀」→「離職率は？ 前職の実績は？ 主要メンバーの在籍年数は？」）
- **残る問題**: 変換の網羅性をどう保証するか

### O2: 証拠の独立性
```
3つの記事が同じことを言っている → 元が同じプレスリリースなら、証拠は1つ
```
- `derived_from` 辺で引用の連鎖を辿る設計にしたが、**辿れないケースが多い**（出典が書かれていない）
- **確率計算で独立性を仮定すると、確信度が過大になる**（最も危険な誤り）
- **暫定案**: 独立性が確認できない証拠は**同一クラスタとして1件に縮約**する（保守的に倒す）

### O3: 網羅性の分母が分からない
```
「見落とし率」を測るには「見落としうる全事象」が要る。それは原理的に得られない
```
- 反実仮想 DD は「**実際に問題化した事象**」を分母にする（＝生存バイアスの一種）
- 問題化しなかったが危なかった事象は、永遠に測れない
- **暫定案**: 「実際に問題化した事象の Recall」と明記し、**網羅性を主張しない**

### O4: 較正の母数不足
```
案件は年5–15件。Brier を安定させるには数百の予測が要る
```
- **暫定案**: 案件単位ではなく**命題単位**で母数を稼ぐ（1案件に20–50の検証可能命題）
- **残る問題**: 命題間の相関（同じ案件の命題は独立でない）

### O5: 型層の抽象化における情報漏洩
```
「顧客集中は、こう検証すると決着する」は横断してよい（A9）
しかし「上位2社で68%の SaaS 企業で、解約が起きた」は、特定できてしまうかもしれない
```
- **暫定案**: 型層には**数値と業種の粒度を落として**格納（「顧客集中が高い」まで）
- **残る問題**: k-匿名性の保証をどう設計するか。**法務レビュー必須**（U7）

### O6: MNPI の自動判定
- 質問生成器に「MNPI を引き出す質問を作らせない」フィルタが必要（→ [t-primary-research](../topics/04-domain/primary-research-and-expert-networks.md)）
- **禁止パターンの体系が手元にない**（Q29）
- **暫定案**: 保守的な禁止リスト＋人間の最終確認。**自動化しない**

## 2. 実務的に解けていない

### O7: 「調べても分からない」の扱い
```
EVPI が高い論点でも、情報が世の中に存在しないことがある
（例: 未公表の解約交渉、経営陣の本音）
```
- 探索が空振りしたとき、**「調べたが分からなかった」を価値として提示できるか**
- **暫定案**: 「未解決のまま残るリスク」として明示し、**契約条件（表明保証・アーンアウト）に落とす提案をする**
  → これは実は**強い価値**かもしれない（DD の目的の一つは、リスクを契約に転嫁すること）
- **要検証**: 実務家がこれを価値と認めるか

### O8: 人間の入力品質のばらつき
- I1'（死因を3つ書く）の品質は人によって大きく違う `推定`
- 良い死因を書ける VP と、書けないアソシエイトで、**製品の価値が変わってしまう**
- **暫定案**: 型ライブラリから**選択式**にする（自由記述＋候補提示のハイブリッド）

### O9: 「反証」の心理的受容
- F1 で部分的に成立が確認された（ソーシング段階では歓迎されない）
- **言葉を変えれば済むのか、それとも本質的な抵抗があるのか**が未検証
- **要検証**: モックを見せたときの表情と最初の一言（ヒアリングで観察する）

### O10: 誰が最初の顧客になるか
- PE 本体 / DD ファーム / 事業会社の投資部門 / 銀行 — **セグメントが未確定**（U8、穴 H3）
- **DD ファームの方が導入が速い可能性**（彼らは分析が本業で、ツール投資に抵抗が少ない `推定`）
- **要検証**: 両方に当たってみる

## 3. この一覧の使い方

```
O1 / O2 / O5 → 設計に直接効く。M1 の前に暫定案を決める
O3 / O4      → 評価の限界。★主張を誇張しないための歯止めとして使う
O6           → 法務・コンプラと詰める
O7 / O8 / O9 → 顧客ヒアリングで観察する
O10          → 最初のヒアリング先の選定そのもの
```

> **重要**: この一覧は**弱みの告白ではなく、資産である。**
> 競合が同じ問題に気づいていないなら、我々は先に走っている。
> そして **O3（網羅性の分母）を正直に扱うことは、信頼の源になる。**
> 「見落としゼロ」と言う競合より、「**実際に問題化した事象の 6割を事前に指摘した**」と言う方が強い。
