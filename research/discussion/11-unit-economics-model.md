# 単価と原価のモデル

**「粗利が出るのか」を、仮定を明示して計算する。** 全て `推定`。M0 後に実測で置き換える。

## 1. 1案件あたりの変動費（DD 1本）

### 前提（明示する）
```
IC メモ           : 30–60ページ
関連資料（VDR等）  : 300–1,500ページ
主張の数           : 40–80件
反証課題           : 10–25件
検索クエリ         : 100–300回
実行時間           : 20分–2時間
```

### 内訳

| 費目 | 計算 | 金額 `推定` |
|---|---|---|
| **文書取り込み（OCR/レイアウト）** | 1,000ページ × ¥1–3/ページ | **¥1,000–3,000** |
| **抽出・正規化 LLM** | 入力 1–2M トークン、キャッシュ 70% で実効 0.3–0.6M `[S-129]` | **¥1,000–3,000** |
| **検証（接地）** | 60主張 × 5サブ質問 × 2.5k トークン ≒ 0.75M（別ベンダ、キャッシュ効きにくい） | **¥3,000–8,000** |
| **探索（検索 API）** | 200クエリ × ¥2–20/クエリ `[S-020]` | **¥400–4,000** |
| **数値エンジン** | コード実行（自前） | **¥100 未満** |
| **ストレージ（スナップショット）** | 1案件 数GB | **¥100–500** |
| **小計（機械）** | | **¥5,600–18,500** |
| **人間 QA**（初期は必須） | 0.25–1 人日 × ¥50,000–150,000 | **¥12,500–150,000** ← ★支配的 |
| **合計** | | **¥18,000–170,000** |

> ### 🔑 決定的な洞察
> **機械の原価は誤差レベル。原価は「人間 QA」で決まる。**
> したがって **粗利率を決めるのは、出荷ゲートの自動化率**である。
> - 自動ゲートが緩い → 人間 QA が厚くなる → 粗利が消える
> - **G1–G15 の自動化は、品質施策であると同時に、粗利施策**（→ [../coding-strategy/07-quality-gates.md](../coding-strategy/07-quality-gates.md)）

## 2. 価格別の粗利（1案件）

| 価格 | 機械原価 | 人間QA（初期） | 粗利率（初期） | 人間QA（成熟） | 粗利率（成熟） |
|---|---|---|---|---|---|
| ¥300,000 | ¥12,000 | ¥75,000 | **71%** | ¥12,500 | **92%** |
| ¥500,000 | ¥12,000 | ¥75,000 | **83%** | ¥12,500 | **95%** |
| ¥1,000,000 | ¥18,000 | ¥150,000 | **83%** | ¥25,000 | **96%** |

**→ 価格 ¥300,000 でも成立する。** 原価は制約にならない。**制約は「買ってもらえるか」だけ。**

## 3. 1顧客あたりの年間売上（`推定`）

```
中規模 PE の年間案件数:
  初期検討まで   50–150件
  本格 DD まで   10–30件
  IC 提出まで     5–15件

課金対象を「IC 提出まで」とすると:
  年 5–15件 × ¥300,000–1,000,000 = 年 ¥1.5M–15M / ファンド
  ＋ サブスク（記憶・監査基盤）年 ¥3.6M–12M
  = ARPU 年 ¥5M–27M
```

**「本格 DD まで」に広げると 2–3倍**になるが、初期は IC に絞る（→ 05 の楔）。

## 4. 損益分岐（`推定`）

```
チーム 5人（エンジニア3 / ドメイン1 / 営業1）
  人件費         年 ¥60M–90M
  インフラ・API   年 ¥5M–15M
  データ調達      年 ¥5M–20M（ベンダーライセンス）
  合計           年 ¥70M–125M

必要顧客数 = ¥70M–125M ÷ ARPU ¥5M–27M
           = 3社（強気） 〜 25社（弱気）
→ 現実的な目標: 初年度 3–5社、2年目 10–15社
```

> **これは「大量の顧客が要る事業ではない」ことを意味する。**
> **数社の深い顧客で成立する。** → **顧客ごとの深さ（記憶・正本化）に投資する戦略と整合する。**

## 5. 感度分析（自社にトルネードをかける）

**どの前提が事業を反転させるか。** 我々の製品思想を自分に適用する。

| 前提 | 悲観 | 基準 | 楽観 | **事業への影響** |
|---|---|---|---|---|
| **1案件あたり価格** | ¥100,000 | ¥500,000 | ¥1,500,000 | **★最大**（15倍の幅） |
| **年間課金案件数/社** | 3 | 8 | 25 | **★大**（8倍） |
| **顧客数（2年目）** | 3 | 10 | 20 | **★大** |
| 人間 QA の削減率 | 0% | 70% | 95% | 中（粗利率 71%→96%） |
| 機械原価 | 2倍 | 基準 | 半分 | **小**（誤差） |
| 導入期間 | 18ヶ月 | 12ヶ月 | 6ヶ月 | 中（キャッシュに効く） |

> ### 🔑 結論
> **原価の最適化に工数を割く価値はほとんどない。**
> **価格帯と課金案件数（＝どの工程まで入り込めるか）が、事業を決める。**
> → だから **05 の「楔をどう広げるか」が、技術より重要**である。

## 6. 反証条件

- 人間 QA が **90%以上必要**な品質しか出せないなら、粗利率が 50% を割り、事業として弱くなる
  → **G7–G15 の自動ゲートが機能するかが、事業の前提条件**（M1 の終了条件に含める）
- 価格 ¥100,000 でしか売れないなら、**顧客数を 3倍必要**とし、深い顧客戦略が崩れる
  → その場合は**セルフサーブ型に転換**するか、撤退を検討
