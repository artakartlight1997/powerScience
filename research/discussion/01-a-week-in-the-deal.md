# 投資プロの1週間 — 解像度を上げる

**設計を実務から逆算するために、まず「時間がどこに溶けているか」を書き出す。**
`推定` はヒアリングで検証する（Q12/Q25/Q28）。

## 1. ディールの時間配分（中規模 PE、1案件、`推定`）

| 工程 | 期間 | 主な作業 | 人時 `推定` | 痛みの所在 |
|---|---|---|---|---|
| ソーシング / 初期選別 | 常時 | ロングリスト、簡易スクリーニング | 20–40h | **量。ただし既に自動化が進む** `[S-076]` |
| 初期検討 → IOI | 2–4週 | 事業理解、市場規模、簡易バリュエーション | 60–120h | 情報が薄い段階で「進めるか」を決める |
| **本格 DD** | **6–10週** | 財務/商業/法務/人事/IT/ESG | **400–1,000h** | **ここに全部ある** |
| ├ 財務 DD | | QoE、運転資本、会計方針 | 100–250h | 数字の正常化。**外部会計事務所に外注**が多い |
| ├ 商業 DD | | 市場、競合、顧客、チャネル | 100–300h | **一次情報が薄い**／外部 DD ファームに **¥5M–30M** |
| ├ 法務 DD | | 契約、訴訟、許認可、CoC | 80–200h | 弁護士費用。**条項→価格影響の翻訳が属人的** |
| └ その他 | | 人事/IT/ESG | 60–150h | |
| IC 準備 | 1–2週 | メモ執筆、想定問答、資料 | 40–80h | **IC で刺される論点の予測** |
| 交渉 / SPA | 2–6週 | 価格・表明保証・アーンアウト | 60–150h | DD の発見を条件に落とす |
| PMI / モニタリング | 100日〜数年 | 統合、KPI 追跡 | 継続 | **ほぼ手つかず** `[S-076]` |

## 2. 時間が溶ける具体的な場所（設計の標的）

| # | 溶ける場所 | 現状 | 我々が効くか |
|---|---|---|---|
| **P1** | **エキスパートコールの分析** | 1万語×30本 → **シニアで3–4日** `[S-135]` | △ 要約は既に他社が提供。**質問設計**なら◎ |
| **P2** | **VDR の資料読み込み** | 数百〜数千ファイル | ○ 抽出は既存製品が強い `[S-081]` |
| **P3** | **数字の突合** | 開示 vs マネジメント資料 vs 実績 | ◎ **矛盾検出は我々の中核**（P20） |
| **P4** | **IC メモの裏取り** | 「この数字の出典は？」で往復 | ◎◎ **出典スナップショット＋座標で30秒に** |
| **P5** | **IC の想定問答** | パートナーが何を突くかを予想 | ◎ **反証エンジンの出力そのもの** |
| **P6** | **前提の感度分析** | Excel で手作業、属人的 | ○ トルネード/EVPI `[S-121]` |
| **P7** | **過去案件の参照** | 「あの時どうしたっけ」→ 人に聞く | ◎ ケースベース記憶（M4） |
| **P8** | **モニタリング** | 四半期報告を読む | ○ thesis tracking（第二波） |

> ### 🔑 P4 と P5 が最も筋が良い理由
> - **P4（裏取り）**: 我々の証拠グラフが**構造的に**解決する。副産物ではなく必然。
> - **P5（想定問答）**: **反証エンジンの出力が、そのまま IC の想定問答になる。**
>   投資プロにとって「IC で刺されなかった」は**極めて具体的な実益**である。
>   しかも**その日のうちに効果が分かる**（＝デモで伝わる）。

## 3. 「IC で刺される」の中身（`推定`、要検証）

パートナーが典型的に刺す論点:
```
1. 「この成長は市場のもの？ それとも一時的な特需？」        → 仮説の切り分け
2. 「上位顧客の集中度は？ 解約されたらどうなる？」          → 集中リスク
3. 「この利益は正常化後でいくら？ 一過性は抜いた？」        → QoE
4. 「キーマンが辞めたら？」                                → 人的リスク
5. 「競合が同じことをやったら？」                          → 参入障壁
6. 「なぜ売主は今売るのか？」                              → 情報の非対称
7. 「その数字の出典は？ いつの数字？」                      → ★裏取り
8. 「前提が◯◯だったら IRR はどうなる？」                   → 感度
```

**1–6 は仮説と反証、7 は出典、8 は感度。全て我々の設計の射程内にある。**
逆に言えば、**IC の想定問答を出せない製品は、投資プロにとって実益が薄い。**

## 4. 誰が実際に使うのか（ペルソナ）

| 役割 | 何に困っているか | 我々への期待 | 導入の障害 |
|---|---|---|---|
| **アソシエイト**（20代後半） | 裏取りと資料作りで深夜 | **時間**（V1） | 「AI が作った」と言えない空気 |
| **VP / ディレクター** | IC で刺される、見落としが怖い | **見落とし回避**（V2） | 自分の判断を機械に否定されたくない |
| **パートナー / IC 委員** | 判断の質、説明責任 | **V2 + V4** | 使うのは他人。だが**予算を握る** |
| **リサーチ / 分析チーム** | ツールの運用 | 標準化 | 既存ツールとの重複 |

> ### 設計への示唆
> **買うのはパートナー、使うのはアソシエイト、価値を感じるのは VP。**
> → **UI はアソシエイト向け、価値訴求は VP 向け、購買資料はパートナー向け**に、
> **3層で作り分ける必要がある。** 1つの資料で全員を説得しようとすると失敗する。

【決着】**最初の標的は P4（裏取り）と P5（想定問答）。両方とも VP の痛みであり、IC の直前に効く。**
【未決】上記の人時と外部費用は `推定`。**顧客ヒアリング5–10件で検証する**（Q12/Q28）
