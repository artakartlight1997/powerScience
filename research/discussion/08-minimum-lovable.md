# 実益を最短で出す最小形

**抽象論を終える。具体的な画面と成果物を書く。**

## 1. 成果物（1枚目）— 「IC レディネス・シート」

```
┌──────────────────────────────────────────────────────────────┐
│  案件: ◯◯社  |  基準日: 2026-08-22  |  検証済み: 42/47 主張    │
├──────────────────────────────────────────────────────────────┤
│  ▍ IC で問われそうな論点（重要度順）                            │
│                                                                │
│  1. 顧客集中 — 上位2社で売上の68%                    [重要度 高] │
│     根拠: 有報 P.34 [開く] / マネジメント資料 P.12 [開く]        │
│     ⚠ 食い違い: 有報68% vs MGMT資料 54%  ← 未解決                │
│     → 決着させるには: 顧客別売上の月次推移（VDR 未提出）          │
│                                                                │
│  2. 成長は市場要因か特需か                            [重要度 高] │
│     あなたが挙げた死因: なし  ← ★差分                           │
│     根拠: 競合3社も同時期に同率成長 [開く]                       │
│     → 決着させるには: 業界統計 or 顧客ヒアリング3件（想定 ¥180,000)│
│                                                                │
│  3. 会計方針の変更（FY23 に売上認識を変更）           [重要度 中] │
│     ...                                                        │
├──────────────────────────────────────────────────────────────┤
│  ▍ 根拠が見つからなかった主張（5件）                            │
│     「市場は年率12%成長」— 出典なし                             │
│     「解約率は業界平均以下」— 出典なし                          │
│     ...                                                        │
├──────────────────────────────────────────────────────────────┤
│  ▍ 調査の打ち切り理由                                          │
│     残る論点3件の期待情報価値 合計 ¥340,000 に対し、             │
│     取得コスト ¥520,000。→ これ以上は判断が変わらないと判断      │
└──────────────────────────────────────────────────────────────┘
```

**この1枚に、我々の設計思想が全部入っている**:
- 出典の座標ジャンプ（証拠グラフ・L1）
- **矛盾の保存と提示**（P20）— 平均しない
- **人間の死因先出しとの差分**（論点2）
- 未解決論点とその決着方法（反証エンジン）
- **調査を止めた理由の説明**（EVPI）← 他社が絶対に出せない
- 基準日の常時表示（point-in-time）

## 2. 画面（3つだけ）

| 画面 | 内容 | 誰が使う |
|---|---|---|
| **① 投入** | メモをドラッグ＆ドロップ ＋ **「死因を3つ書く」欄（30秒）** | アソシエイト / VP |
| **② レディネス・シート** | 上記1枚 | VP / パートナー |
| **③ 証拠ビュー** | 主張をクリック → 原文がハイライトされて開く | 全員（**裏取りの現場**） |

**作らない画面**: ダッシュボード、チャット、設定の海、進捗のアニメーション。

## 3. 60秒デモの台本

```
0:00  「IC メモをください」→ ドロップ
0:05  「まず、この投資の死因を3つ書いてください」→ VP が書く（ここが仕掛け）
0:35  実行
1:00  「47の主張のうち5つは、資料の中に根拠がありません」← 空気が変わる
1:15  クリック → 「該当なし」
1:25  「そして、この主張は有報と食い違っています」→ 両方を並べて表示 ← ★決定的
1:40  「あなたが挙げなかった論点が2つあります」← 差分の提示
1:55  「残る論点は、あと ¥180,000 の調査で決着します」
```

> **1:25 が勝負**。矛盾を並べて見せた瞬間に、
> 「これは要約ツールではない」と伝わる。**汎用 LLM は矛盾を平均するか抑制する** `[S-125]`。

## 4. 最小形に含めない（が、器は作る）

| 除外するもの | 理由 | いつ入れるか |
|---|---|---|
| 確率の数値表示 | F2 が未検証。誤った精密さのリスク | 顧客が求めたら（論点3） |
| ケース記憶 | 案件が溜まらないと価値が出ない | M4（器は M1 から） |
| 自動 Web 探索 | セキュリティ審査と、精度劣化のリスク | M2 以降、限定的に |
| レポート生成 | 生成は100倍安い `[S-112]`。差別化にならない | 副産物として後から |
| 財務モデル構築 | M0/E1 の結果次第 | E1 が通れば M2 |

## 5. 最小形の成立条件（これが満たせなければ作り直し）

```
□ 実在の IC メモで、根拠なし主張を 3件以上検出できる
□ 矛盾を 1件以上検出できる
□ 誤検出（実際は根拠がある主張を「なし」と言う）が 5% 未満
□ 人間の死因と AI の論点の差分が、実際に「気づき」になる
□ 投入から結果まで 30分以内
□ 顧客データを外部 API に出さない構成が選べる
```

**この6つが M1 の終了条件**（→ [../coding-strategy/05-milestones.md](../coding-strategy/05-milestones.md)）
