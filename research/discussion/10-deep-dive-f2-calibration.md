# F2 の徹底解剖

**02 で唯一「反証しきれなかった」失敗仮説。事業の生死に直結するので、単独で掘る。**

> **F2**: 較正された確率は、投資実務では使われない。
> 「この前提が成り立つ確率は 62%」と言われて、投資委員会は何をするのか。

## 1. なぜ確率が拒否されるのか（メカニズムの分解）

拒否には**5つの異なる理由**があり、対処法がそれぞれ違う。混ぜて議論してはいけない。

| # | 拒否の理由 | 中身 | 対処可能性 |
|---|---|---|---|
| **R1 誤った精密さ** | 「62%」の2桁目に意味があるのか。根拠を問われて答えられない | ◎ **表示を粗くすれば解決**（高/中/低、または 60±15%） |
| **R2 行動に繋がらない** | 62% と言われて、Go にするのか No にするのか変わらない | ◎ **決定境界と紐づければ解決**（「55%を割ると価格を10%下げるべき」） |
| **R3 責任の所在** | 機械の確率で判断したと言えない。**署名するのは人間** `[S-118]` | ◎ 確率は**補助**であり判断ではないと位置づける |
| **R4 実務の慣習** | 実務は3シナリオ（ベース/アップ/ダウン）で扱う `推定` | ○ **シナリオ確率として出せば慣習に乗る** |
| **R5 そもそも当たらないと思っている** | 「将来のことは誰にも分からない」 | △ **較正の実績提示でしか崩せない**（時間がかかる） |

> ### 🔑 重要な発見
> **R1–R4 は「表示と接続の設計」で解ける。R5 だけが本質的な壁である。**
> つまり **F2 は「確率が使われない」ではなく「素の点推定確率が使われない」**である可能性が高い。
> これは**製品を殺す仮説ではなく、UI を規定する仮説**かもしれない。

## 2. では、投資プロは実際に何を使っているのか（`推定`、要検証）

| 実務の道具 | 中身 | 確率との関係 |
|---|---|---|
| **3シナリオ** | ベース / アップ / ダウンの IRR | **暗黙の確率**（等確率でないことは皆知っている） |
| **感度分析** | 前提を振って IRR がどう動くか | **確率なしの不確実性表現** |
| **ダウンサイド・プロテクション** | 「最悪でも元本は守れるか」 | **裾の確率**を気にしている |
| **ブレークイーブン分析** | 「成長率が何%を割ると損するか」 | **決定境界そのもの** |
| **赤旗リスト** | IC メモの「懸念事項」欄 | **確率ではなく列挙** |

> **観察**: 実務家は確率を口に出さないが、**裾（ダウンサイド）と閾値（ブレークイーブン）は必ず見ている**。
> **我々が売るべきは「62%」ではなく、「この前提が◯◯を割ると判断が反転する。その可能性は無視できない」である。**

## 3. 3つの表示案を設計して、顧客に選ばせる（検証設計）

**議論で決めない。モックを3つ作って見せる。** これが U1 の検証方法。

### 案α: 確率を出さない（列挙のみ）
```
未解決の論点（重要度順）
  1. 顧客集中 — 上位2社で68%          [重要度: 高]
  2. 成長の持続性                      [重要度: 高]
```
- 拒否リスク: 最小
- 差別化: **薄い**（既存の「懸念事項リスト」と同じに見える）

### 案β: 決定境界と紐づける（★推奨）
```
判断が反転する条件
  1. 上位2社の解約 → IRR が hurdle を下回る
     現時点の評価: 「起こりにくいが、起きたら致命的」
     決着させる方法: 顧客別月次売上（VDR 未提出）／ 想定コスト ¥120,000
  2. 成長が市場要因だった場合 → 出口マルチプルが 1.5x 下振れ
     現時点の評価: 「競合3社も同率成長」という反証材料あり ← ★要注意
```
- **確率を数値で出さず、「判断への影響」で語る**
- R1/R2/R3/R4 を全部回避しつつ、**中身は確率計算そのもの**
- 差別化: **強い**（他社は「判断が反転する条件」を出せない）

### 案γ: 確率を明示
```
  1. 顧客集中による下振れ確率: 23%（±8%）
     過去の較正実績: 当社の「20-30%」は実際に 26% で実現（n=47）
```
- 拒否リスク: **最大**
- 差別化: **最大**（較正実績は誰も出していない）
- **n が溜まるまで出せない**（鶏と卵）

**【暫定決着】案β を既定、案γ を「開けば見える」層に置く。**
案α は差別化が薄すぎるので採らない。
**【検証】** 3案のモックを顧客5–10名に見せ、**どれを見たいかではなく「どれなら IC に持って行くか」を聞く** 🔧

## 4. F2 が本当だった場合の退路

| 前提 | 我々に残るもの |
|---|---|
| 確率表示が全否定される | **反証（仮説A）と記憶（仮説C）は無傷**。案β の「判断が反転する条件」は確率を出さずに成立する |
| 較正の実績提示も無意味とされる | 検証（Fact Check）と監査（V4）は残る |
| **全部否定される** | そのときは **V1（時間短縮）製品**しか残らない → 撤退判断（→ [08-risks](../coding-strategy/08-risks-and-kill-criteria.md) B1） |

> **重要**: **確率は内部では必ず持つ。**
> 探索の優先度づけ（EIG）に必須であり、**表示するかどうかとは独立の問題**である。
> F2 が真でも、**内部の確率計算は捨てない。**

## 5. 逆側の検討 — F2 が偽である証拠は何か

公平を期すため、**確率が受け入れられる証拠**も探す。

| 証拠 | 強さ |
|---|---|
| クオンツ/ヘッジファンドは確率で会話する | ○ ただし **PE とは文化が違う** |
| 保険・与信の世界では確率が標準 | ○ ただし**大量反復がある領域** |
| LLM 予測が superforecaster 級に到達 `[S-060]` | △ 供給側の証拠であって需要側ではない |
| ダウンサイド・ブレークイーブンは既に使われている（2節） | **◎ 最も強い**。**確率的思考は既にある。表現が違うだけ** |

**【結論】F2 は「確率という言葉と数値表示への拒否」であり、「確率的思考への拒否」ではない `推定`。**
**したがって、案β（確率的計算を、実務の言葉で出す）が最も筋が良い。**
**【反証条件】** 顧客が案β すら「これは机上の空論」と言うなら、F2 は本物であり、仮説B を降ろす
