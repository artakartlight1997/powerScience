# 自社仮説への ACH 適用

> 我々の製品思想は「**支持証拠を集めるのではなく、反証されない仮説を採る**」である。
> **その思想を、まず自分たちに適用する。** ここで生き残らない設計は、顧客の前でも生き残らない。

## 討論の構造

競合仮説（我々の事業が失敗する理由）を列挙し、証拠で反証を試みる。
**最も反証されなかった失敗仮説が、我々の最大のリスクである。**

---

## 失敗仮説 F1: 「反証は売れない。人は肯定を買う」

**主張**: 投資プロは案件を進めたい。**反対材料を出す道具は、心理的に歓迎されない。**
「この案件はやめろ」と言うツールに、案件を進めたい人間が金を払うか。

### 反証の試み
| 証拠 | 効果 |
|---|---|
| IC で刺される論点を事前に潰すのは、**案件を通すため**の行為である（01, P5） | **強い反証**。反証エンジンは「案件を殺す道具」ではなく「**案件を通す道具**」として売れる |
| DD の本質は「買わない理由を探す」こと。実務家はそれを職業として行っている | 中程度の反証 |
| 一方、**ソーシング段階**では肯定バイアスが強い | F1 は**工程によって成立する**（初期検討では反証は歓迎されない） |

**【判定】部分的に成立。** ソーシング/初期検討では F1 が効く。**IC 前後では効かない。**
→ **設計への反映: 入口を「IC 前」に置く。**「案件を殺す」という見せ方をしない。
**画面の言葉を「反証」ではなく「想定問答」「未解決の論点」にする。** 🔧

---

## 失敗仮説 F2: 「較正された確率は、実務では使われない」

**主張**: 「この前提が成り立つ確率は 62%」と言われて、投資委員会が何をするのか。
**実務家は確率ではなく、Go/No-Go と価格で考える。** 誤った精密さ（false precision）は嫌われる。

### 反証の試み
| 証拠 | 効果 |
|---|---|
| LLM は superforecaster 級に到達している `[S-060]` | **技術的な可能性の証拠であって、需要の証拠ではない**。反証として弱い |
| 投資はそもそも確率的な営み（IRR の期待値、シナリオ分析） | 中程度。ただし**実務では「3シナリオ」で扱うことが多く、点推定の確率は使わない** `推定` |
| **較正の証明（Brier/ECE）は、組織の信頼獲得には効く** | ○ ただし**購買理由になるかは別** |

**【判定】反証しきれない。F2 は生き残る。**
→ **これは我々の最大級のリスク。** 仮説B（較正）は**技術的には正しいが、需要が未検証**。
→ **設計への反映**:
  - 確率は**内部の探索優先度づけに使い**、外部表示は**慎重に**する 🔧
  - 顧客向けの一次表示は「**未解決の論点とその重要度**」にし、確率は**任意で開く**
  - **F2 の検証を最優先**（Q12）。ここが空振りなら仮説B を降ろす（→ [08-risks](../coding-strategy/08-risks-and-kill-criteria.md) B1）

## 失敗仮説 F3: 「証拠グラフは過剰設計。ただの RAG で足りる」

**主張**: 出典リンクを貼るだけで実務は回っている。
**グラフ、追記専用、ハッシュ連鎖、taint 伝播** — 誰も求めていない工学的自己満足ではないか。

### 反証の試み
| 証拠 | 効果 |
|---|---|
| フロンティアの引用でも **Fact Check 39–77%** `[S-057]` | **強い反証**。「リンクを貼る」だけでは事実が合っていない |
| 探索を増やすと **−42%** `[S-057]` | 強い反証。素朴な実装は規模とともに壊れる |
| 5つの要求（検証・監査・taint・時点・圧縮）を**1構造で満たす** `[S-128]` | 強い反証。**別々に作る方が高くつく** |
| ただし **M1 でそこまで要るか** は別問題 | **部分的に成立** |

**【判定】ほぼ反証された。ただし「いつ作るか」には妥当性がある。**
→ **設計への反映**: スキーマは最初から正しく定義するが、
**実装は段階的**（M1 は最小のノード/辺だけ。taint とハッシュ連鎖は M1 で入れるが、
コミュニティ要約や記憶は後）🔧

## 失敗仮説 F4: 「PE はそもそもツールを使わない。使うのは外部のアドバイザーだ」

**主張**: 商業 DD は外部ファームに ¥5M–30M で外注する。財務 DD は会計事務所。
**PE 本体は薄い組織で、内製ツールに投資しない。**

### 反証の試み
| 証拠 | 効果 |
|---|---|
| 大手 PE の **60%超が agentic AI を試験導入/拡大中** `[S-076]` | 強い反証 |
| **86% のディールメーカーが生成 AI を使用** `[S-076]` | 強い反証 |
| ただし **scaling できているのは 10–15%** `[S-076]` | **F4 の変形が成立**: 「使うが、定着しない」 |
| 外部ファームこそが**我々の顧客**になりうる（DD ファーム向けに売る）| 反証というより**転換の選択肢** |

**【判定】原型は反証された。変形（定着しない）が生き残る。**
→ **設計への反映**: **定着を設計の一部にする。**
  - 1工程の**正本化**（system of record）から入る
  - 既存の Excel / VDR / メールのワークフローを壊さない
  - **「使わないと次の案件で困る」構造**（記憶の蓄積）を早期に作る
→ **販売先の選択肢に「DD ファーム」を残す** 🔧（PE より導入が速い可能性、要検証）

## 失敗仮説 F5: 「フロンティアかデータベンダーが、そのうちやる」

**主張**: OpenAI/Google が引用検証を標準搭載し、PitchBook が反証機能を出したら終わり。

### 反証の試み
| 証拠 | 効果 |
|---|---|
| **較正と棄権はモデル層が構造的に最適化しない**（評価が棄権を罰する `[S-108]`） | 強い反証。**フロンティアの動機がない** |
| 大手は「読みやすい100ページ」を売っており、**反証は自社の売りと矛盾する** | 中程度（イノベーターのジレンマ）`推定` |
| **顧客固有データの蓄積は複製できない** `[S-086]` | 強い反証（ただし**時間が要る**） |
| データベンダーはコネクタで全アプリに供給する道を選んだ `[S-134]` | 中程度の反証（彼らはアプリ層で戦っていない） |
| しかし **PitchBook Navigator は将来 DB 全体にアクセス**と表明 `[S-134]` | **F5 は完全には反証されない** |

**【判定】部分的に成立。時間との競争。**
→ **設計への反映**: **顧客データの蓄積（Class C）を最速で始める。**
  技術的優位（Class B）は時間で溶けるが、**蓄積は溶けない**。
  → M1 から**ケース記憶の器だけは作っておく**（中身は後で埋まる）🔧

## 失敗仮説 F6: 「精度事故で一発退場する」

**主張**: 誤引用1件、捏造された数値1つで、ファンド内の信用は消える。
**そして LLM は構造的に幻覚する** `[S-109]`。

### 反証の試み
| 証拠 | 効果 |
|---|---|
| 幻覚は**理論的に消えない** `[S-109]` | **反証できない**（前提として正しい） |
| ただし**検証は生成より容易**で、道具を与えるとギャップは広がる `[S-036]` | 強い緩和 |
| 数値は**コードで計算すれば確定的** `[S-131]`（P19） | 強い緩和 |
| **三値（NOT_FOUND）**で捏造を構造的に防げる `[S-090]` | 強い緩和 |

**【判定】リスクは消えないが、設計で管理可能。**
→ **設計への反映**: **出荷ゲート（Fact Check ≥95%、恒等式100%、捏造0）を例外なく適用**。
**「たまに間違えます」を許容する製品にしない。** それは我々の存在理由と矛盾する。

## 4. 生き残った失敗仮説（＝真のリスク）

| 順位 | 失敗仮説 | 生存度 | 対処 |
|---|---|---|---|
| **1** | **F2: 較正は使われない** | **高** | **最優先で顧客検証（Q12）**。空振りなら仮説B を降ろす |
| **2** | **F4′: 使うが定着しない** | **高** | 正本化・記憶・既存ワークフロー非破壊を設計に組む |
| **3** | **F5: 大手が降りてくる** | 中 | 顧客データ蓄積を最速で開始 |
| 4 | F1′: ソーシングでは反証が歓迎されない | 中 | 入口を IC 前に置く。言葉を変える |
| 5 | F3′: いつ作るか | 低 | 段階実装 |
| 6 | F6: 精度事故 | 低（管理可能） | 出荷ゲート |

【決着】**F2 と F4′ が本命のリスク。両方とも「技術」ではなく「需要と定着」の問題。**
【次の一手】**コードより先に、顧客ヒアリング5–10件で F2 を潰す。**
