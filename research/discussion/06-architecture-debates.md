# 設計上の6つの対立点

**各論点で両側を強く書き、決着と反証条件を置く。**

---

## 論点1: 証拠グラフ vs 素朴な RAG

**立場A（素朴側）**: 出典リンク付き RAG で十分。グラフは開発コストが3倍になり、M1 が遅れる。
実務家は「リンクが貼ってあれば」満足する。

**立場B（グラフ側）**: リンクは貼れても**事実が合っていない**（Fact Check 39–77% `[S-057]`）。
そして5つの要求（検証・監査・taint・時点・圧縮）を後から足すと、**作り直しになる**。

**【決着】立場B。ただし M1 のスキーマは最小限にする。**
- M1 で作る: Source / Evidence / Claim / Question の4型と、cites / supports / contradicts の3辺
- M1 で作らない: CaseMemory、コミュニティ要約、複雑な推論
- **ただし追記専用とハッシュ連鎖、as_of、trust_label は M1 から**（後付け不可能なため）
**【反証条件】** M1 の開発が4週を超えて遅延するなら、スキーマをさらに削る

---

## 論点2: 決定境界は人間が入れる vs 自動抽出

**立場A（自動）**: 人間に入力させるのは「AI が考えていない」ように見える。
LLM で IC メモから前提を自動抽出できるはず。

**立場B（人間）**: 意思決定分析の実務では**フレーミングは人間が行うのが標準**。
フレーミングの誤りは技法では救えない。しかも **AI の出力を先に見せると過信を招く** `[S-114]`。

**【決着】立場B を主、A を補助。**
```
① 人間が「この投資の死因を3つ」書く（30秒。★AI の出力を見る前）
② AI が独自に候補を列挙する
③ ★差分だけを提示する ←「あなたが挙げなかった論点が2つあります」
```
> **これが最も価値が伝わる瞬間である。**
> 人間の入力を「手抜き」ではなく「**差分を作るための基準線**」として設計する。
**【反証条件】** 顧客が入力を面倒がって使わないなら、①を任意にして②から始める

---

## 論点3: 確率を表示する vs しない

**立場A（表示する）**: 投資は確率的な営み。較正を証明できれば強い差別化（仮説B）。

**立場B（表示しない）**: **誤った精密さ**は嫌われる。「62%」の根拠を聞かれて答えられないと信用を失う。
そして **F2（較正は使われない）は反証されていない**。

**【決着】段階的に出す。**
| 段階 | 表示 |
|---|---|
| 既定 | **確率を出さない。**「未解決の論点」と「重要度（高/中/低）」だけ |
| 詳細を開く | 「この論点が判断を反転させる可能性」を**3段階＋根拠**で表示 |
| 上級者モード | 確率と較正履歴（Brier/ECE）を表示 |

**内部では最初から確率を持つ**（探索の優先度づけに必須）。**外部表示だけを段階化する。** 🔧
**【反証条件】** 顧客が「数字で欲しい」と言うなら既定表示を上げる（歓迎すべき反証）

---

## 論点4: 自律実行 vs インタラクティブ

**立場A（自律）**: 投げて待てるのは楽。Marlin の8時間は分かりやすい。

**立場B（対話）**: ユーザは**操舵したい** `[S-032]`。しかも **人間+AI は AI 単独に劣ることがある** `[S-114]`
＝ **雑に人間を入れると悪化する**。

**【決着】「非同期だが、介入点が設計されている」。**
```
実行は非同期（投げて閉じてよい）
ただし介入点は4つだけ、明示的に:
  I1' 死因の先出し（実行前・30秒・必須）
  I2  反証課題の優先順位（実行中・任意）
  I3  一次情報の投入（実行中・任意）
  I4  確度の上書き（実行後・任意）
★ 承認型 UI（「AI の提案を承認しますか」）は作らない ← 過信を招く `[S-114]`
```
**介入の価値を可視化する**: 「あなたの I1' により論点が2つ増え、うち1つが重要な事実に到達しました」

---

## 論点5: 案件単体 vs 横断記憶

**立場A（単体）**: MNPI と Chinese Wall がある。案件を跨ぐのは危険。シンプルに保て。

**立場B（横断）**: **記憶こそが唯一モデルに食われない堀** `[S-086]`。横断しないなら差別化が消える。

**【決着】「3層の記憶」で両立させる。** 🔧
| 層 | 内容 | 横断 |
|---|---|---|
| **案件層** | VDR、面談、その案件固有の証拠 | ❌ 物理分離 |
| **型層** | **死因アーキタイプ**（「チャネル依存」「ロールアップの統合失敗」…）と検証の手順 | ✅ 横断（**固有名詞を含まない**） |
| **公開層** | 業界構造、規制、公開企業の情報 | ✅ 横断 |

> **鍵は「型層」**。「A社の売上が上位2社で68%」は案件層（横断禁止）だが、
> **「顧客集中は、こう検証すると決着する」という型は横断してよい。**
> これで **MNPI を犯さずに、経験を蓄積できる。**
**【反証条件】** 法務レビューで型層も NG と判断されたら、記憶はファンド内に閉じる

---

## 論点6: 検証をどこまで厚くするか（コストとの綱引き）

**立場A（薄く）**: 全主張の全証拠を検証すると、コストとレイテンシが跳ねる。重要なものだけでよい。

**立場B（厚く）**: 我々の存在理由は検証である。**1件の誤引用で信用が飛ぶ**（F6）。

**【決着】粒度を適応制御する。** `[S-101]`（VG-Search の知見）
```
主要主張（IC メモの結論を支える）: 全数検証（Fact Check ≥95%）＋ 人間が開ける形で提示
補助的な記述                     : サンプル検証
数値                             : 100% 機械検証（恒等式）— 例外なし
矛盾候補                         : 全数（矛盾は最も価値が高い）
```
> 検証の**粒度が原価と品質を同時に決める**（適応制御で精度+3.1〜3.6%、FLOPs −52% `[S-101]`）。
> **「全部厚く」でも「全部薄く」でもなく、主張の重要度で変える。**
