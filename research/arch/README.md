# Integral Prism 設計仕様

> **対象**: 自社ファンドの投資プロが使う内製リサーチシステム（売らない）。
> **起動入力は「社名または業界名」のみ**。それ以外は全部システムが取りに行く。
> 本仕様は討論の全決定（P1–P24、discussion/18 補正1–4、スペック v0.3）を実装可能な形に落としたもの。

## システムを一言で

**固定の物差し（Biz DD スペック × 業態別ドライバーツリー）に対して、
毎回変動するリサーチ結果（Google DR・Speeda・TDB・コンサル報告書）を突き合わせ、
filled / thin / missing / unknown を機械判定し、薄い箱を最適チャネルで埋め、
その全過程を追記専用の証拠台帳に記録するカバレッジ監査システム。**

```
 投資プロの操作: ①社名を入れる ②届いた資料をフォルダに放り込む — 以上

  社名/業界名 ─┐
              ▼
  ┌─ 業態同定（箱0: セグメント×アーキタイプ）──────────────┐
  │   → スペックとドライバーツリーを実体化                    │
  └──────────────┬────────────────────────────────────────┘
                 ▼
  ┌─ 収集（並列・未信頼側）────────────────────────────────┐
  │  Google DR API / Web / EDINET / ニュース / 求人 / 官報   │
  │  ＋ 手動投入（Speeda・TDB の PDF、IM、コンサル報告書）    │
  └──────────────┬────────────────────────────────────────┘
                 ▼
  ┌─ ★証拠台帳（追記専用・ハッシュ連鎖・as_of・taint）───────┐
  │  抽出(三値) → 接地検証(別ベンダ) → 独立性クラスタ →       │
  │  数値再計算(コード) → 時点整合 → 矛盾検出(保存する)        │
  └──────────────┬────────────────────────────────────────┘
                 ▼
  ┌─ カバレッジ監査 ───────────────────────────────────────┐
  │  項目ごとに filled/thin/missing/unknown を判定            │
  │  （文字数でなく「検証済み・独立・新鮮な証拠の密度」で）      │
  └──────────────┬────────────────────────────────────────┘
                 ▼
  ┌─ 充填ループ（Action Router）── 停止規則で必ず止まる ──────┐
  │  到達可能性で channel 切替: 追加DR / 有償DB / →質問リスト化 │
  └──────────────┬────────────────────────────────────────┘
                 ▼
  射影: 業界パック / 作戦盤+台帳 / ウォッチリスト / 発注仕様書 / 納品物QC / ICメモ骨子
```

## 設計不変条件（絶対に破らない8つ）

| # | 不変条件 | 由来 |
|---|---|---|
| 1 | 起動入力は社名または業界名のみ。存在しない入力を前提にしない | P23（補正1–4の帰結） |
| 2 | レポートは台帳からの射影。逆方向は存在しない | P11 |
| 3 | 台帳は追記専用＋ハッシュ連鎖。全証拠に as_of と出所 | P12 |
| 4 | 数値はコードで計算。抽出は value/NOT_FOUND/AMBIGUOUS の三値 | P19 |
| 5 | 矛盾は平均も抑制もせず、保存して提示する | P20 |
| 6 | 「不在」を「真」に変換しない（unknown は取得手段つきで出力） | P21 |
| 7 | 検証は生成と別ベンダのモデル＋特権ツールで行う | P5 |
| 8 | 探索は停止規則で必ず止まる。長時間投入を価値と呼ばない | P2/P15 |
