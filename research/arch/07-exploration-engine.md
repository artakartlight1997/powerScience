# 探索エンジン提案 — 「深さ」を作る層の設計

> **本書は提案であり、ユーザー(投資プロ)の承認を得るまで実装しない。**
>
> **経緯(誤りの記録)**: PoC v2 までは検証・監査基盤のみを実装し、探索層を持たなかった。
> さらに探索層を、サーベイの結論([t-tree-search-algorithms] §5)を参照せず、
> ユーザー確認も経ずに書き始めるという手順違反を犯した(2度目の中断指示)。
> 本書はその是正であり、以後「リサーチ → 設計 → ユーザー確認 → 実装」の順を厳守する。

## 1. 前提 — Marlin の探索の実像(サーベイ確定分)

- Marlin = **AB-MCTS**(NeurIPS 2025 Spotlight)の製品化。木の各ノードで
  **「幅(新候補生成)/深さ(既存候補の精緻化)/どのモデルか」を Thompson Sampling で適応配分**。
  1セッション数百〜数千回の LLM 呼び出し、最大8時間 [S-001..S-006, S-008..S-011]
- **アルゴリズム自体は堀ではない**: TreeQuest として Apache-2.0 で OSS 公開済み [S-009]
- **非公開の核心は報酬設計**。ARC-AGI/コード生成には機械検証可能な報酬があるが、
  ビジネスリサーチには無い。自己評価を報酬にすれば
  **「確信度の高い誤りが最も深く掘られる」**。実証的にも、探索を長くするほど
  引用の事実正確性は平均42%劣化する(2→150呼び出し)[S-057]
- Marlin の売りは「8時間かけた」という**投入量**であり、**成果の質を保証する指標は公開されていない**

**結論**: 同じ木探索の土俵で「もっと長く回す」competition は無意味。
**勝負は ①報酬の中身 ②展開の質(検証)** — Marlin が公開していない/持っていない2点。

## 2. 候補アーキテクチャ(3案)

### 案A(推奨): 反証駆動・証拠接地 AB-MCTS
サーベイの結論([t-tree-search-algorithms] §5)をそのまま設計にしたもの。

| 構成要素 | 設計 | 根拠 |
|---|---|---|
| 探索機構 | **AB-MCTS(TreeQuest, Apache-2.0)を取り込む** — 幅/深さ/モデルの適応分岐。車輪は再発明しない | [S-008][S-009] |
| 遷移関数(一手) | **「反証課題の解決」** — rStar 型のアクション空間: 仮説追加/仮説分割/反証課題を立てる/証拠取得/証拠検証/数値再計算/矛盾指摘/人間に聞く/確率更新/打切り | [S-099][S-100] |
| 報酬(多目的) | **decision-relevant EIG(判断を反転させうる不確実性の削減)× 反証力 × 検証可能性 − 取得コスト**。仮説の相対順位付けに co-scientist 型ペアワイズ Elo を補助採用 | [S-040][S-022] |
| **展開ゲート** | **原文照合(grounding)を通った証拠からしか子ノードを展開しない**。検証は FineVerify 型サブ質問分解、粒度は適応制御(VG-Search) | [S-102][S-101] |
| 監査 | **探索木そのもの=追記専用監査証跡**(既存のイベント連鎖の上に乗せる) | P12, [S-079] |
| 停止 | EIG 閾値 + 予算 + 収穫逓減(既存 R1-R4 を拡張) | P15 |
| 人間 | 介入4点(仮説承認/反証優先/一次情報投入/確度上書き)。8時間放置にしない | P4/P17, [S-032] |

配分すべき資源は LLM トークンだけでなく **検索クエリ・有償データ・人間の時間**の4種
(AB-MCTS の配分対象を拡張)[t-sakana-ab-mcts §3]。

### 案B: co-scientist 型トーナメント(Elo)を主機構に
generate → debate → evolve + ペアワイズ Elo(Nature 掲載・実証済み)[S-022]。
**弱点**: 討論ベースの評価は P7(敵対的1体で精度-10〜40%、誤答合意+30%)・P10(judge バイアス)と
緊張。検証接地が構造に組み込まれていない。→ **主機構にはせず、案Aの報酬の一部として吸収**。

### 案C: ドラフト反復精緻化(TTD-DR 型)
レポート全体を反復改訂する系。読み物の品質は上がるが、
**「レポートを作る機械」の改良**であり差別化仮説([t-differentiation-hypotheses] §0
「反証可能な証拠構造を作る機械」)と不整合。→ 不採用。

## 3. なぜこれが Marlin を超えるのか(検証可能な主張として)

1. **報酬が投資判断に直結する**: EIG=ACH の診断的証拠(情報分析の数十年の実務知と
   ベイズ実験計画が同じ場所を指す)[t-information-value-eig §4]。Marlin の報酬は非公開
   (自己評価と推定)で、レポートのもっともらしさに向かう
2. **深くしても壊れない**: 展開ゲート(検証済み証拠のみから子を作る)は、
   長時間探索の劣化(引用精度-42%・報酬ハッキング 26→58%)への**構造的**対抗。
   Marlin は「8時間」を売るが品質保証指標を持たない(W1)
3. **探索木=監査証跡**: EU AI Act/FINRA 対応が構造から出る(W4)。金融で売る条件
4. **出力が IC の入力になる**: 台帳・ACH 行列・発注仕様書・残存反証リスク(W2)。
   100ページの読み物ではない
5. **土俵は同じものを使う**: AB-MCTS(OSS)を取り込むので探索機構で負けはない。
   差は報酬と検証 — そこは我々の検証基盤(PoC v2 で実装済み)が既に埋めている

## 4. PoC v2 との接続(捨てるものはない)

PoC v2 の資産 = 展開ゲートと報酬の部品そのもの:
- grounding(別ベンダ二値判定)→ **展開ゲート**
- 独立性クラスタ/矛盾保存 → **反証力・検証可能性の報酬項**
- カバレッジ監査(filled/thin/missing/unknown)→ **幅方向の初期フロンティア**
- イベント連鎖 → **探索木の監査証跡の土台**
- 停止則 R1-R4 → EIG 閾値を加えて拡張

## 5. 実装計画(承認後。契約改訂→実装→テストの順)

- **Phase 1(骨格)**: 一手=反証課題のベストファースト探索 + EIG 近似ランキング
  (仮説×診断性×到達可能性÷コスト)。TreeQuest なしで探索ループを成立させる
- **Phase 2(AB-MCTS)**: TreeQuest 組込み — 幅/深さ/モデルの Thompson Sampling 配分
- **Phase 3(精緻化)**: ペアワイズ Elo 補助、検証粒度の適応制御、資源4種の配分
- 各 Phase に実験基準(E' 系)と kill 基準を先に定義する(EVALUATION 方式)

## 6. 未決論点(ユーザー確認が必要)

- **D3(決定境界)**: 「判断を反転させうる」の入力方法 —
  案1: 簡易バリュエーションの感度分析(数値) / 案2: IC チェックリストの命題化(記号) /
  案3: 投資プロが「この投資の生死を決める3前提」を一言入力(人力・最速)
- **予算**: 1案件あたりの探索予算上限(Marlin 級の数千回呼び出し=数千円〜数万円を許すか)
- **OSS 取込**: TreeQuest(Apache-2.0)を依存に加えることの可否
