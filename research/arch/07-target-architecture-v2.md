# 全体アーキテクチャ v2(承認待ち提案)

> **本書は提案であり、ユーザー(投資プロ)の承認を得るまで実装しない。**
> arch/01〜06(v1.0)は本書の下位層として生き続ける。v1.0 に欠けていたのは
> **L5 探索エンジン**と、全層を「二強を超える」目的で貫く設計だった。
>
> **経緯(誤りの記録)**: ①探索層なしの PoC を「完成」と扱った ②探索層をサーベイの
> 結論とユーザー確認を経ずに書き始めた ③提案の範囲を探索エンジンに閉じ、
> 全体アーキテクチャとして提示しなかった。本書はその是正である。

## 0. 敵の正確な姿(サーベイ確定分)

| | **Google Deep Research** | **Sakana Marlin** |
|---|---|---|
| 中核 | **単一の強いモデルを RL で鍛え、非同期インフラで安定に回す** [S-018][S-019] | **AB-MCTS**: 幅/深さ/モデルを Thompson Sampling で適応配分する木探索 [S-003][S-008] |
| 強み | 安い($2-5/run。検索80-160クエリ、キャッシュ50-70%)・速い・計画承認UX [S-020] | 深い(最大8時間・数千回呼び出し)・マルチモデル集合知(ARC-AGI-2 +15pt)[S-010] |
| 共通の弱点 | **①レポート(読み物)を作る機械である ②検証の保証がない(自己評価) ③探索が長いほど引用精度が劣化(-42%)[S-057] ④意思決定への関連性を最適化していない ⑤監査証跡がない ⑥案件を跨いで蓄積しない** | 同左。加えて8時間の不可視性(W3)・成果の質を保証する指標の不在 | 

**戦略の核**: GDR とは「深さと検証」で、Marlin とは「報酬の中身と検証」で戦う。
探索機構そのもの(AB-MCTS)は **Apache-2.0 OSS(TreeQuest)を取り込む** [S-009] —
アルゴリズムは堀ではない。堀は**報酬設計 × 検証接地 × 監査 × 蓄積**の統合にある。

### 0.1 最新調査での裏付け(2026-08 実施。確度A=一次直接確認/B=一次URL+スニペット/C=二次のみ)

攻めどころ3点が一次情報で確定した:

1. **AB-MCTS の報酬は外部供給が前提**(TreeQuest README で直接確認・確度A)。
   アルゴリズムは評価器を学習しない。コード課題ならテスト通過率だが、
   **オープンエンドのリサーチでは LLM 判定に頼るしかない構造**。
   論文自身も「信頼できる評価器への依存」を limitation に明記(B)
2. **「木のどこかに正解があっても、最終候補を選べない」**: 公表性能(ARC-AGI-2 約30%)は
   Pass@k であり、提出1-2回の設定では大幅低下 — **最終回答の選択=検証が未解決**と
   第三者解説が明記(B)。後続サーベイは二値 pass/fail フィードバックが診断情報を
   捨てる点も指摘(B)。→ **選択問題は検証問題である。検証を一次機構に置く本設計の
   直接の根拠**
3. **「スケールするハルシネーション」批判**: 8時間無監督の実行では、誤った前提が
   100ページ全体に増幅・伝播し、人間による全文ファクトチェックは非現実的(B)。
   独立ベンチマーク・引用品質の第三者検証は見当たらない(不明)

競争環境の更新: Sakana は Fugu(マルチモデル・オーケストレーション基盤、2026-06 GA)を
下層に持つ垂直スタックであり、**MUFG(包括提携・AI融資)/Citi(戦略投資 2026-02)/
大和証券(本番開発移行 2026-08)/SMBC(提案書AI実装 2026-04)** と金融浸透が進む(B)。
Marlin 自体の導入は未確認だが、**「外部から買える深掘り」が金融に標準装備される前に
内製の型を確立する時間的猶予は長くない**。EDINET-Bench(Sakana 自身の公表)では
最先端 LLM でも不正検知はロジスティック回帰並み・利益予測はほぼ当たらない(B) —
**LLM に数値と判断を任せない本設計(P19・人間協働)の傍証**でもある。

## 1. 全体像(9層)

```
 L0 入力       社名のみで起動(P23)。IM等は任意の補助(売り手の主張)
 L1 台帳       追記専用イベント連鎖+point-in-time+taint = 探索木の監査証跡 ★実装済(PoC v2)
 L2 収集       検索→取得→必ずスナップショット。Action Router(web/有償DB/VDR/専門家/人間)
 L3 検証       別ベンダ grounding・FineVerify型サブ質問・独立クラスタ・矛盾保存・数値はコード ★実装済
 L4 知識構造   固定スペック(箱0-10×業態) × EBITDAドライバーツリー × ACH仮説行列(P11)
 L5 探索       AB-MCTS(TreeQuest) + 一手=反証課題 + 多目的報酬 + 検証済み証拠のみ展開
 L6 停止・予算 R1-R4 + EIG閾値。資源4種(トークン/検索/有償データ/人間時間)の配分
 L7 人間協働   計画承認(GDRの良い点を採る) + 介入4点。8時間放置にしない(P17)
 L8 出力       作戦盤/ACH行列/発注仕様書/検収QC/証拠台帳/較正確率 — レポートは view(P11)
 L9 記憶・較正 ケース記憶(外した理由込み)+Brier/ECE公開。長期資産(P24)
 横断: セキュリティ(CaMeL taint, P18) / 監査(EU AI Act, P12) / モデルルーティング
```

## 2. L5 探索エンジン(新規の中核)— 反証駆動・証拠接地 AB-MCTS

| 構成要素 | 設計 | 根拠 |
|---|---|---|
| 探索機構 | **AB-MCTS(TreeQuest)**: 幅(新仮説・新サブ質問)/深さ(既存の精緻化)/モデル選択を Thompson Sampling で適応配分。難問は深く・易問は幅(計算最適則) | [S-008][S-009][S-101] |
| 遷移関数(一手) | **「反証課題の解決」**。アクション空間は rStar 型に DD 固有で設計: 仮説追加/分割/反証課題/証拠取得/検証/数値再計算/矛盾指摘/人間に聞く/確率更新/打切り | [S-099][S-100] |
| 報酬(多目的) | `Score = w1·EIG + w2·反証力 + w3·検証可能性 + w4·決定関連性 − w5·コスト`(RL報酬設計の第2-3世代を**学習なしで推論時スコアに流用**)。仮説の相対順位はペアワイズ Elo 補助(co-scientist 型) | [S-040][S-043][S-044][S-022] |
| **展開ゲート** | **原文照合を通った証拠からしか子ノードを展開しない**。検証は FineVerify 型サブ質問分解(4軌跡で +8.2pt の実証)、検証粒度は適応制御(VG-Search: 精度+3%とFLOPs-52%を両立) | [S-102][S-101] |
| 幅の初期フロンティア | カバレッジ監査の gap(箱0-10 の missing/thin)= v1.0 のループがそのまま探索の第0層になる | arch/02 |
| 深さの誘導 | ACH で story/rival が未決のドライバー = 診断的証拠の在り処(EIG と ACH の一致) | [S-040][S-061] |

**なぜこれが「深いのに壊れない」のか**: 二強の探索は生成側の自己評価で伸びる。
本設計は**子ノードの存在自体を検証済み証拠に依存させる**ため、木が深くなるほど
接地点が増える。長時間劣化(引用-42%・報酬ハッキング26→58%)への構造的対抗 [S-057][S-103]。

**Pass@k 問題への回答(§0.1-2)**: AB-MCTS の公知の未解決点は「良い候補が木に
あっても選べない」こと。本設計では最終選択を LLM の判断にしない —
**候補の優劣は検証済み独立クラスタ数・反証の生存・矛盾の有無という機械計算可能な
量で決まる**(台帳がそのまま選択関数になる)。Marlin が埋めていない穴を、
我々は L3(実装済み)で最初から埋めている。

## 3. 二強超えのマトリクス(層ごとの勝ち筋)

| 次元 | GDR | Marlin | **IP v2** |
|---|---|---|---|
| 深さ | 80-160クエリで浅い | 8時間深いが劣化保証なし | AB-MCTS 同等機構+**劣化しない展開ゲート** |
| 検証 | グラウンディング(自己) | 自己評価(推定) | **別ベンダ二値+FineVerify+独立クラスタ+矛盾保存** |
| 報酬 | RL済み(汎用) | 非公開 | **decision-relevant EIG=判断を反転させる不確実性に集中** |
| 成果物 | 読み物 | 100p読み物+スライド | **台帳/ACH/発注仕様書/検収QC**(ICの入力になる) |
| 人間 | 計画承認のみ | 8時間放置 | 計画承認+**介入4点**(反証優先・確度上書き 他) |
| 監査 | なし | なし | **探索木=追記専用監査証跡**(EU AI Act/FINRA) |
| 蓄積 | なし | 実行ごとに消える | ケース記憶+**較正の公開**(Brier/ECE) |
| 原価 | $2-5 | ¥9,800 | EIG配分で検索予算を絞る(検索費>LLM費の実測に対する構造的対策)[S-020] |

**模倣困難性**: 目的関数の転換(読み物品質→反証可能な証拠構造)は**製品思想の転換**であり、
「読みやすい100ページ」を売る限り両社は採れない [t-differentiation-hypotheses]。

## 4. PoC v2 との接続(捨てるものはない)

L1/L3 は実装・検証済み(テスト139件)。それらは L5 の**展開ゲートと報酬の部品**になる:
grounding→展開ゲート/独立クラスタ・矛盾→反証力・検証可能性項/カバレッジ監査→幅の
第0層/イベント連鎖→探索木の監査証跡/停止則→EIG閾値を加えて拡張。

## 5. 実装計画(承認後。契約改訂→実装→テスト→バグ狩りループの順)

- **Phase 1(探索の骨格)**: 一手=反証課題のベストファースト探索+多目的スコア近似+
  ACH行列(仮説はアーキタイプ由来テンプレ=P3)。TreeQuest なしで成立させ、E' 基準で計測
- **Phase 2(AB-MCTS化)**: TreeQuest 組込み(幅/深さ/モデルの Thompson Sampling)。
  非同期・共有状態・部分回復の実行基盤(GDR から学ぶ)[S-018]
- **Phase 3(精緻化)**: Elo 補助/検証粒度の適応制御/資源4種の配分/計画承認UX
- **Phase 4(長期)**: ケース記憶・較正公開(P24: 効くのは数年後と明示して着手)
- 各 Phase に実験基準と kill 基準を先に定義(EVALUATION 方式)。
  ブラインド比較の相手は **GDR 出力と Marlin 出力(入手可能なら)の両方**
