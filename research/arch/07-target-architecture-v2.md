## 0. 敵の正確な姿(サーベイ確定分)

| | **Google Deep Research** | **Sakana Marlin** |
|---|---|---|
| 中核 | **単一の強いモデルを RL で鍛え、非同期インフラで安定に回す** [S-018][S-019] | **AB-MCTS**: 幅/深さ/モデルを Thompson Sampling で適応配分する木探索 [S-003][S-008] |
| 強み | 安い($2-5/run。検索80-160クエリ、キャッシュ50-70%)・速い・計画承認UX [S-020] | 深い(最大8時間・数千回呼び出し)・マルチモデル集合知(ARC-AGI-2 +15pt)[S-010] |
| 共通の弱点 | **①レポート(読み物)を作る機械である ②検証の保証がない(自己評価) ③探索が長いほど引用精度が劣化(-42%)[S-057] ④意思決定への関連性を最適化していない ⑤監査証跡がない ⑥案件を跨いで蓄積しない** | 同左。加えて8時間の不可視性(W3)・成果の質を保証する指標の不在 | 

**戦略の核**: GDR とは「深さと検証」で、Marlin とは「報酬の中身と検証」で戦う。
探索機構そのもの(AB-MCTS)は **Apache-2.0 OSS(TreeQuest)を取り込む** [S-009] —
アルゴリズムは堀ではない。堀は**報酬設計 × 検証接地 × 監査 × 蓄積**の統合にある。

### 0.1 最新調査での裏付け(2026-08 実施。確度A=一次直接確認/B=一次URL+スニペット/C=二次のみ)

攻めどころ3点が一次情報で確定した:

1. **AB-MCTS の報酬は外部供給が前提**(TreeQuest README で直接確認・確度A)。
   アルゴリズムは評価器を学習しない。コード課題ならテスト通過率だが、
   **オープンエンドのリサーチでは LLM 判定に頼るしかない構造**。
   論文自身も「信頼できる評価器への依存」を limitation に明記(B)
2. **「木のどこかに正解があっても、最終候補を選べない」**: 公表性能(ARC-AGI-2 約30%)は
   Pass@k であり、提出1-2回の設定では大幅低下 — **最終回答の選択=検証が未解決**と
   第三者解説が明記(B)。後続サーベイは二値 pass/fail フィードバックが診断情報を
   捨てる点も指摘(B)。→ **選択問題は検証問題である。検証を一次機構に置く本設計の
   直接の根拠**
3. **「スケールするハルシネーション」批判**: 8時間無監督の実行では、誤った前提が
   100ページ全体に増幅・伝播し、人間による全文ファクトチェックは非現実的(B)。
   独立ベンチマーク・引用品質の第三者検証は見当たらない(不明)

競争環境の更新: Sakana は Fugu(マルチモデル・オーケストレーション基盤、2026-06 GA)を
下層に持つ垂直スタックであり、**MUFG(包括提携・AI融資)/Citi(戦略投資 2026-02)/
大和証券(本番開発移行 2026-08)/SMBC(提案書AI実装 2026-04)** と金融浸透が進む(B)。
Marlin 自体の導入は未確認だが、**「外部から買える深掘り」が金融に標準装備される前に
内製の型を確立する時間的猶予は長くない**。EDINET-Bench(Sakana 自身の公表)では
最先端 LLM でも不正検知はロジスティック回帰並み・利益予測はほぼ当たらない(B) —
**LLM に数値と判断を任せない本設計(P19・人間協働)の傍証**でもある。

### 0.2 探索SOTA調査の要点(2026-08 実施。設計判断を変えた)

2025-26 年の深掘りリサーチ研究は「**全面木探索」から後退**している:

- **選択的分岐が共通認識に**: Chain-in-Tree(確信的なステップは直列、不確実な地点で
  のみ分岐 — トークン75-85%削減・精度維持)、TreeSeeker(テキストUCB+記憶接地の
  branch-and-return)。**「常時分岐は無駄。分岐は争点に限定」** — DD の構造
  (大半が定型確認+少数の争点)とまさに同型
- **ドラフト誘導型が木探索を上回る**: TTD-DR(Google)は「骨子を先に置き、
  検索で全体を反復改訂」でOpenAI DR等に勝率69-75%
  【裏取り注記: この勝率はLLM judge依存の弱い根拠。我々はドラフト誘導を品質主張の
  根拠でなく制御構造として採用するため、判断は勝率に依存しない — t-draft-guided】。
  木探索の「局所深掘りによる全体整合性の喪失」「報酬定義不能」を回避
- **証拠メモリ接地が引用品質の解**: WebWeaver は証拠メモリバンク+参照付き
  アウトライン+「セクション単位で必要証拠のみ取り出し」で引用精度93.4%(SOTA)
- **ルーブリック・ゲートが劣化への最も原理的な防御**: DeepRubric(検証可能な葉から
  報酬を逆合成)、DeepFact(Audit-then-Score: 検証**ラベル**の精度が60.8%→90.9% —
  検証自体が難しいことの証拠)。ルーブリックRL研究では検証を強化しても
  「網羅性偏重・事実性劣化」への最適化が残る(ルーブリック判定者85.8% vs
  フリー判定者78.4%が逆選好)— 対策は検証可能な葉でのゲート+**held-outの
  抜き打ち検査**【SpecBenchの「探索が長いほど悪化」は裏取りで不正確と判明し撤回。
  長時間劣化の根拠は引用正確性研究(2605.06635、−42pt平均・モデル分散−62〜−22pt・
  統合段階特異)のみを使う — t-verification-claims-audit】
- **計画幻覚の複利伝播**(DeepHalluBench): 劣化は後半で起きるのではなく
  **初期計画の欠陥が増幅される** → 計画への人間承認(L7)の研究的根拠
- RL学習系(WebSailor/Kimi型)は性能上限が高いが、内製第一段としては非推奨
  (インフラ・報酬ハッキング・ドメイン適合の三重コスト)

**含意**: Marlin と同じ土俵(全面AB-MCTS)で戦うのは、追いつく戦略であって
超える戦略ではない。**次世代の合流点 = ドラフト誘導 × 証拠メモリ接地 ×
選択的分岐 × ルーブリック・ゲート**で組む。しかも我々の固定スペック(箱0-10×
アーキタイプ)は DeepRubric の言う「検証可能な葉」を**人手で既に持っている**
(合成不要)、PoC v2 の証拠台帳は WebWeaver の証拠メモリバンクに相当する —
**SOTA の要求部品を先に実装済み**である。

## 1. 全体像(9層)

```
 L0 入力       社名のみで起動(P23)。IM等は任意の補助(売り手の主張)
 L1 台帳       追記専用イベント連鎖+point-in-time+taint = 探索木の監査証跡 ★実装済(PoC v2)
 L2 収集       検索→取得→必ずスナップショット。Action Router(web/有償DB/VDR/専門家/人間)
 L3 検証       別ベンダ grounding・FineVerify型サブ質問・独立クラスタ・矛盾保存・数値はコード ★実装済
 L4 知識構造   固定スペック(箱0-10×業態) × EBITDAドライバーツリー × ACH仮説行列(P11)
 L5 探索       AB-MCTS(TreeQuest) + 一手=反証課題 + 多目的報酬 + 検証済み証拠のみ展開
 L6 停止・予算 R1-R4 + EIG閾値。資源4種(トークン/検索/有償データ/人間時間)の配分
 L7 人間協働   計画承認(GDRの良い点を採る) + 介入4点。8時間放置にしない(P17)
 L8 出力       作戦盤/ACH行列/発注仕様書/検収QC/証拠台帳/較正確率 — レポートは view(P11)
 L9 記憶・較正 ケース記憶(外した理由込み)+Brier/ECE公開。長期資産(P24)
 横断: セキュリティ(CaMeL taint, P18) / 監査(EU AI Act, P12) / モデルルーティング
```

## 2. L5 探索エンジン(新規の中核)— 争点集中型ハイブリッド(2025-26 SOTA の合流点)

**基本形**: 全面木探索ではなく、**「定型は幅広く直列・並列、争点だけ深く分岐」**。

```
 骨格ループ(ドラフト誘導・TTD-DR型):
   「ドラフト」= レポートではなく作戦盤そのもの(固定スペック×ACH行列の現在状態)
   毎ラウンド: ドラフトの欠落(gap)と争点が、次の検索・照会を導く
   → PoC v2 のカバレッジ監査ループはこの原始形。これを拡張する
      │
      ├─ 定型確認(大半の項目): 分岐しない。並列収集→検証→充足(Chain-in-Tree の直列側)
      │
      └─ 争点(少数): ①ACH で story/rival が未決のドライバー ②未解消の矛盾
         ③追撃で出た予想外の発見 — ここでだけ木を開く(選択的分岐)
           ├─ 一手 = 反証課題の解決(rStar型アクション空間: 仮説追加/分割/
           │         反証課題/証拠取得/検証/再計算/矛盾指摘/人間に聞く/打切り)
           ├─ 次の一手の選択 = EIG(BED-LLM型: どの照会が仮説対立を最も動かすか)
           ├─ 分岐の評価 = テキストUCB(TreeSeeker型: 価値・不確実性・リスク)
           │              + 検証済み証拠のみから子を展開(展開ゲート)
           └─ 分岐予算の配分 = Thompson Sampling(AB-MCTS の縮退採用。
                              幅/深さ/モデル選択は争点内でのみ)
```

| 構成要素 | 設計 | 根拠 |
|---|---|---|
| 骨格 | **ドラフト誘導ループ**: 作戦盤=構造化ドラフト。欠落と争点が次の収集を導く(全体整合性を常に保持) | TTD-DR(勝率69-75%) |
| 証拠接地 | **証拠台帳=証拠メモリバンク**(実装済み)。生成時はセクション単位で必要証拠のみ取り出し | WebWeaver(引用精度93.4%) |
| **進行・報酬ゲート** | **固定スペック項目=検証可能な葉**。項目の充足(独立クラスタ×grounded×新鮮)だけが進行の報酬。「項目を埋めた風」を構造的に排除 | DeepRubric / DeepFact / SpecBench知見 |
| 分岐制御 | **選択的分岐**: 争点でのみ木を開く。争点=ACH未決+矛盾+予想外の発見 | Chain-in-Tree / TreeSeeker |
| 争点内の一手 | 反証課題の解決(rStar型アクション空間) | [S-099][S-100] |
| 争点内の選択 | decision-relevant EIG + 反証力 + 検証可能性 − コスト(多目的。RL報酬設計の推論時流用) | [S-040][S-043] BED-LLM |
| 分岐予算 | Thompson Sampling(AB-MCTS を**争点内に縮退採用**。TreeQuest は Phase 3 で判断) | [S-008] |
| 検証 | FineVerify型サブ質問分解+別ベンダ二値(実装済み)。粒度は適応制御 | [S-102][S-101] |
| 文脈管理 | IterResearch型ワークスペース再構成+文脈はID・本体は台帳(P8)+執筆済み節のマスク — いずれも動く実装が存在する定石の採用 | t-alibaba(確度A) |
| 品質監査 | **held-out抜き打ち検査**(スペック外の合成チェック・ランダム原文再照合)— 可視ゲートの飽和対策 | t-verification-claims-audit |
| 検収 | DeepFact 型 Audit-then-Score をコンサル納品物QCに拡張 | DeepFact |
| 監査規格 | **AAR標準(2602.13855)準拠を明示**(provenance coverage / soundness / contradiction transparency / audit effort) | t-finance-dd-landscape |
| 監視 | 計画幻覚のカスケード対策(定性): 計画を生成せず型+人間承認 | DeepHalluBench(定量値は非依拠) |

**なぜこれが「深いのに壊れない」のか**: 二強の探索は生成側の自己評価で伸びる。
本設計は**子ノードの存在自体を検証済み証拠に依存させる**ため、木が深くなるほど
接地点が増える。長時間劣化(引用-42%・報酬ハッキング26→58%)への構造的対抗 [S-057][S-103]。

**Pass@k 問題への回答(§0.1-2)**: AB-MCTS の公知の未解決点は「良い候補が木に
あっても選べない」こと。本設計では最終選択を LLM の判断にしない —
**候補の優劣は検証済み独立クラスタ数・反証の生存・矛盾の有無という機械計算可能な
量で決まる**(台帳がそのまま選択関数になる)。Marlin が埋めていない穴を、
我々は L3(実装済み)で最初から埋めている。

## 3. 二強超えのマトリクス(層ごとの勝ち筋)

| 次元 | GDR | Marlin | **IP v2** |
|---|---|---|---|
| 深さ | 80-160クエリで浅い | 8時間深いが劣化保証なし | AB-MCTS 同等機構+**劣化しない展開ゲート** |
| 検証 | グラウンディング(自己) | 自己評価(推定) | **別ベンダ二値+FineVerify+独立クラスタ+矛盾保存** |
| 報酬 | RL済み(汎用) | 非公開 | **decision-relevant EIG=判断を反転させる不確実性に集中** |
| 成果物 | 読み物 | 100p読み物+スライド | **台帳/ACH/発注仕様書/検収QC**(ICの入力になる) |
| 人間 | 計画承認のみ | 8時間放置 | 計画承認+**介入4点**(反証優先・確度上書き 他) |
| 監査 | なし | なし | **探索木=追記専用監査証跡**(EU AI Act/FINRA) |
| 蓄積 | なし | 実行ごとに消える | ケース記憶+**較正の公開**(Brier/ECE) |
| 原価 | $2-5 | ¥9,800 | EIG配分で検索予算を絞る(検索費>LLM費の実測に対する構造的対策)[S-020] |

**模倣困難性**: 目的関数の転換(読み物品質→反証可能な証拠構造)は**製品思想の転換**であり、
「読みやすい100ページ」を売る限り両社は採れない [t-differentiation-hypotheses]。

## 4. PoC v2 との接続(捨てるものはない)

L1/L3 は実装・検証済み(テスト139件)。それらは L5 の**展開ゲートと報酬の部品**になる:
grounding→展開ゲート/独立クラスタ・矛盾→反証力・検証可能性項/カバレッジ監査→幅の
第0層/イベント連鎖→探索木の監査証跡/停止則→EIG閾値を加えて拡張。

## 5. 実装計画(承認後。契約改訂→実装→テスト→バグ狩りループの順)

- **Phase 1(骨格=ドラフト誘導+ルーブリック・ゲート)**: PoC v2 のカバレッジ
  ループを TTD-DR 型に拡張(作戦盤=構造化ドラフト、欠落が次の収集を導く)。
  進行報酬は項目充足のみ(DeepRubric 型)。ACH 行列(仮説はアーキタイプ由来
  テンプレ=P3)を一次データ構造として追加
- **Phase 2(争点モジュール)**: 選択的分岐 — 争点(ACH未決・矛盾・予想外の発見)
  でのみ木を開く。一手=反証課題、選択=EIG、評価=テキストUCB+展開ゲート
- **Phase 3(分岐配分と基盤)**: 争点内の Thompson Sampling 配分(TreeQuest 採用可否を
  ここで判断)/検証粒度の適応制御/非同期・共有状態・部分回復の実行基盤
  (GDR から学ぶ)[S-018]/計画承認UX
- **Phase 4(長期)**: ケース記憶・較正公開(P24: 効くのは数年後と明示して着手)、
  DeepFact 型 Audit-then-Score の検収QC拡張
- 各 Phase に実験基準と kill 基準を先に定義(EVALUATION 方式)。
  ブラインド比較の相手は **GDR 出力と Marlin 出力(入手可能なら)の両方**
