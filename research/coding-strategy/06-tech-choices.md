# 技術選択の指針

**確定しているのは「何を満たすべきか」であって、具体的な製品名ではない。** 🔧

## 1. 実行基盤

| 論点 | 指針 | 根拠 |
|---|---|---|
| **非同期・長時間** | プランナとワーカで**共有状態**を持ち、**部分失敗から全体再実行なしに回復**する | Gemini DR の設計 `[S-018]` |
| **セッションの分割** | 8時間の単一セッションにしない。**チェックポイント付きの短いセッションの連鎖** | KV キャッシュは DRAM 上限がある `[S-129]` |
| **文脈** | 積み上げない。**ラウンドごとに作業文脈を再構成**（IterResearch 型） | context rot `[S-050]`、Tongyi `[S-030]` |
| **再現性** | 全実行はイベントから**リプレイ可能**に | 監査 `[S-128]`、デバッグ |

## 2. モデルの使い分け 🔧

```
生成（取得・仮説・執筆）: 案件内では ★同一モデルに固定★
    理由: プレフィックスキャッシュのヒット率＝粗利率 `[S-129]`
検証（接地・数値・整合）: ★別ベンダ★（独立性の担保）
    理由: 同一モデルは同一の盲点を共有する `[S-036]`
安価な足切り        : 小型モデル（SIFT 型の階層化）`[S-093]`
    ただし ★judge と真指標の相関を常時監視★（相関 34% vs ほぼ0 `[S-093]`）
```

**キャッシュ設計 🔒**
- プレフィックス（ファンド方針・業界固定知識・ツール定義）を**先頭に固定**、変動部を末尾に
- 目標: **ヒット率 60–85%**（達成可能な水準 `[S-129]`）
- 監視: ヒット率を**ダッシュボードの一級指標**にする（＝粗利率）

## 3. データ層

| 用途 | 選択 |
|---|---|
| イベント / グラフ | **PostgreSQL**（追記専用テーブル + ハッシュ連鎖 + 再帰CTE） |
| ベクタ | **pgvector**（別サービスは規模が出てから） |
| 原文スナップショット | オブジェクトストレージ（content_hash をキー） |
| 大域センスメイキング | **案件単位**のコミュニティ要約。全社グラフは作らない `[S-047]` |
| 案件隔離 | **物理的に分離**（スキーマ or DB 単位）。MNPI `[S-079]` |

## 4. 数値・文書 🔒

- 計算は **Python の決定論的エンジン**。LLM は「どの数値をどう計算するか」の指定と解釈のみ（P19）
- XBRL は**タクソノミ拡張・期間・単位**を吸収する正規化層を自作
- 文書は **document AI（購入）→ 正規化 → 座標保持**。LLM 単独でパイプライン全体を賄わない `[S-136]`
- 抽出は必ず **`value | NOT_FOUND | AMBIGUOUS`**

## 5. セキュリティ 🔒

```
Web/外部文書を読むモデル  : ツール権限なし（隔離LLM）
統率するモデル            : 信頼できる指示のみを読む（特権LLM）
全ツール呼び出し          : C15 ポリシーゲートを必ず経由
値のメタデータ            : trust_label を伝播（証拠グラフの属性として実装）
egress                    : 外部送信は明示許可のみ
ツール説明文              : ★未信頼として扱う★（MCP 経由の侵害事例 `[S-126]`）
```

## 6. コスト管理

| 指標 | 目標 | 理由 |
|---|---|---|
| キャッシュヒット率 | 60–85% | 粗利に直結 `[S-129]` |
| 検索クエリ数 / 案件 | EIG で配分、上限を設定 | 1 run の半分が検索費になりうる `[S-020]` |
| 高価な検証の回数 | 上位候補のみ（SIFT 型） | 評価コストが律速 `[S-093]` |
| **人間の検証時間** | **最小化が最重要** | 実質的に最大の原価であり、購買を左右する（評価D） |

## 7. 意図的に採らない選択 🔒

- ❌ 専用グラフDB / KG プラットフォームの早期導入（規模が問題になってから）
- ❌ 自前のモデル学習（P16 / Class A）
- ❌ エージェントフレームワークへの深い依存（差し替え可能な薄い層に留める `[S-113]`）
- ❌ 「全部入り」の巨大プロンプト（context rot `[S-050]`）
