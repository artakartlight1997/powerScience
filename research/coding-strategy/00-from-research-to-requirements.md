# 設計原則 → 実装要件

**本フォルダの全ての記述は、この表に紐づく。** 根拠のない「作りたいもの」は書かない。

| 原則 | 実装要件（何を作るか） | 検証方法（どう確かめるか） |
|---|---|---|
| **P1** タスクが独立並列のときだけマルチ | 反証課題ごとの**独立ワーカ**は並列、**証拠統合と確率更新は単一の統制下** | 並列度を変えた A/B で品質とコストを比較 |
| **P2** 停止条件と検証を一級市民に | **停止条件エンジン**（EIG閾値/予算/反証枯渇/確度収束）を独立コンポーネントとして実装 | 停止せずに走り続けるケースが0であること |
| **P3** 視点は実務由来の型で与える | **視点テンプレート**（買い手/競合/退職者/規制/premortem…）を設定ファイルで持つ | 人間が出した死因との差分カバレッジ |
| **P4/P17** 介入は「人間が先」「減速」 | **I1'（人間が先に死因を3つ書く）**を UI の必須ステップに。承認型 UI を作らない | 介入前後の確率変動を記録 |
| **P5** 検証器に特権を与える | 検証器のみが **原文取得 / コード実行 / DB 参照 / 別ベンダ呼び出し**の権限を持つ（権限を実装で分離） | 生成器から特権 API が呼べないことをテスト |
| **P6** 報酬は decision-relevant EIG | **決定フレーム → 感度分析 → EVPI → 探索予算配分**のパイプライン | EIG 上位の探索が実際に確率を動かしたか |
| **P7/P20** 討論で合意させない・矛盾は保存 | 討論の出力は**「検証すべき課題」に限定**。矛盾は `contradicts` 辺として**グラフに保存** | 矛盾検出数と、その後の解消率 |
| **P8** 忘れる設計・出典IDを失わない | 文脈には**要約とID参照のみ**。原文は外部ストア。ラウンド毎に作業文脈を再構成 | 圧縮後に全主張から原文へ到達できること |
| **P9** 記憶は選別して残す | ケースは**「意思決定に効いた事実＋反証結果」**のみ。時効付き | 記憶ヒット時の品質改善（A/B） |
| **P10** judge は原文支持の二値判定のみ | 判定 API を**二値/三値に物理的に制限**（自由記述スコアを返せない型にする） | 順序入替の一致率、複数judgeのκ |
| **P11** ACH 行列が一次データ | **レポートは view**。生成物はグラフから射影する | レポートの全文から証拠IDへ逆引きできること |
| **P12** 監査証跡は一次記録 | **追記専用＋ハッシュ連鎖**のイベントストア | 改竄検知テスト、任意時点の再現 |
| **P13** 自己改善はスキャフォールドに限定 | プロンプト/ルーブリックの版管理と**人間承認フロー**。評価器の自動書換は禁止 | 版差分の記録 |
| **P14** 評価は階層化・judge を監視 | 安価judge → 高価検証の2段。**judge と真指標の相関を定期測定** | 相関が閾値を割ったらアラート |
| **P15** 探索に上限・乖離を停止条件に | 探索長の上限、**proxy_gain − real_gain** の監視 | 劣化曲線（ツール呼び出し数 vs Fact Check） |
| **P16** ∂V/∂M で投資対象を選ぶ | **Class A に工数を割かない**という判断を、リポジトリ構成で表現（薄いアダプタに閉じる） | 四半期ごとに「モデル更新で消えた機能」を棚卸し |
| **P18** 未信頼隔離・capability 門番 | **二層 LLM**（Web読み取り側にツール権限なし）＋ taint 伝播 ＋ egress ポリシー | インジェクション・レッドチーム（AgentDojo 型） |
| **P19** 数値はコードで計算・三値返却 | **決定論的な計算エンジン**と `value/NOT_FOUND/AMBIGUOUS` 型 | 恒等式チェック100%、捏造ゼロ |
| **P20** 矛盾は平均も抑制もしない | 集約器に「平均化」「抑制」の実装を**そもそも持たせない** | 矛盾ケースの回帰テスト |

## この表の使い方

1. **新機能を提案するとき**: どの P に紐づくかを書けなければ、作らない。
2. **削るとき**: P に紐づかない機能から削る。
3. **レビューするとき**: 「検証方法」の列が埋まっていない要件は、実装しても測れないので保留。
