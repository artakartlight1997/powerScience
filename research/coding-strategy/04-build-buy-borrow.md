# 自作 / 購入 / OSS

| 領域 | 判断 | 具体 | 理由 |
|---|---|---|---|
| **証拠グラフ / イベントストア** | **自作** 🔒 | PostgreSQL 上に自前スキーマ | ここが唯一の中心。他人の抽象に縛られてはいけない |
| **接地検証（サブ質問分解）** | **自作** 🔒 | FineVerify 型を実装 `[S-102]` | 出荷ゲートそのもの。品質の定義を他社に委ねない |
| **数値エンジン** | **自作** 🔒 | Python + XBRL パーサ + 恒等式ルール | FinAuditing 13.86% `[S-130]`＝既製品では解けていない |
| **探索アルゴリズム** | **OSS** | TreeQuest（Apache-2.0）`[S-009]` ほか | 自作の価値がない |
| **LLM** | **購入（複数）** | 生成は案件内固定、検証は別ベンダ | コモディティ `[S-088]`。差し替え可能に保つ |
| **オーケストレーション** | **薄く自作 or 購入** 🔧 | 単純なカスケード。必要なら Fugu 等 `[S-104]` | 既に製品化されている領域 |
| **OCR / レイアウト** | **購入（差し替え可能に）** | 商用 document AI。日本語は要実測（Q30） | RealDoc-Bench 0.847 `[S-136]`。自作は無駄 |
| **企業/ディールDB** | **購入 or 提携** | PitchBook / Capital IQ / Preqin / Speeda 等 `[S-134]` | 我々の堀ではない。**ライセンス条項の確認が先**（Q26） |
| **Web 検索** | **購入** | 検索 API（複数） | コスト管理が主眼（1 run の半分が検索費 `[S-020]`） |
| **エキスパートネットワーク** | **提携** | GLG / AlphaSights / Third Bridge / ミーミル 等 | 質問設計だけ自作（→ [t-primary-research](../topics/04-domain/primary-research-and-expert-networks.md)） |
| **意思決定分析** | **OSS 参照 + 自作** 🔧 | SilverDecisions 等を参照実装に `[S-121]` | 計算は単純。統合部分が価値 |
| **確率推論** | **OSS** | PyMC / pgmpy 等 | 車輪の再発明は不要。**LLM に計算させないことが要点** |
| **ベクタ / 全文検索** | **OSS** | pgvector + 全文検索 | 二層索引の局所側 `[S-049]` |
| **プロンプトインジェクション防御** | **自作（CaMeL 型）** 🔒 | 二層 LLM + capability + egress ゲート `[S-127]` | 既製品では案件隔離まで面倒を見ない |
| **監視 / 評価基盤** | **自作** 🔒 | 出荷ゲート、劣化曲線、judge 相関 | **評価軸そのものが我々の point of view** `[S-087]` |
| **レポート / スライド生成** | **最小自作** | グラフからの射影 | 生成は100倍安い `[S-112]`。凝らない |

## 依存の原則 🔒

1. **差し替え可能性**: 購入するものは全て**2社以上を想定した抽象**の裏に置く（モデル・OCR・検索・DB）
2. **`adapters/` を厚くしない**: 外部依存はアダプタに閉じ、中核ロジックに漏らさない
3. **ライセンスを先に読む**: ベンダーデータの **AI 利用・再加工の可否**（Q26）は**契約前に確認**。
   ここが NG なら データ戦略ごと変わる
4. **オープンモデルの自社ホストを選択肢に残す**: 顧客データを外部 API に出せない案件がある `[S-030]`
