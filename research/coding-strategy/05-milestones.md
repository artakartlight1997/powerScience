# マイルストーン

**各段階に「測定可能な終了条件」を置く。** 終了条件を満たさずに次へ進まない。

---

## M0 — 技術検証（最優先） 🔒

> **「そもそも作れるか」を確かめる段階。M0 が通るまで、M1 以降は仮の計画である。**

| # | 実験 | 問い | 合格条件（仮） | 宿題 |
|---|---|---|---|---|
| **E1** | **EDINET XBRL の自動整合検証** | 恒等式チェック・計算リンク検証は日本の有報でどこまで通るか | 主要恒等式（BS一致・PL/CF整合・前期比連続性）で **自動検証率 ≥ 90%**、誤検知 ≤ 5% | Q22 |
| **E2** | **日本語実務文書の OCR/レイアウト実測** | 和暦・縦書き・押印・手書き注記で使えるか | 表の抽出 F1 ≥ 0.85、**座標(bbox)が取れること** | Q30 |
| **E3** | **競合の引用精度の実測** | Marlin / Gemini DR の Fact Check は実際どうか | 実測値を得る（＝営業資料になる）`[S-057]` の枠組みを適用 | Q3 |
| **E4** | **FineVerify の定性主張への適用** | サブ質問分解は「市場は伸びる」型の主張にも効くか | 数値主張と定性主張で判定一致率を比較。**定性で κ ≥ 0.6** | Q20 |

**E1 と E2 が落ちたら**: 財務 DD の差別化（検証器の再計算権）が成立しない
→ **商業 DD に絞るか、スコープを組み直す**（→ [08-risks-and-kill-criteria.md](08-risks-and-kill-criteria.md)）

**並行して行う（コードではない）**: 顧客ヒアリング 5–10件（Q12 / Q25 / Q28）。
**「較正された確度に金を払うか」は文献では出ない。**

## M1 — 薄い縦串（1工程だけ）

**スコープ 🔧（❓ D10 の決定待ち）**: 推奨は「**既に書かれた IC メモを叩いて穴を出す**」。
理由: 既存ワークフローを壊さない / 価値が5分で伝わる / 教師データが手に入る / AI が書いた文章への抵抗を回避。

**作るもの**
1. 証拠グラフ（スキーマ・イベントストア・不変条件 I1–I7）
2. 取り込み: 1ソース種別（PDF または EDINET）
3. 接地検証器（サブ質問分解 + 原文照合）
4. 数値エンジン（恒等式 + 三値）
5. ACH 行列の最小形（人間が入れた死因 + 抽出した証拠の対応）
6. 射影: 「主張 / 出典 / 未解決の反証」の3点セット
7. C15 ポリシーゲート（最初から。後付けしない）

**終了条件**
- 実案件1件で、**IC メモの全主張に出典を機械照合**できる
- **Fact Check ≥ 95%**（主要主張）
- 不変条件 I1–I7 のテストが全て緑
- アナリストが「裏取り時間が減った」と言う（定性でよい。ただし**時間を計測する**）

## M2 — 探索の目的関数

**作るもの**
1. 決定フレーム（❓ D3 の3案を段階導入: 人力 → 命題 → 数値モデル）
2. 感度分析（トルネード）と**決定境界の算出**
3. **EVPI 計算 → 調査予算の上限提示**
4. 探索プランナ（EIG/コストでの Question ランキング、並列度制御）
5. 停止条件エンジン（閾値・予算・枯渇・収束・**劣化検知**）
6. 反証エンジン C9 の分離

**終了条件**
- 「この論点の調査上限は◯◯円」を**顧客に提示できる**
- 探索が**自動で止まる**（人間が止めない）
- **劣化曲線**: ツール呼び出し 150 回時点でも Fact Check ≥ 90% `[S-057]`
- proxy_gain − real_gain の監視が動いている `[S-103]`

---

## M3 — 較正と評価

**作るもの**
1. 確率層（構造抽出 → アルゴリズム推論 → 論拠と確率の整合チェック）
2. **point-in-time 評価基盤**（as_of による cutoff、リーク検出）`[S-133]`
3. **反実仮想 DD データセット**（過去案件 N 件、数人月）
4. Brier / ECE の蓄積と、**四半期の較正レポート**

**終了条件**
- 反実仮想 DD で **見落とし率**と **Brier** が測れる
- 「T 以降の証拠を1つも使っていない」を**機械的に証明**できる
- 較正レポートを顧客に出せる（**外れた実績も含めて**）

---

## M4 — 記憶と常駐監視

**作るもの**
1. ケースベース記憶（選別・時効・案件隔離ポリシー）
2. 同型ケースの供給（新規案件で「この形は◯◯と同型」）
3. 反証役の世代的強化（RQGM/DRQ 型）`[S-094][S-015]`
4. **thesis tracking**（❓ D1 の C 案: 投資仮説の継続監視）

**終了条件**
- 記憶ヒットが**探索コストを下げる**（測定）
- 記憶が増えても**検索が濁らない**（P9 の警告 `[S-052]`）

## 進め方の原則 🔒

| # | 原則 |
|---|---|
| 1 | **M0 を飛ばさない。** 「作りながら確かめる」は、E1/E2 が落ちたときの手戻りが大きすぎる |
| 2 | **証拠グラフより先に UI を作らない。** view はグラフからの射影であって、逆ではない |
| 3 | **ポリシーゲート（C15）は M1 から。** セキュリティは後付けできない `[S-126]` |
| 4 | **評価基盤は「後で」ではない。** 出荷ゲート（M1）→ 反実仮想（M3）と段階的に厚くする |
| 5 | **各 M の終了条件は数値で書く。** 「良くなった気がする」で次に進まない |
