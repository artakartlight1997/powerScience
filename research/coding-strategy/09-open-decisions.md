# 実装に効く未決定事項

**`../notes/discussion-agenda.md` の D1–D10 のうち、コードに直接影響するものだけを抜き出した。**
❓ が付いたものは、**決まるまで実装が仮置きになる**。

## 1. ブロッキング（M1 開始前に必要）

| # | 未決定 | 何が変わるか | 推奨（暫定） |
|---|---|---|---|
| **D10** | **最初のスコープ** | M1 の全体 | **既存 IC メモを叩く**（既存ワークフローを壊さず、教師データが手に入る） |
| **D1** | **一次商品**（A レポート / B 反証エンジン / C 常駐監視） | 射影器の設計、課金モデル | **B を核に、A は副産物、C は第二波** |
| **D6** | **最初に扱うデータ**（公開日本語 / 顧客プライベート） | 取り込み層と隔離設計 | **両方**。公開でデモ品質、顧客データで抜けられなくする |

## 2. M2 開始前に必要

| # | 未決定 | 何が変わるか | 推奨（暫定） |
|---|---|---|---|
| **D3** | **決定境界の形式化**（人力 / 命題 / 数値モデル） | 探索プランナと EVPI 計算 | **人力 → 命題 → 数値**の段階導入。最初から数値モデルを作らない |
| **D2** | **探索の報酬**（自己評価 / Elo / EIG / 多目的） | プランナのスコア関数 | **decision-relevant EIG を主、ペアワイズを補助** |
| **D5** | **自律 vs 協働の既定値** | UI とワークフロー | **介入は任意**（放置すれば自律）。ただし I1' だけは必須ステップ |

## 3. M3 以降

| # | 未決定 | 何が変わるか |
|---|---|---|
| **D4** | マルチモデルの使い方（集合知 / カスケード / クロスベンダ） | 生成と検証のベンダ配分、キャッシュ設計 |
| **D7** | 監査証跡をどこまで最初から作るか | → **実質的に決着済み**: 証拠グラフが同じ構造を要求するため**最初から作る** |
| **D8** | 評価の自製にいつ工数を払うか | 反実仮想 DD の構築時期（数人月） |
| **D9** | 対外的な一言説明 | 営業資料。「Deep Research の一種」と言わないことだけは確定 |

## 4. 未決定でも先に進める部分 🔒

以下は **D1–D10 の結論に依存しない**ので、決定を待たずに着手してよい。

- 証拠グラフのスキーマとイベントストア（どの商品形態でも必要）
- 接地検証器（Fact Check）
- 数値エンジン（恒等式・三値）
- ポリシーゲート C15（セキュリティ）
- 出荷ゲート G1–G6（構造テスト）
- **M0 の技術検証 E1–E4**

> **つまり: 議論が終わっていなくても、M0 と M1 の骨格は今日から書ける。**
> 決定が要るのは「何を、誰に、どう売るか」であって、「何を土台にするか」ではない。
