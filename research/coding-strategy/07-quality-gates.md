# 出荷ゲート

**「良くなった気がする」で出荷しない。** 全て CI で自動測定し、閾値割れで落とす。

## 1. 構造テスト（毎コミット）🔒

| # | テスト | 閾値 |
|---|---|---|
| G1 | 不変条件 I1–I7（→ [02-evidence-graph.md](02-evidence-graph.md)） | **違反 0** |
| G2 | 生成器から特権 API（原文取得/コード実行/DB）が呼べない | **違反 0** |
| G3 | `trust_label=untrusted` 由来の値が特権ツール引数に到達しない | **違反 0** |
| G4 | 評価モードで `as_of > cutoff` の Evidence に到達しない | **違反 0** |
| G5 | 数値を含む Claim が ToolCall（計算）に紐づく | **違反 0** |
| G6 | イベントストアの改竄検知（ハッシュ連鎖の検証） | **違反 0** |

## 2. 品質ゲート（毎リリース）🔒

| # | 指標 | 閾値（仮） | 根拠 |
|---|---|---|---|
| G7 | **Fact Check**（主要主張） | **≥ 95%** | フロンティアで 39–77% `[S-057]` |
| G8 | Fact Check（全主張） | ≥ 90% | 同上 |
| G9 | Link Works | ≥ 99% | スナップショット保持で原理的に達成可 |
| G10 | **劣化曲線**: ツール呼び出し 150 回時点の Fact Check | **≥ 90%** | 2→150 で −42% `[S-057]` |
| G11 | **数値の恒等式チェック** | **100%**（不一致は Claim に出さない） | 計算52% `[S-131]` |
| G12 | 数値の捏造（NOT_FOUND を返すべき場面での値の生成） | **0件** | 6モデル中4つが捏造 `[S-131]` |
| G13 | judge の順序入替一致率 | **κ ≥ 0.8** | 位置バイアス `[S-058]` |
| G14 | **judge と真指標の相関** | **Pearson ≥ 0.5**、割ったらアラート | 34% vs ほぼ0 `[S-093]` |
| G15 | プロンプトインジェクション耐性（AgentDojo 型） | **攻撃成功 0件**（既知パターン） | ASB 84.3% `[S-126]` |

## 3. 実験ゲート（四半期）

| # | 指標 | 目的 |
|---|---|---|
| G16 | **反実仮想 DD の見落とし率** | 主力の売り文句。過去案件で「後に材料化した事実」の事前検出率 |
| G17 | **Brier / ECE** | 較正の証明。**外れた実績も公開する** |
| G18 | **proxy_gain − real_gain の乖離** | 報酬ハッキングの監視 `[S-103]` |
| G19 | **アナリストの検証時間** | 購買を最も左右する数字（評価D）。競合比較も同じ手順で |
| G20 | **キャッシュヒット率** | 粗利率そのもの `[S-129]` |

## 4. 判定の作法 🔒

1. LLM judge は **「この主張は、この原文のこのスパンに支持されるか」の二値/三値のみ**（P10）
2. **順序ランダム化 + 両順序評価**、不一致は人手レビューへ
3. **複数 judge のκを常時記録**
4. **judge 自体を四半期ごとに人手サンプルで較正**（P14）
5. 自由記述の「品質スコア」は**実装として存在させない**（型で禁止する）

## 5. ゲートの運用

```
毎コミット : G1–G6（構造テスト）        … 数秒〜数分
毎リリース : G7–G15（品質ゲート）        … 固定の回帰セットで実行
四半期    : G16–G20（実験ゲート）        … 実案件と反実仮想 DD

★ G7 / G10 / G11 / G15 のいずれかが割れたら出荷停止。例外なし。
```

**なぜ例外を作らないか**: IC 資料の1文が誤引用なら、資料全体の信頼が飛ぶ。
**「95%」は妥協点ではなく、我々の商品定義そのもの**である。
