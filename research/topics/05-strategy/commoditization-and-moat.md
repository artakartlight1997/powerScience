# コモディティ化と堀

## 1. コモディティ化は「起きるかも」ではなく「起きた」

| 証拠 | 内容 |
|---|---|
| **推論単価** | MMLU で GPT-3.5 相当の性能を出す単価は **2022/11 約 $20/M → 2024/10 約 $0.07/M**（**約1/300**）`[S-088]` |
| **オープンモデル** | Tongyi DeepResearch 30B(A3B) が BrowseComp 43.4 / GAIA 70.9 `[S-030]` |
| **DR 機能の標準化** | Gemini DR API は **$2/task** `[S-020]`。DR は各フロンティアの標準機能に |
| **探索アルゴリズム** | **TreeQuest（AB-MCTS）は Apache-2.0** `[S-009]` |

> **モデルは「購入する投入物」であり、帯域幅のように価格づけされる** `[S-088]`。
> → **モデル層に価値を置く設計は、設計時点で減価する。**
> → ユーザの読み（フロンティア/オープンのコモディティ化）は正しく、Sakana のモデル非依存戦略も正しい。
> → **同時に、探索アルゴリズムも堀ではない。**

## 2. 2026年に残る堀

実務的コンセンサス `[S-086][S-087]`:

| 堀 | 内容 | IP での実装 |
|---|---|---|
| **ワークフローの深さ** | 業務の**正本（system of record）**になる | IC メモ・DD 台帳の正本を握る |
| **累積する自社データ** | 使うほど貯まり、他社が複製できない | ケースベース記憶＋反証結果 |
| **流通 / 距離** | 顧客業務への埋め込み | 既存 VDR / CRM / Excel への接続 |
| **スイッチングコスト** | 抜けると痛い | 過去案件の証拠構造が中に溜まる |
| **規制の深さ** | 監査・準拠が参入障壁 | EU AI Act 準拠の監査証跡 |
| **視点（point of view）** | **何を良しとするかの独自の定義** | **反証・較正という評価軸そのものの所有** |

> 「最強の初期の堀は『より良い AI』ではなく、**より締まった成果と、より速く学習する系**」`[S-087]`
> 「防御可能性は、モデル提供者が機能追加では複製できない3つの資産に宿る:
>  **製品自身の使用が生むデータ、正本となったワークフロー、その両方を保持できる契約上の権利**」`[S-088]`

**警告サイン** `[S-086]`: 「基盤モデルを薄く包んだだけのインタフェースで、他の価値層がない」製品。

## 3. IP は堀を3つに絞る

1. **証拠構造の正本化** — ワークフロー ＋ スイッチングコスト
2. **反証・較正という評価軸の所有** — point of view
3. **監査可能性** — 規制の深さ

**採らない堀**: アルゴリズム（公開済み）、モデル（コモディティ）、単なる速度（模倣容易）。

## 4. なぜ「反証・較正」が真似されにくいか

技術的には真似できる。**しかし製品思想として採用しにくい。**

- 競合は「読みやすい100ページ」「速い」を売っている
- 「反証」を前面に出すと、**自社の生成物の弱さを認めることになる**
- 「較正を公開する」と、**外れたときに数字で残る**
- → **既存の売り文句と矛盾する**ため、大手ほど採りにくい（イノベーターのジレンマ的構造）`C`

ただしこれは**永続的な堀ではない**。堀になるのは、
その評価軸の上に**顧客データが累積したとき**（＝堀①②の合わせ技）。
