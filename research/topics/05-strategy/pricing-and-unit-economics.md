# 価格と単価構造

## 1. 参照点

| | 1実行/1案件あたり | 顧客 |
|---|---|---|
| **Gemini DR API 標準 / Max** | **$2 / $5**（≒¥300 / ¥800）`[S-020]` | 開発者 |
| **Sakana Marlin** | **≒ ¥9,800**（100クレジット）／ 月額 **¥150,000〜** `[S-004]` | 金融・コンサル法人 |
| アナリスト 1人日 | **¥50,000〜150,000** | — |
| 外部 DD ファーム（商業 DD 1本） | **¥5M〜30M** | — |

## 2. 空白帯域

```
¥300 ─── ¥10,000 ────────── ¥100,000 ─────── ¥1,000,000 ────── ¥5,000,000〜
Gemini    Marlin              ★空白★                          外部DDファーム
```

**`¥100,000 〜 ¥1,000,000 / 案件` に1桁分の空白がある** `C`。
「外部 DD の一部を代替する」ポジションが取れる帯域。

**ただし正当化条件がある**:
> 成果物が**レポートではなく「検証済みの証拠構造」**である場合にのみ、この価格は正当化できる。
> レポートを売るなら Marlin と比較され、¥9,800 に引きずられる。

## 3. 原価構造（設計制約）

Gemini DR の実測から学べること `[S-020]`:

| 項目 | 事実 | IP への含意 |
|---|---|---|
| **検索コスト** | 標準80クエリ / Max 160クエリ、$14/1K → **1 run あたり $1.12〜$2.24**。**LLM コストを超えうる** | **クエリ予算配分（EIG）は品質施策であると同時に原価施策** |
| **キャッシュ** | 暗黙キャッシュが入力の **50〜70%** をカバー。これがループを安価に保つ主因 | **案件内の文脈再利用設計がそのまま粗利になる** |
| **文脈膨張** | ループ内で文脈が膨張し、**200K トークン閾値**が価格に効く | 文脈を積まない設計（IterResearch 型）が原価にも効く |
| **エージェント層** | Gemini は**上乗せなし**（素のモデルレート） | 我々の粗利は「検証・構造化・記憶」から取るしかない |

### ルーティング/カスケードの効果 `[S-089]`
- RouteLLM: **最大85% コスト削減、GPT-4 品質の約95%維持**、フロンティア呼び出しは**約26%**
- 実務チーム: **請求額 40〜85% 削減**

→ Marlin の「マルチモデル探索」は**品質戦略であると同時にコスト戦略**。IP も必ず踏襲する。
→ [t-model-routing](../02-methods/model-routing-and-cascades.md)

## 4. 課金モデルの選択肢

| モデル | 長所 | 短所 |
|---|---|---|
| **従量（1案件いくら）** | 分かりやすい。Marlin と比較しやすい | **知識の累積が価値にならない**（Marlin の構造的弱点と同じ罠） |
| **サブスク（席数/ファンド）** | 蓄積が価値になる | 初期の価値証明が要る |
| **成果連動** | 説得力 | 投資成果への帰属が困難 |
| **ハイブリッド（サブスク＋案件従量）** | 現実的 | 設計が複雑 |

**推奨（叩き台）**: **サブスク（記憶とワークフローの正本）＋ 案件従量（探索の実コスト）** `C`
理由: 堀（記憶の累積）を課金構造で殺さないため。→ [t-commoditization-moat](commoditization-and-moat.md)
