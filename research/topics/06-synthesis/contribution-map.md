# 貢献マップ

**各研究が Integral Prism のどの部品に効くか。** 優先度 ★★★ = 設計の骨格に入る。

| # | 研究 / 知見 | 何が言えるか | IP のどこに効くか | 優先 |
|---|---|---|---|---|
| R1 | **AB-MCTS / TreeQuest** `[S-008][S-009]` | 幅/深さの動的配分、モデル選択の探索化、Thompson Sampling | 探索プランナの骨格。**OSS なのでそのまま使える** | ★★★ |
| R2 | **co-scientist の Elo トーナメント** `[S-022][S-023]` | 絶対報酬がない領域は**ペアワイズ比較**で順位づけできる。test-time compute で Elo 向上 | 仮説ランキング層 | ★★★ |
| R3 | **BED-LLM / EIG** `[S-040][S-041][S-042]` | 「次に何を調べるか」を**期待情報利得**で決められる | 探索報酬の理論的背骨 | ★★★ |
| R4 | **ACH / SATs** `[S-061][S-062]` | 支持証拠でなく**反証されない仮説**を採る。診断的証拠を優先 | 一次データ構造（ACH 行列） | ★★★ |
| R5 | **Cited but Not Verified** `[S-057]` | 引用の Fact Check は 39-77%。**探索を増やすと -42%** | 検証ループ＝出荷ゲート | ★★★ |
| R6 | **Judge バイアス研究** `[S-058][S-059]` | 位置/冗長/権威バイアス、非決定性 | 判定は**二値の接地判定に限定**する設計制約 | ★★★ |
| R7 | **ForecastBench / AIA Forecaster** `[S-060]` | LLM は superforecaster 級。ECE≈0.042 まで較正可能 | 確率提示層。**「較正されている」を売れる** | ★★★ |
| R8 | **MAST** `[S-029]` | 失敗の 41.8% は仕様/停止条件、21.3% は検証不足。誤り増幅 17倍→4.4倍 | オーケストレーション制約。**停止条件を一級市民に** | ★★★ |
| R9 | **Anthropic Research 実装知** `[S-028]` | 並列分解できるタスクでのみ多エージェントが勝つ。引用は**専任パス** | サブエージェント設計、Citation の独立工程化 | ★★ |
| R10 | **IterResearch / Heavy Mode** `[S-030]` | 文脈は積まず**毎ラウンド再構成** | 長時間実行の文脈設計 | ★★★ |
| R11 | **context rot / compaction** `[S-050][S-051]` | 長文脈は性能を落とす。編集+記憶で +39%。圧縮は検証対象 | 圧縮時に**出典 ID を落とさない**設計 | ★★ |
| R12 | **Agent KB / CBL / AgentCL** `[S-052][S-053]` | 経験再利用は可能だが、記憶が増えると検索が濁る | ケースベース記憶（選別つき）＝事業の堀 | ★★ |
| R13 | **GraphRAG / HippoRAG / RAPTOR** `[S-047][S-048][S-049]` | 大域センスメイキングはグラフ、局所検索はベクタ | 二層索引。**時間つき KG** | ★★ |
| R14 | **STORM / Co-STORM** `[S-031]` | 多視点の質問生成、協調的談話プロトコル | 視点テンプレート（買い手/競合/退職者/規制…） | ★★ |
| R15 | **Digital Red Queen** `[S-015]` | 敵対的共進化で反証役が強くなる | レッドチームの自動強化 | ★★ |
| R16 | **討論の負の証拠** `[S-045][S-046]` | 説得的な1体が精度を 10-40% 落とす | **討論で合意させない**という設計制約 | ★★★ |
| R17 | **検証器の非対称性** `[S-036][S-037][S-038][S-039]` | 検証側に**追加ツール**を与えるとギャップ拡大 | 検証器に特権（原文/再計算/時系列/別ベンダ） | ★★★ |
| R18 | **RL 探索の多面報酬** `[S-043][S-044]` | 情報利得・カバレッジ・コスト・幻覚抑制を報酬に | **学習せずに推論時スコアへ流用** | ★★ |
| R19 | **ルーティング/カスケード** `[S-089]` | 40-85% のコスト削減、品質 95% 維持 | 原価設計。マルチモデルの正当化 | ★★ |
| R20 | **EDINET-Bench / XBRL 課題** `[S-016][S-017][S-078]` | 日本語金融データは構造化が難所。Sakana は既に参入 | 日本語 DD 評価セットの自製＝資産 | ★★ |
| R21 | **PE 採用実態** `[S-076][S-077]` | 関心は飽和、scaling は 10-15% | 「全社導入」ではなく**1工程の正本化**から | ★★★ |
| R22 | **EU AI Act Art.12/13** `[S-079][S-080]` | 追記専用・改竄検知・10年保持 | 探索木＝監査証跡（規制と製品価値が一致） | ★★ |
| R23 | **HITL / IntentRL / InterDeepResearch** `[S-032][S-033][S-034][S-035]` | 自律性-対話ジレンマ。意図明確化を POMDP 化 | 4つの介入点の設計 | ★★ |
| R24 | **DR タクソノミ** `[S-019]` | 静的/動的 × 単一/マルチ × API/ブラウザ | 自己位置の明示 | ★ |
| R25 | **モート論** `[S-086][S-087][S-088]` | 堀はデータ蓄積・ワークフロー・規制・視点 | 3つの堀の選択 | ★★★ |
| R26 | **OpenAI DR の end-to-end RL** `[S-026][S-027]` | 探索をモデル内部に焼き込む路線 | **採らない**判断の根拠（資源とデータの制約） | ★ |
| R27 | **Tongyi の到達点** `[S-030]` | オープン 30B が BrowseComp 43.4 | モデル層に価値を置かない根拠。自社ホストの選択肢 | ★★ |
| R28 | **長文生成研究** `[S-070]` | 階層計画・反省・クエリ固有ルーブリック | view 生成層（証拠構造 → レポート） | ★ |
| R29 | **金融ベンチの潮流** `[S-067][S-068]` | 軌跡・検証・較正へ重心移動。IPO DD のベンチ化 | 自製評価の手法借用 | ★★ |
| R30 | **VC DD のマルチエージェント研究** `[S-090]` | レイアウト認識 OCR ＋ **データ不在を明示フラグ**する抽出（幻覚対策） | 財務抽出層の実装方針 | ★★ |
| R31 | **DIALECTIC（スタートアップ評価）** `[S-090]` | **弁証法的推論**で反復的・論争的な評価を模す | 反証エンジンの先行事例 | ★★ |
| R32 | **汎用 DR ベンチ** `[S-066][S-069]` | 短答は測りやすいが実務乖離、レポート級は注釈コスト | 自製評価を作る根拠 | ★ |
| R33 | **金融特化製品群** `[S-081]` | 抽出と定型生成は埋まっている。反証と較正は空白 | ポジショニング | ★★★ |
| R34 | **推論単価の崩壊** `[S-088]` | 約1/300 | モデルに賭けない | ★★★ |
