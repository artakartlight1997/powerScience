# 貢献マップ

**各研究が Integral Prism のどの部品に効くか。** 優先度 ★★★ = 設計の骨格に入る。

| # | 研究 / 知見 | 何が言えるか | IP のどこに効くか | 優先 |
|---|---|---|---|---|
| R1 | **AB-MCTS / TreeQuest** `[S-008][S-009]` | 幅/深さの動的配分、モデル選択の探索化、Thompson Sampling | 探索プランナの骨格。**OSS なのでそのまま使える** | ★★★ |
| R2 | **co-scientist の Elo トーナメント** `[S-022][S-023]` | 絶対報酬がない領域は**ペアワイズ比較**で順位づけできる。test-time compute で Elo 向上 | 仮説ランキング層 | ★★★ |
| R3 | **BED-LLM / EIG** `[S-040][S-041][S-042]` | 「次に何を調べるか」を**期待情報利得**で決められる | 探索報酬の理論的背骨 | ★★★ |
| R4 | **ACH / SATs** `[S-061][S-062]` | 支持証拠でなく**反証されない仮説**を採る。診断的証拠を優先 | 一次データ構造（ACH 行列） | ★★★ |
| R5 | **Cited but Not Verified** `[S-057]` | 引用の Fact Check は 39-77%。**探索を増やすと -42%** | 検証ループ＝出荷ゲート | ★★★ |
| R6 | **Judge バイアス研究** `[S-058][S-059]` | 位置/冗長/権威バイアス、非決定性 | 判定は**二値の接地判定に限定**する設計制約 | ★★★ |
| R7 | **ForecastBench / AIA Forecaster** `[S-060]` | LLM は superforecaster 級。ECE≈0.042 まで較正可能 | 確率提示層。**「較正されている」を売れる** | ★★★ |
| R8 | **MAST** `[S-029]` | 失敗の 41.8% は仕様/停止条件、21.3% は検証不足。誤り増幅 17倍→4.4倍 | オーケストレーション制約。**停止条件を一級市民に** | ★★★ |
| R9 | **Anthropic Research 実装知** `[S-028]` | 並列分解できるタスクでのみ多エージェントが勝つ。引用は**専任パス** | サブエージェント設計、Citation の独立工程化 | ★★ |
| R10 | **IterResearch / Heavy Mode** `[S-030]` | 文脈は積まず**毎ラウンド再構成** | 長時間実行の文脈設計 | ★★★ |
| R11 | **context rot / compaction** `[S-050][S-051]` | 長文脈は性能を落とす。編集+記憶で +39%。圧縮は検証対象 | 圧縮時に**出典 ID を落とさない**設計 | ★★ |
| R12 | **Agent KB / CBL / AgentCL** `[S-052][S-053]` | 経験再利用は可能だが、記憶が増えると検索が濁る | ケースベース記憶（選別つき）＝事業の堀 | ★★ |
| R13 | **GraphRAG / HippoRAG / RAPTOR** `[S-047][S-048][S-049]` | 大域センスメイキングはグラフ、局所検索はベクタ | 二層索引。**時間つき KG** | ★★ |
| R14 | **STORM / Co-STORM** `[S-031]` | 多視点の質問生成、協調的談話プロトコル | 視点テンプレート（買い手/競合/退職者/規制…） | ★★ |
| R15 | **Digital Red Queen** `[S-015]` | 敵対的共進化で反証役が強くなる | レッドチームの自動強化 | ★★ |
| R16 | **討論の負の証拠** `[S-045][S-046]` | 説得的な1体が精度を 10-40% 落とす | **討論で合意させない**という設計制約 | ★★★ |
| R17 | **検証器の非対称性** `[S-036][S-037][S-038][S-039]` | 検証側に**追加ツール**を与えるとギャップ拡大 | 検証器に特権（原文/再計算/時系列/別ベンダ） | ★★★ |
| R18 | **RL 探索の多面報酬** `[S-043][S-044]` | 情報利得・カバレッジ・コスト・幻覚抑制を報酬に | **学習せずに推論時スコアへ流用** | ★★ |
| R19 | **ルーティング/カスケード** `[S-089]` | 40-85% のコスト削減、品質 95% 維持 | 原価設計。マルチモデルの正当化 | ★★ |
| R20 | **EDINET-Bench / XBRL 課題** `[S-016][S-017][S-078]` | 日本語金融データは構造化が難所。Sakana は既に参入 | 日本語 DD 評価セットの自製＝資産 | ★★ |
| R21 | **PE 採用実態** `[S-076][S-077]` | 関心は飽和、scaling は 10-15% | 「全社導入」ではなく**1工程の正本化**から | ★★★ |
| R22 | **EU AI Act Art.12/13** `[S-079][S-080]` | 追記専用・改竄検知・10年保持 | 探索木＝監査証跡（規制と製品価値が一致） | ★★ |
| R23 | **HITL / IntentRL / InterDeepResearch** `[S-032][S-033][S-034][S-035]` | 自律性-対話ジレンマ。意図明確化を POMDP 化 | 4つの介入点の設計 | ★★ |
| R24 | **DR タクソノミ** `[S-019]` | 静的/動的 × 単一/マルチ × API/ブラウザ | 自己位置の明示 | ★ |
| R25 | **モート論** `[S-086][S-087][S-088]` | 堀はデータ蓄積・ワークフロー・規制・視点 | 3つの堀の選択 | ★★★ |
| R26 | **OpenAI DR の end-to-end RL** `[S-026][S-027]` | 探索をモデル内部に焼き込む路線 | **採らない**判断の根拠（資源とデータの制約） | ★ |
| R27 | **Tongyi の到達点** `[S-030]` | オープン 30B が BrowseComp 43.4 | モデル層に価値を置かない根拠。自社ホストの選択肢 | ★★ |
| R28 | **長文生成研究** `[S-070]` | 階層計画・反省・クエリ固有ルーブリック | view 生成層（証拠構造 → レポート） | ★ |
| R29 | **金融ベンチの潮流** `[S-067][S-068]` | 軌跡・検証・較正へ重心移動。IPO DD のベンチ化 | 自製評価の手法借用 | ★★ |
| R30 | **VC DD のマルチエージェント研究** `[S-090]` | レイアウト認識 OCR ＋ **データ不在を明示フラグ**する抽出（幻覚対策） | 財務抽出層の実装方針 | ★★ |
| R31 | **DIALECTIC（スタートアップ評価）** `[S-090]` | **弁証法的推論**で反復的・論争的な評価を模す | 反証エンジンの先行事例 | ★★ |
| R32 | **汎用 DR ベンチ** `[S-066][S-069]` | 短答は測りやすいが実務乖離、レポート級は注釈コスト | 自製評価を作る根拠 | ★ |
| R33 | **金融特化製品群** `[S-081]` | 抽出と定型生成は埋まっている。反証と較正は空白 | ポジショニング | ★★★ |
| R34 | **推論単価の崩壊** `[S-088]` | 約1/300 | モデルに賭けない | ★★★ |

| R36 | **Sakana Namazu** `[S-105]` | 日本語特化（Kimi K2.6 チューン）。主権AIは**事前学習でなくチューニングとオーケストレーション** | 日本語品質では戦わない。日本語金融への降下リスクを高く見積もる | ★★★ |
| R37 | **Darwin Gödel Machine** `[S-092]` | 自己改変で SWE-bench 20→50%。**改善はモデル・言語を跨いで転移** | **改善対象はモデルでなくスキャフォールド**。学習せずに資産を積める | ★★★ |
| R38 | **SIFT** `[S-093]` | **RSI の律速は評価コスト**。$25 で +11pt。**judge 忠実度で相関 34% vs ほぼ0** | 検証コストの階層化（P14）と judge 監視 | ★★★ |
| R39 | **Red Queen Gödel Machine** `[S-094]` | 固定評価器の前提を捨て、**評価器を共進化**させる。安価な進化レビュアーで**探索トークン 1.35-1.72倍削減** | **反証役の共進化**＝品質とコストに同時に効く | ★★★ |
| R40 | **AlphaEvolve** `[S-095]` | 進化的コーディングで新発見＋本番展開。2026-07 に GA。**評価器はクライアント側で実行しコードは顧客インフラから出ない** | 進化的探索の実証。**検証器を顧客環境で回す**構成の前例 | ★★ |
| R41 | **ADAS / Meta Agent Search** `[S-097]` | エージェント設計自体を自動化。設計アーカイブを保持し、**モデル/ドメインを跨いで転移** | 長期の自己改善ロードマップ。ただし P13 の制約下で | ★★ |
| R42 | **GEPA** `[S-098]` | **反射的プロンプト進化が RL を上回りうる**。軌跡ベース＋パレート選択 | **学習せずにシステムを改善する**現実的な入口 | ★★★ |
| R43 | **木探索・報酬の統一サーベイ** `[S-099]` | 探索＝〔探索機構〕＋〔報酬定式化〕＋**〔遷移関数〕**。TTS と自己改善を統一的に見る | **「一手」の定義**が設計の要（IP は「反証課題の解決」を一手とする） | ★★★ |
| R44 | **rStar / MCTS-RAG** `[S-100]` | **人間的な推論アクション空間**で MCTS を拡張、生成-識別の自己対戦 | DD 固有のアクション空間設計（仮説追加/分割/反証/再計算/人に聞く…） | ★★ |
| R45 | **検証粒度と計算最適配分** `[S-101]` | ビームサーチ=難問低予算、BoN=易問高予算。**粒度で両者は連続**。適応制御で精度 +3.1〜3.6%、FLOPs −52% | 検証粒度の**動的制御**が原価と品質を同時に決める | ★★★ |
| R46 | **FineVerify** `[S-102]` | **サブ質問へ分解して局所判断**。4軌跡で +8.2pt / +5.6%。**解釈可能な検証トレース** | **L1 接地層の実装型そのもの**。P10 の実証済みの形 | ★★★ |
| R47 | **報酬ハッキングの定量** `[S-103]` | プロキシのみの改善が **73.8% / 46.8%**。10→100 step で **26.4%→57.8%** に悪化。Retrospection は不安定 | **停止条件（P15）**と、プロキシ-現実の乖離監視 | ★★★ |
| R48 | **RSI 安全性** `[S-106]` | 自己改変は**信頼できないコードとして扱う**。テスト環境の識別で評価パラダイムが崩れる懸念 | 金融での自己改善の**範囲制限**（P13） | ★★ |
| R49 | **MoSA / MCCE / 進化的アンサンブル** `[S-107]` | **マルチLLM × MCTS** は複数研究群が同時到達。共進化型も登場 | Sakana 固有の優位ではないことの確認 | ★ |

## v0.4 追加分（「モデルが賢くなっても勝てるか」の深掘り）

| # | 研究 / 知見 | 何が言えるか | IP のどこに効くか | 優先 |
|---|---|---|---|---|
| R50 | **Calibrated LMs Must Hallucinate** `[S-109]` | 較正されたモデルは**理論的に一定率で幻覚する**。アーキテクチャ・データと無関係の統計的下限 | 幻覚はモデル改善では消えない。**外部検証の永続的な必要性** | ★★★ |
| R51 | **Why Language Models Hallucinate** `[S-108]` | 3要因（希少情報・表現限界・計算量的困難）。**主要評価の10個中9個が棄権を罰し、自信ある誤答を報いる** | **モデル層は較正を最適化しない構造** → 較正はアプリ層の補完財（∂V/∂M>0） | ★★★ |
| R52 | **アレアトリック不確実性** `[S-115]` | データ生成過程に内在するノイズは**モデルを良くしても減らない**。性能に硬い天井がある | 「当てる」でなく**epistemic を潰し aleatoric を較正する**という二段構えの理論的正当化 | ★★★ |
| R53 | **jagged frontier / 能力-信頼性ギャップ** `[S-111]` | 平均性能が上がってもギザギザは残る。**本番とベンチで37%差、3回に1回失敗** | 最悪ケースの保証は**モデル外の仕組み**でしか作れない | ★★★ |
| R54 | **METR 時間地平** `[S-110]` | 倍化105日だが**成功率50%での定義**。首位14.5時間 | **50% と業務要求95%+ の溝**が我々の商品領域 | ★★★ |
| R55 | **GDPval** `[S-112]` | 実世界タスクで**専門家の約100倍速く安い** | 生成では戦えない。**選別と保証**に価値が移る | ★★★ |
| R56 | **ハーネスの目減りと残存** `[S-113]` | モデル更新の方が大きい（49→73.2%）が、**状態管理・エラー回復は削減不能なインフラ問題** | 投資対象は「推論の巧妙さ」でなく「証拠と状態の構造」 | ★★★ |
| R57 | **人間-AI 補完性のメタ分析** `[S-114]` | **人間+AI はしばしば AI 単独に劣る**。意思決定タスクでは損失。過信が原因 | **P17**: 介入は「先に人間が判断」「減速」形式に限定 | ★★★ |
| R58 | **AI 駆動のアルファ減衰** `[S-117]` | シグナル半減期 5-7年 → **18ヶ月**。ポートフォリオ収束 +42%。モノカルチャー均衡で純アルファゼロ | **モデル由来の優位は投資では自己消滅する**。私有情報と処理の差だけが残る | ★★★ |
| R59 | **責任と署名（FINRA 2026 ほか）** `[S-118]` | AI 生成の推奨に**人間の署名と代替案検討の文書化**が要求される。責任は署名者に帰属 | **署名者を支える記録**の需要はモデル能力と無関係 | ★★★ |
| R60 | **評価の危機（飽和・汚染）** `[S-116]` | MMLU 93%、GSM8K 99% で飽和。**全フロンティアが SWE-bench Verified の一部を逐語再現**できた | 公開ベンチでの優位は主張できない。**自製評価が資産** | ★★ |
| R61 | **長文脈の実効性能** `[S-119]` | 4K→128K で **15-30% 低下**、実効文脈 200-400K、**意味的に似た妨害要素で急落** | 投資 DD は妨害要素の塊。文脈設計は食われない | ★★ |
| R62 | **Commoditize your complement** `[S-120]` | 補完財の価格がゼロに向かうと、**希少なままのものに価値が流れる** | 生成が無料になったとき希少なのは**検証・責任・較正** | ★★★ |
