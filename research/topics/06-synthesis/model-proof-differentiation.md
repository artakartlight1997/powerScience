# モデルが賢くなっても勝てる要素

> **問い（本プロジェクトで最も重要な戦略的問い）**
> フロンティアモデルがこの先どれだけ賢くなっても、**我々の価値が食われない要素**は何か。

## 0. 判定基準

ある差別化要素 X について、次を問う。

```
X の価値は、モデル能力 M の関数としてどう振る舞うか？

  ∂V(X)/∂M < 0   → 消える（モデルが吸収する）      … Class A
  ∂V(X)/∂M ≈ 0   → 独立（モデルと無関係に残る）    … Class C / D
  ∂V(X)/∂M > 0   → 補完的（賢くなるほど価値が上がる）… Class B ★最良
```

**★ 狙うべきは Class B（補完財）である。** モデルの進歩が我々の追い風になる要素。

---

## Class A — 消えるもの（賭けてはいけない）

| 要素 | 消える証拠 |
|---|---|
| **巧妙なプロンプト・スキャフォールド** | 同一ハーネスでモデル更新だけで **49.0% → 73.2%**。Manus はハーネスを**4回作り直した**。「単純なハーネスが複雑なものを上回ることが多い」 `[S-113]` |
| **マルチモデルのオーケストレーション** | **Sakana Fugu が商用モデルとして出荷済み** `[S-104]` |
| **日本語の言語品質** | **Namazu** が特化済み `[S-105]` |
| **探索アルゴリズムそのもの** | **TreeQuest は Apache-2.0** `[S-009]` |
| **成果物の生成速度・量** | GDPval: フロンティアは専門家の **100倍速く100倍安い** `[S-112]` |
| **素朴な多段検索・要約** | DR は各社の標準機能、$2/task `[S-020]` |

> **結論**: 「賢い作り方」で差別化しない。**作る能力はゼロに向かう。**

---

## Class B — 補完的（モデルが賢くなるほど価値が上がる）★本命

### B1. 較正と棄権（calibrated abstention）
**理論**: 較正された生成モデルは**必ず一定率で幻覚する** `[S-109]`。
**構造**: 主要評価の **10個中9個が二値採点**で、「わからない」を罰し**自信に満ちた誤答を報いる** `[S-108]`。

> **つまりモデル層は、較正と棄権を最適化しない構造的インセンティブの下にある。**
> **モデルが賢くなるほど「自信満々で流暢な誤り」の説得力が上がるため、
> 較正を外から与える価値はむしろ上がる。**

→ ∂V/∂M **> 0**。**最も強い賭けどころ。**

### B2. 特権を持つ検証（原文取得・再計算・時系列・別ベンダ）
**理論**: 検証側が生成側にないツールを持つと、**生成-検証ギャップは拡大する** `[S-036]`。
モデルが賢くなれば**生成も検証も両方強くなるが、ギャップは残る**（むしろ道具が増えるほど広がる）。

さらに: **モデルが賢くなるほど、誤りは「巧妙で見つけにくい」ものに変わる**
（jagged frontier `[S-111]`、報酬ハッキングの高度化 `[S-103]`）。
→ **機械的な検証の必要性は減らない。**

→ ∂V/∂M **≥ 0**。

### B3. 「何を調べるべきか」の目的関数（decision-relevant EIG）
モデルは**与えられた問いに答える**能力を伸ばすが、
**どの問いが顧客の意思決定を反転させるか**は、顧客の効用関数に依存する。
これはモデルの外側にある情報である。

さらに **アレアトリック不確実性は削減不能** `[S-115]` なので、
「もっと考える」では解けず、**どこを掘るかの選択**だけが効く。

→ ∂V/∂M **≥ 0**（賢いモデルほど、良い問いを与えたときの出力が良くなる ＝ 我々の入力価値が上がる）。

### B4. 選別と保証（selection & assurance）
GDPval が示す通り、**生成は100倍安くなる** `[S-112]`。
供給が無限になった財の価値は落ち、**「どれが正しいか」の選別価値が上がる**。
これは「補完財の commoditize」の古典的帰結である `[S-120]`:

> **補完財の価格がゼロに向かうと、需要と価値は「希少なままのもの」へ流れる** `[S-120]`。

生成が無料になったとき希少なのは、**検証済みであること・責任を取れること・較正されていること**。

→ ∂V/∂M **> 0**。

## Class C — 構造的に残る（モデルと独立）

### C1. 存在しない情報は、どんなモデルにも読めない
非公開情報（VDR、経営者面談、退職者の証言、取引先の本音）は
**訓練データにも Web にも存在しない**。
モデル改善の対象外であり、**取得の設計（誰に何を聞くか）**だけが効く。
→ [t-data-sources](../04-domain/data-sources.md)

### C2. 責任と署名（accountability）
- **FINRA の 2026年の期待**: AI が生成・要約した推奨には
  **合理的に利用可能な代替案の検討の文書化と、人間による署名（sign-off）**が求められる `[S-118]`
- 公開企業の財務諸表監査は **CPA の署名が必要** — AI が分析しても**署名は人間** `[S-118]`
- **AI の誤りは、それに署名した専門家の責任になる** `[S-118]`

> **モデルがどれだけ賢くなっても、責任は取れない。**
> 責任を取る人間を支える仕組み（何を見て、何を確認し、何が未解決かの記録）は、
> **モデル能力と無関係に必要とされ続ける。**

→ [t-regulation-compliance](../04-domain/regulation-and-compliance.md)

### C3. 監査証跡
EU AI Act Art.12/13 の要求（改竄検知・10年保持・人間の監督）`[S-079]` は
モデルの賢さと無関係。むしろ**自律性が上がるほど要求が強まる**。

### C4. 顧客固有の記憶と、ワークフローの正本化
使うほど貯まる資産。モデル提供者は複製できない `[S-086][S-088]`。

### C5. 投資領域固有 — アルファ減衰
**全員が同じモデルを使うと、そのモデル由来の優位は消える**（シグナル半減期 5-7年 → 18ヶ月）`[S-117]`。
→ **モデルが賢くなることは、投資領域では「優位の源泉」ではなく「優位の消滅速度」を上げる要因**。
→ [t-alpha-decay](../04-domain/alpha-decay-and-homogenization.md)

## Class D — 減るが完全には消えない

| 要素 | 見立て |
|---|---|
| **状態管理・エラー回復・文脈設計** | 多段実行には**削減不能な協調要件**がある（推論問題ではなくインフラ問題）`[S-113]`。ただし単純化は進む |
| **長文脈の扱い** | 窓は広がるが、**意味的妨害下の劣化は残る**（4K→128K で 15-30% 低下）`[S-119]` |
| **信頼性の作り込み** | 平均は上がるが **jagged さと本番ギャップ 37%** は残る `[S-111]` |

## ⚠️ 逆風の証拠 — 人間協働は自動的には勝たない

我々は「人間との協働（介入点）」を差別化に挙げてきたが、**研究は厳しい**。

- メタ分析: **人間+AI のチーム性能は、多くの場合 AI 単独に劣る** `[S-114]`
- **意思決定タスクでは損失、創造タスクでは利得**という傾向 `[S-114]`
- 原因は**過信（over-reliance）と不適切な依存** — 人間が「どこで自分の判断を足すべきか」を誤る `[S-114]`
- 有効な介入: **AI の答えを見る前に人間が先に判断する**、**意図的に減速させる** `[S-114]`

> ### 🔑 設計への反映（P4 の修正）
> 「人間が介入できる」だけでは価値にならない。**むしろ悪化しうる。**
> IP の介入点は、研究が有効性を確認した形に限定する:
> 1. **人間が先に判断してから AI の結果を見る**（仮説と死因の先出し ＝ 介入点 I1 の再定義）
> 2. **意図的な減速**（IC 前に「未解決の反証」を必ず読ませる）
> 3. **AI の正誤を人間が識別できる形にする**（＝ 証拠と確度の提示。ブラックボックスの推奨をしない）

## 最終的な賭けどころ（優先順位つき）

| 順位 | 賭ける要素 | クラス | 根拠 |
|---|---|---|---|
| **1** | **較正された確度と棄権** | B（補完） | 理論的下限＋評価インセンティブの構造的欠陥 `[S-108][S-109]` |
| **2** | **特権を持つ独立検証** | B | 生成-検証ギャップは道具で広がる `[S-036]`。誤りは巧妙化する `[S-111]` |
| **3** | **顧客固有の情報と記憶** | C | 存在しない情報は読めない。アルファ減衰への唯一の対抗 `[S-117]` |
| **4** | **decision-relevant な問いの設計** | B | 効用関数はモデルの外にある。アレアトリックは削減不能 `[S-115]` |
| **5** | **責任・署名・監査証跡** | C | FINRA の人間署名要求 `[S-118]`、EU AI Act `[S-079]` |
| **6** | **選別と保証（生成ではなく）** | B | 生成は100倍安い `[S-112]`。希少なものに価値が移る `[S-120]` |
| — | 巧妙なスキャフォールド／統率／言語品質／速度 | A | **賭けない** `[S-113][S-104][S-105][S-112]` |

## 一行の結論

> **「賢いモデルを上手に使う」ものを作ってはいけない。それはモデルに食われる。**
> **「賢いモデルが構造的に提供できないもの」を作る。**
> **それは ①較正された確度 ②特権を持つ検証 ③持たない情報 ④責任の記録 の4つである。**
> **そしてこの4つは、モデルが賢くなるほど価値が上がる。**
