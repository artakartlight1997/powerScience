# 設計原則 P1–P24

**各原則は、サーベイで見つかった具体的な証拠に紐づいている。**
「好み」ではなく「そうしないと壊れると分かっているもの」だけを並べた。
機械可読版は `../../metadata/taxonomy.json` の `design_principles`。

| # | 原則 | 根拠 | 破ると何が起きるか |
|---|---|---|---|
| **P1** | **タスクが独立並列に分解できるときだけマルチエージェントにする** | Anthropic: *architecture follows task structure* `[S-028]` | コストだけ増えて品質が落ちる |
| **P2** | **停止条件と検証をアーキテクチャの一級市民にする** | MAST: 失敗の 41.8% が仕様/停止、21.3% が検証 `[S-029]` | 終わらない／誤りが伝播する |
| **P3** | **視点の多様性は自動発見に任せず、実務由来の型で与える** | LLM の対立仮説は訓練分布＝主流に偏る `[S-061]`。STORM の視点発見は百科事典向け `[S-031]` | **バイアス緩和の自動化＝バイアスの自動化** |
| **P4** | **自律だけを売らず、介入点を設計して売る** | ユーザは操舵したい `[S-032]`。意図明確化は POMDP `[S-034]` | 途中で軌道修正できず、8時間を無駄にする |
| **P5** | **検証器には生成器が持たない権限を与える**（原文取得・再計算・時系列・別ベンダ） | 検証側にツールを与えると生成-検証ギャップが拡大 `[S-036]` | 自信満々な誤りが検証を通る `[S-037]` |
| **P6** | **探索の報酬は decision-relevant な期待情報利得に置く** | BED-LLM / EIG `[S-040]`、ACH の診断的証拠 `[S-062]` | もっともらしさの最大化に堕ちる。検索コストも膨らむ `[S-020]` |
| **P7** | **討論で合意させない。討論は反証の生産にのみ使う** | 敵対的1体で精度 -10〜40%、誤答合意 +30% `[S-046]` | **説得力のあるストーリーに賭ける**という最悪の失敗 |
| **P8** | **長時間実行では「何を忘れるか」を設計し、圧縮時に出典 ID を失わない** | context rot は主要モデル横断 `[S-050]`。圧縮の妥当性検証が研究課題 `[S-051]` | 引用検証・監査・受け渡しが同時に壊れる |
| **P9** | **記憶は量ではなく「意思決定に効いた事実＋反証結果」だけを残す** | 安定性-可塑性ジレンマは検索段階に再出現 `[S-052]` | 記憶が増えるほど検索が濁る |
| **P10** | **LLM judge には「良い/悪い」を聞かず、原文支持の二値判定だけを聞く** | 位置/冗長/権威バイアス、非決定性 `[S-058][S-059]` | 評価がノイズになり、改善が測れなくなる |
| **P11** | **ACH 行列を一次データ構造にする（レポートは view にすぎない）** | ACH `[S-061][S-062]`。引用検証には構造が要る `[S-057]` | 「レポートから証拠を逆算する」不可能な設計になる |
| **P12** | **監査証跡は後付けせず、探索木そのものを追記専用の一次記録にする** | EU AI Act Art.12/13：改竄検知・10年保持 `[S-079][S-080]` | 規制対応が二度手間になり、検証ループも作れない |
| **P13** | **自己改善はスキャフォールド（プロンプト・ワークフロー・反証ルーブリック）に限定し、「何を良しとするか」の定義は人間の承認を経る** | DGM の転移性 `[S-092]`、GEPA `[S-098]`、RQGM の非定常性 `[S-094]`、RSI 安全性 `[S-106]` | 監査可能性が崩壊する。評価器に過適合する |
| **P14** | **評価は階層化する（安価な判定で足切り → 高価な検証は上位のみ）。ただし judge と真の指標の相関を常時監視する** | SIFT: 評価コストが律速。judge 忠実度で相関 34% vs ほぼ0 `[S-093]` | 検証コストで破綻するか、**改善したつもりで何も改善しない** |
| **P15** | **探索の長さに上限を置き、プロキシと現実の乖離を停止条件にする** | 引用精度 −42%（2→150 呼び出し）`[S-057]`、報酬ハッキング 26.4%→57.8%（10→100 step）`[S-103]` | 長く走らせるほど見かけが良くなり実質が悪化する |
| **P16** | **差別化要素は ∂V/∂M（モデル能力に対する価値の微分）で選別し、∂V/∂M>0 の補完財だけに賭ける** | 較正の構造的欠陥 `[S-108][S-109]`、生成は100倍安い `[S-112]`、ハーネスの目減り `[S-113]`、補完財の commoditize `[S-120]` | **モデルの進歩に食われる**ものに投資してしまう |
| **P17** | **人間の介入は「AI の出力を見る前に人間が先に判断する」「意図的に減速させる」形式に限定する** | 人間+AI はしばしば AI 単独に劣る。意思決定タスクでは損失 `[S-114]` | 承認型の介入は**過信を招き、精度を下げる** |
| **P18** | **未信頼コンテンツは隔離し、ツール呼び出しは capability で門番する。Web を読んだ LLM に機密アクセス権とツール権限を同時に与えない** | ASB 最高攻撃成功率 84.3% `[S-126]`、プロンプト内防御は上書きされうる `[S-126]`、CaMeL `[S-127]` | **機密情報の持ち出し**。金融機関のセキュリティ審査を通らない |
| **P19** | **数値は必ずコードで計算する。モデルに計算させない。抽出は value / NOT_FOUND / AMBIGUOUS の三値を返す** | FinAuditing 13.86% `[S-130]`、抽出88% vs 素の計算52% `[S-131]`、6モデル中4つが捏造 `[S-131]` | **流暢だが誤った数値**が最終結論を静かに壊す |
| **P20** | **矛盾する証拠は平均も抑制もせず、保存して提示し、追加取得タスクに変換する** | LLM の既定戦略（加重合意/平均化/抑制/多視点）`[S-125]` | **最も価値ある発見（矛盾）を捨てる**ことになる |
| **P21** | **到達可能性（retrievability）を探索の一級変数にする。Web で見つからないと判定した瞬間に channel を VDR/専門家/計算へ切り替える。「不在」を「真」に変換しない（supported_negative / unknown / not_searched の三値）** | 外部評価文書（v2.0 統合）が指摘。ARGUS 型の検索死角、CROWN-QA 型の completeness-sensitive negative reasoning の問題意識と一致 | Web 予算を無駄に浪費し続ける。**「見つからなかった」を「無い」と偽って報告する** |
| **P22** | **証拠の独立性はクラスタで正規化する。同一の上流ソース（同じプレスリリース発）に由来する複数の記事を、独立した支持証拠として数えない** | O2（証拠の独立性、未解決の難問）への暫定解。CAMA 型の latent-source 問題意識と一致 | **確信度の過大評価**（5記事=5独立証拠という誤算） |
| **P23** | **（最終形）起動に必要な入力は「社名または業界名」のみ。それ以外は全部システムが取りに行く。**要求項目は固定スペックとして一度だけ定義し、薄さはリサーチ結果をスペックに突き合わせるカバレッジ監査で機械が検出（文字数でなく検証済み・独立・新鮮な証拠の密度で測る）。ティーザーは中身がなく、IM は「売り手の主張」として取り込んで外部証拠と突合する | ユーザー判定の累積（[disc-internal-build](../../discussion/18-internal-build-and-zero-input.md) 補正1-4）: ICメモ→30秒入力→初期資料と、**その時点に存在しない入力を前提にする誤りを3度訂正**した帰結 | 存在しない入力を前提にした設計は、**使われないまま終わる** |
| **P24** | **較正のMoat主張は時間軸を分けて語る。近期の価値は台帳自体（検証・矛盾・Unknown管理）に置き、Worker/Source較正は「案件数年分かけて効いてくる長期資産」と位置づける** | IC 級案件は年5–15件、結果判明まで2–5年。較正行列のセル数はデータ点数を何年も上回る | **近い将来に効くと誇張**すると、較正が効くまでの期間に「効果が出ない」と判定されて終わる |

## 原則同士の関係

```
        P11（ACH 行列が一次構造）
          ├── P6（EIG で探索）───── P3（視点は型で与える）
          ├── P5（検証器の特権）─── P10（二値判定）── P7（討論は反証生産）
          ├── P8（文脈と出典の分離）── P12（追記専用の監査記録）
          └── P9（選別された記憶）
        P1/P2（並列性と停止条件）は全体にかかる骨組み
        P4（介入点）は P3 と P9 に人間の入力を供給する
```

**追加分（P13–P15）の位置づけ**: いずれも **「長く回すほど良くなる」という素朴な前提への反証**から来ている。
P13 は自己改善の範囲を、P14 は評価コストの構造を、P15 は探索の停止を規定する。
この3つは **Marlin の「8時間」という売り方への、直接的な対抗軸**でもある。

**P18–P20 の位置づけ**: いずれも **「動くものを作れるか」ではなく「金融の本番で使えるか」** を決める制約。
P18 がないと導入審査を通らず、P19 がないと数値が壊れ、P20 がないと最も価値ある発見を捨てる。

**P21–P24 の位置づけ（v2.0 統合設計で追加）**: 外部提供された設計評価文書（討論 [16](../../discussion/16-prism-proposal-vs-sakana.md) の後に受領）との統合から生まれた。
P21/P22 は Evidence Graph のスキーマを拡張する概念（→ [cs-evidence-graph](../../coding-strategy/02-evidence-graph.md)）、
P23/P24 は「良い設計だが実務に降ろすと壊れる」という外部文書自体の弱点への修正。
詳細は [17-integrated-design-v2.md](../../discussion/17-integrated-design-v2.md)。

**P16 / P17 の位置づけ**: P16 は**何に投資するかの選別基準**であり、他の全原則の上位にある。
P17 は P4（介入点）の**修正**である — 「人間を入れれば良くなる」という素朴な前提は研究に否定されている。
→ [t-model-proof](model-proof-differentiation.md)

**注目**: P11 を採ると、P5・P8・P12 が自動的に満たしやすくなる。
逆に「自然言語のレポートを中間成果物にする」設計を採ると、**P5・P8・P10・P12 が同時に壊れる**。
ここが設計上の分岐点であり、**最初に決めるべき一点**。
