# 差別化仮説

> ⚠️ **これはアーキテクチャ提案ではない。議論のための仮説の束である。**
> 確定は `../../notes/discussion-agenda.md` の論点を潰してから行う。

## 0. 一枚の主張

**Sakana Marlin と Google Deep Research は、どちらも『レポートを作る機械』である。**
**Integral Prism は『投資判断の反証可能な証拠構造を作る機械』にする。**

| | Marlin | Gemini DR | **Integral Prism（仮説）** |
|---|---|---|---|
| 最終成果物 | 100ページのレポート＋スライド | 引用つきレポート | **仮説×証拠の行列（ACH）＋較正済み確率＋残存リスク＋次の3手** |
| 探索の報酬 | 非公開 `D` | RL 済み方策 | **decision-relevant EIG** |
| 検証 | 自己評価 `C` | 自己評価＋グラウンディング | **生成器より強い権限を持つ独立検証器** |
| 人間 | 8時間放置 `C` | 計画を承認 | **4つの介入点で協働** |
| 蓄積 | 実行ごとに消える `C` | しない | **ケースベース記憶（外した理由込み）** |
| 監査 | 不明 | 不明 | **探索木＝監査証跡** |

## 仮説 A: 「反証エンジン」— 探索の目的関数を変える

**内容**: 探索の報酬を「レポート品質」ではなく
**「投資判断を反転させうる証拠の発見」** に置く。

**理論的裏付け**
- **EIG**（BED-LLM `[S-040]`）と **ACH の診断的証拠**（`[S-061][S-062]`）が同じ場所を指している
- 「もっと探索すれば良くなる」は成立しない（引用精度 -42% `[S-057]`）ため、
  **探索の方向を絞る目的関数が必要**

**実装の骨子**
```
1. 投資判断（Go/No-Go, 価格, 条件）を明示化
2. 「これが偽なら判断が変わる前提」を列挙（＝仮説空間）
3. 各前提について、証拠取得による期待確率変動 ÷ 取得コスト でランキング
4. 上位から探索。EIG が閾値を下回ったら停止
5. 出力 = ACH 行列 ＋ 残存する反証リスク ＋ 次に確認すべき3件
```

**検証方法**: 反実仮想 DD（→ [t-ip-evaluation-design](../03-evaluation/integral-prism-evaluation-design.md)）で
**見落とし率**が下がるか。

**なぜ競合が真似しにくいか**
目的関数の変更は**アルゴリズムではなく製品思想**である。
「読みやすい100ページ」を売っている限り、この目的関数は採用できない（自社の売りと矛盾する）`C`。

**リスク**
- 決定境界の形式化が難しい（→ 未決論点 D3）
- 「反証ばかり出す悲観的なシステム」に見える恐れ → 出力設計で緩和が必要
- 反証は無限に作れる → **打ち切り基準が必須**（→ [t-failure-modes-mast](../02-methods/failure-modes-mast.md)）

## 仮説 B: 「較正された確度」— 出力の単位を変える

**内容**: すべての主要主張に **確率と根拠強度**を付け、
**その較正を継続測定して顧客に開示する**。

**裏付け**
- LLM は既に superforecaster 級（Brier 0.0753 vs 人間 0.0740）`[S-060]`
- 較正は測れる（Brier / ECE）。ECE ≈ 0.042 の達成報告あり `[S-060]`
- **Argumentative Coherence Filter**（論拠と確率の不整合を除去）で集団精度が改善 `[S-060]`

**実装の骨子**
```
主張 → 論拠グラフ（証拠 ID の集合） → 確率
     → 論拠と確率の整合チェック（強気の結論 × 弱い根拠 を検出）
     → 実現との突合を蓄積 → Brier / ECE を四半期公開
```

**販売メッセージ**: **「うちの 70% は、実際に約70%当たる」を四半期ごとに証明する。**

**なぜ効くか**: 投資プロは確率で考える職業である。**彼らの母語で話す唯一のシステム**になる。

**リスク**
- 外れたときに数字で残る（＝競合が採りにくい理由でもある）
- 命題設計が難しい（**後で答え合わせできる形**でなければ較正できない）
- PE の保有期間は長い → **中間指標で較正サイクルを短くする**工夫が要る

## 仮説 C: 「ファンドの記憶」— 資産の所在を変える

**内容**: 案件をまたいで **「何を見て、何を外したか」** を構造化蓄積し、
新規案件に**同型ケース**として供給する。

**裏付け**
- Agent KB / CBL による経験の構造化再利用 `[S-053]`
- 堀の議論：**累積する自社データ・ワークフローの正本・規制の深さ** `[S-086][S-087]`
- Digital Red Queen 的な**反証役の世代的強化** `[S-015]`

**制約（研究の警告）**
- **記憶は増やすほど検索が濁る** `[S-052]`
  → **意思決定に効いた事実のみ、反証結果つきで残す**
- MNPI / Chinese Wall との両立（→ 未決論点 D6）

**効果**: 使うほど強くなる ＝ **スイッチングコストと粗利の同時改善**。

## 「単調で薄っぺらくない」ための構造上の要請

1. **多層の目的関数** — 単一スコアで探索しない。
   〔情報利得〕〔反証力〕〔検証可能性〕〔コスト〕〔意思決定関連性〕の多目的最適化
2. **異質なエージェント** — 同じモデルの複製を並べない。**役割ごとに権限とツールを変える**
3. **時間の一級市民化** — 全証拠に取得時刻と有効期間。**point-in-time 再現**ができること
4. **失敗の記録** — 反証されて捨てた仮説を捨てない。**それが次案件の資産**
5. **停止条件の理論** — 「いつ調べ終わるか」を EIG 閾値と予算で定義する
6. **人間の介入点** — 4点（仮説承認 / 反証優先 / 一次情報投入 / 確度上書き）
7. **監査の一次記録化** — 後付けログではなく、**探索木そのもの**を追記専用で保存
