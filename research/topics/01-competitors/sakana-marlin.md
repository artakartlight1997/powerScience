# Sakana Marlin

最重要の直接競合。**「長時間 × 木探索 × マルチモデル」で高単価 B2B を取りに来ている。**

## 1. 製品事実

| 項目 | 内容 | 確度 |
|---|---|---|
| 発表日 | **2026-06-15**。Sakana AI 初の商用プロダクト `[S-001][S-002][S-004]` | A |
| 位置づけ | 自律型リサーチアシスタント。対外的に **"Virtual CSO"（仮想 CSO）** `[S-005][S-006]` | A |
| カテゴリ名 | **"Ultra Deep Research"** — 既存 Deep Research との差を**実行時間**で定義 `[S-003][S-005]` | A |
| 実行時間 | **最大約8時間**の無人自律実行 `[S-001][S-003][S-004][S-005]` | A |
| 出力 | 数十〜**最大100ページ級**のテキストレポート ＋ プレゼン用スライド（画像生成AI併用） `[S-002][S-004][S-005]` | A |
| 前史 | **2026-04** からクローズドβ。**金融機関・コンサルティングファーム**に限定提供 `[S-002][S-004]` | A |
| 顧客 | 法人専用（非コンシューマ）。金融機関 / コンサル / 事業会社の経営企画・事業開発 `[S-004]` | A |
| 価格 | Pay-per-use（**1実行 = 100クレジット**、追加クレジット **¥98/個**）＋ 月額プラン **¥150,000〜**（Pro / Team / Enterprise） `[S-004][S-005]` | B |
| データ方針 | 顧客入力を学習・ファインチューンに**使わない**。外部 AI プロバイダにも同条件を課す（明示的オプトイン時を除く） `[S-005]` | B |

### 単価の含意

1実行 ≒ 100クレジット × ¥98 ≒ **¥9,800/回**（pay-per-use 換算）`C`

- Gemini Deep Research API は **$2〜$5/task**（≒¥300〜¥800）`[S-020]` → **10〜30倍の価格差**
- つまり Marlin は「安いレポート量産機」ではなく「**高単価・低頻度・意思決定級**」を狙っている `B`
- この価格帯を正当化する根拠は、現状「**8時間かけた**」という**投入量**である。
  **成果の質を直接保証する指標は公開されていない**（→ ここが我々の攻めどころ）

## 2. アーキテクチャ

Sakana 自身の説明では、Marlin は **2つの自社研究の直接的な製品化**である `[S-005][S-006]`。

1. **AB-MCTS**（NeurIPS 2025 Spotlight）→ [t-sakana-ab-mcts](sakana-ab-mcts-treequest.md)
2. **The AI Scientist** 由来のワークフロー自動化基盤（Nature 掲載）→ [t-sakana-ai-scientist](sakana-ai-scientist.md)

報じられている動作原理（`B`〜`C`）:

- 木の各ノードで、外部フィードバック信号に基づき
  **「広げる（新しい仮説・候補を生成）」** か **「深める（既存候補を精緻化・監査）」** を動的選択 `[S-003]`
- **第3の軸として「どのモデルを呼ぶか」を探索対象に含める**。
  フロンティア各社のモデルを **plug-and-play な集合知ネットワーク**として扱う `[S-003]`
- 1セッションで **数百〜数千回の LLM 呼び出し**、計算資源を有望な枝に動的配分 `[S-003]`
- 自律的に仮説を立て、情報を集め、**矛盾するデータを突き合わせて調停**し、成果物へ統合 `[S-005]`

```
 Marlin（推定される制御構造）
 ┌──────────────────────────────────────────────────────┐
 │ ルート = リサーチ課題                                  │
 │   ├─ 幅方向 : 新規仮説 / 新規サブクエスチョンを生成      │ ← Thompson Sampling で
 │   ├─ 深さ方向: 既存の暫定回答を精緻化・監査            │    確率的に配分
 │   └─ モデル方向: どの LLM に任せるか                   │ ← マルチモデル集合知
 │                                                        │
 │ 各ノードのスコア = 「外部フィードバック」               │ ★ここが非公開
 └──────────────────────────────────────────────────────┘
```

### 非公開の核心 — 報酬設計 `D`

木探索の**スコア（報酬）を何で与えているか**が公開されていない。

- ARC-AGI-2 やコード生成では「テストが通る/通らない」という**機械検証可能な報酬**が存在する
- しかし **ビジネスリサーチには自明な報酬が存在しない**
- ここを Marlin がどう埋めているか（自己評価か、外部検証か、人間フィードバックか）は不明

→ 未検証課題 Q1 / Q2（`notes/open-questions.md`）。**本プロジェクト最大の攻めどころ**。

## 3. 弱点仮説（同じ土俵で戦わないための整理）

### W1. 報酬設計の穴
自己評価が報酬なら、**確信度の高い誤りが最も深く掘られる**。
実証的に、DR 系はツール呼び出しを 2 → 150 に増やすと **引用の事実正確性が平均約42%低下**する `[S-057]`。
「長く探索するほど良い」は自明ではない。→ [t-citation-attribution](../03-evaluation/citation-attribution.md)

### W2. 成果物が「レポート」で終わっている
100ページのレポートは、IC（投資委員会）にとって**入力であって出力ではない**。
PE 実務家が欲しいのは *この投資仮説を殺しうる事実は何か / それは今いくら確からしいか / 誰が次に何を確認すべきか*。
→ [t-pe-dd-workflow](../04-domain/pe-dd-workflow.md)

### W3. 8時間の不可視性
途中で軌道修正できない長時間バッチは実務で嫌われる。
ユーザ調査では「リアルタイムに研究方向を操舵したい」要求が繰り返し報告されている `[S-032]`。
Sakana の設計は自律性に振り切っており、**mixed-initiative に弱い**可能性が高い `C`。
→ [t-human-in-the-loop](../02-methods/human-in-the-loop.md)

### W4. 監査可能性
数千回の LLM 呼び出しの結果は、**なぜそう結論したかの経路が復元しにくい**。
EU AI Act 高リスク要件（Art.12/13、2026-08-02 完全適用、10年保持・改竄検知）を踏まえると、
金融領域では「探索木そのものが監査証跡である」設計が要る `[S-079]`。
→ [t-regulation-compliance](../04-domain/regulation-and-compliance.md)

### W5. 知識が案件をまたいで蓄積されない可能性
1実行 = 1レポートの課金モデルは、**知識の累積を製品価値にしない**構造を生みやすい `C`。
PE ファンドの真の資産は「過去100件で何を見て、何を外したか」。ここは空いている。
→ [t-memory-continual-learning](../02-methods/memory-and-continual-learning.md)

## 4. 戦略評価 —「Sakana の戦略は正しいか」

| Sakana の賭け | 内容 | 評価 |
|---|---|---|
| ① モデル非依存 | フロンティア/オープンモデルを差替え可能な部品として扱う | **正しい**。推論単価は 2022→2024 で MMLU 同等性能あたり $20/M → $0.07/M（約1/300）`[S-088]` |
| ② 推論時計算に賭ける | 学習でなく推論時探索で性能を出す | **正しいが他社も来る**。公知領域であり、勝負は検証器設計に移っている |
| ③ 時間軸で差別化 | 「8時間考える」を売る | **短期は正しい、中期は脆い**。時間は模倣可能。Google DR も Max 版で検索回数を倍化 `[S-020]` |
| ④ 高単価 B2B | 消費者向けを捨てる | **正しい**。DR 機能は各フロンティアの標準機能化＝コモディティ化 |
| ⑤ RSI（自己改善） | AI 開発プロセス自体を AI で最適化 `[S-007]` | 長期的には合理的。ただし Marlin の顧客価値には**まだ直結していない** |

**結論**: ①②④は構造的に正しい。③は模倣容易。
Sakana の実質的な堀は「AB-MCTS そのもの（OSS 公開済み `[S-009]`）」ではなく、
**「探索を長時間安定に走らせるエンジニアリング資産」＋「金融/コンサルの初期顧客基盤」** `C`。
