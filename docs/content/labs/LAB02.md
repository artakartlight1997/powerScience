所要45分。現実の「経理部が作ったExcel」に近い、意図的に汚したデータを整形します。

## このラボのゴール

[sales_dirty.csv](data/sales_dirty.csv) を、分析可能な整然データに変換します。

このファイルには、次の問題が意図的に含まれています。

| # | 問題 | 対処するステップ |
|---|---|---|
| 1 | 1行目に余計なタイトル行がある | ステップ1 |
| 2 | 月が横持ちの列になっている | ステップ4 |
| 3 | 店舗名に全角スペースが混ざる | ステップ3 |
| 4 | カテゴリ名の末尾に全角スペース | ステップ3 |
| 5 | 金額に `1,234,567` のような桁区切り文字列 | ステップ5 |
| 6 | 金額に `N/A` という文字列 | ステップ5 |
| 7 | 空欄（null） | ステップ5 |
| 8 | 「◯◯店 小計」という集計行が混ざる | ステップ2 |
| 9 | 完全に重複した行がある | ステップ6 |
| 10 | 空行がある | ステップ2 |

## ステップ1：読み込みとヘッダーの修正（5分）

1. **データを取得 → テキスト/CSV** で `sales_dirty.csv` を選択
2. **データの変換** をクリック
3. プレビューを見ると、1行目に「Northstar Retail 月次売上速報…」という余計な行があります
4. **ホーム → 行の削除 → 上位の行の削除 → 1行**
5. **変換 → 1行目をヘッダーとして使用**

これで `店舗名 / 商品カテゴリ / 2025年1月 / … / 備考` が見出しになりました。

## ステップ2：ゴミ行を除去（5分）

### 小計行を消す

1. `店舗名` 列のフィルターボタン（▼）→ **テキストフィルター → 指定の値を含まない**
2. 「小計」と入力してOK

> [!TIP]
> 実務では「小計」の表記が揺れます（「合計」「計」「Total」）。列プロファイルで実際の値を確認してから条件を決めてください。

### 空行を消す

1. **ホーム → 行の削除 → 空白行の削除**

### 備考列を消す

分析に使わないので削除します。

1. `備考` 列を右クリック → **削除**

> [!TIP]
> 本来は「他の列の削除」で使う列だけ残すほうが安全ですが、ここでは残す列がこの後のピボット解除で変わるため、不要列の個別削除で進めます。

## ステップ3：文字列のクレンジング（8分）

### 全角スペースを半角に

1. `店舗名` 列を選択 → **変換 → 値の置換**
2. 検索する値：全角スペース（`　`）を入力 ※IMEで全角空白を入力してください
3. 置換後：半角スペース（` `）
4. `商品カテゴリ` 列にも同じ操作を行う

> [!TRAP]
> 全角スペースは見た目では判別しにくい文字です。値の置換ダイアログに直接入力するのが難しい場合は、次のステップの数式バーで直接書く方法を使ってください。

### トリミングとクリーン

1. `店舗名` と `商品カテゴリ` を両方選択（Ctrlキー）
2. **変換 → 書式 → トリミング**
3. 続けて **変換 → 書式 → クリーン**

### 数式で一括処理する方法（上級）

上の3操作は、詳細エディタで1ステップにまとめられます。

```m
= Table.TransformColumns(前のステップ, {
    {"店舗名",       each Text.Trim(Text.Replace(_, "　", " ")), type text},
    {"商品カテゴリ", each Text.Trim(Text.Replace(_, "　", " ")), type text}
  })
```

## ステップ4：ピボット解除で縦持ちに（8分）

ここがこのラボの核心です。

1. `店舗名` と `商品カテゴリ` の**2列を選択**（Ctrlキー）
2. 右クリック → **その他の列のピボット解除**

`2025年1月` 〜 `2025年4月` の4列が、`属性` と `値` の2列にまとまりました。

3. `属性` 列を右クリック → **名前の変更** → `年月`
4. `値` 列を → `売上金額`

```mermaid ピボット解除の効果
flowchart LR
  A["店舗名 | カテゴリ | 1月 | 2月 | 3月 | 4月<br/>（30行 × 4列）"] --> B["店舗名 | カテゴリ | 年月 | 売上金額<br/>（120行 × 4列）"]
  style B fill:#e0f5ee,stroke:#14926b
```

> [!EXAM]
> **「選択した列のピボット解除」ではなく「その他の列のピボット解除」を使う**のがポイントです。5月の列が追加されても、クエリを直さずに自動で取り込まれます。この判断は試験でも問われます。

## ステップ5：数値のクレンジング（10分）

`売上金額` 列にはまだ問題が残っています。

1. **表示 → 列の品質・列の分布・列のプロファイル** をすべてオン
2. ステータスバーで **「データセット全体に基づく列プロファイル」** に切り替え
3. `売上金額` 列を見ると、`N/A` や桁区切り付きの文字列が混在していることが分かります

### 桁区切りのカンマを除去

1. `売上金額` 列を選択 → **変換 → 値の置換** → 検索 `,` → 置換後は空欄

### N/A を null に

1. 同じく **値の置換** → 検索 `N/A` → 置換後は空欄
   - 「詳細設定オプション → セル全体の内容を一致させる」にチェック

### 型を整数に変換

1. `売上金額` 列の型アイコン → **整数**
2. エラーが出た場合、列の品質でエラー行を確認

### 空欄の扱いを決める

「売上がない」のか「データが未入力」なのかで対応が変わります。

| 判断 | 操作 |
|---|---|
| 売上ゼロとみなす | 値の置換で null → 0 |
| データなしとして集計から除外 | そのまま null にしておく |
| 行ごと不要 | ホーム → 行の削除 → 空白行の削除 |

> [!WARN]
> このラボでは **null のまま残す** ことにします。SUM は null を無視するため、集計結果は正しくなります。0 に置き換えると「売上0円の実績があった」という別の意味になります。

## ステップ6：重複の除去（3分）

1. **ホーム → 行の削除 → 重複の削除**（列を選択せずに実行 = 全列一致の行を削除）
2. 削除前後で行数を確認（ステータスバーに表示されます）

## ステップ7：年月を日付に変換（5分）

`2025年1月` という文字列のままでは、時系列分析ができません。

1. **列の追加 → カスタム列**、列名 `年月日`

```m
= Date.FromText(
    Text.Replace(Text.Replace([年月], "年", "-"), "月", "-01")
  )
```

2. 型を **日付** に設定
3. 元の `年月` 列は残しても構いません（表示用として使えます）

> [!TIP]
> `2025年1月` → `2025-1-01` → 日付、という変換をしています。ステップを分けて `Text.Replace` の結果を確認しながら進めると、どこで失敗しているか分かりやすくなります。

## ステップ8：仕上げ

1. クエリ名を `Fact_月次売上` に変更
2. **ホーム → 閉じて適用**
3. テーブルビューで結果を確認
