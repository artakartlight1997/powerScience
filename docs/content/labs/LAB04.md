## メジャー専用テーブルを作る（5分）

メジャーが増えるので、先に置き場所を用意します。

1. **ホーム → データの入力**
2. 列1に何も入力せず、テーブル名を `_Measures` にして「読み込む」
3. 作成後、`Column1` を右クリック → **レポートビューでは非表示**

以降、メジャーを作ったら **メジャーツール → ホームテーブル** で `_Measures` に移動します。

> [!TIP] なぜ専用テーブルを作るのか
> メジャーを `Fact_売上` に置くと、列とメジャーが混ざってデータペインが探しにくくなります。空テーブルにまとめると、名前が `_` で始まるためデータペインの先頭に固定され、メジャーだけを一望できます。

## 1本目：総売上（3分）

```dax
総売上 = SUM( Fact_売上[SalesAmount] )
```

書式：10進数、小数点0桁、桁区切りオン。

## 2本目：原価合計（5分）

売上テーブルには原価がありません。商品マスタの `StandardCost` を参照します。

```dax
原価合計 =
SUMX(
    Fact_売上,
    Fact_売上[Quantity] * RELATED( Dim_商品[StandardCost] )
)
```

> [!TRAP] メジャーの中でいきなり `RELATED` は使えない
> `原価合計 = SUM( Fact_売上[Quantity] ) * RELATED( ... )` はエラーになります。`RELATED` は**行コンテキスト**（今どの行にいるか）がないと動きません。`SUMX` が行コンテキストを作っているからこそ使えるのです。理屈は [コンテキスト遷移](lesson.html?id=L1302) で扱います。

## 3本目：粗利（1分）

```dax
粗利 = [総売上] - [原価合計]
```

メジャーからメジャーを呼ぶのは正しい書き方です。`SUM(...)` を書き直さないでください。定義が1か所にまとまり、後で変更するときに1本直すだけで済みます。

## 4本目：粗利率（2分）

```dax
粗利率 = DIVIDE( [粗利], [総売上] )
```

書式：パーセンテージ、小数点1桁。

> [!TRAP] `/` ではなく `DIVIDE` を使う
> 分母が0や空白になる状況（フィルター結果が空の行など）で、`/` は無限大やエラーを返します。`DIVIDE` は空白を返して静かに済みます。第3引数を書けば代替値も指定できます（`DIVIDE( a, b, 0 )`）。

## 5本目：前年同期売上（5分）

```dax
前年売上 = CALCULATE( [総売上], SAMEPERIODLASTYEAR( Dim_日付[Date] ) )
```

確認：マトリックスに行 `Dim_日付[年]` → `Dim_日付[月]`、値に `総売上` と `前年売上` を置きます。データの最初の年では `前年売上` が空白になるはずです。

> [!EXAM] タイムインテリジェンスの3条件
> `SAMEPERIODLASTYEAR` などが動くには、(1) 専用の日付テーブルがある、(2) 日付テーブルとしてマークされている、(3) 日付に抜けがなく連続している、の3つが必要です。1つでも欠けると結果は空白になります。PL-300 の「2.4 タイムインテリジェンス」の中心論点です。

## 6本目：前年比増減率（5分）

```dax
前年比増減率 =
VAR 今年 = [総売上]
VAR 前年 = [前年売上]
RETURN
    IF(
        ISBLANK( 前年 ) || 前年 = 0,
        BLANK(),
        DIVIDE( 今年 - 前年, 前年 )
    )
```

書式：パーセンテージ、小数点1桁。

> [!TIP] 0ではなく `BLANK()` を返す
> 前年データがない期間に0を返すと、折れ線が0まで急落して「前年比0%だった」と誤読されます。`BLANK()` なら線が途切れ、「データがない」ことが正しく伝わります。

## 7本目：年度累計（YTD）（5分）

Northstar Retail は4月始まりの会計年度とします。

```dax
売上YTD = TOTALYTD( [総売上], Dim_日付[Date], "3/31" )
```

第3引数の `"3/31"` が年度末日です。これを省略すると暦年（12/31締め）になります。

確認：マトリックスに行 `Dim_日付[年度]` → `Dim_日付[月]`、値に `総売上` と `売上YTD` を置き、4月から累積していくことを確認します。

## 8本目：カテゴリ構成比（8分）

```dax
カテゴリ構成比 =
DIVIDE(
    [総売上],
    CALCULATE( [総売上], ALLSELECTED( Dim_商品[Category] ) )
)
```

書式：パーセンテージ、小数点1桁。

### 実験：ALL と ALLSELECTED の違いを見る

```dax
カテゴリ構成比_ALL =
DIVIDE( [総売上], CALCULATE( [総売上], ALL( Dim_商品[Category] ) ) )
```

テーブルに `Category`・`カテゴリ構成比`・`カテゴリ構成比_ALL` を並べ、カテゴリスライサーで2つだけ選んでみてください。

| メジャー | 選択した2カテゴリの合計 | 意味 |
|---|---|---|
| カテゴリ構成比（ALLSELECTED） | 100% | 「見えている範囲での構成比」 |
| カテゴリ構成比_ALL（ALL） | 100%未満 | 「全カテゴリに対する構成比」 |

## 9本目：売上ランキング（8分）

```dax
商品ランク =
IF(
    ISBLANK( [総売上] ),
    BLANK(),
    RANKX( ALL( Dim_商品[ProductName] ), [総売上], , DESC, DENSE )
)
```

> [!TRAP] `RANKX` の第1引数を間違えると全部1位になる
> 第1引数の `ALL` を忘れて `RANKX( Dim_商品, [総売上] )` と書くと、各行のフィルターコンテキストで商品が1つに絞られているため、全商品が1位になります。**「何の中での順位か」を第1引数で明示する**のが `RANKX` の作法です。

引数の意味は次のとおりです。

| 引数 | 値 | 意味 |
|---|---|---|
| 第1 | `ALL( Dim_商品[ProductName] )` | 順位を付ける母集団 |
| 第2 | `[総売上]` | 順位の基準になる式 |
| 第3 | （空） | 比較する値。省略で第2引数を使う |
| 第4 | `DESC` | 大きいほうが1位 |
| 第5 | `DENSE` | 同順位の次を飛ばさない（1,2,2,3） |

## 10本目：累計売上（Running Total）（8分）

```dax
売上累計 =
VAR 現在日付 = MAX( Dim_日付[Date] )
RETURN
    CALCULATE(
        [総売上],
        Dim_日付[Date] <= 現在日付,
        ALL( Dim_日付 )
    )
```

確認：折れ線グラフのX軸に `Dim_日付[年月]`、Y軸に `売上累計` を置くと、右肩上がりの線になります。

```figure
{ "type":"steps", "title":"累計メジャーの3手順", "caption":"この型は移動平均・期首残高など多くの指標に流用できる",
  "items":[
    {"title":"現在位置を捕まえる","text":"VAR 現在日付 = MAX( Dim_日付[Date] ) で、今いる行の日付を先に確保する","tone":"blue"},
    {"title":"日付フィルターを解除する","text":"ALL( Dim_日付 ) で「今月だけ」という制約を外す","tone":"amber"},
    {"title":"新しい条件を掛け直す","text":"Dim_日付[Date] <= 現在日付 で期首からの範囲を指定する","tone":"green"} ] }
```

> [!TRAP] `VAR` を使わないと壊れる
> `CALCULATE( [総売上], Dim_日付[Date] <= MAX( Dim_日付[Date] ), ALL( Dim_日付 ) )` と書くと、`MAX` が `ALL` 適用後のコンテキストで評価され、常に最終日を返します。結果は全期間の合計が全行に並びます。**外側のコンテキストの値は `VAR` で先に確保する**のが鉄則です。

### 12本目：新規顧客数

```dax
新規顧客数 =
VAR 期間開始 = MIN( Dim_日付[Date] )
VAR 現在顧客 = VALUES( Fact_売上[CustomerID] )
VAR 過去顧客 =
    CALCULATETABLE(
        VALUES( Fact_売上[CustomerID] ),
        Dim_日付[Date] < 期間開始,
        ALL( Dim_日付 )
    )
RETURN
    COUNTROWS( EXCEPT( 現在顧客, 過去顧客 ) )
```

`EXCEPT` は「A にあって B にない行」を返します。つまり「今期買った人のうち、過去に一度も買っていない人」です。

### 13本目：7日移動平均

```dax
売上_7日移動平均 =
AVERAGEX(
    DATESINPERIOD( Dim_日付[Date], MAX( Dim_日付[Date] ), -7, DAY ),
    [総売上]
)
```

### 14本目：値引きによる損失額

```dax
値引額 =
SUMX(
    Fact_売上,
    Fact_売上[Quantity] * ( RELATED( Dim_商品[ListPrice] ) - Fact_売上[UnitPrice] )
)
```

定価（`ListPrice`）と実売単価（`UnitPrice`）の差が、値引きで失った金額です。

### 15本目：達成状況の色（条件付き書式用）

```dax
前年比_色 =
VAR 率 = [前年比増減率]
RETURN
    SWITCH( TRUE(),
        ISBLANK( 率 ),  "#8A93A6",
        率 >= 0.1,      "#14926B",
        率 >= 0,        "#8FBF5A",
        率 >= -0.1,     "#C77700",
        "#D33A4B"
    )
```

テーブルビジュアルで `前年比増減率` の書式 → **条件付き書式 → フォントの色 → 書式スタイル「フィールド値」** にこのメジャーを指定してください。

> [!TIP] `SWITCH( TRUE(), ... )` の型
> 条件を上から順に評価し、最初に真になったものの値を返します。`IF` の入れ子より圧倒的に読みやすく、条件の追加も容易です。DAXで分岐を書くときの標準形として覚えてください。

## トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| `RELATED` でエラー | リレーションシップがない／方向が逆 | モデルビューで1対多・単一方向を確認 |
| `RELATED` が「行コンテキストがない」と言う | `SUMX` の外で使っている | 反復関数の中に入れる |
| 前年売上が全部空白 | 日付テーブルとしてマークしていない | LAB03のステップ3を実施 |
| 前年売上が一部だけ空白 | 日付テーブルに抜けがある | `CALENDAR` の範囲を年初〜年末に広げる |
| 累計が累計にならない | `ALL( Dim_日付 )` を忘れている | 第3引数を追加 |
| 累計が全行で同じ値 | `VAR` を使わず `MAX` を直接書いた | `VAR 現在日付` に置き換える |
| ランクが全部1 | `RANKX` の第1引数に `ALL` がない | 母集団を明示する |
| 構成比が全部100% | 分母のCALCULATEでフィルターを解除できていない | `ALLSELECTED` の引数がカテゴリ列か確認 |
| YTDが1月始まりになる | 第3引数を省略した | `"3/31"` を指定 |
| 総計行の値がおかしい | 行ごとの計算を総計でもそのまま実行している | `HASONEVALUE` で総計時の挙動を分岐 |

総計行の分岐は次のように書きます。

```dax
商品ランク_総計対応 =
IF(
    HASONEVALUE( Dim_商品[ProductName] ),
    [商品ランク],
    BLANK()
)
```

## 発展課題

### 課題1：値引きが粗利に与える影響を測る（15分）

`値引額` と `粗利` を使って、「値引きがなければ粗利はいくらだったか」を出してください。

```dax
値引前粗利 = [粗利] + [値引額]
```

散布図のX軸に `値引額`、Y軸に `粗利率`、詳細に `Dim_商品[ProductName]` を置くと、「値引きしても粗利率が落ちない商品」と「値引きが粗利を食っている商品」が分離して見えます。

### 課題2：曜日別の売れ方を調べる（10分）

`Dim_日付[曜日]` を軸にした縦棒グラフで `総売上` を見てください。並べ替え列（`曜日番号`）が効いていれば月曜から並びます。さらに `Dim_日付[平日区分]` をスライサーに置き、平日と週末で売れ筋カテゴリが変わるかを確認します。

### 課題3：メジャーの依存関係を図に描く（10分）

15本のメジャーが互いにどう依存しているかを紙に描いてください。`粗利率` → `粗利` → `総売上` / `原価合計` のように矢印でつなぎます。この図が描けるモデルは、後から安全に変更できます。
