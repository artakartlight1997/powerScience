## ステップ1：わざと遅いレポートを作る（15分）
代表的なアンチパターンを5つ仕込みます。1〜3はメジャー、4〜5はレポート側です。
```dax
まとめ買い売上_遅い =
CALCULATE( SUM( Fact_売上[SalesAmount] ), FILTER( Fact_売上, Fact_売上[Quantity] >= 2 ) )

高額商品売上_遅い =
SUMX( Fact_売上, IF( RELATED( Dim_商品[ListPrice] ) >= 50000, Fact_売上[SalesAmount], 0 ) )

粗利判定_遅い =
IF( DIVIDE( [粗利], [総売上] ) > 0.3, DIVIDE( [粗利], [総売上] ), DIVIDE( [粗利], [総売上] ) * 0.5 )
```
4. テーブルビジュアルに `Fact_売上[OrderID]`（約6,900種類）と `総売上` を置く

> [!TRAP] 「本番はもっと大きい」を言い訳にしない
> このサンプルは約6,900行で差は数百ミリ秒です。同じコードが1,000万行では数十秒になります。

## トラブルシューティング
| 症状 | 原因 | 対処 |
|---|---|---|
| 2回測ると極端に速い | キャッシュが効いている | `Clear Cache then Run` を使う |
| DAX Studio が外部ツールに出ない | インストール時に統合を選んでいない | 再インストールで統合を有効化 |
| Server Timings が空 | オンにせず実行した | オンにしてから再実行 |
| 直したのに速くならない | ボトルネックが別の場所 | 「その他」「表示」の数字を見る |
| SE Queries が数百 | 反復の中で関連テーブルを引いている | フィルターに書き換える |
| ファイルサイズが減らない | 高カーディナリティ列が残っている | 上位の列を削除・分割する |
| 更新が遅い（表示は速い） | Power Query 側の問題 | [LAB07](lab.html?id=LAB07) で折りたたみを確認 |
| DirectQuery で遅い | ソース側のクエリが重い | 集計テーブルかインポートを検討 |
## 発展課題
### 課題1：`DISTINCTCOUNT` の代替を比べる（15分）
```dax
顧客数_A = DISTINCTCOUNT( Fact_売上[CustomerID] )

顧客数_B = COUNTROWS( SUMMARIZE( Fact_売上, Fact_売上[CustomerID] ) )
```
両方を同じマトリックスに置いて計測します。結果はデータの形で変わります。一般論ではなく、このモデルで測って選びます。
### 課題2：カーディナリティを実感する（15分）
`Fact_売上[OrderID]`（一意）と `Fact_売上[StoreID]`（14種類）のサイズを VertiPaq Analyzer で比べます。行数は同じでもサイズは桁違いです。

### 課題3：集計テーブルを作る（20分）
```dax
Agg_日別売上 =
SUMMARIZECOLUMNS( Fact_売上[OrderDate], Fact_売上[StoreID],
```
