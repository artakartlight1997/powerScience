所要30分。Power BI Desktop を起動して、実際に手を動かしながら読んでください。読むだけでは身につきません。

## このラボのゴール

架空の小売企業「Northstar Retail」の売上データから、次の要素を含むレポートを1枚作ります。

- KPIカード（総売上・販売数量・取引件数）
- カテゴリ別売上の横棒グラフ
- 月次売上推移の折れ線グラフ
- 店舗スライサー

このラボが終わると、「Power BIでレポートを作る」という行為の全体像が体でわかります。

## 準備

[sales.csv](data/sales.csv) と [products.csv](data/products.csv) をダウンロードしてください。列構成は次のとおりです。

| 列 | 型 | 説明 |
|---|---|---|
| OrderID | テキスト | 注文ID（O000001形式） |
| OrderDate | 日付 | 受注日 |
| ShipDate | 日付 | 出荷日 |
| StoreID | テキスト | 店舗ID（S001〜S014） |
| CustomerID | テキスト | 顧客ID |
| ProductID | テキスト | 商品ID（P0001〜P0032） |
| Quantity | 整数 | 数量 |
| UnitPrice | 整数 | 販売単価（値引後） |
| Discount | 10進数 | 値引率（0〜0.3） |
| SalesAmount | 整数 | 売上金額 |

`sales.csv` は約6,900行、`products.csv` は32行です。この行数の差が、後で学ぶ「ファクト」と「ディメンション」の違いそのものです。

## ステップ1：データを読み込む（6分）

1. **ホーム → データを取得 → テキスト/CSV** で `sales.csv` を選択
2. プレビュー画面右上の「ファイル発生源」が `65001: Unicode (UTF-8)` になっていることを確認
3. **「データの変換」** をクリックします（「読み込み」ではありません）
4. Power Query エディタが開いたら、各列の型を確認・修正する

| 列 | 設定する型 |
|---|---|
| OrderDate, ShipDate | 日付 |
| Quantity, UnitPrice, SalesAmount | 整数 |
| Discount | 10進数 |
| OrderID, StoreID, CustomerID, ProductID | テキスト |

型は列見出しの左にあるアイコンをクリックして変更します。

5. 右ペインの「クエリの設定 → プロパティ → 名前」を `Fact_売上` に変更
6. 同じ手順で `products.csv` を読み込み、名前を `Dim_商品` にする
7. **ホーム → 閉じて適用**

> [!TRAP] 「読み込み」を押してしまったとき
> 慌てなくて大丈夫です。**ホーム → データの変換** でいつでも Power Query エディタに戻れます。Power BI は「取り込んだ後から整形をやり直せる」設計になっています。

> [!TIP] IDは必ずテキスト型に
> `S001` のような値は勝手に数値にはなりませんが、`ProductID` が仮に `1` `2` `3` だった場合、Power BI は整数と判断します。IDは計算対象ではないのでテキストにしておくと、後で先頭ゼロが消える事故を防げます。

## ステップ2：2つの表をつなぐ（4分）

1. 左端の **モデルビュー**（3つ目のアイコン）を開く
2. `Dim_商品[ProductID]` から `Fact_売上[ProductID]` へ線が引かれているか確認する
3. 線がなければ、`Dim_商品[ProductID]` を `Fact_売上[ProductID]` へドラッグする
4. 線をダブルクリックし、次を確認する

| 項目 | 値 |
|---|---|
| 基数 | 1対多（1:*） |
| クロスフィルターの方向 | 単一 |
| このリレーションシップをアクティブにする | オン |

```figure
{ "type":"pipeline", "title":"このラボのモデル", "caption":"商品マスタ側でカテゴリを選ぶと、売上側の行が絞り込まれる",
  "nodes":[
    {"id":"p","label":"Dim_商品\n32行","tone":"blue"},
    {"id":"f","label":"Fact_売上\n約6,900行","tone":"amber"} ],
  "edges":[{"from":"p","to":"f","label":"1対多・単一方向"}] }
```

「1」の側がマスタ（重複のない側）、「多」の側が実績です。**フィルターは常に1側から多側へ流れます。** 商品カテゴリを選ぶと売上が絞られるのはこのためです。

> [!NOTE] 用語
> **リレーションシップ**とは、2つのテーブルを共通の列でつなぐ設定のこと。Excel の VLOOKUP のように値をコピーするのではなく、「フィルターの通り道」を作ります。

## ステップ3：メジャーを3本作る（5分）

**モデリング → 新しいメジャー** で、次の3つを作成します。作るたびに数式バーで Enter を押してください。

```dax
総売上 = SUM( Fact_売上[SalesAmount] )
```

```dax
販売数量 = SUM( Fact_売上[Quantity] )
```

```dax
取引件数 = DISTINCTCOUNT( Fact_売上[OrderID] )
```

```figure
{ "type":"formula", "lang":"dax", "title":"メジャーの読み方",
  "code":"総売上 = SUM( Fact_売上[SalesAmount] )",
  "caption":"「どの範囲を」はビジュアル側が決める。メジャーには書かない",
  "parts":[
    {"match":"総売上","label":"メジャー名。ビジュアルに表示される見出しになる","tone":"blue"},
    {"match":"SUM","label":"集計方法。合計を取る","tone":"violet"},
    {"match":"Fact_売上[SalesAmount]","label":"集計する列。テーブル名を必ず付ける","tone":"amber"} ] }
```

作成後、それぞれを選択して **メジャーツール → 書式** を設定します。

| メジャー | 書式 | 小数点 | 桁区切り |
|---|---|---|---|
| 総売上 | 10進数 | 0 | オン |
| 販売数量 | 10進数 | 0 | オン |
| 取引件数 | 10進数 | 0 | オン |

> [!TIP] なぜ `COUNTROWS` ではなく `DISTINCTCOUNT` か
> 1つの注文（OrderID）に複数の商品行が含まれます。`COUNTROWS( Fact_売上 )` は「明細行数」、`DISTINCTCOUNT( Fact_売上[OrderID] )` は「注文件数」です。「取引件数」として自然なのは後者です。指標名と計算内容が一致しているか、作るたびに自問してください。

## ステップ4：KPIカードを配置（5分）

1. レポートビューに戻り、キャンバスの**余白**をクリック
2. 視覚化ペインから **カード** を選択
3. `総売上` をフィールドにドラッグ
4. 書式ペイン（筆アイコン）で調整する
   - **吹き出しの値 → フォントサイズ** を 32 に
   - **カテゴリラベル** をオンにする
5. カードをキャンバス上部左に配置し、幅を調整
6. 同じ手順で `販売数量` と `取引件数` のカードを作り、横一列に並べる

> [!TIP] 3つのカードをきれいに揃える
> 3つを Ctrl キーで選択して **書式（リボン）→ 配置 → 上揃え**、続いて **横方向に均等配置** を実行します。手でドラッグして揃えようとしないでください。1ピクセルのずれは必ず気づかれます。

## ステップ5：カテゴリ別の横棒グラフ（4分）

1. 余白をクリック → **集合横棒グラフ**
2. Y軸に `Dim_商品[Category]`、X軸に `総売上`
3. グラフ右上の「…」→ **軸の並べ替え → 総売上 → 降順**
4. 書式ペイン → **データラベル** をオン

```figure
{ "type":"chart", "kind":"hbar", "title":"できあがる横棒グラフのイメージ",
  "caption":"降順に並べ替えるだけで「どこが大きいか」が一瞬で読める",
  "categories":["家電","衣料","食品"],
  "series":[{"name":"総売上","values":[62,25,13],"tone":"blue"}],
  "highlight":0, "unit":"%" }
```

> [!TRAP] 縦棒ではなく横棒を選ぶ理由
> カテゴリ名が日本語で長くなるとき、縦棒グラフではラベルが斜めになったり省略されたりします。**カテゴリ比較は横棒**、**時系列は折れ線**、が基本の使い分けです。

## ステップ6：月次推移の折れ線グラフ（5分）

1. 余白をクリック → **折れ線グラフ**
2. X軸に `Fact_売上[OrderDate]`、Y軸に `総売上`
3. X軸のフィールドの下矢印 → **日付の階層** が選ばれていることを確認
4. グラフ右上のドリルダウンボタン（下向き二重矢印）で「年 → 四半期 → 月」と掘り下げられることを確認

> [!TRAP] 線がギザギザになる
> `OrderDate` をそのまま入れると日単位になり、1日ごとの上下で線が読めなくなります。フィールドの下矢印から「日付の階層」を選ぶと、年→四半期→月→日の順で見られるようになります。将来的には自前の日付テーブルを使いますが、それは [LAB03](lab.html?id=LAB03) で扱います。

## ステップ7：スライサーを追加（3分）

1. 余白をクリック → **スライサー**
2. フィールドに `Fact_売上[StoreID]` をドラッグ
3. スライサー右上の「…」→ **ドロップダウン** に変更（縦のスペースを節約できます）

## 詰まったときの答え

| 症状 | 原因と対処 |
|---|---|
| 日本語が文字化けする | 読み込み画面の「ファイル発生源」を `65001: Unicode (UTF-8)` に変更する |
| `Dim_商品` に線が引かれない | 両テーブルの `ProductID` の型が違う。両方テキストにしてから引き直す |
| カードに「(空白)」と出る | フィールドにメジャーではなく列を入れている。`総売上` を入れ直す |
| 横棒グラフに1本しか出ない | Y軸に `Category` ではなく `ProductID` を入れている可能性がある |
| 折れ線がドリルできない | X軸のフィールドが「日付の階層」ではなく `OrderDate` 単体になっている |
| スライサーを操作しても何も変わらない | ビジュアルとスライサーが別ページにある、または相互作用が「なし」になっている |
| 数字が想定と桁違い | `SalesAmount` が10進数のまま。整数に変更して再確認する |

## 発展課題

### 課題1：粗利を出してみる（10分）

`Dim_商品[StandardCost]` を使って粗利を計算します。次のメジャーを作り、KPIカードを4枚目として追加してください。

```dax
原価合計 =
SUMX(
    Fact_売上,
    Fact_売上[Quantity] * RELATED( Dim_商品[StandardCost] )
)
```

```dax
粗利 = [総売上] - [原価合計]
```

`RELATED` は「多側の各行から、1側の対応する値を取ってくる」関数です。`SUMX` が1行ずつ処理しているからこそ使えます。詳しくは [計算列とメジャーの違い](lesson.html?id=L0702) で扱います。

### 課題2：値引きの影響を見る（10分）

値引率別に売上がどう分布しているかを調べます。

1. `Fact_売上[Discount]` をX軸、`総売上` をY軸にした集合縦棒グラフを作る
2. `Discount` のフィールドの下矢印 → **合計をやめて「グループ化しない」** を選ぶ
3. 値引率0の売上が全体の何割を占めるかを読み取る

### 課題3：作り直してみる（15分）

このレポートをゼロからもう一度作ってください。2回目は15分を切れるはずです。**手順が体に入っているかどうか**が、次のラボの進みやすさを決めます。
