「今月の売上は前月比 −18%。緊急に対策が必要です」。この報告が会議に出るのは、たいてい2月と8月です。2月は日数が少なく、8月は多くの業種で閑散期だからです。毎年同じ月に同じ危機感を持ち、毎年同じ「対策」が打たれ、翌月には自然に回復して「対策が効いた」と記録されます。

時系列データは、**トレンド・季節性・残差**の3つに分けて初めて読めます。分けずに前月比だけを見るのは、雑音を信号だと思い込む行為です。

このレッスンでは、時系列の分解・平滑化・異常検知を、DAX の実装コードまで含めて扱います。

> [!DS]
> **時系列データ（time series）** は、同じ対象を等間隔の時点で繰り返し測ったデータです。普通のデータと決定的に違うのは、**順序に意味があり、隣り合う値が相関する**点です。この性質があるため、行をシャッフルしてよい通常の分析手法（相関・平均の比較）をそのまま当てはめると誤ります。

### 加法モデルと乗法モデル

| | 式 | 季節変動の性質 | 使う場面 |
|---|---|---|---|
| 加法モデル | 観測値 = T + S + R | 水準が上がっても振れ幅は一定 | 客数、件数、気温 |
| 乗法モデル | 観測値 = T × S × R | 水準が上がると振れ幅も比例して拡大 | 売上金額、Web訪問数 |

見分け方は簡単です。**グラフを描いて、山と谷の幅が右に行くほど広がっていれば乗法モデル**です。売上金額はほぼ常に乗法モデルなので、迷ったら乗法（＝季節指数を%で持つ）を選びます。

### DAX：中心化12か月移動平均

```dax
売上_トレンド :=
VAR CurDate = MAX( Dim_日付[日付] )
VAR 期間 =
    FILTER(
        ALL( Dim_日付 ),
        Dim_日付[日付] >= EDATE( CurDate, -6 )
            && Dim_日付[日付] <= EDATE( CurDate, 6 )
    )
RETURN
    CALCULATE( AVERAGEX( VALUES( Dim_日付[年月] ), [売上合計] ), 期間 )
```

> [!TRAP] 移動平均は必ず遅れる
> 12か月後方移動平均は、平均して6か月前の水準を表しています。**急な変化が起きたとき、移動平均は最後に気づく指標です。** 「移動平均が下がり始めた」と気づいたときには、実際の落ち込みは半年前から始まっています。異常検知に移動平均だけを使ってはいけません。トレンドの確認には移動平均、変化の検知には残差やZスコアを使います。

### 移動平均の期間はどう決めるか

**季節周期と同じ長さにする**のが原則です。

| データの粒度 | 移動平均の期間 | 消える変動 |
|---|---|---|
| 日次 | 7日 | 曜日変動 |
| 日次（小売） | 28日 | 曜日 + 月内周期 |
| 週次 | 13週 | 四半期内の変動 |
| 月次 | 12か月 | 年間の季節性 |

7日移動平均を使えば曜日変動は完全に消えます。**5日や10日にすると曜日変動が消え残り、意味のない波が残ります。**

## 季節指数を計算する

季節指数は「その月は年間平均の何%か」を表す数字です。乗法モデルの S にあたります。

```dax
// ① 各月の平均売上 ÷ 全期間の月平均 = 季節指数
季節指数 :=
VAR 月平均 =
    CALCULATE(
        AVERAGEX( VALUES( Dim_日付[年月] ), [売上合計] ),
        ALLEXCEPT( Dim_日付, Dim_日付[月番号] )
    )
VAR 全体平均 =
    CALCULATE(
        AVERAGEX( VALUES( Dim_日付[年月] ), [売上合計] ),
        REMOVEFILTERS( Dim_日付 )
    )
RETURN
    DIVIDE( 月平均, 全体平均 )
```

```dax
// ② 季節調整済み売上 = 実績 ÷ 季節指数
売上_季節調整済 := DIVIDE( [売上合計], [季節指数] )
```

季節調整済みの系列を折れ線で並べると、**季節性を取り除いた「本当の動き」**が見えます。政府統計の「季節調整値」はこれと同じ考え方です。

## 前年同月比という便利な道具

季節性を消す最も簡単な方法は、**同じ月どうしを比べる**ことです。

```dax
売上_前年同月 := CALCULATE( [売上合計], SAMEPERIODLASTYEAR( Dim_日付[日付] ) )
売上_YoY率 := DIVIDE( [売上合計] - [売上_前年同月], [売上_前年同月] )
```

前年同月比は、季節性が毎年同じであるかぎり、季節調整と同じ効果を持ちます。ただし弱点があります。

| 手法 | 長所 | 短所 |
|---|---|---|
| 前年同月比 | 計算が簡単、説明しやすい | 前年が異常値だと今年の評価が歪む（基準年効果） |
| 季節調整 | 直近の月どうしを比較できる | 指数の作成に複数年が必要 |
| 移動平均 | トレンドが素直に見える | 遅れる、最新の変化を捉えられない |

> [!WARN] 注意
> 前年同月比は**前年の数字が異常だった場合に暴れます**。前年8月に大型キャンペーンをした場合、今年8月は「−30%」と表示されます。これは今年が悪いのではありません。前年同月比を主要KPIにするなら、**2年前比（対2年前）も並べて出す**のが実務的な防御策です。

## 異常検知 — 本当に見るべき変化を見つける

残差が「説明できない部分」だとすれば、異常とは**残差が普段より大きい時点**です。

```figure

  {"title":"ばらつきを測る","text":"同じ窓での標準偏差、または中央絶対偏差（MAD）。歪む系列ではMADを使う。","tone":"green"},
  {"title":"Zスコアを計算する","text":"Z = (実績 − 中心) ÷ ばらつき。「平常時の何個ぶん離れているか」を表す。","tone":"amber"},
  {"title":"閾値で判定し可視化する","text":"|Z| > 2 を注意、|Z| > 3 を異常とするのが一般的。条件付き書式で色を付ける。","tone":"violet"} ] }
```

```dax
// 直近28日を平常時とみなした移動Zスコア
売上_Zスコア =
VAR 窓 = DATESINPERIOD( Dim_日付[日付], MAX( Dim_日付[日付] ) - 1, -28, DAY )
VAR 平均 = CALCULATE( AVERAGEX( VALUES( Dim_日付[日付] ), [売上合計] ), 窓 )
VAR 偏差 =
    SQRT(
        DIVIDE(
            CALCULATE(
                SUMX( VALUES( Dim_日付[日付] ), ( [売上合計] - 平均 ) ^ 2 ),
                窓
            ),
            28
        )
    )
RETURN
    DIVIDE( [売上合計] - 平均, 偏差 )
```

窓を `MAX( Dim_日付[日付] ) - 1` から遡らせているのは、**判定したい当日を平常時の計算に含めないため**です。異常な日を含めて平均と標準偏差を作ると、異常が異常に見えなくなります。

### 外れ値に強いロバストZスコア

売上のように歪む系列では、平均と標準偏差そのものが外れ値に引っ張られます。中央値と MAD（中央絶対偏差）に置き換えます。

```dax
// ロバストZスコア（MAD版）
売上_ロバストZ =
VAR 窓 = DATESINPERIOD( Dim_日付[日付], MAX( Dim_日付[日付] ) - 1, -28, DAY )
VAR 中央値 = CALCULATE( MEDIANX( VALUES( Dim_日付[日付] ), [売上合計] ), 窓 )
VAR MAD =
    CALCULATE(
        MEDIANX( VALUES( Dim_日付[日付] ), ABS( [売上合計] - 中央値 ) ),
        窓
    )
RETURN
    DIVIDE( 0.6745 * ( [売上合計] - 中央値 ), MAD )
```

`0.6745` は、正規分布のとき MAD を標準偏差と同じスケールに揃えるための係数です。これにより、通常のZスコアと同じ感覚（|Z| > 3 で異常）で閾値を設定できます。

> [!DS]
> 異常検知には必ず **偽陽性（正常なのに異常と判定）と偽陰性（異常なのに見逃す）のトレードオフ** があります。閾値を2にすれば見逃しは減りますが、正常な日の約5%がアラートになります。日次で運用すれば月に1〜2回の誤報です。「アラートが多すぎて誰も見なくなる」のは、閾値設計の失敗であって、手法の失敗ではありません。**運用できるアラート数から逆算して閾値を決める**のが正解です。

## 指数平滑 — 直近を重く見る平滑化

移動平均は窓の中の値を平等に扱い、窓の外を完全に無視します。指数平滑は逆に、**すべての過去を使いながら、古いものほど軽く扱います**。

```text
S(t) = α × 実績(t) + (1 − α) × S(t−1)
```

α（平滑化定数、0〜1）が大きいほど直近に強く反応し、小さいほど滑らかになります。α = 0.3 のとき、各時点の重みは 0.3、0.21、0.147、0.103… と指数関数的に減衰します。

```figure
    {"name":"α = 0.6（敏感）","values":[100,101,99,100,100,124,111,104,103,101],"tone":"amber"} ],
  "caption": "t−4 の突発値140への反応が違う。α が大きいほど速く反応し、速く忘れる。ノイズが多い系列では α を小さくする。" }
```

| α の値 | 性格 | 向いている場面 |
|---|---|---|
| 0.05 〜 0.2 | 鈍いが安定 | ノイズが多い日次データ、長期の水準把握 |
| 0.2 〜 0.4 | 標準 | 月次売上、需要予測の出発点 |
| 0.5 〜 0.8 | 敏感 | 変化点の検知、短期の在庫補充 |

Power BI の分析ペインの「予測」は、この指数平滑を季節性まで拡張した **ホルト・ウィンタース法** を使っています。L1505 で詳しく扱います。

> [!DS]
> 指数平滑は「過去の予測を、今回の誤差ぶんだけ修正する」と読み替えられます。式を変形すると `S(t) = S(t−1) + α × ( 実績(t) − S(t−1) )` になり、括弧の中は予測誤差です。**誤差の一定割合だけ学習する**——この構造は、機械学習の勾配降下法と同じ発想です。α は学習率にあたります。

> [!TRAP] 進行中の期間をそのまま比較しない
> 7月10日時点で「7月の売上は前年比 −67%」と表示されるダッシュボードは、毎月10日に全社を混乱させます。**進行中の期間は、必ず「同日までの累計」で比較する**か、当月を別扱いで表示してください。カードビジュアルに「7/10時点」と注記を入れるだけでも事故は激減します。

## まとめ

- 時系列は トレンド + 季節性 + 残差（または掛け算）に分けてから読む
- 前月比の変動の多くは季節性。前年同月比か季節調整で消す
- 移動平均の期間は季節周期と同じに。7日・12か月が基本
- 移動平均は必ず遅れる。変化の検知には使わない
- 季節指数は「その月は年平均の何%か」。最低2年のデータで作る
- 異常検知はZスコア。歪む系列では中央値とMADのロバスト版
- 判定対象の期間を、平常時の計算に含めない
- 折れ線ビジュアルの分析ペインには予測と異常検出が用意されている
- 日数・営業日数・進行中の期間は、比較する前に必ず揃える
