## パターン5：ABC分析（パレート分析）

売上の上位20%の商品が全体の80%を占める——これを可視化します。

```dax
-- 1. 累積売上（売上の大きい順に積み上げる）
累積売上 =
VAR CurrentSales = [売上合計]
VAR ProductTable =
    ADDCOLUMNS( ALLSELECTED( Dim_商品[ProductName] ), "@売上", [売上合計] )
RETURN
    SUMX( FILTER( ProductTable, [@売上] >= CurrentSales ), [@売上] )
```

```dax
-- 2. 累積構成比
累積構成比 =
DIVIDE( [累積売上], CALCULATE( [売上合計], ALLSELECTED( Dim_商品[ProductName] ) ) )
```

```dax
-- 3. ABCランク
ABCランク =
VAR Cum = [累積構成比]
RETURN
    SWITCH(
        TRUE(),
        ISBLANK( Cum ), BLANK(),
        Cum <= 0.8, "A",
        Cum <= 0.95, "B",
        "C"
    )
```

> [!DS] データサイエンス視点
> ABC分析は**パレートの法則（80:20の法則）**の実装です。統計的には累積分布関数（CDF）を降順に取ったものにあたります。実務では在庫管理での重点管理品目の選定、営業リソースの配分、商品カットの判断に使われます。しきい値は 80% / 95% が慣習ですが、業界によって変えます。「A品目が全体の何%の品目数を占めるか」を併記すると、集中度が一目で分かります。

> [!WARN] 注意
> `累積売上` は商品数ぶんのイテレーションが走ります。商品が数万件あるモデルでは重くなります。その場合は**ABCランクを計算列として持たせる**（更新時に1度だけ計算する）ことを検討してください。ただし計算列にするとスライサーの選択に追随しなくなります。

## パターン6：新規顧客・既存顧客

新規顧客数 =

            VALUES( Dim_顧客[CustomerID] ),

            RETURN
                FirstPurchase >= PeriodStart && FirstPurchase <= PeriodEnd

```dax
既存顧客数 = [購入顧客数] - [新規顧客数]

購入顧客数 = DISTINCTCOUNT( Fact_売上[CustomerID] )
```

コホート表の値を、0か月目に対する割合に変えます。

        Fact_売上[経過月数] = 0,

## パターン9：バスケット分析の入口

「Aを買った人がBも買っている率」を出します。

```dax
-- 比較対象の商品を選ぶための切断テーブル（Dim_商品 のコピー）
併売率 =
VAR SelectedProduct = SELECTEDVALUE( Dim_商品比較[ProductName] )
VAR CustomersWithA =
    CALCULATETABLE(
        VALUES( Fact_売上[CustomerID] ),
        ALL( Dim_商品 ),
        Dim_商品[ProductName] = SelectedProduct
    )
VAR CustomersWithBoth =
    COUNTROWS( INTERSECT( VALUES( Fact_売上[CustomerID] ), CustomersWithA ) )
RETURN
    DIVIDE( CustomersWithBoth, COUNTROWS( CustomersWithA ) )
```

> [!NOTE] 要点
> `Dim_商品比較` は `Dim_商品` をコピーして作った、**リレーションを張らない独立テーブル**です。「切断テーブル（disconnected table）」と呼びます。ユーザーが選ぶための入力欄として使い、メジャーの中で `SELECTEDVALUE` で値を取り出します。この手法は、パラメータを受け取るあらゆる分析に応用できます。

## パターン10：目標達成率

```dax
目標額 =
CALCULATE(
    SUM( Fact_目標[TargetAmount] ),
    TREATAS( VALUES( Dim_店舗[Region] ), Fact_目標[Region] ),
    TREATAS( VALUES( Dim_日付[YearMonth] ), Fact_目標[YearMonth] )
)

達成率 = DIVIDE( [売上合計], [目標額] )

未達額 =
VAR Gap = [目標額] - [売上合計]
RETURN
    IF( Gap > 0, Gap, 0 )
```

> [!WARN] 注意
> **除算には必ず `DIVIDE` を使ってください。** `[売上合計] / [目標額]` は目標額がゼロや空白のとき無限大やエラーになります。`DIVIDE` は第3引数（省略時は BLANK）を返します。`DIVIDE( a, b, 0 )` とすればゼロを返せます。

## パターン11：動的タイトル

```dax
レポートタイトル =
VAR RegionText =
    IF(
        ISFILTERED( Dim_店舗[Region] ),
        CONCATENATEX( VALUES( Dim_店舗[Region] ), Dim_店舗[Region], "・" ),
        "全地域"
    )
VAR PeriodText =
    FORMAT( MIN( Dim_日付[Date] ), "YYYY年M月" ) & " 〜 " &
    FORMAT( MAX( Dim_日付[Date] ), "YYYY年M月" )
RETURN
    RegionText & "　" & PeriodText & " の売上"
```

テキストボックスやカードビジュアルのタイトルに、このメジャーを**条件付き書式 → タイトル → fx** から割り当てます。

> [!TIP] 実務のコツ
> 選択肢が多すぎるとタイトルが長大になります。`IF( COUNTROWS( VALUES( Dim_店舗[Region] ) ) > 3, "複数地域（" & COUNTROWS( VALUES( Dim_店舗[Region] ) ) & "件）", CONCATENATEX( ... ) )` のように件数で切り替えるとレイアウトが崩れません。

## パターン12：条件付き書式用の色メジャー

```dax
達成率カラー =
VAR Rate = [達成率]
RETURN
    SWITCH(
        TRUE(),
        ISBLANK( Rate ), "#CCCCCC",
        Rate >= 1.0, "#14926B",
        Rate >= 0.9, "#E0A800",
        "#C0392B"
    )
```

ビジュアルの**書式 → セル要素 → 背景色 → 条件付き書式 → 書式スタイル「フィールド値」**でこのメジャーを指定します。

## 理解度チェック

**問1.** カテゴリスライサーで「家電」を選択した状態で商品別構成比を表示したところ、合計が35%にしかなりません。原因と修正方法を答えてください。

<details>
<summary>解答</summary>

分母に `ALL( Dim_商品 )` を使っているため、家電以外の商品も分母に含まれています。`ALLSELECTED( Dim_商品 )` に変えると、スライサーの選択（家電）を尊重した分母になり、合計が100%になります。
</details>

**問2.** 新規顧客数メジャーで、初回購入日を求めるときに `ALL( Dim_日付 )` が必要な理由を説明してください。

<details>
<summary>解答</summary>

ビジュアルの行（たとえば2025年5月）による日付フィルターが効いた状態で `MIN( Fact_売上[OrderDate] )` を評価すると、**5月の中での最も古い注文日**が返ってしまいます。求めたいのは全期間での初回購入日なので、`ALL( Dim_日付 )` で日付フィルターを外す必要があります。
</details>

**問3.** 条件付き書式用の色メジャーで、データのない行が赤く表示されてしまいます。どう直しますか。

<details>
<summary>解答</summary>

`SWITCH( TRUE(), ... )` の**最初の条件に `ISBLANK( Rate )` を置きます**。BLANK は数値比較で 0 として扱われるため、`Rate >= 1.0` などの条件をすべて外れて最後の「else」に落ち、赤色になっています。BLANK を明示的に判定して灰色や BLANK を返してください。
</details>
