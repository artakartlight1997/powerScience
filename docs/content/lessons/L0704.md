実務の指標は、突き詰めると **分岐** と **割り算** でできています。

- 「単価が5,000円以上なら高単価、それ以外は通常」——分岐
- 「実績 ÷ 目標」で達成率——割り算
- 「利益 ÷ 売上」で利益率——割り算
- 「達成率が100%を超えたら○、90%以上なら△、それ以下は×」——分岐

そしてこの2つは、**初月に必ず事故を起こします**。ゼロ除算でレポート全体が赤いエラー表示になり、
`IF` を5段ネストした式は翌週の自分にも読めません。このレッスンで、両方に決着をつけます。

## IF — まずは基本形

```dax
高単価判定 =
IF(
    [平均単価] >= 5000,
    "高単価",
    "通常"
)
```

`IF( 条件, 真のときの値, 偽のときの値 )` の3引数です。第3引数は省略でき、省略すると **BLANK** が返ります。

```figure
    {"match":"\"重点\"","label":"条件が真のときの戻り値","tone":"green"},
    {"match":"\"通常\"","label":"偽のときの戻り値。省略すると BLANK になる","tone":"pink"} ] }
```

> [!WARN] 分岐で返す型をそろえる
> `IF( 条件, "対象外", 0 )` のように、文字列と数値を混ぜて返す式は避けてください。
> DAXは型を推論しますが、混在すると列の型が文字列に倒れ、後段の集計や並べ替えが壊れます。
> **数値を返すなら全分岐で数値、文字列なら全分岐で文字列**。BLANK はどちらの型とも共存できます。

## IF の入れ子は3段でやめる

ランクを4段階で判定する式を、`IF` の入れ子で書いてみます。

```dax
-- ✗ 読みにくい：ネストしたIF
売上ランクNG =
IF(
    [売上合計] >= 50000000, "S",
    IF(
        [売上合計] >= 20000000, "A",
        IF(
            [売上合計] >= 5000000, "B",
            "C"
        )
    )
)
```

条件が1つ増えるたびに右へ深くなり、閉じかっこの数が合わなくなります。
これを `SWITCH( TRUE(), ... )` で書き直すと、**すべての条件が同じ高さに並びます**。

```dax
-- ✓ 読みやすい：SWITCH( TRUE(), ... )
売上ランク =
SWITCH(
    TRUE(),
    [売上合計] >= 50000000, "S",
    [売上合計] >= 20000000, "A",
    [売上合計] >=  5000000, "B",
    "C"
)
```

> [!TIP] SWITCH には2つの書き方がある
> ひとつは **値マッチ形式**。`SWITCH( [列], "家電", 1, "衣料", 2, 0 )` のように、第1引数の値と一致するものを選びます。
> もうひとつが上の **`TRUE()` 形式** で、これは「条件式を上から順に評価し、最初に真になったものを返す」という使い方です。
> 大小比較や複合条件を書きたいときは、必ず `TRUE()` 形式を使います。

## DIVIDE — 割り算は必ずこれを使う

DAXの `/` 演算子は、分母が0のときエラーを返します。エラーが1セルでも出ると、
**ビジュアル全体が「エラーが発生しました」の表示になり、正常なセルまで見えなくなります**。

```dax
-- ✗ 分母が0のときエラー
達成率NG = [売上合計] / [目標金額]

-- ✓ 分母が0でも壊れない
達成率 = DIVIDE( [売上合計], [目標金額] )

-- ✓ 分母が0のときに0%と表示したい場合
達成率ゼロ表示 = DIVIDE( [売上合計], [目標金額], 0 )
```

### 実際に何が起きるか

店舗別の目標達成率で確認します。名古屋店は目標が未設定（0）です。

| StoreName | 実績（百万円） | 目標（百万円） | `/` の結果 | `DIVIDE` の結果 |
|---|---|---|---|---|
| 東京 | 33 | 30 | 110.0% | 110.0% |
| 大阪 | 20 | 25 | 80.0% | 80.0% |
| 名古屋 | 5 | 0 | **エラー** | *(空白)* |
| 福岡 | 0 | 20 | 0.0% | 0.0% |

```figure
  "categories":["東京","大阪","名古屋","福岡"],

```

> [!TRAP] 第3引数に安易に 0 を入れない
> `DIVIDE( [実績], [目標], 0 )` と書くと、名古屋店の達成率は **0%** と表示されます。
> しかしこれは「達成率0%」ではなく「目標が未設定」です。**意味が違います。**
> 0% と表示すると「頑張っていない店」に見え、誤った意思決定を招きます。
> 既定の BLANK のままにして、空白を「データなし」として扱うほうが誠実です。

> [!DS] 0 と欠測は違う
> 統計・分析の基本原則です。**0は「測った結果ゼロだった」、欠測は「測っていない」。**
> 両者を同じ値にすると、平均・合計・比率のすべてが歪みます。
> 「未回答を0点として平均する」「未計測日を売上0として月平均を出す」といった処理は、
> 数字を作れてしまうぶん危険です。DAXでは BLANK が欠測を表現する手段であり、意識的に使い分けてください。

## BLANK の性質を正確に知る

BLANK は「値がない」ことを表す特別な値で、独自のルールを持ちます。

```figure

  "items":[
    {"icon":"＋","title":"足し算では 0 のように振る舞う","text":"BLANK + 10 は 10 になる。SUM も BLANK を無視して合計する。","tone":"blue"},
```

最後の性質は、良くも悪くも大きな影響があります。

```dax
-- 売上のない商品を「表に出したくない」場合：そのままでよい
売上合計 = SUM( Fact_売上[SalesAmount] )

-- 売上のない商品も「0として表示したい」場合
売上合計ゼロ表示 = SUM( Fact_売上[SalesAmount] ) + 0
```

`+ 0` を付けると BLANK が 0 になり、行が表から消えなくなります。
ただし **全商品が表示されるぶん、行数が増えて重くなる** ので、必要なときだけ使ってください。

> [!NOTE] BLANK を検査する関数
> - `ISBLANK( [売上合計] )` — 空かどうかを判定する
> - `COALESCE( [売上合計], 0 )` — 最初に空でない値を返す。`IF(ISBLANK(...), 0, ...)` より短く速い
> - `BLANK()` — 明示的に空を返す。`IF` の分岐で「何も表示しない」を表現するときに使う

> 文字列化するのは「—」や「目標未設定」など、数値では表現できない情報を出すときだけにしてください。

## 条件の組み合わせ

複数条件は `&&`（かつ）と `||`（または）でつなぎます。`AND()` `OR()` 関数もありますが、

```dax
重点顧客判定 =

    [売上合計] >= 10000000 && [注文件数] >= 12,  "最重点",
    [売上合計] >= 10000000 || [注文件数] >= 12,  "重点",
    "一般"
)
```

> ゼロ除算の対処を問う設問では、答えは `DIVIDE` です。`IFERROR` や `IF( [分母] = 0, ... )` も
> 動きはしますが、**DIVIDEはエンジン内部で最適化されており、可読性でも性能でも優れます**。
> また「未設定を0と表示すべきでない」という設計判断を問う問題も出題されます。

## 理解度チェック

**問1.** `IF` を4段ネストした式のレビューを頼まれた。どう書き換えるべきか、理由とともに述べよ。

<details><summary>答え</summary>
`SWITCH( TRUE(), 条件1, 値1, 条件2, 値2, ..., 既定値 )` に書き換える。条件と戻り値が同じ高さに並び、条件の追加・削除が1行の差分で済み、閉じかっこの対応ミスも起きないため。
</details>

**問2.** 目標が未設定（BLANK）の店舗について、達成率を `DIVIDE( [実績], [目標], 0 )` と書いた。何が問題か。

<details><summary>答え</summary>
「目標未設定」と「達成率0%」が同じ表示になり、区別できなくなる。0は測定結果、BLANKは欠測であり意味が違う。第3引数を省略してBLANKのままにするか、`ISBLANK` で「目標未設定」と明示する。
</details>

**問3.** 売上のない商品もテーブルに0円で表示したい。どうするか。また、その副作用は何か。

<details><summary>答え</summary>
メジャーに `+ 0` を付けるか `COALESCE( [売上合計], 0 )` とする。副作用として、売上のない全商品が行として現れるため行数が増え、ビジュアルが重くなる可能性がある。
</details>

## よくあるエラーと原因

| 症状・エラー | 原因 | 対処 |
|---|---|---|
| ビジュアル全体が「エラーが発生しました」 | `/` によるゼロ除算 | `DIVIDE` に置き換える |
| 分岐の結果が全部文字列になる | `IF` の各分岐で型が混在 | 全分岐の戻り値の型をそろえる |
| `SWITCH` で下の条件に到達しない | 緩い条件を上に書いた | 厳しい条件から順に並べ替える |
| 「関数 SWITCH には引数が…」 | 条件と戻り値のペアが崩れている | 引数が「条件, 値」の対になっているか数える |
| 達成率が0%と表示される | `DIVIDE` の第3引数に0を指定した | 第3引数を省略しBLANKにする |
| 売上0の商品が表から消える | メジャーがBLANKを返し行が除外された | `+ 0` または `COALESCE` で0を返す |
| `AND()` で3条件を書こうとしてエラー | `AND` は2引数まで | `&&` 演算子でつなぐ |

> [!NOTE] このレッスンのまとめ
> 多分岐は `SWITCH( TRUE(), ... )` で平らに書き、**厳しい条件から順に並べます**。
> 割り算は例外なく `DIVIDE`。第3引数は安易に0にせず、欠測は欠測のまま残すのが誠実です。
> BLANK は「測っていない」を表す値であり、0とは違う——この区別が、信頼される数字を作ります。
