ビジュアルを正しく選んでも、置き場所を間違えると伝わりません。読み手はレポートを「読む」のではなく、**数秒で見て、判断できなければ閉じる**からです。

レイアウトの目的はただ一つ、**読み手の視線を、こちらが意図した順序で歩かせること**です。このレッスンでは視線導線の作り方と、その根拠になる知覚の原則を扱います。

## 5秒ルール — レポートの合格基準

```figure

  "caption":"作った本人には効かないテスト。必ず他人に頼む",
  "items":[
    {"title":"1. 第三者を1人つかまえる","text":"できればそのレポートの想定読者。データに詳しくない人ほどよい","tone":"blue"},

    {"title":"4. 意図とズレていた箇所を直す","text":"ズレの原因は9割が『配置』か『色の強調位置』。ビジュアルの種類ではない","tone":"pink"} ] }
```

## 視線導線 — Zパターンと Fパターン

人の視線は自由に動くわけではなく、文化的な読み方の癖に強く支配されます。日本語・英語のような横書き文化では、視線は**左上から始まり、右へ、そして下へ**進みます。

```figure
{ "type":"flow", "dir":"row", "title":"1画面の視線の流れ（Zパターン）",
  "caption":"情報量が少ない画面では視線はZを描く。左上が最も価値の高い場所になる",
  "items":[
    {"label":"① 左上","sub":"最重要のKPI／結論","tone":"pink","icon":"★"},
    {"label":"② 右上","sub":"補助的なKPI・期間表示","tone":"amber"},
    {"label":"③ 左下","sub":"内訳・詳細","tone":"blue"},
    {"label":"④ 右下","sub":"明細表・注釈","tone":"gray"} ] }
```

要素が多く並んだ画面では、視線は Z ではなく **F パターン**（左端を縦に走査しつつ、横に何度か視線を出す）を描きます。どちらのパターンでも共通するのは次の 2 点です。

- **左上が最も価値の高い領域**である
- **右下は最も見られない領域**である

したがって、レポート設計の第一原則は「**最も伝えたい 1 つを左上に置く**」になります。ロゴやタイトルバナーで左上を潰すのは、最も貴重な土地に看板を立てる行為です。

```figure
{ "type":"compare", "title":"左上に何を置くか",
  "caption":"左上はレポートで最も価値の高い一等地",
  "panels":[
    {"title":"よくある配置","tone":"bad",
     "items":["左上に会社ロゴと大きなタイトルバナー","KPIは画面中央に散らばる","スライサーが上部を横一列に占有し、本文が下に押し出される"],
     "note":"一等地の浪費"},
    {"title":"設計された配置","tone":"good",
     "items":["左上に今月の結論を表す KPI カード","タイトルは小さく左上端に1行","スライサーは左端に縦に集約するか、フィルターペインに寄せる"],
     "note":"推奨"} ] }
```

```figure
{ "type":"cards", "cols":2, "title":"グリッド設計の基本",

    {"icon":"📏","title":"間隔を統一する","text":"ビジュアル間の余白を8pxまたは16pxに固定する。ばらついた余白は無秩序に見える","tone":"green"},
    {"icon":"🔲","title":"高さもそろえる","text":"同じ行に並ぶビジュアルは上端と高さをそろえる。Power BI の書式ペインで X/Y/幅/高さを直接数値入力できる","tone":"amber"},
```

> ビジュアルの位置は**マウスでドラッグせず、書式ペインの「全般 → プロパティ → サイズと位置」に数値を打ち込みます**。X=16, Y=96, 幅=304, 高さ=200 のように決めておくと、ピクセル単位でそろい、見た目の完成度が一段上がります。整列は Ctrl 選択後の「配置」メニューでも可能です。

## 情報の階層 — 上から下へ、粗から細へ

```figure
{ "type":"stack", "title":"1ページの情報階層",
  "caption":"上に行くほど粗く、下に行くほど細かく。読み手は必要なところで止まれる",
  "layers":[
    {"label":"見出し・期間・フィルター状態","sub":"このページが何のいつのデータかを1行で示す","tone":"gray"},
    {"label":"KPI カード（3〜5枚）","sub":"結論。前期比・目標比を添える","tone":"pink"},
    {"label":"主要ビジュアル（1〜2枚）","sub":"KPIがそうなった理由を説明する推移や比較","tone":"blue"},
    {"label":"内訳ビジュアル（2〜3枚）","sub":"どのセグメントが効いたのかを分解する","tone":"green"},
    {"label":"明細テーブル／注釈","sub":"確認したい人だけが見る。既定では小さくてよい","tone":"amber"} ] }
```

この階層は**ピラミッド構造**と呼ばれる文書構成そのものです。結論を先に置き、根拠を後ろに置く。ビジネス文書のルールがそのままレポートに適用できます。

> [!DS] データサイエンス視点：ゲシュタルト原則
> 人はバラバラの要素を「まとまり」として自動的に知覚します。この法則をゲシュタルト原則と呼び、レイアウトはこの原則の応用にほかなりません。
>
> - **近接**：近くにあるものは同じグループに見える。関連するビジュアルは近づけ、無関係なものは離す。余白がグループを作る
> - **類同**：同じ色・形のものは同じ種類に見える。予算は常に灰色、実績は常に青、というルールを全ページで守る
> - **囲み**：枠や背景色で囲まれた領域は 1 つの単位になる。区切り線を引くより、薄い背景の矩形を敷くほうが静かで強い
> - **連続**：整列した要素は一続きに読まれる。上端をそろえるだけで「同じ行の情報」として処理される
> - **閉合**：完全な枠がなくても、人は輪郭を補完する。四辺を囲まなくても、左端の縦線と余白だけでグループは成立する
>
> **区切り線を引きたくなったら、まず余白で試す**。線を1本引くのは、余白を4px広げるのに失敗したときの最終手段です。

```figure
{ "type":"compare", "title":"近接の原則を使ったグルーピング",
  "caption":"線を足すのではなく、余白を操作してグループを作る",
  "panels":[
    {"title":"すべて等間隔＋区切り線だらけ","tone":"bad",
     "items":["どのグラフとどのグラフが関連するのか分からない","線が増えてデータインク比が下がる","スライサーが本文と同じ距離にあり、どこに効くのか不明"],
     "note":"無秩序"},
    {"title":"グループ内8px・グループ間32px","tone":"good",
     "items":["余白の差だけで3つのブロックが知覚される","線を1本も引かずに構造が伝わる","スライサーは対象グラフの近くに置き、効く範囲を暗示する"],
     "note":"推奨"} ] }
```

## タイトルは「主張」で書く

ビジュアルのタイトルを「売上推移」にするのは、情報を 1 つも足していません。タイトルは**読み手に読み取ってほしい結論**を書く場所です。

```figure
{ "type":"tablediff", "arrowLabel":"主張のタイトルに書き換える",
  "before":{"title":"ラベル型タイトル（情報量ゼロ）","tone":"bad",
    "head":["ビジュアル","タイトル"],
    "rows":[["折れ線","月次売上推移"],["横棒","部門別売上"],["カード","売上合計"]]},
  "after":{"title":"主張型タイトル","tone":"good",
    "head":["ビジュアル","タイトル"],
    "rows":[["折れ線","!下期に入って売上は3か月連続で増加"],["横棒","!法人営業が全社売上の34%を占める"],["カード","!売上 182百万円（前年比 +23%）"]]} }
```

> [!TRAP] つまずきポイント
> 主張型タイトルは**データが変わると嘘になる**という弱点があります。フィルターで期間を変えたら「3か月連続で増加」が成立しなくなることがあります。対策は 2 つ。(1) 動的タイトル（DAX メジャーの結果をタイトルに条件付き書式で流し込む）を使う。(2) 主張はテキストボックスの注釈として置き、ビジュアルのタイトルは中立にする。定期配信レポートでは (1)、単発の分析レポートでは (2) が向きます。

## 装飾を削る — データインク比の実践

> [!DS] データサイエンス視点：データインク比とチャートジャンク
> Tufte はグラフの総インク量に対するデータのインク量の比を**データインク比**と定義し、これを高めよと述べました。データを表さない装飾を彼は**チャートジャンク**と呼びます。Power BI の既定設定には、グリッド線・境界線・背景・凡例といった控えめなチャートジャンクが最初から入っています。削るだけで読みやすくなります。

```figure
{ "type":"steps", "title":"既定のビジュアルから削るもの（上から順に実行）",
  "caption":"すべて書式ペイン（ペンキローラーのアイコン）で操作する",
  "items":[
    {"title":"1. 影・境界線を消す","text":"全般 → 効果 → 影／境界線 をオフ。カードが浮いて見える必要はない","tone":"blue"},
    {"title":"2. グリッド線を薄くするか消す","text":"視覚化 → Y軸 → グリッド線。値ラベルを出すならグリッド線は不要","tone":"green"},
    {"title":"3. 凡例を消して直接ラベルに変える","text":"系列が1〜2本なら凡例オフ＋データラベル。視線の往復が消える","tone":"amber"},
    {"title":"4. 目盛の桁を整える","text":"Y軸 → 表示単位を『百万』に。182,000,000 は読めない","tone":"violet"},
    {"title":"5. 色を1色＋グレーに減らす","text":"強調1色、その他はグレー。カラフルさは情報ではない","tone":"pink"},
    {"title":"6. 背景の白を統一する","text":"ビジュアル背景を透明にし、ページ背景1枚で色を管理する","tone":"cyan"} ] }
```

> [!WARN] 注意
> データインク比の最大化は「削れば削るほど良い」ではありません。**軸ラベル・単位・出典・更新日時**は削ってはいけない情報です。削ってよいのは「消しても意味が失われないもの」であり、判断の基準は美しさではなく意味の保存です。

```figure
{ "type":"matrix", "title":"どのページに置くかの判断",
  "xLabel":"読み手の人数", "yLabel":"更新頻度",
  "xLow":"少数（分析者）","xHigh":"多数（経営・現場）","yLow":"低い","yHigh":"高い",
  "quadrants":[
    {"title":"分析用ページ","text":"探索的。スライサー多め。1ページに詰め込んでよい","tone":"violet"},
    {"title":"サマリーページ","text":"KPIと結論のみ。ビジュアルは5枚まで。既定で開くページにする","tone":"good"},
```

## スライサーの置き場所

スライサー（絞り込み用の部品）は、レイアウトを最も壊しやすい要素です。数が増えると上部を占領し、本文が下へ押し出されます。

```figure
{ "type":"cards", "cols":3, "title":"スライサーの3つの置き方",
  "caption":"読み手の操作頻度で置き場所を決める",
  "items":[
    {"icon":"⬅","title":"左端に縦一列","text":"操作頻度が高い1〜3個のスライサー向け。視線が最初に通る位置にあり、操作を促せる","tone":"blue"},
    {"icon":"🎛","title":"フィルターペインに寄せる","text":"操作頻度が低い、または項目数が多い絞り込み。キャンバスを一切消費しない","tone":"green"},
    {"icon":"📄","title":"ブックマークで開閉するパネル","text":"スライサーをグループ化し、ボタンで表示・非表示を切り替える。画面が広く使える","tone":"violet"} ] }
```

> [!TRAP] つまずきポイント
> スライサーを上部に横一列で並べると、**「どのビジュアルに効くのか」が視覚的に伝わりません**。既定ではページ内の全ビジュアルに効くため実害は少ないのですが、相互作用の編集（L0904）で一部だけに効かせている場合、読み手は必ず誤解します。効く範囲が限定的なスライサーは、対象ビジュアルの近くに置くか、同じ背景ブロックの中に入れます。

## 注釈とテキストの使い方

数字だけのレポートは、読み手に解釈を丸投げしています。**1 ページに 1 つ、書き手の解釈を文字で置く**と、レポートの価値は跳ね上がります。

```figure
{ "type":"chart", "kind":"bar", "title":"月次売上（注釈なしの図）",
  "caption":"7月に跳ねている。だが読み手には理由が分からない。図だけでは『何が起きたか』しか伝わらない",
  "categories":["4月","5月","6月","7月","8月","9月"],
  "series":[{"name":"売上","values":[120,124,131,178,140,146],"tone":"blue"}],
  "highlight":3, "unit":"百万円" }
```

上の図に「7月はキャンペーンによる一時的な増加。8月以降は通常水準に戻っている」というテキストボックスを 1 行添えるだけで、読み手は誤った期待を持たずに済みます。**注釈は前注意的属性ではありませんが、誤読を防ぐ最後の安全装置**です。

> [!TIP] 実務のコツ
> テキストボックスに DAX の結果を出したい場合は、**カードビジュアル＋メジャー**を使います。`"7月の売上は " & FORMAT([売上合計], "#,##0") & " 百万円"` のような文字列メジャーを作り、カードで表示すれば、フィルター状態に追随する動的な注釈になります。

## 書き出しと印刷を前提にした配置

レポートは画面で見られるだけではありません。PowerPoint に貼られ、PDF で配られ、会議資料として印刷されます。

```figure
{ "type":"matrix", "title":"出力先ごとの配置上の注意",
  "xLabel":"インタラクションの有無", "yLabel":"画面の大きさ",
  "xLow":"静的（PDF・PPT）","xHigh":"操作あり（サービス）","yLow":"小さい（スマホ）","yHigh":"大きい（PC）",
  "quadrants":[
    {"title":"PDF / 印刷","text":"スライサーの選択状態が消えるため、期間をタイトルに文字で焼き込む","tone":"amber"},
    {"title":"Power BI サービス","text":"ドリルダウン・ツールチップ前提で情報を隠してよい","tone":"good"},
    {"title":"スマホの静止画共有","text":"KPIカード中心。文字サイズは12pt以上","tone":"blue"},
    {"title":"モバイルレイアウト","text":"縦1列に再配置する。L0906で扱う","tone":"violet"} ] }
```

## 理解度チェック

1. レポートの左上に会社ロゴと大きなタイトルバナーを置くのは、なぜ設計上もったいないのか。視線導線の観点から説明せよ。
2. 3 つのビジュアル群を視覚的にグループ分けしたい。区切り線を引く以外の方法を、ゲシュタルト原則の名前を挙げて 2 つ述べよ。
3. 「売上推移」というビジュアルタイトルを主張型に書き換えると何が改善するか。またその方式の弱点と対策を述べよ。

<details>
<summary>解答の要点</summary>

1. 横書き文化の読み手の視線は左上から始まり、Z または F パターンで進む。左上は 5 秒で必ず見られる**最も価値の高い領域**であり、そこに情報量ゼロのロゴを置くと、最重要の KPI が視線の後半に押し出される。ロゴは右上か下端の小さな帯に置き、左上には結論を置く。
2. (1) **近接**：グループ内の余白を狭く（8px）、グループ間を広く（32px）取る。余白の差だけでまとまりが知覚される。(2) **囲み**：薄い背景色の矩形を敷いて 1 つの領域として囲む。線を引くよりデータインク比を下げずに構造を示せる。（類同：同じ色調でそろえる、も可）
3. 「売上推移」はビジュアルの種類を繰り返しているだけで情報を足さない。主張型にすると読み手は図を解読する前に結論に到達でき、5 秒ルールを満たしやすくなる。弱点は**フィルター操作でデータが変わると記述が事実と食い違う**こと。対策は DAX メジャーによる動的タイトル、または主張を注釈テキストに分離しビジュアルタイトルは中立にすること。
