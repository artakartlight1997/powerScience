会議で「先月の売上は？」と聞かれ、営業部が12.4億、経理部が11.8億と答える。どちらも嘘ではありません。

原因は計算式ではなく、**モデルの境界をどこに引くかを誰も決めなかったこと**です。

## 設計チェックリスト

- [ ] 分割方針を選び、理由を6軸で記録した
- [ ] セキュリティ境界に該当する領域を独立モデルにした
- [ ] 同じ語が別の意味で使われていないか棚卸しした
- [ ] バスマトリクスを作り、共有ディメンションを特定した
- [ ] 共有Dimの粒度と包含範囲が全ドメインで一致していることを確認した
- [ ] レポートは共有モデルへのライブ接続を既定とし、例外の申請経路を用意した
- [ ] 複合モデルのチェーンの深さに上限を定めた
- [ ] 「列が足りない」要望の受付窓口とリードタイムを決めた
- [ ] 全モデルに所有者と後継者を必須で記録した
- [ ] 廃止の条件と通知期間を定めた

## 理解度チェック

1. 2つのモデルの`Dim_商品`がコンフォームドと言えるには、名前のほかに何が一致すべきですか。2つ挙げてください。
2. 「共有モデルに自部門の目標値を足したい」に対し、A・B・Cのどれを勧めますか。追加質問を1つ挙げて答えてください。
3. 統合より分割のほうが後から取り返しがつかないと言われる理由を述べてください。

> 分けるとは定義を分けること。6軸で判断し、上位3軸は技術で緩和できない。標準解はドメイン別モデル＋共有ディメンション＋シンレポート。方針は台帳で実物と突き合わせ続ける。
