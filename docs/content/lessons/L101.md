Power BI は 100 種類以上のデータソースに接続できます。ただし覚えるべきは接続先の数ではなく、**「取り込み方の違い」**です。

## 接続モードの3択

```mermaid 3つの接続モード
flowchart TB
  subgraph IM["インポート"]
    I1["データをPower BI内にコピー"] --> I2["高速・全DAX機能が使える"] --> I3["更新しないと古いまま"]
  end
  subgraph DQ["DirectQuery"]
    D1["データは元の場所に置いたまま"] --> D2["常に最新・大容量OK"] --> D3["遅い・DAXに制限"]
  end
  subgraph LC["ライブ接続"]
    L1["既存のセマンティックモデルに接続"] --> L2["モデルは作らずレポートだけ作る"]
  end
```

| | インポート | DirectQuery | ライブ接続 |
|---|---|---|---|
| データの場所 | Power BI 内（圧縮保存） | 元のデータベース | 既存のモデル |
| 速度 | 非常に速い | 元DBの性能次第 | モデル次第 |
| データ鮮度 | 更新時点 | 常に最新 | 常に最新 |
| データ量上限 | モデルサイズ制限あり | 実質無制限 | — |
| Power Query | 自由に使える | 一部の変換のみ | 使えない |
| DAX | 全機能 | 一部制限 | 全機能（レポート側の制約あり） |

> [!EXAM]
> 「10億行あり、常に最新データが必要」→ DirectQuery。「複雑な計算を高速に」→ インポート。「他部署が作ったモデルを使ってレポートだけ作る」→ ライブ接続。この3択は必ず出ます。

**迷ったらインポート**が実務の原則です。DirectQuery は「そうせざるを得ない理由」があるときだけ選びます。

## よく使うコネクタ

| ソース | メニュー | 注意点 |
|---|---|---|
| Excel | ホーム → Excel ブック | シートよりも**テーブル／名前付き範囲**を選ぶほうが安全 |
| CSV | テキスト/CSV | 文字コード（UTF-8 / Shift-JIS）と区切り記号を確認 |
| フォルダ | データを取得 → フォルダー | 同じ形式のファイルをまとめて読み込める |
| SQL Server | データを取得 → SQL Server | サーバ名・DB名。SQL文の直書きは極力避ける |
| Web | Web | 表形式のページならURLだけで取り込める |
| SharePoint | SharePoint フォルダー | 社内共有ファイルの定番 |

> [!TRAP]
> Excel を「シート」として読み込むと、行を挿入しただけで範囲がずれて壊れます。元ファイルで **Ctrl+T のテーブル化**をしてから、テーブルとして読み込んでください。

## フォルダ接続 — 毎月のファイルをまとめる

「202501.csv, 202502.csv …」が毎月増えるケース。1つずつ読み込む必要はありません。

```mermaid フォルダ接続の仕組み
flowchart LR
  F["フォルダ"] --> L["ファイル一覧を取得"]
  L --> S["サンプルファイルから<br/>変換手順を自動生成"]
  S --> A["全ファイルに同じ手順を適用"]
  A --> C["1つのテーブルに結合"]
```

1. **データを取得 → フォルダー** でフォルダを選択
2. 「結合 → データの結合と変換」
3. サンプルファイルを選ぶと、変換用の関数とヘルパークエリが自動生成される
4. 以降、フォルダにファイルを追加するだけで更新時に自動で取り込まれる

> [!TIP]
> この機能を知っているだけで「毎月のファイル追加作業」が消えます。実務でもっとも投資対効果の高いテクニックのひとつです。

## 認証と資格情報

接続時に聞かれる認証方式は、ソースによって異なります。

| 方式 | 使う場面 |
|---|---|
| 匿名 | 公開Web API・公開CSV |
| 基本 | ユーザー名とパスワード |
| 組織アカウント | Microsoft 365 / SharePoint / Azure |
| Windows | 社内のSQL Server（統合認証） |

> [!WARN]
> Desktop で保存した資格情報は、Service に発行しても引き継がれません。Service 側で **セマンティックモデルの設定 → データソースの資格情報** から再入力が必要です。「Desktopでは更新できるのにServiceで失敗する」原因の第1位がこれです。

## プライバシーレベル

複数のデータソースを組み合わせるとき、Power BI は「機密データが外部へ漏れないか」を判定します。

| レベル | 意味 |
|---|---|
| プライベート | 他のソースと絶対に組み合わせない |
| 組織 | 組織内のソースとのみ組み合わせ可 |
| パブリック | 制限なし |

厳しく設定すると、後述の**クエリ フォールディング**（L106）が効かなくなり、性能が落ちることがあります。速度と安全のトレードオフです。

## まとめ

- まずインポートを検討。DirectQuery は必要に迫られたときだけ
- Excel は必ずテーブル化してから読む
- 繰り返し届くファイルはフォルダ接続でまとめる
- Service での更新には資格情報の再設定が必要
