## フィルター引数の3つの書き方

```figure
{ "type":"cards", "cols":3, "title":"フィルター引数に書けるもの", "caption":"実務では上2つで足りる",
  "items":[{"icon":"=","title":"ブール述語","text":"Dim_商品[Category] = \"家電\" のような単純な条件。1つの述語には1つの列しか書けない。最も速い。","tone":"blue"},
    {"icon":"▦","title":"テーブル式","text":"ALL( Dim_商品 ) や VALUES( … ) など表そのもの。フィルターを外すときに使う。","tone":"green"},
    {"icon":"ƒ","title":"FILTER 関数","text":"複数列にまたがる条件やメジャーを含む条件で必要。表を1行ずつ走査するので重い。","tone":"violet"} ] }
```

```dax
-- ✓ 同じ列への複数値は IN
CALCULATE( [売上合計], Dim_商品[Category] IN { "家電", "食品" } )

-- ✓ 違う列は引数を分ける（AND になる。これが最速）
CALCULATE( [売上合計], Dim_商品[Category] = "家電", Dim_店舗[Region] = "関東" )

-- ✗ 1つの述語に2列は書けない
CALCULATE( [売上合計], Dim_商品[Category] = "家電" && Dim_店舗[Region] = "関東" )
```

> [!WARN] 遷移はコストが高い
> 行ごとにコンテキストを作り直します。反復対象は `VALUES( 列 )` など小さい表にします。

> [!NOTE] 覚えるべき一文
> フィルター引数が先、式は後。同じ列は上書き、違う列は追加。

> [!EXAM] PL-300で問われる
> 上書きを使うのが `CALCULATE`、行の条件を残すのが `KEEPFILTERS`。この違いが頻出です。

## 理解度チェック

**問1.** `CALCULATE( [売上合計], Dim_商品[Category] = "家電" )` が全カテゴリ行で同じ値になる理由は。

<details><summary>答え</summary>
フィルター引数と行の条件が同じ列なので、行の条件が上書きされる。異なる列なら追加（AND）となり行ごとに違う値になる。
</details>

**問2.** `Dim_商品[Category] = "家電" && Dim_店舗[Region] = "関東"` がエラーになる理由と正しい書き方は。

<details><summary>答え</summary>
ブール述語には1つの列しか書けないため。引数を分けて `CALCULATE( [売上合計], 条件A, 条件B )` の形にする（複数引数はAND）。
</details>

**問3.** フィルター引数と第1引数のどちらが先に評価されるか。それが重要な理由は。

<details><summary>答え</summary>
フィルター引数が先。変更前の外側のコンテキストで評価され、その結果で新しいコンテキストを組み立ててから式が評価される。
</details>

## よくあるエラーと原因

| 症状・エラー | 原因 | 対処 |
|---|---|---|
| 全行で同じ値になる | 同じ列への条件で上書きされた | 意図どおりなら正常。残すなら `KEEPFILTERS` |
| 「単一の列を参照する必要があります」 | 述語で2つの列を参照した | 引数を分けるか `FILTER` |
| 前年売上が当年と同じ | 第1引数に変数を渡した | 変数ではなく式・メジャーを渡す |
| 構成比の合計が100%にならない | 分母のフィルター除去範囲が不適切 | `REMOVEFILTERS` の対象列を見直す |
| 極端に遅い | 大きな表を `FILTER` で反復 | 述語形式に書き換える |
| 反復の中の値が全体値 | 式を直接書いた | メジャー参照にする |
