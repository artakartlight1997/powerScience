「来期の売上予測は12億4,300万円です」。この報告には致命的な欠陥があります。**外れたときに、どれくらい外れうるかが書かれていない**からです。実績が11億2,000万円だったとき、この予測をした人は「予測が外れた」と評価されます。次からは誰も予測を求めなくなり、意思決定は勘に戻ります。

正しい報告はこうです。「来期の売上予測は中央値12億4,000万円、80%の確率で11億1,000万〜13億8,000万円の範囲に収まります。11億を下回るのは、主要顧客A社の契約更新が失注した場合です」。

この報告なら、**下振れに備えた意思決定ができます**。予測の価値は、当てることではなく、意思決定の材料になることにあります。

> [!DS]
> 予測が外れる原因は2つに分けられます。**削減可能な不確実性**（モデルが悪い、変数が足りない、データが古い）と、**本質的な不確実性**（明日の天気、顧客の気まぐれ）です。前者はモデル改善で減らせますが、後者はどれだけ努力しても消えません。予測区間の幅は、この2つの合計を表しています。幅がゼロの予測は、嘘です。

## 予測の精度をどう測るか

誤差指標にはそれぞれ性格があります。目的に合ったものを選びます。

| 指標 | 式 | 性格 | 使う場面 |
|---|---|---|---|
| MAE（平均絶対誤差） | 平均( \|実績−予測\| ) | 単位そのまま。外れ値に穏やか | 在庫・人員など「量」の誤差が直接コストになるとき |
| RMSE（二乗平均平方根誤差） | √平均( (実績−予測)² ) | 大きな外れを強く罰する | 大外しが致命的なとき（キャパシティ計画） |
| MAPE（平均絶対率誤差） | 平均( \|実績−予測\| ÷ 実績 ) | %表示。規模の違うものを比較できる | 商品別・店舗別の精度比較 |
| バイアス（平均誤差） | 平均( 実績−予測 ) | 符号を残す。偏りを見る | 常に上振れ／下振れしていないかの点検 |

```dax
予測_MAE :=
AVERAGEX( VALUES( Dim_日付[年月] ), ABS( [売上合計] - [売上予測] ) )

予測_RMSE :=
SQRT( AVERAGEX( VALUES( Dim_日付[年月] ), ( [売上合計] - [売上予測] ) ^ 2 ) )

予測_MAPE :=
AVERAGEX(
    VALUES( Dim_日付[年月] ),
    DIVIDE( ABS( [売上合計] - [売上予測] ), [売上合計] )
)

予測_バイアス :=
AVERAGEX( VALUES( Dim_日付[年月] ), [売上合計] - [売上予測] )
```

> [!TRAP] MAPE は実績がゼロに近いと爆発する
> 実績が2、予測が4なら、絶対誤差は2でも MAPE は100%です。実績0の期間があれば、`DIVIDE` によりゼロ除算は避けられますが、その期間は評価から抜け落ちます。**需要が小さい商品や、欠品で売上ゼロの日を含むデータで MAPE を使うと、精度評価が壊れます。** その場合は MAE か、実績と予測の平均で割る sMAPE を使ってください。

## What-if パラメータでシナリオを作る

不確実性を伝えるもう1つの方法が、シナリオです。Power BI の **What-if パラメータ**（モデリング → 新しいパラメータ → 数値範囲）を使うと、スライダーで前提を動かせるレポートが作れます。

```figure
{ "type": "pipeline", "title": "What-if パラメータの仕組み",
  "nodes": [
    {"id":"p","label":"パラメータ表\n（0%〜30%を1%刻みで生成）","tone":"blue"},
    {"id":"s","label":"スライサー\n（ユーザーが値を選ぶ）","tone":"green"},
    {"id":"m","label":"パラメータ値メジャー\nSELECTEDVALUE で取得","tone":"amber"},
    {"id":"r","label":"シナリオ売上メジャー\n実績 × (1 + 成長率)","tone":"violet"} ],
  "edges": [
    {"from":"p","to":"s","label":"自動生成される"},
    {"from":"s","to":"m","label":"選択値を渡す"},
    {"from":"m","to":"r","label":"計算に使う"} ],
  "caption": "What-if パラメータは「値だけを持つ独立テーブル」。ファクトとのリレーションシップは張らない。" }
```

```dax
// 自動生成されるパラメータ値メジャー
成長率 = SELECTEDVALUE( '成長率'[成長率], 0.05 )

// シナリオ予測
売上予測_シナリオ :=
VAR 基準 = [売上_前年同月]
RETURN
    基準 * ( 1 + [成長率] )

// 3シナリオを固定で並べる場合
売上予測_悲観 := [売上_前年同月] * 0.92
売上予測_標準 := [売上_前年同月] * 1.05
売上予測_楽観 := [売上_前年同月] * 1.18
```

> [!TIP] 実務のコツ
> シナリオは3本（悲観・標準・楽観）に絞ります。5本以上並べると、意思決定者はどれを信じればよいか分からなくなり、結局「標準」だけを見ます。さらに重要なのは、**各シナリオが成立する条件を1行で書く**ことです。「悲観：主要顧客2社の失注」「楽観：新店3店舗が計画どおり立ち上がる」。条件が書かれたシナリオは、モニタリング指標に変わります。

## 予測区間を自分で作る

分析ペインの予測を使わず、自作メジャーで予測する場合も、区間は作れます。**バックテストで得た誤差のばらつきを、そのまま将来にあてはめる**のが最も実務的な方法です。

```figure
{ "type": "steps", "title": "残差から予測区間を作る4手順", "items": [
  {"title":"過去期間で予測値を計算する","text":"季節ナイーブでも移動平均でもよい。同じ式を過去に適用する。","tone":"blue"},
  {"title":"残差（実績−予測）を集める","text":"直近24か月ぶんなど、十分な件数を確保する。","tone":"green"},
  {"title":"残差の標準偏差を求める","text":"STDEV.S。バイアス（平均残差）がゼロから離れていれば、まず予測式を直す。","tone":"amber"},
  {"title":"予測値 ± 1.28σ で80%区間","text":"正規分布を仮定した場合の係数。95%なら1.96、50%なら0.67。","tone":"violet"} ] }
```

```dax
予測_残差SD :=
VAR 検証期間 =
    FILTER(
        ALL( Dim_日付[年月] ),
        Dim_日付[年月] >= [検証開始月] && Dim_日付[年月] <= [検証終了月]
    )
RETURN
    STDEVX.S( 検証期間, [売上合計] - [売上予測] )

売上予測_上限80 := [売上予測] + 1.28 * [予測_残差SD]
売上予測_下限80 := [売上予測] - 1.28 * [予測_残差SD]
```

このやり方の限界は、**先の期間ほど誤差が大きくなる性質を表現できない**点です。1か月先も12か月先も同じ幅になります。簡便法として、`√h`（h は何期先か）を掛けて広げる補正がよく使われます。

```dax
売上予測_上限80_期先補正 :=
[売上予測] + 1.28 * [予測_残差SD] * SQRT( [予測何期先] )
```

> [!DS]
> 「残差の標準偏差から区間を作る」方法は、残差が正規分布に従い、かつ時間的に独立であることを仮定しています。実際の残差はしばしば自己相関を持ち（悪い月の翌月も悪い）、その場合は区間が狭すぎる方向に誤ります。厳密さが必要なら、残差をブートストラップ（復元抽出）でシミュレーションする方法がありますが、Power BI 単体では現実的ではありません。**Python / R ビジュアル、または Fabric のノートブックで計算し、結果をテーブルとして取り込む**のが実務的な解です。

## 因果型予測の入口 — 単回帰

説明変数から目的変数を予測するのが回帰です。最も単純な単回帰は、DAX でも書けます。

```dax
// 傾き（最小二乗法）
回帰_傾き :=
VAR T = ADDCOLUMNS( VALUES( Dim_日付[年月] ),
        "@X", [広告費合計], "@Y", [売上合計] )
VAR MX = AVERAGEX( T, [@X] )
VAR MY = AVERAGEX( T, [@Y] )
RETURN
    DIVIDE(
        SUMX( T, ( [@X] - MX ) * ( [@Y] - MY ) ),
        SUMX( T, ( [@X] - MX ) ^ 2 )
    )

// 切片
回帰_切片 :=
VAR T = ADDCOLUMNS( VALUES( Dim_日付[年月] ),
        "@X", [広告費合計], "@Y", [売上合計] )
RETURN
    AVERAGEX( T, [@Y] ) - [回帰_傾き] * AVERAGEX( T, [@X] )

// 予測値
売上予測_回帰 := [回帰_切片] + [回帰_傾き] * [広告費合計]
```

> [!WARN] 注意
> 因果型予測には決定的な弱点があります。**説明変数の将来値が必要**なことです。「広告費から売上を予測する」モデルは、来月の広告費が決まっていなければ使えません。気温から需要を予測するモデルは、気温予報の精度に縛られます。説明変数が自分でコントロールできる値（広告費・価格・出店数）である場合にのみ、因果型予測はシナリオ分析の道具として真価を発揮します。

```figure
   "note":"計画に使う予測"} ] }
```

> [!TRAP] 集約すると精度は必ず上がって見える
> 店舗別の MAPE が平均18%でも、全社合計の MAPE は5%になることがあります。店舗ごとの上振れと下振れが打ち消し合うためです。これは予測が良くなったのではなく、**評価する粒度を粗くしただけ**です。「全社予測の精度は5%です」と報告して店舗別の発注に使わせると、現場は毎回ずれた数字を渡されます。**予測は、使う粒度で評価してください。**

## 予測を運用に載せる

作りっぱなしの予測は、3か月で誰も見なくなります。更新と検証のサイクルを最初に決めておきます。

```figure
{ "type": "timeline", "title": "予測の運用サイクル（月次の例）", "items": [
  {"label":"月初 第1営業日","title":"実績を確定させる","text":"前月の締めが終わったデータで、予測の入力を更新する。締まっていない期間は入れない。","tone":"blue"},
  {"label":"月初 第2営業日","title":"予測を再計算する","text":"モデルを回し、前回予測との差分（リビジョン）を記録する。差分が大きい月は理由を書く。","tone":"green"},
  {"label":"毎月","title":"バックテストを更新する","text":"直近12か月のMAPEとバイアスをダッシュボードに常設し、劣化を監視する。","tone":"amber"},
  {"label":"四半期ごと","title":"モデルを見直す","text":"季節指数の作り直し、構造変化の確認、ベースライン比較の再実施。","tone":"violet"},
  {"label":"随時","title":"監視項目が動いたら再作成","text":"価格改定・大型受注・競合参入など、前提が壊れたら期を待たずに作り直す。","tone":"pink"} ] }
```

> [!TIP] 実務のコツ
> **予測の履歴を残してください。** 「3か月前に立てた今月の予測」と「実績」を並べたテーブルを常設すると、予測の癖（常に強気、季節の変わり目に弱い）が見えます。この履歴テーブルは、予測メジャーとは別に「予測スナップショット」というファクトテーブルとしてモデルに持たせるのが定石です。データフロー（L1105）で毎月末に追記していく形が、最も運用が軽くなります。

## まとめ

- 予測は必ず幅（区間）とセットで出す。1本の線は意思決定に使えない
- 区間は先に行くほど広がる。幅が一定なら計算していない証拠
- 時系列予測は「過去のパターンが続く」という仮定の上に成り立つ
- Power BI の予測は折れ線グラフの分析ペイン。X軸は日付型・等間隔
- 「無視する最後のポイント」でバックテストする。検証なき予測は使わない
- 誤差指標は MAE / RMSE / MAPE / バイアスを目的で使い分ける
- 必ず季節ナイーブ法と比較する。勝てないモデルは不要
- What-if パラメータでシナリオを3本作り、成立条件を1行で書く
- 予測と目標を混ぜない。ギャップこそが行動を生む
