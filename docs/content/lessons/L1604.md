PL-300 の問題文は作問ルールに従うため、言い回しが驚くほど定型的です。

「最小限の労力で」「常に最新のデータを」「将来の列にも対応させる」。これらは装飾ではなく、**正解を1つに絞る条件語**です。

> [!NOTE] 使い方
> 1周目は読む。2周目はキーワードだけ見て正解の方向を口に出す。3周目で詰まった番号が弱点です。

> [!TRAP] 「動く案」と「正解」は違う
> 日付テーブルの複製もロールの大量作成も動きます。「最小限の労力」がある限り誤答です。常に条件語へ戻ってください。

## 30パターン以外の頻出キーワード

| 問題文の表現 | 正解の方向 |
|---|---|
| 組織の公式データであることを示す | 認定済み（Certified） |
| 作成者が自分で品質を保証する | 昇格済み（Promoted） |
| 複数レポートで同じ数字の定義を使う | 共有セマンティックモデル + ライブ接続 |
| 明細を1万行、印刷用に出力する | ページ分割されたレポート |
| Excelのピボットで分析させたい | 「Excelで分析」 |
| 定期的にメールで送る | サブスクリプション |
| どのレポートが影響を受けるか調べる | 影響分析 / 系列（リネージ） |
| 使われていないレポートを特定する | 使用状況メトリック |
| 誰がいつエクスポートしたか調べる | 監査ログ（Purview） |
| フィルターを閲覧者に変更させたくない | フィルターカードのロック |
| 特定のビジュアルだけ別の期間を見せる | ビジュアルレベルフィルター |
| 多対多になってしまう | ブリッジテーブル、または粒度の見直し |

## まとめ

- 問題文は「工程 → 条件語 → 選択肢」の順に読む
- 「最小限の労力」＝標準機能・既存の再利用。動くだけの案は誤答
- 「常に最新」＝DirectQuery、「最速」＝インポート
- 「将来の列」＝その他の列のピボット解除
- 「100人に配布」＝アプリ、「行ごとに変える」＝RLS
- ドリルダウン（同じビジュアル）とドリルスルー（別ページ）を混同しない
- フィルターはセキュリティではない
- 誤答の理由を言語化できて初めて、そのパターンは身についている
