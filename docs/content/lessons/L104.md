分析しやすいデータには決まった形があります。それが**整然データ（tidy data）**です。この回では、崩れた形を整然データに直す3つの主要技術を扱います。

## 整然データの3条件

```mermaid 整然データの条件
flowchart TB
  A["① 1列 = 1変数"] --> D["整然データ"]
  B["② 1行 = 1観測"] --> D
  C["③ 1テーブル = 1種類の観測"] --> D
  style D fill:#e0f5ee,stroke:#14926b,stroke-width:3px
```

### 崩れている例：横持ちデータ

| 商品 | 1月 | 2月 | 3月 |
|---|---|---|---|
| ノートPC | 120 | 135 | 128 |
| マウス | 300 | 280 | 310 |

人間には読みやすい形ですが、Power BI には最悪の形です。4月が来たら列を追加することになり、そのたびにグラフが壊れます。

### 整然データ：縦持ち

| 商品 | 月 | 数量 |
|---|---|---|
| ノートPC | 1月 | 120 |
| ノートPC | 2月 | 135 |
| ノートPC | 3月 | 128 |
| マウス | 1月 | 300 |
| ... | ... | ... |

4月が来ても**行が増えるだけ**。グラフは何も変えなくてよい。これが整然データの威力です。

## ピボット解除 — 横持ちを縦持ちに

```mermaid ピボット解除の動き
flowchart LR
  A["商品 | 1月 | 2月 | 3月"] -->|"月の列を選択して<br/>列のピボット解除"| B["商品 | 属性 | 値"]
```

手順：

1. **保持したい列（商品）を選択**
2. 右クリック → **その他の列のピボット解除**
3. 生成された「属性」「値」列を、意味の分かる名前（月、数量）にリネーム

> [!TIP]
> 「選択した列のピボット解除」ではなく **「その他の列のピボット解除」** を使ってください。将来4月の列が増えても、自動的に取り込まれます。列を明示指定する方法は、新しい列に対応できません。

> [!EXAM]
> 「毎月列が追加されるExcelを取り込む。将来の列にも自動対応させたい」→ **その他の列のピボット解除**。頻出パターンです。

## 列のピボット — 縦持ちを横持ちに（必要な場合のみ）

逆方向の操作もあります。**変換 → 列のピボット**。値列と集計方法を選びます。

使う場面は限られます。「属性名・属性値」の2列で複数の属性が縦に並んでいるデータ（EAV形式）を、まともなテーブルに直すときです。

| 顧客ID | 属性名 | 属性値 |
|---|---|---|
| C001 | 年齢 | 35 |
| C001 | 性別 | 男性 |

これは「1行1観測」ではないので、ピボットして次の形にします。

| 顧客ID | 年齢 | 性別 |
|---|---|---|
| C001 | 35 | 男性 |

## 列の分割

**ホーム → 列の分割** から選べます。

| 方法 | 使いどころ | 例 |
|---|---|---|
| 区切り記号 | カンマ・タブ・ハイフン区切り | `東京都-新宿区` → 2列 |
| 文字数 | 固定長データ | `20250401` → `2025` + `04` + `01` |
| 位置 | 特定位置で切る | 商品コードの体系別分解 |
| 大文字小文字の変わり目 | キャメルケース | `SalesAmount` → `Sales` + `Amount` |
| 数字と数字以外の変わり目 | 単位付き数値 | `500ml` → `500` + `ml` |

> [!TRAP]
> 区切り記号で分割するとき、**「最も左の区切り記号」「最も右の区切り記号」「各出現箇所」**の選択を間違えると結果が変わります。住所を「都道府県 / 市区町村以降」に分けたいなら「最も左の区切り記号」です。

## 列のマージ

複数列を1列に結合します。**列を選択 → 変換 → 列のマージ**。区切り記号を選べます。

用途は主に**複合キーの作成**です。

例：`店舗コード` + `商品コード` で一意になるデータの場合、両者をマージして1つのキー列を作れば、リレーションシップを1本で張れます。

> [!TIP]
> 複合キーを作るときは、区切り記号に「元データに絶対に出てこない文字」（例：`|`）を使ってください。`A` + `BC` と `AB` + `C` が同じキーになる事故を防げます。

## 例：フルネームの分割と再構成

```m
let
    ソース = ...,
    // 「山田 太郎」を姓と名に分ける
    分割 = Table.SplitColumn(ソース, "氏名",
             Splitter.SplitTextByDelimiter(" ", QuoteStyle.Csv),
             {"姓", "名"}),
    型 = Table.TransformColumnTypes(分割, {{"姓", type text}, {"名", type text}}),
    // 表示用に「山田太郎」を作る
    結合 = Table.AddColumn(型, "表示名", each [姓] & [名], type text)
in
    結合
```

## 実務での判断基準

| 元データの形 | やること |
|---|---|
| 月ごとに列が横に伸びている | その他の列のピボット解除 |
| 「項目名・値」の2列に何でも入っている | 列のピボット |
| 1つの列に複数の情報が詰まっている | 列の分割 |
| キーが複数列に分かれている | 列のマージ |
| 見出しが2行にまたがっている | 上位N行の削除 → ヘッダーの昇格 |
| 小計行が混ざっている | フィルターで除去（小計行の目印を探す） |

> [!WARN]
> Excelの「見た目のための空白行」「セル結合」「小計行」は、そのまま取り込むと分析を壊します。取り込み後に必ず列プロファイルで行数を確認し、想定と合うか検証してください。

## チェック：この形は整然データか

| 日付 | 東京売上 | 大阪売上 | 名古屋売上 |
|---|---|---|---|

答え：**整然ではありません**。「店舗」という1つの変数が3つの列に分かれています。ピボット解除して `日付 / 店舗 / 売上` の3列にするのが正解です。
