DAX の関数は返り値で2種類。1つの値を返す**スカラー関数**と、表を返す**テーブル関数**。
上級DAXは「まず表を組み立て、その上で集計する」二段構えで書きます。

## テーブルを変数に入れる

```dax
売上上位顧客の売上 =
VAR TopCustomers =
    TOPN(
        10,
        ADDCOLUMNS( VALUES( Dim_顧客[CustomerID] ), "@売上", [売上合計] ),
        [@売上], DESC
    )
RETURN
    SUMX( TopCustomers, [@売上] )
```

## 理解度チェック

**問1.** `ADDCOLUMNS( SUMMARIZE( Fact_売上, Dim_商品[Category] ), "売上", SUM( Fact_売上[SalesAmount] ) )` が全行同じ値になる理由は。

<details>
<summary>解答</summary>

式の直書きなので遷移が起きず、行コンテキストが集計に効かないためです。`[売上合計]` に替えるか CALCULATE で包めば直ります。
</details>

**問2.** `VALUES( Dim_商品[ProductName] )` と `DISTINCT(…)` で行数が1つ違いました。何が起きていますか。

<details>
<summary>解答</summary>

マスタ未登録の商品IDがあり、不明メンバーの空白行が自動追加されています。VALUES はこれを含み、DISTINCT は含みません。
</details>

**問3.** メジャー内で `SUMMARIZECOLUMNS` がエラーになりました。どう書き換えますか。

<details>
<summary>解答</summary>

`ADDCOLUMNS( SUMMARIZE( 起点テーブル, グループ化列 ), "名前", メジャー )` に書き換えます。メジャー内での利用は避けるのが安全です。
</details>

## 実務チェックリスト

- [ ] SUMMARIZE の集計列を ADDCOLUMNS に分離した
- [ ] ADDCOLUMNS 内の集計をメジャー参照か CALCULATE で包んだ
- [ ] 追加列名に `@` を付けて実列と区別できるようにした
- [ ] 仮想テーブルの想定行数を見積もり、爆発していないか確認した
- [ ] VALUES と DISTINCT のどちらが要件に合うか判断した
- [ ] メジャーの最終返り値がスカラーになっているか確認した
