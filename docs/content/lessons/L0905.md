表は情報密度が最も高いビジュアルです。1 画面に数百の数値を載せられます。しかし、そのままでは読み手はどこを見ればよいか分かりません。

このレッスンでは、密度を落とさずに読みやすくする 3 つの道具を扱います。**条件付き書式**（表を読めるようにする）、**ツールチップページ**（詳細を画面から追い出す）、**スモールマルチプル**（多系列を破綻させずに並べる）です。

## 条件付き書式 — 表に視覚的な手がかりを足す

```figure
{ "type":"tablediff", "arrowLabel":"条件付き書式を適用",
  "before":{"title":"素の行列（数字の壁）","tone":"bad",
    "head":["店舗","売上","前年比","粗利率"],
    "rows":[["新宿","182","112%","31.2%"],["渋谷","146","98%","28.4%"],["池袋","131","87%","24.1%"],["上野","98","104%","33.0%"],["品川","61","72%","19.8%"]]},
  "after":{"title":"データバー＋アイコン＋背景色","tone":"good",
    "head":["店舗","売上（バー）","前年比","粗利率"],
    "rows":[["新宿","!████████ 182","▲ 112%","31.2%"],["渋谷","!██████ 146","▼ 98%","28.4%"],["池袋","!█████ 131","▼ 87%","24.1%"],["上野","!████ 98","▲ 104%","33.0%"],["品川","!██ 61","!▼ 72%","19.8%"]]} }
```

条件付き書式は、表の書式ペイン →**「セル要素」**（またはフィールドの右クリック →「条件付き書式」）から設定します。使えるのは 4 種類です。

```figure
{ "type":"cards", "cols":2, "title":"条件付き書式の4種類と使い分け",
  "caption":"何を読み取らせたいかで選ぶ。全部を同時に使ってはいけない",
  "items":[
    {"icon":"🎨","title":"背景色","text":"ヒートマップ的に量を示す。列全体に適用すると強すぎるので、注目列1つに限定する。シーケンシャルパレットを使う","tone":"blue"},
    {"icon":"🔤","title":"フォントの色","text":"背景色より控えめ。負の値だけ色を変える用途に向く。コントラスト比に注意","tone":"green"},
    {"icon":"📊","title":"データバー","text":"セル内に横棒を描く。共通の基線から伸びるため、知覚精度が最も高い。量の比較にはこれが第一候補","tone":"amber"},
    {"icon":"🔺","title":"アイコン","text":"▲▼● などの記号。色覚に依存しない冗長符号化になる。閾値は3段階までに絞る","tone":"violet"} ] }
```

> [!DS] データサイエンス視点：表の中でも知覚精度の順序は変わらない
> 条件付き書式の 4 種類を Cleveland & McGill の順序に当てはめると、**データバー（共通軸上の長さ）＞ アイコン（形）＞ 背景色・フォント色（色の濃淡）** になります。色の濃淡は知覚精度の最下位です。したがって「どの店舗が何番目に大きいか」を読ませたいならデータバー、「異常な行がどこにあるかをざっと見つけさせたい」なら背景色、という使い分けになります。**背景色で順位を読ませようとするのは、最下位の符号化に最も難しい仕事をさせることです**。

> [!TIP] 実務のコツ
> 条件付き書式の「書式スタイル」には **グラデーション／ルール／フィールド値** の 3 つがあります。最も強力なのは**フィールド値**で、DAX メジャーが返した色コード（`"#C0492F"` のような文字列）をそのまま書式として使えます。「前年比が -10% を下回り、かつ売上が上位20%の店舗だけ赤」といった複合条件は、メジャーで書いてフィールド値で適用します。

```text
色_要対応 =
VAR 前年比 = DIVIDE([売上合計], [売上合計_前年])
VAR 規模大 = [売上合計] >= 100
RETURN
    IF( 前年比 < 0.9 && 規模大, "#C0492F", "#1F2933" )
```

## スモールマルチプル — 多系列を破綻させずに見せる

折れ線を 12 本重ねると読めなくなります（L0901）。解決策は、**小さな同じ形のグラフを格子状に並べる**ことです。これをスモールマルチプルと呼びます。

```figure
{ "type":"chart", "kind":"line", "title":"12系列を1枚に重ねた場合",
  "caption":"線が交差し、どの系列がどう動いたのか追えない。凡例との往復で読み手が消耗する",
  "categories":["1月","2月","3月","4月","5月","6月"],
  "series":[
    {"name":"新宿","values":[120,131,128,142,138,151],"tone":"blue"},
    {"name":"渋谷","values":[118,122,130,126,133,129],"tone":"green"},
    {"name":"池袋","values":[95,101,99,110,104,118],"tone":"amber"},
    {"name":"上野","values":[88,92,86,94,99,91],"tone":"pink"},
    {"name":"品川","values":[72,68,75,71,78,74],"tone":"violet"},
    {"name":"横浜","values":[131,128,140,136,145,149],"tone":"cyan"} ],
  "unit":"百万円" }
```

```figure
{ "type":"compare", "title":"スモールマルチプルの共通スケール",
  "caption":"軸をそろえるかどうかで、読み取れるものが変わる",
  "panels":[
    {"title":"各パネルで軸を自動調整","tone":"bad",
     "items":["すべてのパネルの線が同じくらいの高さになる","規模の違いが完全に消える","売上5億の店舗と売上5千万の店舗が同じに見える"],
     "note":"規模の比較ができない"},
    {"title":"全パネルで共通のY軸","tone":"good",
     "items":["規模の差がパネル間の高さの差として読める","形（トレンド）の比較も同時にできる","Cleveland & McGill の第2位『共通しない軸上の位置』が機能する"],
     "note":"推奨（既定でこうなる）"} ] }
```

> [!DS] データサイエンス視点：スモールマルチプルは Tufte の中心的な手法
> Edward Tufte はスモールマルチプル（small multiples）を「情報デザインにおける最も効果的な手法」と呼びました。理由は、**読み手が一度グラフの読み方を学習すれば、あとはパネルを目で走査するだけで比較が完了する**ことにあります。1 枚の複雑なグラフは読み方の学習コストが毎回かかりますが、同じ形の小さなグラフの反復は認知負荷がほぼゼロです。
>
> 実装上の絶対条件は **すべてのパネルで軸のスケールをそろえること**。軸が違えば、隣り合うパネルの高さの差が意味を失います。Power BI のスモールマルチプル機能は既定で共通スケールになりますが、書式ペインで個別スケールに変更できてしまうため、意図せず変えないよう注意します。

```figure
{ "type":"steps", "title":"スモールマルチプルの設定と設計",
  "caption":"視覚化ペインの『スモール マルチプル』フィールドウェルにカテゴリ列を入れるだけ",
  "items":[
    {"title":"1. 通常どおりビジュアルを作る","text":"折れ線グラフで、軸＝月、値＝売上 とする","tone":"blue"},
    {"title":"2. 『スモール マルチプル』に分割軸を入れる","text":"Dim_店舗[店舗名] をドラッグする","tone":"green"},
    {"title":"3. グリッドの行数・列数を決める","text":"書式ペイン → スモール マルチプル → レイアウト。3×4 程度までが実用の上限","tone":"amber"},
    {"title":"4. パネル数を絞る","text":"20枚を超えたら、上位N件に絞るか階層を上げる。全部見せる必要はない","tone":"violet"},
    {"title":"5. 並び順を意味のある順にする","text":"アルファベット順ではなく、売上降順・地域順など読み手の関心に沿った順にする","tone":"pink"} ] }
```

> [!TIP] 実務のコツ
> スモールマルチプルでは、各パネルのデータラベルと軸ラベルを**ほぼすべて省略**します。パネルが小さいためラベルは読めず、ノイズにしかなりません。残すのはパネルのタイトル（店舗名）と、左端・下端の軸だけです。これはデータインク比の考え方そのものです。

## スパークライン — 表の中に文脈を埋め込む

テーブル／マトリックスの列として、**セル内に小さな折れ線**を表示できます（視覚化ペインの「スパークラインの追加」）。

```figure
{ "type":"tablediff", "arrowLabel":"スパークラインを追加",
  "before":{"title":"当月の値だけ","tone":"neutral",
    "head":["店舗","当月売上","前年比"],
    "rows":[["新宿","182","112%"],["渋谷","146","98%"],["品川","61","72%"]]},
  "after":{"title":"6か月のトレンドを添える","tone":"good",
    "head":["店舗","6か月推移","当月売上","前年比"],
    "rows":[["新宿","!╱╱╱╱╱","182","112%"],["渋谷","!╲╱╲╱╲","146","98%"],["品川","!╲╲╲╲╲","!61","72%"]]} }
```

スパークラインが解決するのは「**当月の数字だけでは、それが良いのか悪いのか分からない**」という問題です。同じ 98% でも、下がり続けての 98% と、回復途上の 98% では意味がまったく違います。

> [!WARN] 注意
> スパークラインは 1 つのテーブルに **5 列まで**という上限があり、行数が多いと描画が重くなります。表全体が遅くなるようなら、上位 N 件に絞るか、別の集計ビジュアルに置き換えます。

## 小さな倍数と「異常を見つける」設計

密度の高いレポートの本当の目的は、**異常を見つけること**です。正常な値をすべて読ませる必要はありません。

```figure
{ "type":"chart", "kind":"hbar", "title":"前年比の偏差（異常検知の見せ方）",
  "caption":"100%を基線にした偏差で描くと、良い店舗と悪い店舗が左右に分かれる。ダイバージング配色の出番",
  "categories":["新宿","上野","渋谷","池袋","品川"],
  "series":[{"name":"前年比の偏差","values":[12,4,-2,-13,-28],"tone":"blue"}],
  "highlight":4, "unit":"pt" }
```

前年比 112%、104%、98%、87%、72% を並べるより、**基準からの差（+12, +4, -2, -13, -28）**として描くほうが異常が一瞬で見つかります。基線を 100% に置き換えるだけで、棒の向きが良し悪しを表すようになります。

> [!TIP] 実務のコツ
> Power BI では「基準線」（分析ペイン → 定数線）を引くか、差分のメジャーを作って棒グラフにします。差分メジャーのほうが強力で、条件付き書式やソートも効きます。目標比・前年比・予算比はすべてこの形に直せます。

## 理解度チェック

1. 店舗別売上のマトリックスで「どの店舗が大きいか」を素早く読ませたい。背景色のグラデーションとデータバーのどちらを選ぶべきか、理由とともに答えよ。
2. ツールチップページに重要な補足指標を置いたところ、スマホで見ている役員から「その数字が見当たらない」と言われた。原因と対処を述べよ。
3. 12 店舗の売上推移をスモールマルチプルで並べたが、どの店舗も同じような形に見えて規模の差が分からない。原因として考えられる設定と対処を述べよ。

<details>
<summary>解答の要点</summary>

1. **データバー**。データバーはセル内の共通基線から伸びる長さで量を表し、Cleveland & McGill の順序で上位に位置する。背景色の濃淡は同順序の最下位であり、順位の読み取りには不向き。背景色が適するのは「異常値のある領域をざっと見つける」用途に限られる。
2. 原因は**ツールチップがモバイル表示および PDF/PowerPoint 書き出しに含まれない**こと。ホバー操作自体がタッチ環境に存在しない。対処は、判断に必要な指標をツールチップから画面本体（KPI カードや表の列）に移すこと。ツールチップには「あると便利」な補足だけを残す。
3. **各パネルの Y 軸が個別スケールに設定されている**可能性が高い。個別スケールでは各パネルが自身の最大値に合わせて描画されるため、規模の差が消え、形だけが残る。対処は書式ペインでスモールマルチプルの軸を**共通スケール（既定）に戻す**こと。規模差と形の両方を同時に読ませたい場合、共通スケールは必須。

</details>

## 実務チェックリスト

- [ ] 条件付き書式は「量の比較＝データバー」「異常検知＝背景色」で使い分けた
- [ ] アイコンを併用し、色だけに意味を載せていない
- [ ] 複合条件はメジャー＋フィールド値で実装した
- [ ] マトリックスの小計が「合計の合計」でないことを理解し、必要なら非表示にした
- [ ] ツールチップページのキャンバス種類・ツールチップ許可・ページ非表示を設定した
- [ ] ツールチップにしかない情報が判断に必要になっていない
- [ ] スモールマルチプルの軸を共通スケールにした
- [ ] スモールマルチプルのパネル数を 20 枚以下に抑え、意味のある順に並べた
- [ ] 表の行数と列数が描画性能に見合っている
