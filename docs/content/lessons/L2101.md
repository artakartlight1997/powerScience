
| 層 | 主な利用者 | 頻度 | 指標数 | 求められる粒度 |
|---|---|---|---|---|
| 戦略 | 役員・事業責任者 | 月次 | 3〜5 | 集計値と傾向。明細は不要 |
| 戦術 | 部長・マネージャー | 週次 | 5〜10 | セグメント別。要因が追える |
| 運用 | 担当者 | 日次 | 1〜3 + リスト | 行単位。アクション可能 |

> [!TRAP] つまずきポイント
> **役員向けレポートに明細テーブルを載せる**のは頻出の失敗です。「念のため」の明細が細部の議論を誘発し、戦略的判断の時間を奪います。明細は**ドリルスルーの先**に置きます。

## 読者を具体的に書く

「営業部」は読者定義ではありません。読者は人物として書きます。

```text
読者A: 営業所長（全国40名）
  リテラシー: 中。Excelのピボットは使えるがDAXは知らない
  見る場所: 朝会の会議室モニターと移動中のスマホ
  見る頻度: 毎週月曜 8:30、所要3分
  決めること: 今週、どの案件に自分が同行するか
  現在の代替手段: 部下からのExcel報告（毎週2時間かかっている）
  成功の定義: 月曜の朝会でレポートだけを見て同行先が決まる

読者B: 営業企画（3名）
  リテラシー: 高。自分でモデルを触れる／見る頻度: 随時（PC）
  決めること: 施策の効果検証、次期予算配分の提案
  必要なもの: 明細へのアクセス、エクスポート、任意軸での分解
```

> [!TIP] 実務のコツ
> **「現在の代替手段」を必ず書く。** 「今2時間の作業が3分になる」と示せれば定着します。逆に現行より不便な点が1つでもあると、そこを理由に戻られます。

DAX で作った文字列をタイトルに設定すれば、フィルターに応じて主張が変わります。

```dax
ページタイトル =
VAR 差 = [売上合計] - [売上目標]
VAR 率 = DIVIDE( 差, [売上目標] )
RETURN
IF( ISBLANK( [売上合計] ), "対象期間のデータがありません",   -- 0行時の分岐は必須
    "売上は目標比 " & FORMAT( 率, "+0.0%;-0.0%" ) &
    "（" & FORMAT( ABS( 差 ) / 1000000, "#,0" ) & "百万円の" &
    IF( 差 >= 0, "超過", "不足" ) & "）" )
```

```figure
{"type":"cards","cols":2,"title":"情報設計が失敗する5類型と処方箋","caption":"どれも「設計を飛ばした」ことが原因","items":[

{"icon":"🪞","title":"データ構造の写し型","text":"テーブル構造がそのまま画面になっている。処方：読者の問いの順に並べ替える","tone":"bad"},

{"icon":"🧮","title":"自己満足型","text":"高度な分析を見せたいだけ。処方：読者が行動できる形に翻訳する","tone":"amber"},
```

移植依頼では、**移植版と設計版を並べて見せる**のが最も効きます。移植版は1時間で作れ、たいてい誰も選びません。

```text
【スコープ定義】営業所長向け週次レポート v1.0
含むもの:
  - 所属営業所の週次売上・粗利・案件進捗／前年同週比、目標比
  - 滞留案件リスト（14日以上動きのない案件）／担当者別の活動件数
含まないもの（v1では対応しない）:
  - 個人の評価に使える指標（人事利用は別途協議）
  - 見込み顧客のスコアリング（データ未整備のため v2 で検討）
  - リアルタイム更新（基幹システムの連携が日次のため日次更新）
  - Excelエクスポート（定着まで意図的に制限し、要望を蓄積する）
前提:
  - データは基幹システムから毎日 6:00 に更新される
  - 所長は自分の営業所のデータのみ閲覧可（RLS適用）
```

スコープを書かないと要望が無限に増えます。断らずに「v2候補リストに入れます」と受け止め、**リストを見える場所に置く**のが実務的です。

## 理解度チェック

1. 「全社の数字を全部見たい」を設計可能な要件に変換する質問を3つ。
2. 経営会議用に明細テーブルを置くべきでない理由と、明細が必要な場合の代替設計は。
3. 自分が作ったページタイトルを1つ「メッセージ型」に書き換えよ。できないなら何が足りないか。
