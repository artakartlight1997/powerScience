## 集合演算の3関数

`UNION` `EXCEPT` `INTERSECT` は、2つ以上のテーブルを集合として扱います。

```figure
{ "type":"cards", "cols":3, "title":"3つの集合演算",
  "items":[
    {"icon":"∪","title":"UNION","text":"両方の行を積み上げる。重複は削除されない","tone":"blue"},
    {"icon":"−","title":"EXCEPT","text":"第1引数にあって第2引数にない行を返す。差集合","tone":"amber"},
    {"icon":"∩","title":"INTERSECT","text":"両方に共通する行だけを返す。積集合","tone":"green"} ] }
```

### 列の対応ルール

3関数に共通する重要なルールがあります。

> [!WARN] 注意
> **列は「名前」ではなく「位置」で対応します。** 第1引数の1列目と第2引数の1列目が突き合わされます。列名が違っていてもエラーにならず、そのまま処理されます。列数が違う場合のみエラーになります。返る表の列名は、常に**第1引数の列名**になります。

```figure

  "before":{"title":"表A（1列目=顧客ID, 2列目=区分） / 表B（1列目=区分, 2列目=顧客ID）","tone":"bad","head":["表","1列目","2列目"],
    "rows":[["A","C001","法人"],["A","C002","個人"],["B","法人","C003"],["B","個人","C004"]]},
  "after":{"title":"UNION の結果（列名はAのもの・値は混ざる）","tone":"bad","head":["顧客ID","区分"],
    "rows":[["C001","法人"],["C002","個人"],["!法人","!C003"],["!個人","!C004"]]} }
```

エラーにならないまま壊れます。**必ず `SELECTCOLUMNS` で列の順序と名前を揃えてから渡してください。**

```dax
-- 列を明示的に揃える
統合リスト =
UNION(
    SELECTCOLUMNS( 表A, "ID", 表A[顧客ID], "区分", 表A[区分] ),
    SELECTCOLUMNS( 表B, "ID", 表B[顧客ID], "区分", 表B[区分] )
)
```

### UNION は重複を消さない


### EXCEPT で離脱顧客を求める

実務で最も使うのが EXCEPT です。

```dax
離脱顧客数 =
VAR LastYearCustomers =
    CALCULATETABLE(
        VALUES( Fact_売上[CustomerID] ),
        DATEADD( Dim_日付[Date], -1, YEAR )
    )
VAR ThisYearCustomers =
    VALUES( Fact_売上[CustomerID] )
VAR Churned = EXCEPT( LastYearCustomers, ThisYearCustomers )
RETURN
    COUNTROWS( Churned )
```

```dax

    VALUES( Dim_商品[Category] ),
    TOPN( 3, CALCULATETABLE( VALUES( Dim_商品[ProductName] ) ), [売上合計], DESC )
)
```

> [!WARN] 注意
> `CROSSJOIN` は行数が掛け算で増えます。顧客850人 × 商品1,200件 = 102万行になり、これを数式エンジンが実体化すると数百MBのメモリを消費します。**CROSSJOIN を書いたら必ず行数を口に出して見積もってください。**

## NATURALINNERJOIN と NATURALLEFTOUTERJOIN

同名の列で結合する関数です。仮想テーブル同士を突き合わせるときに使います。

```dax
-- 顧客ごとの売上と目標を、CustomerID で結合する
顧客別比較 =
NATURALINNERJOIN(
    SELECTCOLUMNS( 売上テーブル, "CustomerID", [CustomerID], "売上", [@売上] ),
    SELECTCOLUMNS( 目標テーブル, "CustomerID", [CustomerID], "目標", [@目標] )
)
```

> [!TRAP] つまずきポイント
> `NATURALINNERJOIN` は**同じ名前の列がないとエラー**になります。しかも、モデルの実テーブル同士だと「データ系列（データリネージ）」が一致していないと結合してくれません。実務では `SELECTCOLUMNS` で列名を揃えた仮想テーブル同士に使うのが安全です。

## データ系列（データリネージ）

TREATAS を理解する鍵がこの概念です。

> [!NOTE] 用語
> **データ系列（データリネージ）**とは、仮想テーブルの各列が「モデルのどの列に由来するか」という情報のことです。`VALUES( Dim_商品[Category] )` の列は `Dim_商品[Category]` という系列を持ちます。CALCULATE のフィルター引数として渡すと、この系列に従って対応する列にフィルターがかかります。

```figure
{ "type":"stack", "title":"データ系列が決めるフィルターの行き先",
  "caption":"SELECTCOLUMNS で作り直した列は系列を失う。TREATAS はその系列を人為的に付け替える関数である",
  "layers":[
    {"label":"TREATAS( 表, Fact_予算[Category] )","sub":"系列を Fact_予算[Category] に付け替える","tone":"violet"},
    {"label":"SELECTCOLUMNS( … , \"名前\", 式 )","sub":"式によっては系列が失われ、フィルターが効かなくなる","tone":"amber"},
    {"label":"VALUES( Dim_商品[Category] )","sub":"系列 = Dim_商品[Category]。そのままフィルターとして効く","tone":"blue"},
    {"label":"モデルの実列","sub":"すべての系列の出発点","tone":"gray"} ] }
```

> [!TRAP] つまずきポイント
> `SELECTCOLUMNS( Dim_商品, "Cat", Dim_商品[Category] )` は系列を保ちますが、`SELECTCOLUMNS( Dim_商品, "Cat", UPPER( Dim_商品[Category] ) )` のように式を挟むと系列が失われます。系列を失った表を CALCULATE のフィルター引数に渡しても**何も起きません**。エラーにもならないので発見が遅れます。この場合は TREATAS で明示的に系列を与えてください。

> [!DS] データサイエンス視点
> EXCEPT / INTERSECT / UNION は集合論の差集合・積集合・和集合そのものです。TREATAS は**セミジョイン**に相当します。「Bに存在するキーでAを絞る」という操作で、SQL では `WHERE a.key IN (SELECT key FROM b)` と書きます。結合してカラムを持ってくるのではなく、絞り込みだけを行うのがセミジョインの特徴で、これはデータを増やさないため実行計画上とても効率的です。

> [!EXAM] PL-300で問われる
> 「リレーションシップを作成せずに、別テーブルの値でフィルターしたい」という設問では `TREATAS` が正解になります。また「非アクティブなリレーションを一時的に使う」場合は `USERELATIONSHIP` であり、TREATAS とは別物です。**リレーションが存在するなら USERELATIONSHIP、存在しないなら TREATAS**と整理してください。

## 理解度チェック

**問1.** `UNION( 表A, 表B )` の結果で、2列目に本来1列目に入るはずの値が混ざっていました。原因は何ですか。

<details>
<summary>解答</summary>

UNION は**列名ではなく列の位置で対応する**ためです。表Aと表Bで列の並び順が異なっていると、エラーにならないまま値が混ざります。`SELECTCOLUMNS` で両方の列順と列名を明示的に揃えてから UNION に渡してください。
</details>

**問2.** 予算テーブル `Fact_予算` は月×カテゴリ粒度で、`Dim_商品` ともリレーションがありません。カテゴリ別ビジュアルで予算額を正しく表示するメジャーを書いてください。

<details>
<summary>解答</summary>

```dax
予算額 =
CALCULATE(
    SUM( Fact_予算[BudgetAmount] ),
    TREATAS( VALUES( Dim_商品[Category] ), Fact_予算[Category] )
)
```

`VALUES( Dim_商品[Category] )` は現在のビジュアルで選択されているカテゴリを返し、TREATAS がその値を `Fact_予算[Category]` へのフィルターとして適用します。日付でも絞りたければ、同じ形の TREATAS をもう1つ引数に追加します。
</details>

**問3.** `SELECTCOLUMNS( Dim_商品, "カテゴリ", UPPER( Dim_商品[Category] ) )` を CALCULATE のフィルター引数に渡しましたが、何も絞られませんでした。なぜですか。

<details>
<summary>解答</summary>

`UPPER()` を通したことで**データ系列が失われた**ためです。系列のない列はどのモデル列にも対応づけられないので、フィルターとして機能しません。エラーにならないのが厄介なところです。系列を与えたいなら `TREATAS( 表, Dim_商品[Category] )` で明示的に付け替えます。
</details>

## 実務チェックリスト

- [ ] UNION / EXCEPT / INTERSECT に渡す表の列順と列数を SELECTCOLUMNS で揃えた
- [ ] UNION の後に DISTINCT が必要かどうか（重複を許すか）判断した
- [ ] TREATAS を使う前に、物理リレーションや共通ディメンションで解決できないか検討した
- [ ] CROSSJOIN を使う箇所で、返る行数を掛け算で見積もった
- [ ] フィルター引数に渡す仮想テーブルのデータ系列が保たれているか確認した
- [ ] 新規・継続・離脱の顧客数が、合計の恒等式で検算できることを確認した
- [ ] 古いコードの CONTAINS ベースの仮想リレーションを TREATAS に置き換える計画を立てた
