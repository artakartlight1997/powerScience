## 顧客の動きを集合で表す

```dax
離脱顧客数 =
VAR LastYear =
    CALCULATETABLE( VALUES( Fact_売上[CustomerID] ), DATEADD( Dim_日付[Date], -1, YEAR ) )
VAR ThisYear = VALUES( Fact_売上[CustomerID] )
RETURN
    COUNTROWS( EXCEPT( LastYear, ThisYear ) )
```

## 理解度チェック

**問1.** `UNION( 表A, 表B )` の結果で、2列目に1列目の値が混ざりました。原因は。

<details>
<summary>解答</summary>

UNION は列名ではなく列の位置で対応するためです。`SELECTCOLUMNS` で両方の列順と列名を揃えてから渡します。
</details>

**問2.** 月×カテゴリ粒度でリレーションのない `Fact_予算` から、カテゴリ別の予算額を出すメジャーは。

<details>
<summary>解答</summary>

`CALCULATE( SUM( Fact_予算[BudgetAmount] ), TREATAS( … ) )` の形にします。
TREATAS の第1引数は `VALUES( Dim_商品[Category] )`、第2引数は `Fact_予算[Category]` です。
</details>

**問3.** `SELECTCOLUMNS( Dim_商品, "カテゴリ", UPPER( Dim_商品[Category] ) )` をフィルター引数に渡しても絞られません。なぜ。

<details>
<summary>解答</summary>

`UPPER()` を通したことでデータ系列が失われたためです。系列のない列はどのモデル列にも対応せず、エラーも出ません。
</details>

## 実務チェックリスト

- [ ] UNION / EXCEPT / INTERSECT に渡す表の列順と列数を揃えた
- [ ] UNION の後に DISTINCT が必要かどうか判断した
- [ ] TREATAS の前に、物理リレーションで解決できないか検討した
- [ ] CROSSJOIN の返る行数を掛け算で見積もった
- [ ] フィルター引数に渡す仮想テーブルの系列が保たれているか確認した
- [ ] 新規・継続・離脱の顧客数を恒等式で検算した
