KPIが30個並んだレポートを見た経営会議で、決まることは何もありません。指標が多いということは、**優先順位を決める作業を放棄した**ということだからです。

プロがやるべきことは、指標を集めることではなく、**事業を数式に分解し、動かせる変数を特定する**ことです。

```figure

    {"title":"指標の羅列","tone":"bad",
     "items":["売上、粗利、客数、客単価、在庫回転、解約率…が並列に並ぶ","どれが原因でどれが結果か分からない","全部が同時に赤になり、どこから手をつけるか決まらない","部門ごとに違う指標を主張して議論が終わらない"],

    {"title":"KPIツリー","tone":"good",

     "note":"打ち手が決まる"} ] }
```

## North Star Metric — 最上位に1つ置く

North Star Metric（北極星指標、NSM）とは、**その事業が顧客に届けている価値を最もよく表す単一の指標**です。組織全体がこの1つに向かうことで、部門最適を防ぎます。

```figure
{ "type":"stack", "title":"指標の3層構造", "caption":"上に行くほど数が少なく、下に行くほど日々動かせる",
  "layers":[
    {"label":"North Star Metric（1つ）","sub":"例：月間アクティブ配送件数／継続利用世帯数","tone":"pink"},
    {"label":"ドライバー指標（3〜5個）","sub":"NSMを構成する変数。部門が責任を持つ","tone":"amber"},
    {"label":"運用指標（各10個程度）","sub":"日々の活動量。現場が直接動かせる","tone":"green"} ] }
```

| 事業 | よくあるNSMの例 | なぜ売上ではないのか |
|---|---|---|
| ECサイト | 月間購入者数 | 売上は値引きでも作れるが、購入者数は価値提供の結果 |
| SaaS | 週次アクティブ利用組織数 | 契約数より、実際に使われているかが継続を決める |
| 小売 | 来店客数 × リピート率 | 短期の販促で売上は作れるが、来店習慣が事業の本体 |
| メディア | 継続的に読む読者数 | PVは煽り記事で増やせてしまう |

> [!DS] データサイエンス視点：Goodhartの法則
> 「**測定が目標になった瞬間、それは良い測定ではなくなる**」——これがGoodhartの法則です。コールセンターで「1件あたりの通話時間」を目標にすると、担当者は問題を解決せずに電話を切ります。数字は改善し、顧客満足は下がります。対策は3つ。**(1) 単一指標で評価しない**（品質指標とセットにする）、**(2) 指標の定義を頻繁に見直す**、**(3) 指標の背後にある目的を全員が理解している状態を作る**。KPI設計者は、その指標がどう「ハック」されうるかを、設計時に必ず想像してください。

## ユニットエコノミクス — 1単位あたりで考える

事業が持続可能かは、**顧客1人あたりの経済性**で判定します。

```figure
{ "type":"formula", "lang":"text", "title":"ユニットエコノミクスの基本式",
  "code":"LTV = 平均購入単価 × 粗利率 × 購入頻度 × 継続期間     判定：LTV ÷ CAC ≧ 3",
  "parts":[
    {"match":"LTV","label":"顧客生涯価値。1人の顧客が生涯にもたらす粗利","tone":"good"},
    {"match":"継続期間","label":"= 1 ÷ 解約率。解約率が半分になれば継続期間は2倍になる","tone":"amber"},
    {"match":"CAC","label":"顧客獲得コスト。広告費と営業人件費を獲得数で割る","tone":"bad"},
    {"match":"LTV ÷ CAC ≧ 3","label":"広く使われる健全性の目安。1を下回れば獲得するほど赤字","tone":"violet"} ] }
```

この式が強力なのは、**「解約率を下げる」と「単価を上げる」のどちらに投資すべきか**を計算で比較できる点です。継続期間は解約率の逆数なので、解約率5%→4%（1ポイント改善）だけで継続期間は20か月→25か月、LTVは25%増えます。同じ効果を単価で得るには25%の値上げが必要です。どちらが現実的かは明らかです。

> [!DS] データサイエンス視点：バランススコアカードとOKR
> KPIを財務指標だけで組むと、短期最適に陥ります。**バランススコアカード**は、(1)財務、(2)顧客、(3)業務プロセス、(4)学習と成長、の4視点で指標を配置し、因果の連鎖として捉える枠組みです。「学習と成長（従業員のスキル）が業務プロセスを改善し、それが顧客満足を高め、最終的に財務に表れる」という時間差のある因果を意識させます。**OKR**（Objectives and Key Results）は別の枠組みで、定性的な目標（O）に対し、達成を測る3つ程度の定量結果（KR）を紐づけます。KPIツリーが「事業構造の分解」であるのに対し、OKRは「期間内に集中する対象の宣言」です。**両方を混同しないこと**——全KPIをOKRにすると、集中という本来の目的が失われます。

## KPIを Power BI に実装する

```figure
{ "type":"steps", "title":"KPIツリーをモデルに落とす5手順", "caption":"設計した構造を、そのままモデルの構造にする",
  "items":[
    {"title":"1. 定義書を作る","text":"指標名・計算式・分子分母・除外条件・所有部署を1行ずつ確定する","tone":"blue"},
    {"title":"2. 目標テーブルを用意する","text":"指標×期間×組織の粒度で目標値を持つ。ファクトとして扱う","tone":"green"},
    {"title":"3. ベースメジャーを作る","text":"最小単位のメジャー（売上、客数）をまず定義し、それを組み合わせる","tone":"amber"},
    {"title":"4. 表示フォルダで階層化する","text":"メジャーをKPIツリーの階層に沿ったフォルダに整理する","tone":"violet"},
    {"title":"5. 説明欄に定義を書く","text":"各メジャーのdescriptionに定義書の内容を転記する","tone":"pink"} ] }
```

```dax
-- ベースメジャー（最小単位）
売上金額 = SUM( Fact_売上[売上金額] )
客数     = DISTINCTCOUNT( Fact_売上[会員ID] )

-- 分解メジャー（ツリーの構造をそのまま式にする）
客単価   = DIVIDE( [売上金額], [客数] )
買上点数 = DIVIDE( SUM( Fact_売上[数量] ), [レシート枚数] )
平均単価 = DIVIDE( [売上金額], SUM( Fact_売上[数量] ) )

-- 目標比（目標テーブルとの比較）
売上目標   = SUM( Fact_目標[目標金額] )
売上達成率 = DIVIDE( [売上金額], [売上目標] )
売上未達額 = [売上金額] - [売上目標]

-- 寄与度分析：客数と客単価のどちらが売上変動に効いたか
客数寄与 = ( [客数] - [客数_前年] ) * [客単価_前年]
単価寄与 = ( [客単価] - [客単価_前年] ) * [客数]
```

最後の2式は実務で非常に強力です。売上の前年差を**客数要因と単価要因に分解**でき、「売上が-82百万円、うち客数要因が-95百万円、単価要因が+13百万円」という説明ができます。

> [!TIP] 実務のコツ
> 寄与度分解では、要因の合計と実際の差が完全に一致しない場合があります（交互作用項の扱いによる）。差が小さければ「その他」として明示し、大きい場合は分解の方法を見直してください。**合計が合わない表を説明なしに出すと、そこだけが議論の的になります。**

## 目標値の作り方

KPIを決めても、目標値がなければ判断できません。目標の置き方には型があります。

```figure
{ "type":"cards", "cols":2, "title":"目標設定の4方式", "caption":"方式によって、達成/未達の意味が変わる",
  "items":[
    {"icon":"📈","title":"実績ベース","text":"前年比+8%など。現実的だが、構造的な問題を先送りしやすい","tone":"blue"},
    {"icon":"🧮","title":"積み上げ","text":"KPIツリーの末端から計算して合算。根拠が明確で、担当も決まる","tone":"good"},
    {"icon":"🎯","title":"トップダウン","text":"経営目標から逆算して配分。整合性はあるが、現場の納得を得る作業が必要","tone":"amber"},
    {"icon":"🌐","title":"ベンチマーク","text":"業界水準や社内他部門との比較。妥当性の検証に使う","tone":"violet"} ] }
```

実務では**積み上げとトップダウンの2方向から作り、差分を議論する**のが定石です。差分そのものが「何を新たにやる必要があるか」を示します。

```figure
{ "type":"chart", "kind":"bar", "title":"積み上げとトップダウンの差", "caption":"この280百万円のギャップが、新施策の必要量そのもの",
  "categories":["現状延長","積み上げ計画","経営目標"],
  "series":[{"name":"年間売上","values":[12400,13200,13480],"tone":"blue"}],
  "highlight":2, "unit":"百万円" }
```

> [!TIP] 実務のコツ
> 目標テーブルは**必ずデータとして持ってください**。Excelに置いたまま毎月手で更新すると、必ず食い違いが起きます。指標×期間×組織の3軸を持つファクトテーブルとしてモデルに読み込み、期中の目標修正も履歴として残す設計にします。「いつ、誰が、なぜ目標を変えたか」が追える状態は、後の効果測定で効いてきます。

## KPIの見直しサイクル

事業環境が変われば、正しいKPIも変わります。KPIツリーは**生き物として運用**します。

```figure
{ "type":"timeline", "title":"KPI運用の年間サイクル", "caption":"見直しの機会を制度として持つ",
  "items":[
    {"label":"期初","title":"ツリーと目標を確定","text":"関係者ワークショップでツリーを更新し、目標値を合意する","tone":"blue"},
    {"label":"月次","title":"実績レビュー","text":"どのノードが計画から乖離しているかを構造で確認","tone":"green"},
    {"label":"四半期","title":"先行指標の検証","text":"先行指標が本当に結果を予測できているか、相関を再確認","tone":"amber"},
    {"label":"半期","title":"ハックの点検","text":"指標が業務を歪めていないか。Goodhartの兆候を探す","tone":"pink"},
    {"label":"期末","title":"ツリーの再設計","text":"事業モデルの変化を反映。使われなかった指標を削除","tone":"violet"} ] }
```

> [!NOTE] 要点
> KPI設計は、技術ではなく**合意形成**の仕事です。数式そのものは中学生でも書けます。難しいのは、「この指標で評価される」と決まった瞬間に発生する利害の調整です。だからこそ、**関係者と一緒にツリーを描く**というプロセスに価値があります。作られた図より、作る過程で交わされた議論のほうが重要です。

## 理解度チェック

1. 「売上を10%伸ばしたい」という目標を、KPIツリーを使って具体的な行動計画に落とす手順を説明してください。
2. コールセンターで「平均通話時間の短縮」をKPIにしたところ、顧客満足度が下がりました。この現象の名前と、KPI設計の修正案を述べてください。
3. 営業部・経理部・経営企画で「売上」の定義が違うことが判明しました。取るべき対応を、統一以外の方法で説明してください。
