「合計が出ない」「日付でグループ化できない」「リレーションシップが引けない」。初心者が遭遇するトラブルの大半は、原因が1つに収束します。**データ型**です。

型はすべての後工程の前提です。型が正しければ集計もモデリングもタイムインテリジェンスも素直に動き、型が間違っていれば何をやってもうまくいきません。ここは丁寧に押さえます。

## 10進数と固定小数点数の違い

金額を扱うとき、この2つの選択が効いてきます。

> [!DS] 浮動小数点誤差はバグではなく仕様
> コンピュータは10進数の小数を2進数で表現しますが、0.1 のような値は2進数では循環小数になり、正確には表せません。これは Power BI 固有の問題ではなく、ほぼすべてのプログラミング言語で共通する性質です。金融システムが金額に整数（最小単位である「銭」や「セント」）や10進固定小数点型を使うのはこのためです。実務では次の3点を守れば十分です。**① 金額列は固定小数点数（通貨型）にする。② 等号での比較（`金額 = 100`）を避け、丸めてから比較する。③ 表示上の丸めと計算上の丸めを混同しない。**

## ロケール — 同じ文字列が違う日付になる

`03/04/2025` は3月4日でしょうか、4月3日でしょうか。答えは**設定次第**です。

```figure
{ "type": "tablediff", "arrowLabel": "ロケールで解釈が変わる",
  "before": {"title":"元の文字列","tone":"neutral",
    "head":["生データ"],
    "rows":[["03/04/2025"],["12/31/2025"],["1.234,56"]]},
  "after": {"title":"ロケールごとの解釈","tone":"amber",
```

この違いは**サイレントに壊れる**のが恐ろしい点です。エラーにならず、単に違う日付として取り込まれます。12日以降は変換エラーになるため気づけますが、1〜12日のデータは黙って入れ替わります。

> 最も確実な対策は、**元データを `YYYY-MM-DD` 形式（ISO 8601）で出してもらう**ことです。この形式は世界中どのロケールでも一意に解釈されます。このカリキュラムのCSVもすべてこの形式です。データ提供元と話ができる立場なら、まずここを揃えてもらってください。

## サンプルデータで型を決める

[sales.csv](data/sales.csv) の10列について、実際に型を決めてみます。判断の根拠まで含めて考えてください。

| 列 | 設定する型 | 理由 |
|---|---|---|
| OrderID | テキスト | キー。合計する意味がない |
| OrderDate | 日付 | 時系列分析の軸になる |
| ShipDate | 日付 | 受注日との差でリードタイムを計算できる |
| StoreID | テキスト | 名義尺度。storesとの結合キー |
| CustomerID | テキスト | 名義尺度。customersとの結合キー |
| ProductID | テキスト | 名義尺度。productsとの結合キー |
| Quantity | 整数 | 個数。小数はありえない |
| UnitPrice | 固定小数点数 | 金額。丸め誤差を避ける |
| Discount | 10進数 | 0〜1の比率。0.05のような値 |
| SalesAmount | 固定小数点数 | 金額。合計の対象 |

> 試験では「郵便番号が 0120 から 120 になってしまった。原因と対処は」といった実務的な問題が出ます。答えは「数値型として取り込まれたため先頭の0が失われた。テキスト型に変更して再取り込みする」です。**すでに0が失われた列を後からテキストに変えても0は戻らない**という点も重要です。取り込み時に正しい型を指定する必要があります。

## まとめ

- 型はすべての後工程の前提。合計・時系列分析・リレーションシップのすべてが型に依存する
- 「Any（ABC/123）」の列を残さない。全列に明示的な型を設定する
- リレーションシップを結ぶキー列は、両側で型が一致していなければならない
- **IDやコードはテキスト型**にする。尺度水準が名義・順序なら数値にしない
- 金額は固定小数点数（通貨型）が安全。10進数は浮動小数点誤差が蓄積しうる
- ロケールの違いで日付や小数点の解釈が変わる。サイレントに壊れるため最も危険
- ソースにはISO 8601形式（YYYY-MM-DD）を依頼するのが最善の対策
- 型（データの持ち方）と書式（見せ方）は別物
- 型変換は整形の最後に置き、自動生成のステップは意図を持って書き直す
- エラー行を削除する場合は、件数と理由を必ず記録する
