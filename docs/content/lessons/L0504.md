> [!NOTE]
> ピボット解除は「列見出しを、値に変換する」操作です。列見出しは **属性（Attribute）** 列に、セルの中身は **値（Value）** 列に入ります。この2列の名前は後から自由に変更できます（「月」「金額」など、業務の言葉にしてください）。

## 属性列を日付にする

ピボット解除の直後、属性列は `2025年1月` という**文字列**です。このままでは日付テーブルとつなげず、時系列の並べ替えも「10月・11月・1月・2月」という文字列順になります。

カスタム列で、その月の1日を表す `date` 型を作ります。

```m
// 「2025年1月」→ 2025/01/01 の date 型
= Table.AddColumn(
    前のステップ,
    "月初日",
    each #date(
        Number.FromText( Text.BeforeDelimiter([月], "年") ),
        Number.FromText( Text.BetweenDelimiters([月], "年", "月") ),
        1
    ),
    type date
  )
```

`Text.BeforeDelimiter` で「年」の前の `2025` を、`Text.BetweenDelimiters` で「年」と「月」の間の `1` を取り出し、`#date(年, 月, 日)` で日付を組み立てています。**文字列の形が決まっているなら、置換の連鎖より部品を取り出して組み立てるほうが確実**です。

> [!TRAP]
> 月の粒度のデータに日付を与えるとき、**必ず月初日（または月末日）に統一してください**。ある行は月初、ある行は月末、という状態になると、日付テーブルとの結合で月がずれます。月初日で統一しておけば、日付テーブル側の「年月」列と自然に対応します。

## 値がない場合の挙動

ピボット解除には、覚えておくべき仕様が1つあります。**元のセルが空（null）の組み合わせは、行として出力されません**。

```figure
{ "type": "tablediff", "arrowLabel": "null セルは行にならない",
  "before": {"title": "1月の衣料が空欄", "tone": "neutral",
    "head": ["店舗名", "カテゴリ", "2025年1月", "2025年2月"],
    "rows": [["新宿本店", "家電", "283192", "2497347"], ["新宿本店", "衣料", "!（空欄）", "2714341"]]},
  "after": {"title": "解除後：3行しか出ない", "tone": "amber",
    "head": ["店舗名", "カテゴリ", "月", "金額"],
    "rows": [["新宿本店", "家電", "2025年1月", "283192"], ["新宿本店", "家電", "2025年2月", "2497347"], ["新宿本店", "衣料", "2025年2月", "2714341"]]} }
```

「新宿本店・衣料・2025年1月」の行は存在しません。これは多くの場合ありがたい挙動です（存在しない売上の行を作らずに済む）。しかし「全店舗・全カテゴリ・全月の枠を必ず出したい」場合は、この仕様が問題になります。

その場合の対処は2つあります。

1. **ピボット解除の前に、null を 0 で埋める**（0 という売上実績があったことにする）
2. **モデル側で解決する**（日付テーブルとカテゴリテーブルを用意し、DAX で `+0` する）

BI としては 2 が正解です。**「データがない」と「0 だった」は違う情報**なので、データの段階で 0 に潰すべきではありません。表示上 0 にしたいなら、それはビジュアル側の仕事です。

> [!DS]
> 横持ちから縦持ちへの変換は、統計ソフトの世界では **wide-to-long 変換** と呼ばれ、R の `tidyr::pivot_longer`（旧 `gather`）、Python の `pandas.melt` が同じ役割を担います。逆の long-to-wide は `pivot_wider` / `pivot_table` です。用語は違っても操作は同一で、「列見出しに埋もれた変数を、値として1列に降ろす」という一点に集約されます。統計モデリングやグラフ描画のライブラリはほぼ例外なく long 形式を入力に取ります。Power BI も同じ側の道具です。

## 逆操作 — 列のピボット

**列のピボット（Pivot Column）** は、縦持ちを横持ちに戻す操作です。ピボット解除の逆ですが、使う場面はかなり限られます。

```m
// 「区分」列の値を列見出しに展開し、金額を合計する
= Table.Pivot(
    前のステップ,
    List.Distinct( 前のステップ[区分] ),
    "区分",
    "金額",
    List.Sum
  )
```

第5引数の `List.Sum` が**集計関数**です。ここが列のピボット最大の注意点になります。

> [!TRAP]
> 列のピボットで集計関数を指定しないと、同じ組み合わせの行が複数あったときに「**列に複数の値が含まれています**」というエラーが出ます。GUI の「詳細設定オプション」で「集計しない」を選んだ場合がこれです。ピボットは1セルに1値しか置けないので、複数行が来たらどう畳むかを必ず指定する必要があります。

列のピボットが正当に必要になるのは、次のような場面です。

| 場面 | 例 |
|---|---|
| 属性が縦に並んだ縦持ちマスタを、1行1エンティティに直す | `顧客ID / 項目名 / 値` の3列表を、顧客ごとの1行に展開する |
| ソース側が Key-Value 形式で吐いてくる | IoT やアンケートの生ログ |
| 外部システムへ横持ちで渡す必要がある | 連携ファイルの仕様が横持ち |

**「レポートで横に並べたいから」は理由になりません**。それはマトリクスビジュアルの仕事です。モデルは縦持ちのまま持ってください。

## ピボット解除の前に必ず確認すること

| 確認項目 | 理由 |
|---|---|
| 不要な行（小計・注釈）を落としたか | 解除後は行数が数倍になり、除去が面倒になる |
| 残す列（キー列）が確定しているか | 「その他の列のピボット解除」は残す列の指定がすべて |
| 解除対象の列の型が揃っているか | 数値とテキストが混在すると値列が any 型になる |
| 列見出しから日付を復元できるか | `1月` だけでは年が分からない。年の情報が別にあるか確認する |
| 結果の粒度を1文で言えるか | 「店舗 × カテゴリ × 月」のように宣言できるか |

ピボット解除は行数が大きく変わる操作なので、変換の前後で**合計金額が一致するか**を必ず確認します。

検算の手順は単純です。

1. 解除前のステップを選び、月の各列を選択してステータスバーの合計を控える
2. 解除後のステップで金額列の合計を見る
3. 一致しなければ、小計行の残留、null の扱い、対象列の選択ミスのいずれか

> [!TIP]
> 検算用に「行数のカウント」ステップを一時的に足すのも有効です。解除前が R 行 × 解除対象 C 列なら、解除後の行数は最大 R × C 行になります（null セルの分だけ少なくなる）。この数字が桁違いなら、どこかで対象列を取り違えています。**変換の前後で不変な量を1つ決めて監視する**のは、あらゆるデータ処理に通じる基本動作です。

## 理解度チェック

1. 「列のピボット解除」と「その他の列のピボット解除」で生成される M の違いを述べ、なぜ後者が推奨されるのかを、翌月データの例で説明してください。
2. ピボット解除後、`2025年1月` という文字列の属性列を日付型にすべき理由を2つ挙げてください。月末日ではなく月初日に統一する利点は何ですか。
3. 元データのあるセルが空欄だった場合、ピボット解除の結果はどうなりますか。この挙動が問題になるのはどんな分析のときですか。

## よくあるエラーと対処

| 症状 | 原因 | 対処 |
|---|---|---|
