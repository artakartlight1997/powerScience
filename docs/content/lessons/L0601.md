
```m
// フラット表から商品ディメンションを切り出す
let
    ソース = フラット売上,
    商品列だけ = Table.SelectColumns(
        ソース, {"ProductID", "ProductName", "Category", "SubCategory", "StandardCost"}
    ),
    重複削除 = Table.Distinct(商品列だけ, {"ProductID"})
in
    重複削除
```

> [!TRAP] キー列を必ず指定する
> `Table.Distinct` を全列で実行すると、表記ゆれの重複が残る。同じIDが2行残ると多対多になり集計が壊れる。

## 理解度チェック

1. フラットテーブルの4問題のうち、容量以外の3つが分析を壊す理由を説明してください。
2. `Table.Distinct` でキー列を指定しないと、モデル上で何が起きますか。
3. 売上ファクトと予算ファクトを直結してはいけない理由と、正しい設計を述べてください。

## よくあるエラーと対処

| 症状 | 原因 | 対処 |
|---|---|---|
| モデルが重く更新が遅い | ファクトに文字列属性が残っている | 属性をディメンションへ移す |
| 売上0の商品が一覧に出ない | 商品情報をファクトから取っている | 軸を Dim_商品 の列に変える |
| 基数が多対多になる | ディメンションのキーに重複がある | キーで重複削除。粒度を見直す |
| テーブルが多すぎて使いにくい | スノーフレーク化しすぎ | ディメンションを1枚にまとめる |
| ファクト同士で数字が合わない | 粒度の違う表を直結した | 共有ディメンション経由に変える |
