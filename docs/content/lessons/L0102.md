「データはたくさんあるのに、何もわからない」。データ活用の相談で最も多い言葉です。この症状には必ず原因があり、しかもその原因は4か所のどこかに特定できます。

データが意思決定に変わるまでには階段があります。**DIKWモデル**（Data, Information, Knowledge, Wisdom の頭文字を取った、データが知恵に変わる過程を4段階で表すモデル）と呼ばれる整理を使うと、自分の職場が今どの段で止まっているかが見えます。

## 第1段：データ — 事実の記録

**データ**とは、加工されていない生の記録です。[sales.csv](data/sales.csv) の1行は次のようになっています。

```text
OrderID,OrderDate,ShipDate,StoreID,CustomerID,ProductID,Quantity,UnitPrice,Discount,SalesAmount
O000001,2024-01-01,2024-01-02,S005,C00448,P0027,1,1580,0,1580
```

この1行を見ても、経営判断は何もできません。しかしこの1行には、後で情報に変えるための材料がすべて含まれています。**いつ・どこで・誰が・何を・いくつ・いくらで**。この6要素が揃っていれば、ほぼどんな分析にも展開できます。

データの段で最も重要な概念が**粒度（granularity、1行が何を表すかの細かさ）**です。sales.csv の粒度は「1注文明細＝1行」です。粒度は後から粗くできますが、細かくすることは絶対にできません。

```figure
{ "type": "tablediff", "arrowLabel": "月×店舗で集約（不可逆）",
  "before": {"title":"明細粒度（元データ）","tone":"good",
    "head":["OrderID","OrderDate","StoreID","ProductID","SalesAmount"],
    "rows":[
      ["O000001","2024-01-01","S005","P0027","1580"],
      ["O000002","2024-01-01","S008","P0011","6980"],
      ["O000003","2024-01-02","S005","P0002","238000"]]},
  "after": {"title":"月次集約（軽いが情報は失われた）","tone":"amber",
    "head":["年月","StoreID","売上合計"],
    "rows":[
      ["2024-01","S005","!239580"],
      ["2024-01","S008","6980"]]} }
```

集約した後の表からは、「どの商品が売れたか」も「何日に売れたか」も二度と取り出せません。だから**データは可能な限り細かい粒度で保管する**のが原則です。集約は分析時にいつでもできます。

> [!DS] 尺度水準 — 数字なら何でも足せるわけではない
> 統計学では、データを4つの**尺度水準**に分けます。この区別を知らないと、平均してはいけないものを平均してしまいます。
>
> - **名義尺度**：区別だけ。StoreID、ProductID、Category。順序も計算も意味がない。「S005の平均」は無意味
> - **順序尺度**：順番に意味があるが間隔は不定。顧客セグメント（一般＜ゴールド＜プラチナ）、満足度の5段階。「満足度の平均3.7」は厳密には怪しい
> - **間隔尺度**：間隔が一定だが絶対的なゼロがない。気温、西暦。「20℃は10℃の2倍暑い」は誤り
> - **比率尺度**：絶対的なゼロがあり比も意味を持つ。売上金額、数量、単価。合計も平均も比率も自由に取れる
>
> 実務での注意は郵便番号や社員番号です。見た目は数字ですが名義尺度なので、**取り込むときはテキスト型にする**のが正解です（M04で扱います）。

**情報**とは、データを集約して「読める単位」にしたものです。6,948行を眺めても何もわかりませんが、月別に合計すれば24個の数字になり、人間が把握できます。

情報にするには、次の3つを決める必要があります。ここが曖昧なままだと、同じデータから違う数字が出てきます。


> 「先月の売上」と言われたとき、次の質問ができないと危険です。受注日基準か出荷日基準か。値引き後か前か。返品を含むか。税込か税抜か。sales.csv では `SalesAmount` が値引き後の金額ですが、これは**このデータの取り決め**であって世界共通ではありません。指標の定義は必ず文書化します（L0103で扱います）。

## 第3段：知識 — 比較して初めて意味が生まれる

「12月の売上は1,875万円でした」。この数字は情報ですが、まだ知識ではありません。良いのか悪いのかがわからないからです。

数字が意味を持つのは、**何かと比べたとき**だけです。比較の基準は主に4つあります。

```figure
{ "type": "cards", "cols": 4, "title": "4つの比較基準",
  "caption": "どれと比べるかで、同じ数字が「好調」にも「不調」にもなる",
  "items": [
    {"icon":"🎯","title":"目標と比べる","text":"予算・計画に対する達成率。最も行動につながりやすい。","tone":"good"},
    {"icon":"🕰","title":"過去と比べる","text":"前年同月比・前月比。季節性がある業種は必ず前年同月と比べる。","tone":"blue"},
    {"icon":"👥","title":"他と比べる","text":"他店舗・他カテゴリ・業界平均。相対的な位置がわかる。","tone":"violet"},
    {"icon":"📐","title":"基準値と比べる","text":"損益分岐点・在庫適正水準など、業務上の閾値。","tone":"amber"} ] }
```

```figure
{ "type": "compare", "title": "同じ「1,875万円」の2つの解釈",
  "caption": "比較基準を示さない報告は、報告ではなく朗読",
  "panels": [
    {"title":"前月比で見る","tone":"good","items":[
      "11月：1,517万円 → 12月：1,875万円",
      "前月比 +23.6%","「年末商戦が効いた。好調」"],
     "note":"短期の勢いがわかる"},
    {"title":"前年同月比で見る","tone":"amber","items":[
      "2024年12月：1,556万円 → 2025年12月：1,875万円",
      "前年同月比 +20.5%","「季節要因を除いても伸びている。本物」"],
     "note":"季節性を除いた実力がわかる"} ] }
```

12月は多くの小売業で最も売れる月です。だから前月比の +23.6% は「12月だから当たり前」かもしれません。前年同月と比べて初めて、季節要因ではない成長かどうかが判断できます。**季節性のある業種では、前年同月比が知識に変わる最短ルート**です。

> [!DS] 季節調整という考え方
> 時系列データは「トレンド（長期の傾向）」「季節変動（毎年繰り返す周期）」「不規則変動（ノイズ）」の3つに分解できると考えます。これを**時系列分解**といいます。前年同月比は、この季節変動を簡易に打ち消すための最も手軽な方法です。より厳密には移動平均や季節指数を使いますが、実務のBIでは「前年同月比」と「12か月移動平均」の2つで大半の判断がつきます。

> 絶対値（合計金額）だけを見ると規模の大きいものが常に上位に来ます。率（1店舗あたり、1顧客あたり、前年比）だけを見ると、母数の小さいものが極端な値を取って上位に来ます。**両方を並べて初めて、規模と効率の両面から判断できます。** 実務のダッシュボードでは、この2つを左右に並べるレイアウトが定番です。

> 「A店の成長率は300%です」という報告は、A店の売上が10万円から40万円になっただけかもしれません。率を見せられたら必ず分母（元の数値と件数）を聞く。これは資料を読む側の基本動作です。

## まとめ

- データ→情報→知識→意思決定という4段の階段があり、各段の間には集約・比較・行動設計という別々の操作がある
- データの段では**粒度**が決定的に重要。細かい粒度は後から粗くできるが、逆はできない
- 尺度水準（名義・順序・間隔・比率）を意識すると、平均してはいけない数字を平均せずに済む
- 情報にするには期間・切り口・集計方法の3つを決める必要がある
- 数字は比較して初めて知識になる。目標・過去・他者・基準値の4つが比較の軸
- 意思決定に変わる条件は「操作できる・時期がわかる・責任者がいる」の3つ
- データ量を増やす前に、答えたい問いを1つ決めるほうが早く価値が出る
