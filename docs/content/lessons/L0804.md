「このカテゴリは全体の何％か」
「この商品は売上順位で何位か」
「選択された店舗の中での構成比はどうか」

これらはすべて、**いま効いているフィルターを一度外さないと計算できません**。
分母が「全体」でなければ構成比になりませんし、順位は「他の商品」が見えていなければ決められません。

フィルターを外す関数は3つ。使い分けを間違えると、スライサーを動かした瞬間に数字が壊れます。

## ALL — すべて外す

`ALL` はテーブル関数です。引数の指定方法で、外す範囲が変わります。

```dax
ALL( Dim_商品 )                          -- Dim_商品 の全列のフィルターを外す
ALL( Dim_商品[Category] )                -- Category 列のフィルターだけ外す
ALL( Dim_商品[Category], Dim_商品[ProductName] )  -- 2列ぶん外す
ALL( Fact_売上 )                         -- ファクト全体のフィルターを外す（重い）
```

## ALLEXCEPT — 1つだけ残して外す

「同じカテゴリの中での構成比」を出したいときに使います。

```dax
-- カテゴリ内での商品構成比
カテゴリ内構成比 =
DIVIDE(
    [売上合計],
    CALCULATE( [売上合計], ALLEXCEPT( Dim_商品, Dim_商品[Category] ) )
)
```

`ALLEXCEPT( Dim_商品, Dim_商品[Category] )` は「`Dim_商品` のフィルターを全部外すが、`Category` だけは残す」という意味です。

## RANKX と「ALLを忘れる罠」

順位付けは、フィルター除去の理解を試す最良の題材です。

```dax
-- ✗ 全商品が1位になる
売上順位NG = RANKX( VALUES( Dim_商品[ProductName] ), [売上合計] )

-- ✓ 正しい
売上順位 = RANKX( ALL( Dim_商品[ProductName] ), [売上合計] )
```

ビジュアルの行に `ProductName` があるので、そのセルのコンテキストでは商品は1つに絞られています。
`VALUES` はその「絞られた状態の値」を返すため、比較相手が自分1人になり、必ず1位になります。
`ALL` で絞り込みを外すことで、初めて全商品と比較できます。

| ProductName | 売上合計 | 売上順位NG | 売上順位 |
|---|---|---|---|
| その他家電 | 30.5 | 1 | 1 |

> [!TRAP] 「順位が全部1位」を見たら ALL を疑う
> これはDAX学習者が100%通る道です。症状を見た瞬間に原因が言えるようにしてください。
> **順位付けは「比較相手の集合」を明示的に作る作業** であり、その集合を作るのが `ALL` です。

> [!DS] 順位付けの設計判断
> 順位には「同順位をどう扱うか」という設計判断が必ず伴います。
> `Skip`（1, 1, 3）は競技順位、`Dense`（1, 1, 2）は密な順位です。
> また、順位は **元の値の差の大きさを消してしまう** 指標でもあります。
> 1位と2位の差が0.1%でも100倍でも、順位はどちらも「1と2」です。
> 順位を提示するときは、必ず元の値も併記してください。

## ALL は「表」としても使える

`ALL` はフィルター引数だけでなく、反復関数の対象としても使えます。
「全商品を1つずつ見て、そのうち条件を満たすものを数える」といった処理で登場します。

```dax
-- 全商品のうち、売上が平均を上回る商品の数
平均超え商品数 =
VAR 平均売上 = AVERAGEX( ALL( Dim_商品[ProductName] ), [売上合計] )
RETURN
    COUNTROWS(
        FILTER(
            ALL( Dim_商品[ProductName] ),
            [売上合計] > 平均売上
        )
    )
```

このように、`ALL` は「比較のための母集団を作る関数」だと捉えると、
フィルター引数として使う場合も反復対象として使う場合も、同じ発想で書けます。

> [!WARN] ALL( テーブル ) と ALL( 列 ) は別物
> `ALL( Dim_商品 )` はテーブルの全行（全列の組み合わせ）を返し、`ALL( Dim_商品[Category] )` は
> カテゴリの一覧（重複なし）を返します。反復対象にする場合、前者は行数が多く重くなります。
> **必要な列だけを指定する**のが原則です。

## 理解度チェック

**問1.** スライサーで3カテゴリ中2つを選択している。構成比の合計行を100%にしたい。どの関数を使うか。

<details><summary>答え</summary>
`ALLSELECTED`。スライサーの選択を分母に残しつつ、ビジュアル内の行の条件だけを外すため、選択範囲の合計が100%になる。`ALL` を使うと分母が全データになり、合計は70%程度になる。
</details>

**問2.** `売上順位 = RANKX( VALUES( Dim_商品[ProductName] ), [売上合計] )` が全行1位になる理由を述べよ。

<details><summary>答え</summary>
ビジュアルの行に ProductName があるため、各セルでは商品が1つに絞られている。`VALUES` はその絞られた状態の値（1行）を返すので、比較相手が自分自身のみとなり、常に1位になる。`ALL( Dim_商品[ProductName] )` でフィルターを外し、全商品を比較集合にする必要がある。
</details>

**問3.** 「同じカテゴリの中での商品構成比」を出したい。どの関数を使い、どう書くか。

<details><summary>答え</summary>
`ALLEXCEPT` を使う。`DIVIDE( [売上合計], CALCULATE( [売上合計], ALLEXCEPT( Dim_商品, Dim_商品[Category] ) ) )`。Dim_商品 のフィルターをすべて外しつつ Category だけ残すため、分母がそのカテゴリ全体になる。
</details>

## よくあるエラーと原因

| 症状 | 原因 | 対処 |
|---|---|---|
| 順位が全行1になる | 比較集合のフィルターを外していない | `RANKX( ALL( 列 ), … )` にする |
| 構成比の合計が100%にならない | 分母に `ALL` を使い、スライサーで一部選択している | `ALLSELECTED` に変える（要件次第） |
| 構成比が全行100% | 分母のフィルター除去が効いていない | `CALCULATE` で包んでいるか確認する |
| `ALLSELECTED` の結果が予測できない | ネストや反復の中で使っている | `REMOVEFILTERS` で書けないか再検討する |
| メジャーが極端に遅い | `ALL( Fact_売上 )` でファクト全体を展開した | 必要な列だけ `ALL( 表[列] )` で指定する |
| `ALLEXCEPT` が効かない | 残す列の指定が別テーブルの列になっている | 第1引数の表に属する列を指定する |
| 順位に同順位が飛び飛びに出る | 既定の `Skip` 方式 | 第5引数に `Dense` を指定する |

> [!NOTE] このレッスンのまとめ
> フィルターを外すのは、**比較対象（分母・比較集合）を作る**ためです。
> `ALL` / `REMOVEFILTERS` は全体まで戻し、`ALLSELECTED` は利用者の選択を尊重し、`ALLEXCEPT` は上位階層だけ残します。
> 「分母は何か」を日本語で言えれば、関数は自動的に決まります。
> そして順位が全部1位になったら、比較集合に `ALL` を付け忘れています。
