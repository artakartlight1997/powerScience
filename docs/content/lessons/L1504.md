新規顧客が毎月1,000人増えている。素晴らしい成長に見えます。しかし同じ月に950人が離脱していたら、実質の成長は50人です。総顧客数のグラフはゆるやかに右肩上がりを描き、経営は好調だと信じ、マーケティング予算は新規獲得に投じられ続けます。バケツに穴が空いたまま、水を注ぐ量を増やしているのです。

顧客を「今月の合計」で見るかぎり、この穴は見えません。**顧客を獲得時期ごとの集団（コホート）で追い、時間経過とともに何%が残るかを見る**と、穴の大きさと位置が一目で分かります。

このレッスンでは、コホート分析・RFM・LTV・チャーンという顧客分析の4本柱を、Power Query と DAX の実装まで含めて扱います。

> [!DS]
> 顧客分析の中心にあるのは **「顧客を個人としてではなく、集団の振る舞いとして見る」** という発想です。1人の顧客が来月買うかは分かりませんが、「2024年1月に初回購入した5,000人のうち、6か月後も買っている割合」は安定して予測できます。個々はランダムでも、集団は法則に従う——これが統計的思考の核心です。

## コホート分析

**コホート**とは、同じ時期に同じ経験をした集団のことです。顧客分析では「初回購入月」でグループ分けするのが基本です。

### コホート表の構造

行に獲得月、列に経過月を取り、セルに残存率を入れます。

|---|---|---|---|---|---|---|---|
| 2024-01 | 1,200 | 100% | 42% | 31% | 27% | 25% | 24% |
| 2024-02 | 1,350 | 100% | 44% | 33% | 28% | 26% | 25% |
| 2024-03 | 1,180 | 100% | 41% | 30% | 26% | 25% | — |
| 2024-04 | 1,500 | 100% | 52% | 41% | 36% | — | — |
| 2024-05 | 1,610 | 100% | 55% | 44% | — | — | — |

> リテンションカーブで見るべきは3点です。**①最初の落ち込み（M0→M1）の深さ**、**②カーブが平らになる高さ**、**③コホート間でカーブが上下しているか**。②の平らになった高さが、その事業の「本当のファンの割合」です。ここがゼロに向かって下がり続ける事業は、永久に新規獲得を続けなければ縮小します。

### Power Query：初回購入月を付与する

```m
let
    ソース = Fact_売上,
    // 顧客ごとの初回購入日を求める
    グループ化 = Table.Group( ソース, {"顧客ID"},
        {{"初回購入日", each List.Min( [購入日] ), type date }} ),
    // 元表に結合して戻す
    結合 = Table.NestedJoin( ソース, {"顧客ID"}, グループ化, {"顧客ID"}, "初回", JoinKind.LeftOuter ),
    展開 = Table.ExpandTableColumn( 結合, "初回", {"初回購入日"}, {"初回購入日"} ),
    // コホート（初回購入月）と経過月数を計算
    コホート = Table.AddColumn( 展開, "コホート月",
        each Date.StartOfMonth( [初回購入日] ), type date ),
    経過月 = Table.AddColumn( コホート, "経過月",
        each ( Date.Year([購入日]) - Date.Year([初回購入日]) ) * 12
             + ( Date.Month([購入日]) - Date.Month([初回購入日]) ), Int64.Type )
in
    経過月
```

**この計算は Power Query 側で行うのが正解です。** 顧客ごとの初回購入日は事実として1つに定まるため、モデルに静的な列として持たせたほうがレポート実行時の負荷が下がります。

> [!TIP] 実務のコツ
> 初回購入日は `Dim_顧客` テーブルの属性列として持たせ、コホート月はそこから作った**独立したコホート用ディメンション**にします。ファクトに直接コホート月を持たせると、顧客が複数のコホートに属せてしまう事故（返品や再登録での再計算）が起きやすくなります。

### DAX：残存率メジャー

```dax
// 分子：この経過月に購入がある顧客数
コホート_残存顧客数 := DISTINCTCOUNT( Fact_売上[顧客ID] )

コホート_初期人数 :=
CALCULATE(
    DISTINCTCOUNT( Fact_売上[顧客ID] ),
    REMOVEFILTERS( Fact_売上[経過月] ),
    Fact_売上[経過月] = 0
)

コホート_残存率 := DIVIDE( [コホート_残存顧客数], [コホート_初期人数] )
```

> [!TRAP] 打ち切りデータを平均してはいけない
> 上のコホート表で「M3の平均残存率」を計算すると、M3のデータがある1〜3月のコホートしか含まれません。定着の良い4月以降のコホートは、まだM3に到達していないため除外されます。結果、**平均残存率は実態より低く出ます**。これが打ち切り（censoring）です。集計に含める前に、必ず「全コホートが到達している経過月までしか比較しない」という制約を掛けてください。Power BI では `IF( [コホート_初期人数] > 0 && [到達可能フラグ] = 1, [コホート_残存率] )` のように、未到達セルを明示的に空白にします。

顧客を3つの軸でスコア化し、打ち手を分けるための分類手法です。

```figure

```

### 四分位でスコアを付ける

閾値を勘で決めると、データが変わるたびに再調整が必要になります。**分位点で切る**と自動的に相対評価になります。

```dax
// R スコア（1〜5）：最終購入からの日数が短いほど高得点
顧客_最終購入日 := CALCULATE( MAX( Fact_売上[購入日] ), ALLEXCEPT( Dim_顧客, Dim_顧客[顧客ID] ) )

R値_日数 := DATEDIFF( [顧客_最終購入日], TODAY(), DAY )

Rスコア =
VAR 全顧客R =
    ADDCOLUMNS( ALL( Dim_顧客[顧客ID] ), "@R", [R値_日数] )
VAR P20 = PERCENTILEX.INC( 全顧客R, [@R], 0.2 )
VAR P40 = PERCENTILEX.INC( 全顧客R, [@R], 0.4 )
VAR P60 = PERCENTILEX.INC( 全顧客R, [@R], 0.6 )
VAR P80 = PERCENTILEX.INC( 全顧客R, [@R], 0.8 )
VAR MyR = [R値_日数]
RETURN
    SWITCH( TRUE(),
        MyR <= P20, 5,
        MyR <= P40, 4,
        MyR <= P60, 3,
        MyR <= P80, 2,
        1 )
```

F と M は逆向き（大きいほど高得点）なので、比較を反転させます。実装は計算列でもメジャーでも可能ですが、**セグメントでスライサーを切りたいなら計算列**にします。メジャーはスライサーに置けないからです。

```dax
// F スコア（計算列・値が大きいほど高得点）
Fスコア =
VAR MyF = CALCULATE( COUNTROWS( Fact_売上 ) )
VAR 全顧客F = ADDCOLUMNS( ALL( Dim_顧客[顧客ID] ), "@F", CALCULATE( COUNTROWS( Fact_売上 ) ) )
RETURN
    SWITCH( TRUE(),
        MyF >= PERCENTILEX.INC( 全顧客F, [@F], 0.8 ), 5,
        MyF >= PERCENTILEX.INC( 全顧客F, [@F], 0.6 ), 4,
        MyF >= PERCENTILEX.INC( 全顧客F, [@F], 0.4 ), 3,
        MyF >= PERCENTILEX.INC( 全顧客F, [@F], 0.2 ), 2,
        1 )
```

> M（金額）を単純な合計でスコア化すると、法人向けの1件の大型受注が全体の分位点を歪めます。L1501 で見たとおり購入金額は右に強く歪む分布です。**M は合計ではなく「1回あたり平均購入額の中央値」を使う**か、対数変換してからスコア化すると安定します。B2B と B2C が混在するデータでは、そもそも分けてスコア化してください。

## LTV（顧客生涯価値）

顧客1人が取引期間全体でもたらす利益の合計です。**獲得コストの上限を決めるための数字**であり、売上の予測値ではありません。

```figure
{ "type": "stack", "title": "LTVの3段階の精度", "layers": [
  {"label":"第3段階：割引・変動を織り込む","sub":"将来の利益を割引率で現在価値に換算。粗利率とチャーンの変化も考慮","tone":"pink"},
  {"label":"第2段階：粗利ベース","sub":"平均購入額 × 粗利率 × 購入頻度 ÷ チャーン率","tone":"amber"},
  {"label":"第1段階：売上ベース（単純式）","sub":"平均購入額 × 年間購入回数 × 平均継続年数","tone":"blue"} ],
  "caption": "第1段階で十分な場面は多い。ただし粗利率を無視すると、値引きで売上を作る施策が過大評価される。" }
```

### 基本式

```text
LTV = 平均購入額 × 粗利率 × 年間購入回数 ÷ 年間チャーン率
```

チャーン率で割るのは、**平均継続年数 = 1 ÷ チャーン率** という関係があるからです。年間チャーン率が20%なら、平均継続年数は5年です。

具体例：平均購入額8,000円、粗利率40%、年6回購入、年間チャーン率25%。

```text
LTV = 8,000 × 0.4 × 6 ÷ 0.25 = 76,800円
```

この顧客に **76,800円以上の獲得コスト（CAC）をかけると赤字**です。実務では LTV / CAC ≥ 3 を健全性の目安にします。つまり許容 CAC は約25,000円です。

### 割引を織り込む

5年先に得る1万円は、今の1万円と同じ価値ではありません。割引率 d を使って現在価値に直します。

```dax
LTV_割引後 :=
VAR 年間粗利 = [平均購入額] * [粗利率] * [年間購入回数]
VAR チャーン = [年間チャーン率]
VAR 割引率 = 0.1
RETURN
    DIVIDE( 年間粗利 * ( 1 - チャーン ), 1 + 割引率 - ( 1 - チャーン ) )
```

> [!DS]
> LTV には **過去実績ベース（historical LTV）** と **予測ベース（predictive LTV）** があります。前者は「すでに離脱した顧客が実際にいくら使ったか」の集計で、確実ですが遅い。後者は現在の顧客の将来を推定するもので、意思決定に使えますが仮定が必要です。**過去実績ベースの LTV を、まだ在籍中の顧客も含めて計算すると、必ず過小評価になります**（打ち切りのため）。どちらを計算しているのかを、必ずレポートに明記してください。

```dax
// 非契約型のチャーン判定（計算列）

VAR 最終購入 = CALCULATE( MAX( Fact_売上[購入日] ), ALLEXCEPT( Dim_顧客, Dim_顧客[顧客ID] ) )
RETURN
    IF( DATEDIFF( 最終購入, TODAY(), DAY ) > 120, 1, 0 )
```

> [!TRAP] 分母の取り方でチャーン率は変わる
> 期首1,000人、期中に500人の新規、期末に解約が150人。チャーン率は何%でしょうか。
> - 期首基準：150 ÷ 1,000 = **15.0%**
> - 期首+新規基準：150 ÷ 1,500 = **10.0%**
> - 平均在籍基準：150 ÷ 1,250 = **12.0%**
> どれも間違いではありません。**間違いは、定義を書かずに数字だけを報告すること**です。前月と比較する際に定義が変わっていないかも必ず確認してください。成長期の企業では、分母に新規を含めるとチャーン率が実態より低く出ます。

## 顧客数の増減を分解する

「今月の顧客数は先月比 +30人」の中身は、新規・復活・離脱の3成分です。差分だけを見ていると、何が起きているか分かりません。

```figure

  "series": [

    {"name":"離脱","values":[-1310,-1420,-1590,-1680,-1760,-1830],"tone":"bad"} ],
  "unit": "人",
  "caption": "純増は 400 → 430 → 250 → 95 → 0 → −90。総顧客数のグラフでは6月まで好調に見えるが、離脱が静かに膨らんでいる。" }
```

```dax
新規顧客数 :=
CALCULATE(
    DISTINCTCOUNT( Fact_売上[顧客ID] ),
    FILTER( VALUES( Dim_顧客[初回購入月] ), Dim_顧客[初回購入月] = MAX( Dim_日付[年月] ) )
)

復活顧客数 :=
VAR 当月 = VALUES( Fact_売上[顧客ID] )
VAR 前月 = CALCULATETABLE( VALUES( Fact_売上[顧客ID] ), DATEADD( Dim_日付[日付], -1, MONTH ) )
RETURN
    COUNTROWS( EXCEPT( 当月, 前月 ) ) - [新規顧客数]
```

> [!WARN] 注意
> 「復活」を新規と混ぜて数えると、獲得コストの評価が壊れます。復活顧客は広告費をほとんど使わずに戻ってきた顧客なので、獲得チャネル別 CAC の分母から除外してください。逆に、復活が多い事業では**離脱を「永久の別れ」と考えないほうが正確**です。

> [!TRAP] 生存者バイアスは顧客分析の常在菌
> 「優良顧客の特徴を分析したら、初回購入額が高い人が多かった。だから初回に高額商品を勧めよう」——この結論は危険です。優良顧客になれた人だけを見ているため、**初回に高額商品を買って、その後まったく戻らなかった大量の顧客**が視界から消えています。正しくは、初回購入額の帯ごとに全員を分母にした定着率を比較します。分析対象を「成功者」に絞った瞬間、その分析からは因果を読み取れなくなります。

## まとめ

- 顧客は合計ではなくコホート（獲得時期の集団）で追う
- リテンションカーブは ①最初の落ち込み ②平らになる高さ ③コホート間の差 を見る
- コホートのメジャーは「分母のフィルターを外して絞り直す」形になる
- 打ち切りデータを含めて平均すると、必ず実態より悪く出る
- RFM は分位点でスコア化する。閾値を勘で決めない
- M（金額）は歪むので、平均や対数変換で安定させる
- LTV = 平均購入額 × 粗利率 × 購入頻度 ÷ チャーン率。粗利率を落とさない
- チャーン率は定義（離脱の判定、分母）を必ず書く。書かない数字は比較できない
