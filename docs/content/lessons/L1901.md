Power BI は、単体の製品から **Microsoft Fabric の1ワークロード**になりました。

「名前が変わっただけ」と読むと選択肢を取り逃し、「全部Fabricに」と読むと不要な複雑さを抱えます。必要なのは地図です。

## 理解度チェック

1. Fabric の「共通基盤」を3つ挙げ、従来と何が変わったかを説明してください。
2. 「Fabricを導入すれば数字の不一致が解決する」という主張の誤りを指摘してください。
3. モデルにRLSを設定しても Fabric 環境では不十分になりうる理由を述べてください。

## よくあるエラーと対処

| 症状 | 原因 | 対処 |
|---|---|---|
| Fabricにしたのに混乱が広がった | 設計とガバナンスが未整備 | 基盤より先にM17・M18の設計を固める |
| Direct Lakeが期待外れ | 保管層（ゴールド層）が未整備 | 段階2のLakehouse構築から順に進める |
| 見せていない列に到達された | SQL分析エンドポイント経由 | 保管層のアクセス制御を別途設計する |
| 閲覧者のライセンス費が膨らむ | 配信規模から逆算していない | F64以上とProの総額を比較する |
| 議論が噛み合わない | 置き場所・処理・権限が混在 | どの軸の話かを聞き返して整理する |
