## ハルシネーションはなぜ起きるのか

生成AIは「もっともらしい続き」を生成します。存在しない関数、存在しない列、存在しない仕様を、**まったく同じ自信の強さ**で出力します。これがハルシネーション（もっともらしい嘘）です。

```figure
{ "type":"cards", "cols":2, "title":"BI業務で頻出するハルシネーション4類型", "caption":"どれも「動いてしまう」ことがあるのが厄介",
  "items":[
    {"icon":"🧾","title":"存在しない列を使う","text":"`Fact_売上[粗利額]` のように、あってもおかしくない名前を作る。実行するとエラーで気づける","tone":"amber"},
    {"icon":"🧮","title":"集計の粒度を間違える","text":"平均の平均、比率の合計。エラーにならず、数字だけ静かにずれる","tone":"bad"},
    {"icon":"📅","title":"期間の定義を勝手に決める","text":"「今期」を暦年か会計年度か確認せず片方に決める","tone":"bad"},
    {"icon":"📖","title":"仕様を捏造する","text":"「この機能はPower BIでサポートされています」と存在しない設定を説明する","tone":"amber"} ] }
```

最も危険なのは2番目です。エラーが出ないため、レビューを通り、経営会議まで到達します。

```dax
-- Copilot が出しがちな、動くが間違っている例
粗利率_誤 = AVERAGE( Fact_売上[粗利率] )      -- 行ごとの率を平均している

-- 正しい定義
粗利率 = DIVIDE( [売上総利益], [売上金額] )     -- 合計同士で割る
```

小口の取引が多いデータでは、この2つは平気で10ポイント以上ずれます。**比率は必ず「合計÷合計」で定義する**——この原則を知らない人がレビューすると、誤りは通過します。

> [!TRAP] つまずきポイント
> 「Copilotが書いたDAXなので大丈夫だと思った」は、事故報告書で最も多い一文になりつつあります。**生成物の責任は、常に提出した人にあります。** ツールが出力したという事実は、免責の理由になりません。

検証は「気をつける」ではなく、**手順**にします。手順にすれば、忙しい日でも品質が落ちません。

    {"title":"2. 既知の値で突き合わせる","text":"手計算できる小さな条件（1店舗×1日）で、正解が分かっている数字と一致するか確認","tone":"green"},
    {"title":"3. 境界を試す","text":"データが0行、分母が0、日付が期首/期末、空白を含む——この4条件で壊れないか","tone":"amber"},

## AIに強いドキュメントを書く

```figure

比率のため合計行は「合計÷合計」で再計算される。行の平均ではない。
```

この4文があるだけで、AIが式を提案するときの前提が固定され、人間のレビューも速くなります。**ドキュメントは、いまや人間だけでなくAIの入力仕様でもあります。**

> [!NOTE] 要点
> 生成AI時代のBI人材の差は「AIを使えるか」ではありません。**AIが良い出力を出せる環境（整ったモデル、明確な定義、検証手順）を作れるか**です。これは設計の仕事であり、AIには代替されません。
