経営会議でレポートが投影された瞬間、参加者は無意識に判定します。**「これは読む価値があるか」**——判定にかかる時間は5秒です。5秒で要点が伝わらなければ、その後の30分でどれだけ精緻な分析を用意していても、誰も見ません。

だから、ダッシュボードは**時間で情報を階層化**します。5秒・30秒・5分。この3層設計が、使われるレポートと使われないレポートを分けます。

```figure
{ "type":"stack", "title":"時間による情報階層", "caption":"上から下へ、読む人数は減り、情報の詳細度は上がる",
  "layers":[
    {"label":"5分：探索層","sub":"ドリルスルー・明細・ツールチップ／見るのは分析担当だけ","tone":"blue"},
    {"label":"30秒：説明層","sub":"推移・内訳・要因／担当者と管理職が見る","tone":"amber"},
    {"label":"5秒：結論層","sub":"最重要指標と目標差／全員が見る。ここで勝負が決まる","tone":"pink"} ] }
```

> [!NOTE] 要点
> 3層は**画面の上下**に対応します。上から順に「結論 → 説明 → 詳細」。この順序は新聞の逆ピラミッド構成と同じで、読み手がどこで読むのをやめても、その時点までで最も重要な情報が伝わっている状態を作ります。

```figure
     "note":"レポート単体では機能しない"},
```

```figure
     "note":"単体で判断できる"} ] }
```

> [!TIP] 実務のコツ
> Power BI の**KPIビジュアル**や**カード（新しいカード）**は、目標比と傾向を1つのビジュアルで表現できます。それでも足りない場合は、カードとスパークラインを重ねる構成が有効です。**「数字・比較・方向」の3点セットを1枚に収める**という原則さえ守れば、実現手段は何でも構いません。

### 目標値がない場合はどうするか

「目標が設定されていない指標」は5秒層に置けません。代替となる基準を必ず与えます。

| 状況 | 代替の基準 |
|---|---|
| 予算・目標がない | 前年同期比、前月比 |
| 季節変動が大きい | 前年同月比、または季節調整済みの値 |
| 新規事業で履歴がない | 計画値、または直近4週の移動平均からの乖離 |
| 比較対象が本質的にない | 管理限界（平均±2σ）を引き、範囲内か外かで判定 |

> [!TRAP] つまずきポイント
> 基準のない数字を大きく表示するのは、**読み手に判断を丸投げする行為**です。「1,240百万円」を見て良し悪しを判断できるのは、その事業を熟知した数人だけ。基準を添えないカードは、5秒層の場所を占領しているだけの飾りになります。

30秒層の役割は、5秒層で示した結論の**根拠と分解**を示すことです。

```figure
  "items":[
```

> 「売上が -82百万円」の内訳を示すには**ウォーターフォール（滝）グラフ**が最適です。前年からの増減を要因ごとに積み上げ、どの要素がどれだけ押し下げたかを一目で示せます。Power BI 標準ビジュアルにあり、分解の説明で最も費用対効果が高いビジュアルの1つです。

## 5分層：探索の導線を作る

すべてを画面に置く必要はありません。**深い情報は、探しに来た人にだけ見せます**。これをプログレッシブディスクロージャ（段階的開示）と呼びます。

```figure
{ "type":"tree", "title":"深掘りの導線設計", "caption":"入口は5秒層。出口は明細。経路を設計する",
  "root":{"label":"サマリーページ（5秒層）"},
  "children":[
    {"label":"ツールチップページ","sub":"ホバーで小さな詳細を表示","tone":"green",
     "children":[{"label":"用途","sub":"内訳ミニグラフ、定義の説明"}]},
    {"label":"ドリルダウン","sub":"階層を下る（年→四半期→月）","tone":"blue",
     "children":[{"label":"用途","sub":"同じ軸のより細かい粒度"}]},
    {"label":"ドリルスルー","sub":"別ページへ文脈を持って移動","tone":"amber",
     "children":[{"label":"用途","sub":"特定店舗・特定顧客の詳細ページ"}]},
    {"label":"ボタン＋ブックマーク","sub":"表示の切り替え","tone":"violet",
     "children":[{"label":"用途","sub":"グラフ/表の切替、フィルターのリセット"}]} ] }
```

| 手段 | 適する場面 | 注意点 |
|---|---|---|
| ツールチップページ | 補足情報を邪魔せず出す | モバイルでは効かない。必須情報は入れない |
| ドリルダウン | 同じ軸の階層を下る | 現在の階層位置が分かる表示を残す |
| ドリルスルー | 対象を1つに絞って詳細を見る | 「戻る」ボタンを必ず配置する |
| ブックマーク | 表示の切り替え、初期状態への復帰 | 数が増えると保守困難。10個を上限の目安に |

> [!TRAP] つまずきポイント
> **「どこをクリックすれば深掘りできるか分からない」**——これが探索層が使われない最大の理由です。ドリルスルーが設定されていても、右クリックが必要だと誰も気づきません。**明示的なボタンを置く**、**ツールチップに「右クリックで詳細」と書く**、**アイコンで示す**。導線は見えていなければ存在しないのと同じです。

## インタラクションの設計

```figure
{ "type":"compare", "title":"フィルター体験の設計", "caption":"「今どの条件で見ているか」が常に分かることが最低条件",
  "panels":[
    {"title":"よくある失敗","tone":"bad",
     "items":["スライサーがページごとに違う位置にある","選択状態が視覚的に分かりにくい","初期状態に戻す方法がない","相互作用の設定が既定のままで、意図しないフィルターがかかる"],
     "note":"利用者が迷子になる"},
    {"title":"整った設計","tone":"good",
     "items":["スライサーは全ページ左端に固定","選択中の条件をタイトルに動的表示","「条件をリセット」ボタンを常設","相互作用を1つずつ設計（強調表示かフィルターか）"],
     "note":"迷わず使える"} ] }
```

選択中の条件を明示するには、DAX でフィルター状態を文章化します。

```dax
現在の絞り込み =
VAR 地域 =
    IF(
        ISFILTERED( Dim_店舗[地域] ),
        CONCATENATEX( VALUES( Dim_店舗[地域] ), Dim_店舗[地域], "、" ),
        "全地域"
    )
VAR 期間 = MIN( Dim_日付[Date] ) & " 〜 " & MAX( Dim_日付[Date] )
RETURN
"対象：" & 地域 & "／期間：" & 期間
```

> [!DS] データサイエンス視点：プログレッシブディスクロージャと意思決定の速度
> 情報を一度に全部見せる設計は、**選択のパラドックス**（選択肢が多いほど決定が遅く、満足度が下がる現象）を直接引き起こします。段階的開示は、各段階での選択肢を絞ることで、意思決定を速く、そして質を高く保ちます。重要なのは「情報を隠している」のではなく「**必要になった順に提示している**」という点です。設計の説明を求められたら、この違いを明確に伝えてください。

## モバイルと表示速度

```figure
{ "type":"cards", "cols":2, "title":"見落とされがちな2つの設計要件", "caption":"どちらも「使われるか」に直結する",
  "items":[
    {"icon":"📱","title":"モバイルレイアウト","text":"営業所長がスマホで見るなら必須。縦1列、KPIカードを上に、タップ領域を大きく。ツールチップは効かない前提で設計する","tone":"blue"},
    {"icon":"⚡","title":"表示速度","text":"3秒を超えると離脱が始まる。ビジュアル数を減らす、既定のフィルターで対象を絞る、不要な相互作用を切る","tone":"amber"} ] }
```

表示速度は「性能の話」ではなく**デザインの話**です。1ページに20個のビジュアルを置けば、それだけクエリが走ります。ビジュアルを減らすことは、認知負荷と表示速度を同時に改善します。

> [!EXAM] PL-300で問われる
> レイアウトとインタラクションは頻出範囲です。**ドリルスルーの設定手順**、**ツールチップページの作成（ページサイズをツールチップに設定）**、**相互作用の編集（フィルター／強調表示／なし）**、**ブックマークとボタンによるナビゲーション**、**モバイルレイアウトの作成**。「特定の店舗の詳細を別ページで見せたい」→ドリルスルー、「グラフ上でホバーしたときに追加情報を出したい」→ツールチップページ、という対応で覚えてください。

### 5秒テストの実施手順

```text
【5秒テスト】所要10分・被験者3名

準備:
  レポートを画面に表示した状態で伏せておく

実施:
  1. 「これから5秒だけ画面を見せます」と伝える
  2. 5秒表示して隠す
  3. 次の3問を聞く（誘導しない）
     Q1: 何についてのレポートでしたか
     Q2: 状況は良いですか、悪いですか
     Q3: 目に残った数字を1つ挙げてください

判定:
  3名中2名がQ1〜Q3に正しく答えられれば合格
  答えられない場合の修正順序:
    Q1が答えられない → タイトルを主張型に書き換える
    Q2が答えられない → 5秒層に基準との差を追加する
    Q3が答えられない → 強調が分散している。色を1つに絞る
```

毎回ゼロから設計する必要はありません。用途ごとに使い回せる型が3つあります。

## 会議で投影される前提の設計

多くのレポートは、想定より**遠く・暗く・短時間**で見られます。

```figure
{ "type":"compare", "title":"作成環境と利用環境のギャップ", "caption":"自分のモニターで見た印象は、利用者の見え方ではない",
  "panels":[
    {"title":"作る人の環境","tone":"neutral",
     "items":["27インチのモニターを50cmの距離で見る","明るい室内、色再現の良い画面","時間の制約なく、自分で作ったので構造を知っている"],
     "note":"最良の条件"},
    {"title":"見る人の環境","tone":"bad",
     "items":["会議室のプロジェクター、5m離れた席","照明が明るく、コントラストが落ちる","初見、説明を聞きながら5秒で判断","または移動中のスマホ"],
     "note":"最悪の条件"} ] }
```

対策は具体的です。**最小フォントサイズを10pt以上にする**、**薄いグレー（#CCC以下）を細い文字に使わない**、**コントラスト比を4.5:1以上確保する**、**完成後に実際の会議室で1度投影して確認する**。最後の1つが最も効きます。

```figure

  "items":[
```

### 数値表示の細かいルール

最後に、見落とされがちだが効果の大きい表示ルールをまとめます。

| 項目 | ルール | 理由 |
|---|---|---|
| 桁数 | 有効数字3桁まで（1,240百万円、-6.2%） | 桁が多いほど読む時間が延び、精度の錯覚を生む |
| 単位 | ページ内で統一し、タイトルまたは軸に明記 | 単位変換は外在的認知負荷そのもの |
| 増減の符号 | 常に符号をつける（+2.1% / -6.2%） | 方向を読み取る手間をゼロにする |
| 桁区切り | 4桁以上は必ずカンマ区切り | 桁の読み違いを防ぐ |
| 空白 | 「0」と「データなし」を区別して表示 | 0円の売上と未計上は意味が違う |
| 日付 | 更新日時を必ずページ内に表示 | 古い数字で判断される事故を防ぐ |

これらは Power BI ではメジャーの書式設定とテーマで一括制御できます。ビジュアルごとに個別設定していると必ず崩れるので、**モデル側の書式設定を正とする**運用にしてください。
