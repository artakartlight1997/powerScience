経営会議で使われる指標は、ほとんどが時間の比較でできています。

- 「前年同月と比べてどうか」
- 「今年度の累計はいくらか」
- 「直近3か月の平均で見ると傾向はどうか」

ただし、**使える前提条件が厳格** です。そこを飛ばすと、関数は静かに空白を返します。

## 日付テーブルは必須

タイムインテリジェンス関数は、専用の日付テーブルがないと正しく動きません。
`Fact_売上[OrderDate]` を直接使うことはできません。

理由は単純です。**売上のない日が存在しないから**です。
2024年5月3日に取引が1件もなければ、ファクトにその日は存在せず、「連続した日付の並び」が作れません。

```dax
Dim_日付 =
ADDCOLUMNS(
    CALENDAR( DATE(2022,1,1), DATE(2025,12,31) ),
    "年",      YEAR( [Date] ),
    "月番号",  MONTH( [Date] ),
    "月名",    FORMAT( [Date], "M月" ),
    "年月",    FORMAT( [Date], "YYYY/MM" ),
    "四半期",  "Q" & ROUNDUP( MONTH( [Date] ) / 3, 0 ),
    "年度",    YEAR( EDATE( [Date], -3 ) )
)
```

`年度` の列は、4月始まりの会計年度を表します。3か月戻してから年を取ると、
4月〜翌3月が同じ年度としてまとまります。

> [!WARN] マークを忘れると静かに壊れる
> 「日付テーブルとしてマーク」を実行しないと、タイムインテリジェンス関数は
> **エラーを出さずに間違った値を返す**ことがあります。特に日付テーブルに時刻成分が混ざっている場合に顕著です。
> エラーが出ないぶん発見が遅れるので、**モデルを作ったら真っ先にマークする**習慣をつけてください。

## 移動平均で平滑化する

月次の売上は上下に振れます。傾向を見たいときは移動平均を使います。

```dax
売上3か月移動平均 =
AVERAGEX(
    DATESINPERIOD( Dim_日付[Date], MAX( Dim_日付[Date] ), -3, MONTH ),
    [売上合計]
)
```

> [!DS] 移動平均と季節性
> 移動平均は **平滑化** の手法で、短期の変動を抑えて傾向を見やすくします。
> ただし2つの副作用があります。(1) 直近の変化への反応が遅れる、(2) 期間の選び方で見え方が変わる。
> また、小売やBtoBの売上には強い **季節性**（曜日・月・四半期の周期的な変動）があります。
> 季節性がある系列では、移動平均より **前年同月比** のほうが素直に傾向を表すことが多くあります。
> 12か月移動平均を使えば季節性は概ね除去できますが、そのぶん反応はさらに鈍くなります。
> **どの手法にも「何を捨てて何を見るか」というトレードオフがある**ことを理解して選んでください。

## 前年比の表示を整える

```dax
前年比表示 =
VAR 当年 = [売上合計]
VAR 前年 = [前年売上]
RETURN
    SWITCH(
        TRUE(),
        ISBLANK( 前年 ),  BLANK(),          -- 前年データがない期間は空白
        前年 = 0,         BLANK(),          -- ゼロ除算を回避
        DIVIDE( 当年 - 前年, 前年 )
    )
```

> [!WARN] 前年が無い期間を0%と表示しない
> データの最初の年には前年がありません。ここで `0%` と表示すると「前年並み」に見えてしまいます。
> **前年が存在しない期間は空白**にするのが正しい扱いです（L0704の「0と欠測は違う」を思い出してください）。

> [!EXAM] PL-300で問われる
> 「タイムインテリジェンス関数が空白を返す原因」→ **日付テーブルが無い／マークされていない／期間が不完全**。
> 「会計年度が4月始まりの累計」→ `TOTALYTD( …, "3/31" )`。
> 「前年同期比のメジャー」→ `SAMEPERIODLASTYEAR` を使った `CALCULATE`。
> このモジュールで最も出題されやすい領域です。

## 理解度チェック

**問1.** `SAMEPERIODLASTYEAR` を使ったメジャーが全期間で空白を返す。考えられる原因を3つ挙げよ。

<details><summary>答え</summary>
(1) 日付テーブルが存在せず、ファクトの日付列を直接使っている。(2) 「日付テーブルとしてマーク」を実行していない。(3) 日付テーブルの期間が年単位で完結していない、または前年のデータ範囲を含んでいない。加えて、日付列に時刻成分が混ざっているケースもある。
</details>

**問2.** 2024年4月1日〜4月15日を選択している状態で、`DATEADD( Dim_日付[Date], -1, MONTH )` と `PARALLELPERIOD( Dim_日付[Date], -1, MONTH )` はそれぞれどの期間を返すか。

<details><summary>答え</summary>
`DATEADD` は 2024/3/1〜3/15（15日間、期間の長さを保つ）。`PARALLELPERIOD` は 2024/3/1〜3/31（3月全体）。月途中どうしの比較には `DATEADD` を使う。
</details>

**問3.** 4月始まりの会計年度で年度累計を出したい。どう書くか。また暦年で書いた場合との違いは。

<details><summary>答え</summary>
`TOTALYTD( [売上合計], Dim_日付[Date], "3/31" )`。暦年（既定）では1月にリセットされるが、年度指定では4月にリセットされる。日本企業の経営報告では年度版が必要になることが多い。
</details>

## よくあるエラーと原因

| 症状・エラー | 原因 | 対処 |
|---|---|---|
| すべて空白になる | 日付テーブルが無い／マークされていない | 日付テーブルを作りマークする |
| 一部の期間だけ空白 | 日付テーブルの範囲が不足 | 年単位で完結する範囲に広げる |
| 値がずれる | 日付列に時刻成分がある | 日付型に変換し、時刻を切り捨てる |
| 月が4月→8月→…と並ぶ | 月名列の並べ替え列が未設定 | 月名を月番号で並べ替える設定を行う |
| YTDが未来の月まで伸びる | 実績のない期間も評価されている | `IF( NOT ISBLANK( [売上合計] ), … )` で制御 |
| 年度累計が1月にリセットされる | 第3引数の年度末を指定していない | `TOTALYTD( …, "3/31" )` とする |
| 前年比が最初の年に0%と出る | 前年BLANKを0扱いしている | 前年がBLANKなら結果もBLANKにする |
| 週次の前年比が書けない | 標準関数に週の粒度がない | 日付テーブルに週番号を持たせ自前で書く |

> [!NOTE] このレッスンのまとめ
> タイムインテリジェンスの成否は、**日付テーブル**で9割決まります。連続・網羅・マークの3条件を必ず満たしてください。
> 前年比は `SAMEPERIODLASTYEAR`、累計は `TOTALYTD`（会計年度なら第3引数）、平滑化は `DATESINPERIOD` + `AVERAGEX`。
> そして前年データが存在しない期間は、0ではなく空白にする。
>
> ここまでで M08 は完了です。フィルターコンテキスト・行コンテキスト・CALCULATE・フィルター除去・時間比較——
> **実務のDAXで必要な道具は、すべて揃いました。**
