> [!WARN] マークを忘れると静かに壊れる
> マークしないと、エラーを出さずに誤った値を返します。モデルを作ったら真っ先にマークします。

> [!TRAP] 前年が無い期間を0%にしない
> 最初の年には前年がありません。0%は「前年並み」に見えます。BLANKのままにします。

> [!EXAM] PL-300で問われる
> 空白＝日付テーブルが無い／未マーク／期間が不完全。4月始まりの累計＝`TOTALYTD( …, "3/31" )`。

## 理解度チェック

**問1.** `SAMEPERIODLASTYEAR` が全期間で空白を返す。原因を3つ挙げよ。

<details><summary>答え</summary>
(1) 日付テーブルが無くファクトの日付列を使っている。(2) 日付テーブルとしてマークしていない。(3) 期間が年単位で完結していない、または前年を含まない。日付列の時刻成分も原因になる。
</details>

**問2.** 2024/4/1〜4/15 を選択中、`DATEADD( …, -1, MONTH )` と `PARALLELPERIOD( …, -1, MONTH )` は何を返すか。

<details><summary>答え</summary>
`DATEADD` は 2024/3/1〜3/15（15日間、長さを保つ）。`PARALLELPERIOD` は 2024/3/1〜3/31（3月全体）。月途中の比較には `DATEADD`。
</details>

**問3.** 4月始まりの会計年度で年度累計を出すには。暦年との違いは。

<details><summary>答え</summary>
`TOTALYTD( [売上合計], Dim_日付[Date], "3/31" )`。暦年は1月、年度指定は4月にリセットされる。
</details>

## よくあるエラーと原因

| 症状・エラー | 原因 | 対処 |
|---|---|---|
| すべて空白になる | 日付テーブルが無い／未マーク | 日付テーブルを作りマークする |
| 一部の期間だけ空白 | 日付テーブルの範囲が不足 | 年単位で完結する範囲に広げる |
| 値がずれる | 日付列に時刻成分がある | 日付型に変換し時刻を切り捨てる |
| 月が4月→8月→…と並ぶ | 並べ替え列が未設定 | 月名を月番号で並べ替える |
| YTDが未来の月まで伸びる | 実績のない期間も評価される | `IF( NOT ISBLANK( [売上合計] ), … )` |
| 年度累計が1月にリセット | 第3引数が未指定 | `TOTALYTD( …, "3/31" )` |
| 前年比が最初の年に0% | 前年BLANKを0扱い | 前年がBLANKなら結果もBLANK |
| 週次の前年比が書けない | 週の粒度の関数がない | 週番号を持たせ自前で書く |
