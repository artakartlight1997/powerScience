経営会議で出した数字が一度でも間違えば、そのレポートは二度と信用されません。

信頼は非対称です。積み上げに1年、失うのに1日。だから**定義・測定・契約**という仕組みで守ります。

> [!TRAP] つまずきポイント
> 怖いのはエラーで止まる事故ではなく、更新も表示も成功して数字だけが静かに狂う事故。

## 品質ルールをデータとして実装する

```dax
-- 完全性：必須項目の充足率
業種コード充足率 =
DIVIDE( CALCULATE( COUNTROWS( Dim_顧客 ), NOT ISBLANK( Dim_顧客[業種コード] ) ), COUNTROWS( Dim_顧客 ) )

-- 一貫性：Dimに存在しないキーを持つファクト行（参照整合性違反）
孤立行数 = CALCULATE( COUNTROWS( Fact_売上 ), ISBLANK( RELATED( Dim_顧客[顧客SK] ) ) )

-- 妥当性：想定範囲外の行
範囲外金額件数 = CALCULATE( COUNTROWS( Fact_売上 ),
    OR( Fact_売上[売上金額] < 0, Fact_売上[売上金額] > 100000000 ) )

-- 適時性：最新データの鮮度（時間）
データ鮮度_時間 = DATEDIFF( MAX( Fact_売上[更新日時] ), NOW(), HOUR )

-- 総合スコア（各次元を0〜1で評価し加重平均）
品質スコア =
VAR 完全性 = [業種コード充足率]
VAR 一貫性 = IF( [孤立行数] = 0, 1, 0 )
VAR 妥当性 = 1 - DIVIDE( [範囲外金額件数], COUNTROWS( Fact_売上 ) )
VAR 適時性 = IF( [データ鮮度_時間] <= 24, 1, 0 )
RETURN DIVIDE( 完全性 + 一貫性 + 妥当性 + 適時性, 4 )
```

## 理解度チェック

1. 更新は成功しているのに売上が2億円少ない。原因候補を3つ挙げ、確認順を答えてください。
2. 「静かに間違う」事故に最も関係する品質次元を2つ挙げ、測定方法を述べてください。
3. データ提供元に「今まで通りでいいのでは」と言われた。契約が双方に有益な理由は。
