## メジャーは表に何も増やさない

```dax

利益額合計 = SUMX( Fact_売上, Fact_売上[SalesAmount] - RELATED( Dim_商品[StandardCost] ) * Fact_売上[Quantity] )
```

> [!NOTE] 実務の原則
> **迷ったらメジャー。** 計算列は「メジャーでは無理」と説明できるときだけ使う。
> どうしても必要なら、行数の少ないディメンション側に作ります。

> [!DS] 比率の平均は、平均の比率ではない
> 比率どうしの単純平均は誤り。正しくは **分子の合計 ÷ 分母の合計**。
> 規模が違う集団を混ぜるほど差が開きます。BIに限らない鉄則です。

> [!EXAM] PL-300で問われる
> 「スライサーで絞り込めるように」→ **計算列**。
> 「複数ビジュアルで使い回す」「モデルを重くしない」→ **メジャー**。

## 理解度チェック

**問1.** 単価5,000円以上の取引をスライサーで選びたい。どちらで実装するか。

<details><summary>答え</summary>
計算列。スライサーに置けるのは列だけで、メジャーは置けないため。
</details>

**問2.** 利益率を計算列で作り「平均」集計したら全体と合わない。原因は。

<details><summary>答え</summary>
先に比率を出すと金額規模の重みが消えるため。分子と分母を集計してから割る。
</details>

**問3.** `売上NG = Fact_売上[SalesAmount]` がエラーになる理由は。

<details><summary>答え</summary>
メジャーの評価時に行コンテキストがなく、どの行の値か決まらないため。
</details>

## よくあるエラーと原因

| 症状・エラー | 原因 | 対処 |
|---|---|---|
| 1つの値が必要ですが複数の値が… | メジャー内で列を直接参照 | `SUM` などで包むか `SUMX` を使う |
| 計算列がスライサーに反応しない | 更新時に確定するため仕様 | 動的にしたいならメジャーにする |
| 比率の合計行がおかしい | 比率を計算列で作り合計・平均した | メジャーで集計してから割る |
| ファイルサイズが急に膨らんだ | ファクトに計算列を追加した | Power Query 側へ移すか代替する |
| 計算列で `RELATED` がエラー | リレーションが無い／方向が逆 | 多側から一側か確認。逆は `RELATEDTABLE` |
