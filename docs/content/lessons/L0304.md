    {"title":"4. 表示単位を整える","text":"書式設定（ペイントローラーのアイコン）→ 吹き出し値 → 表示単位を「百万」に、小数点以下を1桁に。276.0M ではなく 276.0百万 と読める形にする。","tone":"violet"},

同じ手順で、あと2つ作ります。

| カード | 使う列 | 集計方法 | 期待値 |
|---|---|---|---|
| 売上合計 | SalesAmount | 合計 | 276,029,967 |
| 注文件数 | OrderID | **個別カウント** | 6,948 |
| 平均注文額 | SalesAmount | 平均 | 39,728 |

> [!TRAP] 「カウント」と「個別カウント」は別物
> `OrderID` を単純な「カウント」にすると行数を数えます。1注文が複数行に分かれるデータでは、これは注文件数になりません。**重複を除いた件数を数えるのが「個別カウント（DistinctCount）」**です。sales.csvは1注文1行なので今回はどちらも6,948になりますが、実務データでは必ず食い違います。集計方法は毎回確認してください。

> [!DS] 平均だけのカードを置かない
> L0104で学んだとおり、この平均39,728円は中央値7,900円と大きく乖離しています。**平均のカードを1つだけ置くと、見る人は必ず誤解します。** 実務では「平均注文額」の隣に「中央値」または「注文件数」を並べ、分布の偏りに気づける構成にしてください。指標は単独ではなく、組み合わせで意味を持ちます。

## クロスフィルター — クリックすると他が反応する

Power BI の最大の特徴は、**ビジュアル同士が自動で連動する**ことです。棒グラフの1本をクリックすると、他のビジュアルがその条件で絞り込まれます。

```figure
{ "type": "pipeline", "title": "クリックの伝播",
  "caption": "クリック1つで、画面全体がその条件下の姿に変わる",
  "nodes": [
    {"id":"b","label":"横棒グラフ\nS001をクリック","tone":"amber"},
    {"id":"c","label":"KPIカード\nS001の売上に変わる","tone":"blue"},
    {"id":"l","label":"折れ線\nS001の推移に変わる","tone":"green"},
    {"id":"t","label":"テーブル\nS001の明細だけ表示","tone":"gray"} ],
  "edges": [
    {"from":"b","to":"c","label":"フィルター"},
    {"from":"b","to":"l","label":"フィルター"},
    {"from":"b","to":"t","label":"フィルター"} ] }
```

この挙動は**「書式 → 相互作用を編集」**で個別に変更できます。3つのモードがあります。

| モード | 挙動 | 使いどころ |
|---|---|---|
| フィルター | 該当データだけを表示する | 明細テーブル、折れ線 |
| ハイライト | 全体を残したまま該当部分を濃く表示 | 棒グラフ（全体との比較が保てる） |
| なし | 反応しない | KPIカードを常に全社値にしたいとき |

> [!TRAP] カードが勝手に変わって混乱する
> 「全社の売上」を表示したいKPIカードが、棒グラフのクリックで店舗別の値に変わってしまう。これはクロスフィルターが効いているためです。**相互作用を「なし」に設定する**ことで、常に全体値を表示できます。全体値と選択値を並べて見せると、レポートの説得力が上がります。

## まとめ

- ビジュアルは「種類を選んでからフィールドを置く」順序で作る
- カードは表示単位とタイトルを必ず設定する。単位のない数字は読めない
- 「カウント」と「個別カウント」は別物。注文件数は個別カウントで数える
- 平均のカードは単独で置かない。分布の偏りに気づける組み合わせにする
- 日付を月単位で見るには、Power Queryで月初日の列を作るのが軽くて確実
- 棒グラフは作ったその場で降順ソートする
- クロスフィルターは「フィルター/ハイライト/なし」の3モード。KPIカードは「なし」にすると全体値を保てる
- 装飾は引き算。データインク比を意識し、色は3〜4色に抑える
- 色だけに頼らず、代替テキストとタブ順序も設定する
