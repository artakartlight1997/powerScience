## ② 知覚精度 — Cleveland & McGill の順序

1984年、William Cleveland と Robert McGill は、人が量をどの符号化で最も正確に読み取れるかを実験で測定しました。結果は明確な順序として得られています。

```figure
{ "type":"chart", "kind":"hbar", "title":"符号化ごとの読み取り精度（順位）", "caption":"上ほど正確。棒グラフが強いのは「共通軸上の位置」を使うから",
  "categories":["共通軸上の位置","非共通軸上の位置","長さ","角度・傾き","面積","体積","色の濃さ","色相"],
  "series":[{"name":"精度","values":[100,88,80,66,52,38,28,15],"tone":"blue"}],
  "highlight":0, "unit":"相対値" }
```

| 順位 | 符号化 | 代表的なビジュアル | 実務での判断 |
|---|---|---|---|
| 1 | 共通軸上の位置 | 棒グラフ、ドットプロット、折れ線 | 量の比較は原則これ |
| 2 | 非共通軸上の位置 | 小さな倍数（スモールマルチプル） | 系列が多いときの第一選択 |
| 3 | 長さ | 積み上げ棒の各セグメント | 上限は2〜3系列まで |
| 4 | 角度・傾き | 円グラフ、折れ線の傾き | 円は2〜3分類まで |
| 5 | 面積 | バブル、ツリーマップ | 順序の把握用。値の比較には不向き |
| 6 | 体積 | 3Dグラフ | **使わない** |
| 7 | 色の濃さ | ヒートマップ、塗り分け地図 | 大まかな分布用 |
| 8 | 色相 | カテゴリ色分け | 量ではなく分類にのみ使う |

> [!NOTE] 要点
> **「棒グラフが地味だから円グラフにする」は、精度を4割落として見栄えを買う取引です。** この順序を知っていれば、ビジュアル選択の議論は10秒で終わります。

認知負荷とは、情報を理解するために消費される作業記憶の量です。3種類に分けて考えます。

外在的負荷を生む典型を挙げます。すべて実務でよく見るものです。

| 負荷の原因 | 読み手に起きること | 対処 |
|---|---|---|
| 凡例とグラフの往復 | 目線が何度も移動し、比較が中断される | 系列名をデータに直接ラベル付けする |

| 色の意味が場所ごとに違う | 「青は何だったか」を毎回思い出す | 色の意味をレポート全体で1つに固定 |
| 略語・社内コード | 意味を思い出す作業が発生する | 業務語に置き換える。無理なら凡例を近くに置く |

## 理論を Power BI の操作に落とす

ここまでの4層を、具体的な設定項目に翻訳します。**このリストがそのまま作業手順になります。**

| 理論 | Power BI での具体的操作 |
|---|---|
| 前注意的属性 | 条件付き書式（データの色）で強調1色＋グレー。フォント太さで見出しを差別化 |
| 知覚精度 | 量の比較は棒／ドット。円は2〜3分類のみ。3Dは使わない。ツリーマップは順位把握用 |
| 近接・囲み | ビジュアル間隔をグループ内8px／グループ間24px。シェイプの背景でセクションを囲む |
| 類同 | テーマファイル（JSON）で色を定義し、全レポートで意味を固定する |

> 出題は**アクセシビリティ**に集中します。**代替テキストの設定**、**タブ オーダーの設定**、**カラーブラインドフレンドリーな配色**、**テーマの適用による一貫性確保**、**フォーカスモードと表示形式**。特に「視覚に障害のある利用者のためにレポート作成者が行うべき設定」という問いでは、**代替テキストとタブオーダー**が正解になります。理論の理解があると、選択肢の意図が読めるようになります。
