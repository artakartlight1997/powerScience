アイスクリームの売上と、水難事故の件数には強い正の相関があります。相関係数は 0.9 を超えます。だからといって、アイスの販売を止めれば水難事故が減るわけではありません。両方とも「気温」という第三の要因に引きずられているだけです。

この例は笑い話として語られますが、実務のレポートでは同じ構造の主張が真顔で通ります。「メルマガを開封した顧客は購入率が3倍高い。だからメルマガを増やそう」——開封する人はもともと熱心な顧客です。メルマガが購入を生んだのか、購入意欲が開封を生んだのかは、このデータでは区別できません。

このレッスンでは、相関を正しく読む技術と、因果を主張する前に必ず点検すべき3つの罠を扱います。

> [!DS]
> **相関（correlation）** は2つの変数が一緒に動く度合い、**因果（causation）** は一方が他方を引き起こす関係です。相関は観察するだけで測れますが、因果は介入（実際に変えてみること）か、それに準じた設計がなければ主張できません。この非対称性が、データ分析という仕事の難しさの中心にあります。

### DAX で相関係数を計算する

Power BI の散布図には傾向線とR²の表示がありますが、相関係数そのものをカードに出したいことがあります。定義どおり書けます。

```dax
相関係数_広告費と売上 :=
VAR T =
    ADDCOLUMNS(
        VALUES( Dim_店舗[店舗ID] ),
        "@X", CALCULATE( SUM( Fact_月次[広告費] ) ),
        "@Y", CALCULATE( SUM( Fact_月次[売上] ) )
    )
VAR N  = COUNTROWS( T )
VAR MX = AVERAGEX( T, [@X] )
VAR MY = AVERAGEX( T, [@Y] )
VAR Cov = SUMX( T, ( [@X] - MX ) * ( [@Y] - MY ) )
VAR SX  = SQRT( SUMX( T, ( [@X] - MX ) ^ 2 ) )
VAR SY  = SQRT( SUMX( T, ( [@Y] - MY ) ^ 2 ) )
RETURN
    IF( N >= 3, DIVIDE( Cov, SX * SY ) )
```

```figure
{ "type": "formula", "lang": "dax",
  "code": "DIVIDE( Cov, SX * SY )",
  "parts": [
    {"match":"Cov","label":"共分散。2変数が同じ方向にずれる量の合計","tone":"amber"},
    {"match":"SX * SY","label":"各変数のばらつきの積。これで割ることで単位が消え、−1〜+1に収まる","tone":"blue"} ],
  "caption": "相関係数は「共分散を、それぞれのばらつきで正規化した値」。だから単位に依存しない。" }
```

> [!TRAP] 集約すると相関は水増しされる
> 個人1万人のデータで「学習時間と成績」の相関が 0.35 だったとします。同じデータを都道府県別に平均して47点で相関を計算すると、0.8 を超えることがあります。集約すると個人差というノイズが消え、残った傾向だけが強調されるからです。これを **エコロジカル相関** と呼びます。集約データで得た相関を、個人の話として語ってはいけません。「平均年収が高い県ほど平均寿命が長い」から「あなたの年収が上がれば長生きする」は導けません。

### 逆因果を疑う

「サポートへの問い合わせが多い顧客ほど解約率が低い」。ここから「問い合わせを増やそう」と考えるのは危険です。**解約する気の顧客は、そもそも問い合わせもしません**。関心を失った顧客は静かに去ります。因果の向きが逆かもしれない、と常に疑ってください。

### 交絡を図にする


交絡を疑う手順は決まっています。

1. 「この2つの両方に影響しそうな第三の変数」を列挙する（規模・地域・時期・顧客属性・担当者）
2. その変数で**層別**する（同じ規模の店だけで見る、同じ月だけで見る）
3. 層別しても関係が残るなら、その交絡は説明にならない

Power BI では、散布図に**スモールマルチプル**を設定して層別するのが最短です。フィールドの「小さな倍数」に店舗規模を入れるだけで、層別散布図が並びます。

> [!TIP] 実務のコツ
> **キーインフルエンサー ビジュアル** は、目的の変数（例：解約フラグ）に対して、どの属性がどれだけ効いているかを自動で並べます。ただしこれは相関にもとづくランキングであり、因果ではありません。「影響が大きい」という表示は「一緒に動いている」の意味だと読み替えてください。**分解ツリー** の「AI 分割」も同様です。仮説を探す道具であって、結論を出す道具ではありません。

## シンプソンのパラドックス

層別すると、全体で見た傾向が**すべての層で逆転する**ことがあります。これがシンプソンのパラドックスです。作り話ではなく、実データで普通に起きます。

ある会社が新しい研修プログラムの効果を検証しました。

**全体で見ると：新研修のほうが合格率が低い**

| | 受講者 | 合格 | 合格率 |
|---|---|---|---|
| 旧研修 | 400 | 220 | **55.0%** |
| 新研修 | 400 | 200 | **50.0%** |

新研修は失敗だった、という結論が出そうです。ところが、受講者の経験年数で層別すると景色が変わります。

**新人だけで見ると：新研修のほうが高い**

| | 受講者 | 合格 | 合格率 |
|---|---|---|---|
| 旧研修 | 100 | 30 | 30.0% |
| 新研修 | 300 | 105 | **35.0%** |

**ベテランだけで見ると：やはり新研修のほうが高い**

| | 受講者 | 合格 | 合格率 |
|---|---|---|---|
| 旧研修 | 300 | 190 | 63.3% |
| 新研修 | 100 | 95 | **95.0%** |

```figure
{ "type": "chart", "kind": "bar", "title": "シンプソンのパラドックス：層別すると逆転する",
  "categories": ["全体","新人のみ","ベテランのみ"],
  "series": [
    {"name":"旧研修 合格率","values":[55.0,30.0,63.3],"tone":"gray"},
    {"name":"新研修 合格率","values":[50.0,35.0,95.0],"tone":"blue"} ],
  "unit": "%",
  "caption": "全体では旧研修が勝つが、どちらの層でも新研修が勝つ。原因は「新研修に新人が偏って割り当てられた」こと。" }
```

からくりは受講者の構成です。新研修は受講者の75%が新人（そもそも合格しにくい層）、旧研修は75%がベテランでした。**層ごとの合格率ではなく、層の混ざり方の違いが、全体の数字を逆転させた**のです。

> [!TRAP] 全社集計を信じ切らない
> シンプソンのパラドックスが起きる条件は「グループごとに、比較したい2群の構成比が偏っている」ことだけです。実務では、地域別・チャネル別・商品カテゴリ別で構成比が偏るのはむしろ普通です。**全社の集計値で「A > B」と結論する前に、必ず主要な軸で層別して同じ向きになるかを確認してください。** 向きが変わったら、報告すべきは層別の結果です。

### Power BI での確認手順

```figure
{ "type": "steps", "title": "逆転が起きていないか確認する3手順", "items": [
  {"title":"比率メジャーと分母メジャーを両方作る","text":"合格率だけでなく、必ず受講者数（分母）も同じ表に置く。分母を見れば構成の偏りに気づける。","tone":"blue"},
  {"title":"主要な軸で層別する","text":"マトリックスの行に層（経験年数）、列に比較群（研修）を置き、比率と件数を並べる。","tone":"green"},
  {"title":"加重平均で全体に戻す","text":"層別の比率を、共通の構成比（標準人口）で重み付けし直す。これが標準化。","tone":"violet"} ] }
```

```dax
// 層構成を揃えて比較する（直接標準化）
合格率_標準化 :=
VAR 標準構成 =
    ADDCOLUMNS(
        VALUES( Dim_受講者[経験区分] ),
        "@w", CALCULATE( COUNTROWS( Fact_受講 ), REMOVEFILTERS( Dim_研修 ) )
    )
RETURN
    DIVIDE(
        SUMX( 標準構成, [@w] * CALCULATE( DIVIDE( [合格数], [受講者数] ) ) ),
        SUMX( 標準構成, [@w] )
    )
```

これは「もし新研修と旧研修の受講者構成が同じだったら、合格率はどうなったか」を計算するメジャーです。上の例で計算すると、新研修 **50.0% → 50.0%** ではなく、旧研修と同じ構成に揃えた新研修の合格率は **80.0%** となり、正しい比較ができます。

両方が時間とともに増えているだけで、相関係数は簡単に 0.9 を超えます。これを **見せかけの回帰（spurious regression）** と呼びます。

時系列どうしの関係を見たいときは、必ず次のどちらかを行います。

1. **差分を取る**：前期からの増減どうしで相関を見る（トレンドが消える）
2. **トレンドを除去する**：L1503 の時系列分解で残差を取り出し、残差どうしで相関を見る

```dax
// 前期差分どうしの相関を見るための下ごしらえ
売上_前期差 :=
VAR Cur = [売上合計]
VAR Prev = CALCULATE( [売上合計], DATEADD( Dim_日付[日付], -1, MONTH ) )
RETURN Cur - Prev
```

## 直線でない関係をどう測るか

ピアソンの r が低いのに散布図では明らかに関係がある、という場面では、順位に置き換えて測ります。

| 手法 | 測るもの | 使う場面 |
|---|---|---|
| ピアソンの相関係数 | 直線関係の強さ | 両方が数値で、関係が直線的 |
| スピアマンの順位相関 | 単調な関係の強さ | 曲線でも「増えれば増える」なら捉えられる。外れ値に強い |
| クラメールの V | カテゴリ同士の関連 | 「地域」と「解約有無」のような質的変数どうし |

スピアマンの順位相関は、**各変数を順位に置き換えてからピアソンの r を計算するだけ**です。DAX では `RANKX` で順位列を作り、同じ相関メジャーに通します。

```dax
店舗_売上順位 :=
RANKX( ALLSELECTED( Dim_店舗[店舗ID] ), CALCULATE( [売上合計] ), , ASC, DENSE )
```

> [!DS]
> 順位に置き換えると、外れ値の影響がほぼ消えます。1店舗だけ売上が10倍でも、順位では「1位」でしかないからです。**歪んだ分布を扱うなら順位相関のほうが正直**というのは、L1501 で中央値を選んだのと同じ発想です。ロバスト（頑健）な指標を選ぶ、という一貫した態度が分析者の基本姿勢になります。

## 報告の言葉づかい

因果が確認できていない段階では、言葉を正確に選びます。これは臆病さではなく、誠実さです。

| 使ってよい表現 | 避けるべき表現 |
|---|---|
| 「〜と関連がある」「〜と同時に増えている」 | 「〜が原因で」「〜によって増えた」 |
| 「〜の層で高い傾向がある」 | 「〜すれば上がる」 |
| 「交絡の可能性として規模が考えられる」 | （交絡に触れない） |
| 「効果の検証には実験が必要」 | 「効果は実証済み」 |

> [!EXAM] PL-300で問われる
> PL-300 では因果推論そのものは出ませんが、**3.5 データの探索と分析** と **3.6 AI ビジュアルの活用** で次が問われます。
> - 2つの数値の関係を見るビジュアル → **散布図**（傾向線・再生軸を追加できる）
> - 目的変数に効いている属性を探す → **キーインフルエンサー**
> - 値の増減を要因で分解する → **分解ツリー**（AI 分割は「高い値／低い値を探す」）
> - 異常な変動の説明を自動生成する → ビジュアルの**「増減の説明」（分析情報）**
> これらはすべて「探索の補助」であり、統計的な因果の証明ではないことも押さえておいてください。

## まとめ

- 相関係数は直線関係の強さだけを測る。散布図を見ずに r を語らない
- r が高い理由には、交絡・見せかけの回帰・外れ値・集約が含まれる
- 因果には共変・時間的先行・他の説明の排除の3つが必要
- 交絡は層別で点検する。Power BI ではスモールマルチプルが最短
- シンプソンのパラドックスは実データで普通に起きる。比率と一緒に必ず件数を出す
- 構成比の違いをならすには標準化（加重平均のやり直し）
- 「このデータから消えた人は誰か」を毎回問う
- 因果が示せない段階では「関連がある」と書く
