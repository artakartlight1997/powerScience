## 迷いやすい論点

| 迷う場面 | 判断 |
|---|---|
| Power Query か DAX か | できるなら Power Query |
| 計算列かメジャーか | 迷ったらメジャー。スライサーに置くなら計算列 |
| 双方向を使うか | 原則使わない。多対多のブリッジとRLS伝播だけ |
| 日付テーブルを複製するか | 最小限の労力なら `USERELATIONSHIP`。独立スライサーが要るなら複製 |
| DirectQuery かインポートか | 「常に最新」以外はインポート |
| 増分更新を使うか | 大きく・フォールディングが効き・日付列があるとき |
| スノーフレークのままか | 結合してスターに平坦化する |
| DATEADD か PARALLELPERIOD か | 同じ日数で比べるなら DATEADD、前月全体なら PARALLELPERIOD |

## まとめ

- 領域1・2で出題の半分以上。ここを◎にするのが最短ルート
- 接続方式は「常に最新＝DirectQuery、それ以外＝インポート」から入る
- 「将来の列にも対応」＝その他の列のピボット解除
- フォールディングを壊す操作は最後に置く。ネイティブクエリの表示で確認する
- スタースキーマ、1対多・単一方向が既定形
- 計算列とメジャーの違いは「いつ・何のコンテキストで評価されるか」
- `CALCULATE` は「外す→絞る」の順に読む
- RLS は Desktop で定義、Service で割り当て。複数ロールは OR
