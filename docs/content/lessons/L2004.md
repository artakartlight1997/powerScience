## Power Query での Python スクリプト

Power Query の変換ステップとして Python を挿入できます。入力は `dataset` という名前の pandas DataFrame として渡され、出力も DataFrame です。

```python
# Power Query の「Python スクリプトの実行」に貼るコード
# 入力: dataset（直前のステップの結果が pandas DataFrame として渡される）
import pandas as pd

# 顧客ごとの RFM 指標を作る
ref_date = dataset["受注日"].max()

rfm = (
    dataset.groupby("顧客ID")
    .agg(
        recency=("受注日", lambda s: (ref_date - s.max()).days),
        frequency=("受注番号", "nunique"),
        monetary=("売上金額", "sum"),
    )
    .reset_index()
)

# 出力: 変数名がそのままテーブル名になる
rfm_result = rfm
```

## Python / R ビジュアルの制約

Python ビジュアルは、選択したフィールドを DataFrame として受け取り、matplotlib で描画した**静止画**をレンダリングします。

```python
# Python ビジュアルのコード例
# dataset にはビジュアルにドラッグしたフィールドが入る（重複行は自動的に削除される点に注意）
import matplotlib.pyplot as plt

fig, ax = plt.subplots(figsize=(8, 5))
ax.scatter(dataset["広告費"], dataset["売上金額"], alpha=0.6)
ax.set_xlabel("広告費（千円）")
ax.set_ylabel("売上金額（千円）")
ax.set_title("広告費と売上の関係")
plt.tight_layout()
plt.show()
```

制約は多く、しかも重要です。

| 制約 | 内容 | 実務上の意味 |
|---|---|---|
| 行数の上限 | ビジュアルに渡るデータには上限がある（概ね15万行） | 明細をそのまま渡さず、事前に集計する |
| 重複行の除去 | 渡される DataFrame は重複行が削除される | 一意キーを1列含めないと分布が変わる |
| 実行時間の上限 | 一定時間で打ち切られる | 学習処理をビジュアル内で行わない |
| 出力は画像 | ツールチップ・ドリル・書式設定が効かない | 対話が必要ならネイティブビジュアルを使う |
| ライブラリ制限 | Service 側は許可されたパッケージのみ利用可 | 特殊なライブラリ依存の実装は避ける |
| 公開の制限 | 一部の公開・埋め込みシナリオで表示されない | 社外配布前に必ず表示確認する |

> [!WARN] 注意
> **重複行の自動削除**は最も見落とされる罠です。「価格」と「数量」の2列だけを渡すと、同じ組み合わせの行は1行に潰され、散布図の密度も回帰の結果も変わります。必ず**一意識別子となる列を1本追加**してください。

## よくある質問

**Q. Python を使えば DAX を書かなくて済みますか。**
いいえ。Python は取り込み時または表示時に固定の結果を作るだけで、**フィルターに反応して再計算されません**。スライサーを動かしたときに変わる数字は DAX の担当です。役割が違うので、置き換え関係にはなりません。

**Q. 相関係数や検定を出したいだけです。**
DAX でも計算できます。相関係数は `SUMX` を組み合わせれば書けますし、Power BI の散布図には傾向線があります。**「Python でしかできないか」を必ず先に確認**してください。1つの指標のために運用リスクを背負う必要はありません。

**Q. 予測を毎日更新したいのですが。**
外部でバッチ推論を日次実行し、結果テーブルを更新する構成にしてください。Power BI の更新スケジュールは推論の完了後に走るよう順序を設計します。順序が逆だと、**前日のスコアを今日の実績と並べる**という分かりにくい不整合が起きます。
