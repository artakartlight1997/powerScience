Power BI Desktop の画面は情報量が多く、初見では「どこを見ればいいか分からない」状態になります。しかし構造は単純です。**3つのビュー**を切り替えながら、**3つのペイン**を操作する。これだけです。

この地図を頭に入れると、以降の手順書が一度で読めるようになります。「データペインからフィールドをドラッグして、視覚化ペインのY軸に置く」という説明が、そのまま手の動きに変換できるようになります。

## 3つのペイン

レポートビューの右側には3つのペインが並びます。**右から左へ「素材 → 道具 → 絞り込み」**の順です。

```figure

  "items": [
    {"icon":"🗂","title":"データペイン（最も右）","text":"取り込んだテーブルと列の一覧。ここから列をドラッグして使う。「フィールド」と呼ばれることもある","tone":"blue"},
    {"icon":"🎨","title":"視覚化ペイン（中央）","text":"上半分でビジュアルの種類を選び、下半分でフィールドを配置する。書式設定タブもここ","tone":"violet"},
    {"icon":"🔽","title":"フィルターペイン（左）","text":"ビジュアル単位・ページ単位・レポート単位の3階層でデータを絞り込む","tone":"green"} ] }
```

### データペインのアイコンを読む

データペインの列名の左には小さなアイコンが付いており、その列の性質を表しています。**アイコンを読めるようになると、モデルの状態が一目で分かります。**

| アイコン | 意味 | 注意点 |
|---|---|---|
| Σ（シグマ） | 数値列。既定で合計される | ID列にΣが付いていたら型が誤っている |
| 📅（カレンダー） | 日付/時刻型 | これが付いていないとタイムインテリジェンスが使えない |
| 🌐（地球） | 地理データとして分類された列 | マップビジュアルで使える |
| 🧮（電卓） | メジャー | 計算列ではなくメジャー。表示のたびに再計算される |
| ⊞（階層） | 階層（例：年→四半期→月） | ドリルダウンに使える |

> [!TRAP] ID列にΣが付いていたら要注意
> `StoreID` が `S005` のような文字列ならテキスト型ですが、`ProductID` が数値だけの場合、Power BI は数値型として取り込みます。すると **ID列が合計されます。** 「商品IDの合計 145,832」という無意味な数字が表示されたら、この状態です。対処は M04 で扱う型変換（テキスト型にする）か、集計方法を「集計しない」に変えることです。

### 視覚化ペインのフィールドウェル

ビジュアルを選択すると、視覚化ペインの下半分に**フィールドウェル**（フィールドを置く枠）が現れます。どこに置くかで結果が変わります。

```figure
{ "type": "tablediff", "arrowLabel": "置く場所で結果が変わる",
  "before": {"title":"フィールドウェルの種類","tone":"neutral",
    "head":["枠の名前","置くもの"],
    "rows":[
      ["X軸 / Y軸","分類する軸と、集計する値"],
      ["凡例","系列を分ける列（色分けされる）"],
      ["小さい倍数","グラフ自体を複数に分割する列"],
      ["ツールヒント","ホバー時に追加表示する値"],
      ["ドリルスルー","別ページへ飛ぶときに引き継ぐ列"]]},
  "after": {"title":"同じ2列でも配置で別のグラフになる","tone":"good",
    "head":["配置","結果"],
    "rows":[
      ["X軸=月、Y軸=売上","!月別の推移が1本の線"],
      ["X軸=月、Y軸=売上、凡例=カテゴリ","!カテゴリ別に3本の線"],
      ["X軸=カテゴリ、Y軸=売上","!カテゴリ比較の棒グラフ"]]} }
```

**同じ列でも、置く場所を変えるだけで別の分析になります。** ここが Power BI の面白さであり、最初に体で覚えるべき感覚です。

## リボンの構成

| タブ | 主な機能 | 使う頻度 |
|---|---|---|
| ホーム | データを取得、更新、データの変換、新しいビジュアル | 非常に高い |
| 挿入 | テキストボックス、図形、画像、ボタン、新しいページ | 高い |
| モデリング | 新しいメジャー、新しい列、データカテゴリ、RLS管理 | 高い |
| 表示 | テーマ、ペインの表示/非表示、モバイルレイアウト | 中 |
| 最適化 | 一時停止/更新、パフォーマンスアナライザー | ティア3で使う |
| ヘルプ | バージョン情報、学習リソース | 低い |

> [!TIP] リボンの検索を使う
> リボン右上の検索ボックスに機能名を入力すると、該当のコマンドが直接出てきます。バージョンでメニュー位置が変わっても、**機能名さえ覚えていればたどり着けます。** 「どこにあるか」を暗記するより、「何という機能か」を覚えるほうが長持ちします。

## テーブルビューを使う本当の理由

テーブルビューは「地味な確認画面」に見えますが、**分析の品質を守る最後の砦**です。グラフだけを見ていると、データの異常を見逃します。

```figure
{ "type": "compare", "title": "テーブルビューで何を確認するか",
  "panels": [
    {"title":"グラフだけ見ていると気づかない","tone":"bad","items":[
      "日付が1900/1/1になっている行がある",
      "数量がマイナスの返品行が混ざっている",
      "同じ商品名が全角/半角で2種類ある",
      "取り込み行数が元ファイルと違う"],
     "note":"集計されると隠れる"},
    {"title":"テーブルビューで見えるもの","tone":"good","items":[
      "1行ずつの実際の値",
      "画面下部の行数表示で件数を検算できる",
      "列ヘッダーの絞り込みで異常値を探せる",
      "並べ替えで最大値・最小値をすぐ確認できる"],
     "note":"明細レベルの検証"} ] }
```

> [!DS] 集計値は真実を隠す — アンスコムの四重奏
> 統計学に**アンスコムの四重奏**という有名な例があります。4つのまったく違う形のデータセットが、平均・分散・相関係数・回帰直線のすべてでほぼ同一の値を示すというものです。片方は直線的な関係、片方は曲線、片方は外れ値1点で相関が作られている。**要約統計量だけを見ていては、データの本当の姿は分からない**という強烈な教訓です。BIの現場に翻訳すると、「合計値のカードだけを見て安心せず、明細と分布を必ず目視する」ということです。テーブルビューはそのための道具であり、L0104で学んだ分布の確認と同じ役割を果たします。

## まとめ

- 画面は「3つのビュー × 3つのペイン」で構成される。この地図があれば手順書が読める
- レポートビュー（作る）、テーブルビュー（確認する）、モデルビュー（繋ぐ）を往復する
- テーブルビューはインポート時のみ利用できる。DirectQuery/ライブ接続では表示されない
- データペインのアイコン（Σ・カレンダー・電卓）は列の性質を表す。ID列にΣが付いていたら型の誤り
- 同じ列でもフィールドウェルのどこに置くかで、まったく別の分析になる
- リボンの位置を暗記するより、検索ボックスで機能名を引くほうが確実
- 集計値だけでは異常は見えない。テーブルビューで明細を目視することが品質を守る
