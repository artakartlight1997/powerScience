[sales.csv](data/sales.csv) の6,948件の注文について、1注文あたりの平均金額を計算すると **39,728円** になります。この数字を見て「うちのお客様は平均4万円くらい使う」と考えると、施策は確実に失敗します。

同じデータの**中央値は7,900円**です。平均の5分の1です。どちらも計算は正しく、どちらも「代表的な値」と呼ばれます。この差がなぜ生まれ、どちらを使うべきなのか。それが分かると、数字の読み方が根本から変わります。

## 分布の形を見る

代表値だけを見るのをやめて、**分布**（値がどう散らばっているか）を見る習慣をつけます。実務で出会う分布は主に3つの形です。

```figure
{ "type": "cards", "cols": 3, "title": "実務でよく出会う分布の形",
  "items": [
    {"icon":"🔔","title":"左右対称（正規分布に近い）","text":"身長、製造品の寸法誤差。平均＝中央値。平均と標準偏差で語れる。","tone":"green"},
    {"icon":"📉","title":"右に歪んだ分布","text":"売上金額、所得、滞在時間、待ち時間。平均＞中央値。ビジネスデータの大半はこれ。","tone":"amber"},
    {"icon":"⛰","title":"二山（ふたやま）","text":"平日と休日、法人と個人が混ざっている。平均はどちらの山も表さない。分けて分析すべきサイン。","tone":"pink"} ] }
```

二山の分布は特に重要です。平均が2つの山の谷間に落ちるため、**平均が「実在しない値」になります。** 通販サイトで「平均滞在時間3分」と出たとき、実際は「10秒で離脱する人」と「10分見る人」の混合かもしれません。この場合、やるべきことは平均の改善ではなく、2つの群を分けて分析することです。

> [!DS] 平均が意味を持つ条件
> 平均が「代表値」として機能するのは、分布が単峰（山が1つ）でおおむね対称なときだけです。売上・所得・アクセス数といったビジネスデータの多くは右に歪んだ分布（対数正規分布に近い形）を取ります。この場合、**対数を取ると左右対称に近づく**ため、統計解析では対数変換をよく使います。BIの現場では、そこまでせずとも「中央値と分位数で語る」だけで十分に実務が回ります。

## 外れ値をどう扱うか

**外れ値**とは、他の値から極端に離れた値のことです。統計的には「Q3 + 1.5 × IQR より大きい値」を外れ値の候補とする方法がよく使われます。sales.csv では **69,700円より大きい注文**が該当し、869件（全体の12.5%）です。

ここで重要な事実があります。この「外れ値」869件が、**売上全体の70%を占めています。**

     "note":"データの誤り"},

> 少数が全体の大半を占める現象は、ビジネスでは例外ではなく通常です。サンプルデータでも、**上位10%の顧客が売上の28.7%、上位20%で44.9%**を占めています。この偏りは異常ではなく構造です。だから「全顧客の平均」で施策を設計すると、売上の半分を生んでいる層にも、大多数の一般層にも刺さらない中途半端な施策になります。**分布を見て層に分け、層ごとに違う施策を打つ**。これがセグメンテーションの出発点です。

## 「平均の平均」は平均ではない

実務で最も頻繁に起きる計算ミスがこれです。店舗ごとの平均注文金額を出し、その3店舗の平均を取ると、全体の平均とは一致しません。

```figure
{ "type": "tablediff", "arrowLabel": "正しく計算し直す",
  "before": {"title":"よくある誤り：平均の単純平均","tone":"bad",
    "head":["店舗","注文件数","平均注文額"],
    "rows":[
      ["S001","1,000件","10,000円"],
      ["S002","100件","50,000円"],
      ["S003","10件","100,000円"],

  "after": {"title":"正しい計算：合計 ÷ 合計件数","tone":"good",
    "head":["項目","計算","値"],
    "rows":[
      ["売上合計","1,000万+500万+100万","1,600万円"],
      ["件数合計","1,000+100+10","1,110件"],
      ["全体平均","1,600万 ÷ 1,110","!14,414円"]]} }
```

53,333円と14,414円。3.7倍も違います。件数の少ない店舗の高い平均が、同じ重みで効いてしまうためです。正しくは**件数で重みづけした平均（加重平均）**、つまり「合計 ÷ 合計件数」で計算します。

```figure

  "code": "全体平均 = SUM(売上) / COUNT(注文)   ≠   AVERAGE( 各店舗の平均 )",
  "parts": [
    {"match":"SUM(売上) / COUNT(注文)","label":"正しい。分子と分母をそれぞれ合計してから割る","tone":"good"},
    {"match":"AVERAGE( 各店舗の平均 )","label":"誤り。件数の重みが消える","tone":"bad"} ] }
```

> [!TIP] Power BIならこの罠を自動で回避できる
> Power BI のメジャーは「合計 ÷ 件数」の形で1度定義しておけば、店舗別に見ても全社で見ても、その粒度で分子と分母をそれぞれ再計算します。**Excelで店舗別の平均列を作って合計行で平均する**という手順を踏まないため、この誤りが構造的に起きません。これはM03以降で扱うメジャーの重要な利点です。率や単価は列ではなくメジャーで作る、と覚えてください。

> [!WARN] 率の合計は率にならない
> 同じ理由で、粗利率・購買率・稼働率といった「率」は足し算も単純平均もできません。必ず分子と分母をそれぞれ合計してから割ります。Excelの表で率の列をドラッグして合計してしまう事故は、実務で毎日どこかで起きています。

## まとめ

- 平均・中央値・最頻値は別物。**合計に責任を持つときは平均、典型を語るときは中央値**
- サンプルデータの注文金額は平均39,728円に対し中央値7,900円。右に歪んだ分布ではこの乖離が普通に起きる
- 代表値の前に分布の形（単峰か・対称か・二山か）を確認する。二山なら分けて分析する
- ばらつきは四分位数とIQRで見る。標準偏差が平均を超えるようなら、歪んだ分布のサイン
- 外れ値は「間違い」なら除外、「珍しい事実」なら残す。サンプルデータでは外れ値相当の12.5%が売上の70%を占める
- シンプソンのパラドックス：全体の傾向とグループ別の傾向は逆転しうる。必ず一段分けて確認する
- パーセントは分母・非対称性・小さい母数の3点で誤解を生む。率には必ず件数を併記する
- 棒グラフの軸は0から始める。折れ線は0から始めなくてよい

## 理解度チェック（自分に説明してみる）
