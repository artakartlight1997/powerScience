## 代替手段1・2 — `CROSSFILTER` と `TREATAS`

```figure
{ "type":"compare", "title":"モデルで双方向 vs CROSSFILTER", "caption":"影響範囲がモデル全体か、そのメジャーだけか", "panels":[
  {"title":"リレーションシップを双方向にする","tone":"bad","note":"影響を完全に把握できるときだけ",
   "items":["影響範囲はモデル全体。全レポート・全ビジュアル","他の作成者のレポートにも影響する","曖昧経路が生まれる可能性がある","RLSのセキュリティ境界が広がる","後から外すと既存レポートが壊れうる","モデル図で気づけるのが唯一の利点"]},
  {"title":"CROSSFILTER をメジャー内で使う","tone":"good","note":"既定の選択肢にする",
   "items":["影響範囲はそのメジャーが使われたときだけ","他のメジャー・レポートに影響しない","モデルの構造は単方向のまま","RLSの経路は変わらない","メジャー名で意図を表現できる","DAXを読まないと気づけない。コメントを書く"]}] }
```

```dax
-- 商品カテゴリごとの「購入したことのある顧客数」
-- 関係は単方向のまま、このメジャー内でだけ逆流させる
購入顧客数 =
CALCULATE( DISTINCTCOUNT( Dim_顧客[顧客ID] ),
    CROSSFILTER( Dim_顧客[顧客ID], Fact_売上[顧客ID], BOTH ) )

-- NONE の例：日付フィルターを無視した全期間の合計
全期間売上 =
CALCULATE( SUM( Fact_売上[金額] ),
    CROSSFILTER( Dim_日付[日付], Fact_売上[売上日], NONE ) )

-- TREATAS：関係を使わず、値をフィルターとして送り込む
売れた商品の在庫 =
CALCULATE( SUM( Fact_在庫[在庫数] ),
    TREATAS( VALUES( Fact_売上[商品ID] ), Fact_在庫[商品ID] ) )
```

```dax
-- 「売上のある商品だけスライサーに出す」はレポート側で解ける
-- フィルターペインに置き「1に等しい」を指定する。モデルには影響しない
```

> 「双方向にしたい」と思ったら、まずモデル図がスノーフレークでないか見る。
> 双方向は解決策ではなく、設計の歪みを知らせる症状。

## 理解度チェック

1. `Dim_商品` と `Fact_売上` を双方向にすると「今月売れなかった商品の一覧」はどうなるか。
2. 「カテゴリごとの購入顧客数」を単方向のまま実現するDAXを書け。
3. RLSのあるモデルで双方向を使うとき必ず行う検証手順を述べよ。
