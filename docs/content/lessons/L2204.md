レポートを公開し、メールで案内を送り、「ご活用ください」と書いた。2週間後、アクセスは週3件。作った本人と、その上司だけが開いています。

## チャンピオンモデル

BIチームが40人全員をフォローすることはできません。**各部署に1人、詳しい人を作る**のが唯一の現実的な方法です。

```figure
{ "type":"stack", "title":"チャンピオンによる展開構造", "caption":"BIチームは10人を育て、その10人が400人を支える",
  "layers":[
    {"label":"一般利用者（400名）","sub":"見て使う。困ったら身近なチャンピオンに聞く","tone":"blue"},
    {"label":"チャンピオン（各部署1〜2名／計10名）","sub":"部署内の一次窓口。要望を集約してBIチームに渡す","tone":"amber"},
    {"label":"BIチーム（3名）","sub":"モデル・レポートの開発、チャンピオンの育成、品質と運用","tone":"pink"} ] }
```

| チャンピオンに渡すもの | 内容 |
|---|---|
| 先行アクセス | 一般公開の1週間前に触ってもらい、意見を反映する |
| 専用の説明会 | 30分。設計意図、指標の定義、よくある質問 |
| 質問チャネル | 直接BIチームに聞ける場所。回答は全チャンピオンに共有 |
| 貢献の可視化 | 「◯◯さんの提案で改善しました」と全社に明示する |
| 権限 | 自部署向けの簡単なレポート編集権限を与える |

> [!DS] データサイエンス視点：イノベーション普及理論
> Everett Rogers の普及理論では、新しいものの採用者は5層に分かれます。**革新者（2.5%）→ 初期採用者（13.5%）→ 前期追随者（34%）→ 後期追随者（34%）→ 遅滞者（16%）**。重要なのは、初期採用者と前期追随者の間に**キャズム（深い溝）**があるという点です。革新者と初期採用者は「新しいから」使いますが、大多数を占める追随者は**「周りが使っていて、実績があるから」使います**。だからパイロットの成功事例を数字で言語化する Phase 2 が決定的に重要なのです。「新機能です」ではなく「◯◯部で週2時間削減されました」と言えるかどうかが、キャズムを越えられるかを決めます。

> [!DS] データサイエンス視点：チェンジマネジメントの ADKAR
> 組織変革の枠組みとして広く使われる ADKAR モデルは、個人が変化を受け入れる5段階を示します。**Awareness（認知）→ Desire（欲求）→ Knowledge（知識）→ Ability（能力）→ Reinforcement（定着強化）**。BI導入の失敗は、多くがKnowledge（研修）だけを実施し、DesireとReinforcementを飛ばしていることに起因します。**Desire（使いたいと思う理由）**は、成功事例と「自分の仕事が楽になる」実感からしか生まれません。**Reinforcement（続ける仕組み）**は、業務プロセスへの組み込みと、使っている人が評価される仕組みです。研修は5段階のうち1つに過ぎません。

定着はゴールではありません。使われ始めてから、新しい仕事が始まります。

```figure

  "items":[
```

> 定着の最終形は「レポートがよく見られている」ことではなく、**「データを見ずに決めることが不自然になった」**という状態です。ここに到達すると、BIチームの仕事は「作って配る」から「組織の意思決定の質を上げる」に変わります。これがティア4のゴールそのものです。

## ガバナンスと自由度のバランス

定着が進むと、必ず「自分でも作りたい」という人が現れます。これを禁止するか、支援するかで組織のBI成熟度が変わります。

右上の**「共有モデル上でレポートだけ自作」**が、組織にとって最も健全な状態です。指標の定義はBIチームが保証し、見せ方は現場が工夫する。この分担なら、数字の一貫性を保ったまま自由度を高められます。

| ルールとして決めておくこと | 例 |
|---|---|
| 何を自作してよいか | 認定モデルへのライブ接続レポートのみ。新規モデル作成は申請制 |
| 共有の範囲 | 部門内は自由、部門横断・経営報告はレビューを経る |
| 命名規則 | 「[部門]_[用途]_[版]」。個人名や「最新版2」を禁止 |
| 廃棄のルール | 90日閲覧ゼロで棚卸し対象。所有者が異動したら引き継ぎ必須 |

> [!WARN] 注意
> セルフサービスを無制限に許すと、**同じ指標が微妙に違う定義で20本存在する状態**になります。これはBIの信頼を最も速く破壊するパターンです。自由にしてよいのは「見せ方」であって「定義」ではありません。この線引きを最初に明文化してください。

### 定着施策の優先順位

限られた時間で何から手をつけるか。効果の大きい順に並べると次のとおりです。

| 順位 | 施策 | 想定工数 | 効果 |
|---|---|---|---|
| 1 | 定例会議での利用を運営ルールに入れる | 交渉のみ | 極大 |
| 2 | 経営層に実際に使ってもらう | 数時間の同席 | 極大 |
| 3 | 定期配信（サブスクリプション）を設定 | 30分 | 大 |
| 4 | チャンピオンを任命し先行アクセスを渡す | 各1時間 | 大 |
| 5 | Teams チャネルにタブとして固定 | 15分 | 中 |
| 6 | 3分の操作動画とA4早見表を作る | 半日 | 中 |
| 7 | 集合研修を実施する | 1〜2日 | 小（単独では） |

上位2つは技術的な作業がゼロで、効果が最大です。**定着は技術の仕事ではなく、交渉と設計の仕事**であることが、この表からも分かります。
