## マージ — 横に貼る

「ホーム → クエリのマージ」で、キー列を指定して2つの表を結びつけます。生成される M は次の形です。

```m
// 売上に商品マスタを左外部結合する
let
    マージ = Table.NestedJoin(
        売上, {"ProductID"},
        商品, {"ProductID"},
        "商品",
        JoinKind.LeftOuter
    ),
    展開 = Table.ExpandTableColumn(
        マージ,
        "商品",
        {"ProductName", "Category", "StandardCost"},
        {"ProductName", "Category", "StandardCost"}
    )
in
    展開
```

`Table.NestedJoin` は、一致した行を**テーブルとして入れ子で**保持します。そのままでは使えないので、`Table.ExpandTableColumn` で必要な列だけを取り出します。GUI でマージすると、この2ステップが自動で作られます。

> [!TIP]
> 展開のときは、**必要な列だけにチェックを入れてください**。全列を展開すると、使わない列がモデルに入り込んで容量を食います。また「元の列名をプレフィックスとして使用」のチェックを外すと `商品.ProductName` ではなく `ProductName` になります。列名が衝突しないなら外したほうが扱いやすくなります。

## 一致しない本当の理由

「キーが同じに見えるのにマージされない」ときの原因は、ほぼこの4つに限られます。

| 原因 | 症状 | 対処 |
|---|---|---|
| 型が違う | `text` の `"1001"` と `number` の `1001` | 両方を同じ型に揃える。IDは text 型を推奨 |
| 前後の空白 | `"P0027 "` と `"P0027"` | 両側にトリミング（全角空白に注意） |
| 大文字小文字 | `"p0027"` と `"P0027"` | 両側を大文字に統一 |
| 見えない文字 | 改行、BOM、ゼロ幅スペース | クリーンを適用する |

> [!WARN]
> マージのダイアログには「選択された n 行のうち m 行が一致します」という表示が出ます。**必ずこの数字を読んでください**。「6,948 行のうち 5,120 行が一致します」と出ているのに OK を押すのは、1,828 行の欠落を承知で進むという意思表示です。この数字が想定と違うなら、キーの正規化に戻ってください。

## ファジーマッチ

キーがそもそも整っていない場合（顧客名で突合するなど）は、「あいまい一致を使用してマージを実行します」を有効にします。類似度のしきい値（0〜1）を指定し、近い文字列同士を一致させます。

| オプション | 効果 |
|---|---|
| 類似性のしきい値 | 既定 0.8。上げると厳しく、下げると緩くなる |
| 大文字と小文字を区別しない | 通常オンにする |
| テキストの結合 | 単語の区切りを無視して比較する |
| 変換テーブル | 「東京 → 東京都」のような対応表を明示的に与える |

> [!TIP]
> ファジーマッチは便利ですが、**結果は必ず人が検証してください**。しきい値 0.8 では「新宿本店」と「新宿支店」が一致してしまうことがあります。実務では、ファジーマッチで候補を出し、それを変換テーブルに書き写して**以降は完全一致で運用する**のが安全です。自動判定を本番の恒常処理にしないでください。

中級者が必ず突き当たる問いです。売上に商品名を付けたいとき、Power Query でマージすべきか、モデルでリレーションシップを引くべきか。

```figure
{ "type": "compare", "title": "マージ vs リレーションシップ",
  "caption": "原則はリレーションシップ。マージは「1つの表に畳む必要がある」ときだけ",
  "panels": [
    {"title": "Power Query でマージ", "tone": "bad",
     "items": ["同じ商品名が数百万行に複製される", "モデルが重くなり圧縮も効きにくい", "商品マスタ単独では使えない", "更新のたびに結合処理が走る"],
     "note": "多用しない"},
    {"title": "モデルでリレーションシップ", "tone": "good",
     "items": ["商品名は商品テーブルに1行だけ", "圧縮が効いてモデルが軽い", "売れていない商品も一覧できる", "スライサーやスタースキーマが機能する"],
     "note": "こちらが原則"} ] }
```

**既定はリレーションシップです。** Power Query のマージが正当化されるのは、次のような場合に限られます。

- ディメンションの属性を、ファクトの行に固定して保存したい（受注時点の価格など、履歴として凍結したい値）
- 複数のソースを1つのディメンションに統合する（店舗マスタA＋店舗マスタB → 店舗ディメンション）
- 左反結合による品質チェック（そもそもモデルに載せない検査クエリ）

> [!DS]
> 結合はリレーショナル代数の演算で、SQL の `INNER JOIN` / `LEFT OUTER JOIN` / `FULL OUTER JOIN` と1対1に対応します。反結合は SQL では `NOT EXISTS` や `LEFT JOIN ... WHERE key IS NULL` として書かれるもので、Power Query はこれを独立したコマンドとして用意しています。データウェアハウスの世界では、ファクト側のキーがディメンション側に必ず存在することを **参照整合性（referential integrity）** と呼び、これが保証されていれば内部結合と左外部結合の結果は一致します。逆に言えば、**結果が違うということは参照整合性が壊れている**という診断になります。数字が合わないときは、まずここを疑ってください。

> [!EXAM]
> PL-300 では「一致しない行を特定したい」「マスタに存在しない商品コードを見つけたい」という設問が頻出します。答えは**左反結合（Left Anti Join）**です。また「両方のテーブルに存在する行だけを保持する結合はどれか」には内部結合、「1つ目のテーブルのすべての行を保持する」には左外部結合が対応します。日本語の選択肢では「左側外部（1番目のすべての行、および2番目の一致する行）」という表記で出るので、括弧の中の説明を読めば確実に選べます。

## 結合の前に必ずやること

結合作業は、次のチェックを済ませてから行ってください。ここを飛ばすと、後で数字が合わない調査に何倍もの時間を使います。

| チェック | 方法 | 合格ライン |
|---|---|---|
| 左の行数を控える | ステータスバー、または行数のカウント | 結合後も同じ（左外部結合の場合） |
| 右のキーが一意か | 列の分布で個別＝一意を確認 | 一致していること |
| キーの型が両側で同じか | 列見出しのアイコン | 両方 ABC（text）など揃っている |
| キーが正規化済みか | トリミング・クリーン・大文字統一 | 済んでいること |
| 一致しないキーがあるか | 左反結合を試す | 0行、または内容を説明できる |

## 理解度チェック

1. 売上 6,948 行と商品マスタを内部結合したところ、結果が 5,120 行になりました。何が起きていますか。行を失わずに原因を調査する手順を、使う結合の種類とともに説明してください。
2. マージ後に売上合計が正確に2倍になりました。最も疑うべき原因は何ですか。マージ前にそれを検出する方法を2つ挙げてください。
3. 売上に商品名を付けたい場合、Power Query のマージとモデルのリレーションシップのどちらを選ぶべきですか。理由を圧縮とモデルサイズの観点から説明してください。

## よくあるエラーと対処

| 症状 | 原因 | 対処 |
|---|---|---|
| マージしても全部 null になる | キーの型が違う（text と number） | 両側のキー列を同じ型に揃える。IDは text 型が安全 |
| 一致件数が想定より少ない | 空白・大文字小文字・見えない文字 | 両側にトリミング（全角含む）・クリーン・大文字統一を適用する |
| マージ後に行数が増えた | 右側のキーに重複がある（ファンアウト） | 右側で重複の削除、または粒度を見直す |
| 内部結合で売上が減った | 一致しないファクト行が消えた | 左外部結合に変更し、左反結合で欠落キーを調査する |
| 追加したら列が2倍に増えた | 列名が一致していない | 追加前に列名を完全に揃える |
| 追加したら合計が2倍になった | 同じクエリを2回積んだ | 追加対象のクエリ一覧を確認する |
| 展開すると列名に「商品.」が付く | プレフィックス使用がオン | 展開ダイアログでチェックを外す |
| 更新が急に遅くなった | 異なるソース同士のマージで折りたたみが切れた | 可能なら同一ソース内で結合する。または段階的に絞ってから結合する |
