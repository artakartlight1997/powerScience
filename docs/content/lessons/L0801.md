ここからがDAXの心臓部です。

`売上合計 = SUM( Fact_売上[SalesAmount] )` という式は、たった1行です。
にもかかわらず、下の表では **8つの違う値** を返しています。

| Category | 2023年 | 2024年 | 合計 |
|---|---|---|---|
| 家電 | 24 | 28 | 52 |
| 衣料 | 8 | 10 | 18 |
| 食品 | 13 | 17 | 30 |
| **合計** | **45** | **55** | **100** |

*(単位：百万円)*

式は1つ。値は12個。**この差を生んでいるものの正体が、フィルターコンテキストです。**

```figure

  "caption":"各セルが受け取る条件と、その条件で絞られた行数・合計値を確認できる" }
```

## 定義

**フィルターコンテキスト**とは、式が評価される瞬間にモデルへ適用されている **絞り込み条件の集合** です。

言い換えると「いま、どの行が見えているか」を決めるものです。

```figure
{ "type":"pipeline", "title":"フィルターコンテキストが値を決める仕組み", "caption":"式は毎回同じ。変わるのは入口の条件だけ",
  "nodes":[
    {"id":"a","label":"セルの座標\nCategory=家電, 年=2024","tone":"blue"},
    {"id":"b","label":"フィルターコンテキスト\n2つの条件の集合","tone":"amber"},
    {"id":"c","label":"モデルが絞られる\n該当行だけが見える","tone":"cyan"},
    {"id":"d","label":"SUM が実行される","tone":"violet"},
    {"id":"e","label":"28","tone":"good"} ],
  "edges":[
    {"from":"a","to":"b","label":"行・列・スライサー"},
    {"from":"b","to":"c","label":"リレーションで伝播"},
    {"from":"c","to":"d"},
    {"from":"d","to":"e"} ] }
```

> [!NOTE] 重要な言い換え
> 「メジャーが値を返す」のではありません。**「フィルターコンテキストが、メジャーに値を返させる」** のです。
> DAXを読むときは、式より先に「このセルには何が効いているか」を考えてください。

## フィルターコンテキストの4つの発生源

コンテキストは、どこからともなく現れるわけではありません。発生源は次の4つだけです。

```figure
{ "type":"cards", "cols":2, "title":"フィルターコンテキストを作るもの", "caption":"この4つ以外からは発生しない。原因調査はこの4つを順に確認する",
  "items":[
    {"icon":"▦","title":"ビジュアルの行・列・凡例","text":"表の行に Category を置けば、各行に Category = ○○ という条件が生まれる。最も基本的な発生源。","tone":"blue"},
    {"icon":"⇄","title":"スライサー","text":"利用者が選んだ値が条件になる。何も選ばなければ条件は生まれない。","tone":"green"},
    {"icon":"⛃","title":"フィルターペイン","text":"ビジュアル単位・ページ単位・レポート単位の3階層で適用される。すべて重なって効く。","tone":"amber"},
    {"icon":"ƒ","title":"CALCULATE","text":"DAXの式の中からコンテキストを書き換える唯一の手段。L0803で扱う。","tone":"violet"} ] }
```

さらに、ユーザーの操作でも発生します。

- **相互作用（クロスフィルター）** — 棒グラフの棒をクリックすると、他のビジュアルに条件が伝わる
- **ドリルダウン** — 階層を下ると、上位階層の値が条件として追加される
- **ツールヒント** — ホバーした行の条件がそのまま適用される

いずれも「ビジュアルの座標」または「フィルターペイン」に還元できるので、覚えるのは上の4つで十分です。

```figure

  "layers":[
    {"label":"ビジュアルの行・列","sub":"セルごとに変わる。最も内側","tone":"pink"},
    {"label":"ビジュアルレベルフィルター","sub":"そのビジュアルだけに効く","tone":"violet"},
    {"label":"スライサー・相互作用","sub":"ページ上の操作で変わる","tone":"amber"},
    {"label":"ページレベルフィルター","sub":"そのページの全ビジュアルに効く","tone":"green"},
    {"label":"レポートレベルフィルター","sub":"レポート全体に効く。最も外側","tone":"blue"} ] }
```

> [!WARN] フィルターは「重なる」＝ AND
> レポートレベルで「2024年」、ページレベルで「関東」、ビジュアルの行で「家電」なら、
> 実際に効いている条件は **2024年 かつ 関東 かつ 家電** です。
> どれか1つを緩めても他は残ります。「数字が0になった」ときは、上位階層のフィルターを疑ってください。

## 合計行は「足し算」ではない

冒頭の表で、合計行の値は `45 + 55 = 100` でした。一致しているので気づきにくいのですが、
**エンジンは足し算をしていません**。合計行のセルには「Category の条件がない」だけで、
そこで改めて `SUM` が実行されています。

```figure
{ "type":"tablediff", "arrowLabel":"合計行のセルで起きていること", "title":"合計行は独立した1回の計算",
  "caption":"各行の結果を足しているのではなく、条件を1つ外して計算し直している",
  "before":{"title":"よくある誤解","tone":"bad",

    "rows":[["1","家電24 を計算"],["2","衣料8 を計算"],["3","食品13 を計算"],["4","!24+8+13 を足して45"]]},
  "after":{"title":"実際の処理","tone":"good",
    "head":["処理","内容"],
    "rows":[["1","家電24 を計算（Category=家電）"],["2","衣料8 を計算（Category=衣料）"],["3","食品13 を計算（Category=食品）"],["4","!Category条件なしで再計算して45"]]} }
```

|---|---|
| 家電 | 320 |
| 衣料 | 210 |
| 食品 | 480 |

> 「バグではありません。合計行は各行の和ではなく、絞り込みを外して計算し直した値です。

>

> [!DS] 集計の順序が結果を変える
> 「部分を集計してから足す」と「全体をまとめて集計する」は、一般には一致しません。
> 一致するのは、集計関数が **加法的** な場合だけです。
> 平均・中央値・分散・重複除去カウント・比率は、すべて一致しません。
> 分析設計では、指標ごとに「どの軸で足せるか」を明示しておくことが事故防止になります。

## 同じ列への複数条件は OR、違う列は AND

スライサーで「家電」と「食品」を両方選ぶと、条件は `Category IN {"家電","食品"}` になります。
これは **OR** です。一方、`Category = "家電"` と `年 = 2024` は違う列なので **AND** です。

```figure

      "どちらかに該当すれば残る",
      "結果：52 + 30 = 82百万円"],
     "note":"和集合になる"},
    {"title":"違う列の条件：AND","tone":"violet","items":[

     "note":"積集合になる"} ] }
```

> 「関東 かつ 沖縄限定商品 かつ 2024年1月」のように条件を重ねると、該当行が0になり、
> メジャーは BLANK を返します。数字が消えたら、まず **条件の重なりで該当行が無くなっていないか**を確認してください。

「スライサーを動かしても表の数字が変わらない」という相談の原因は、ほぼ次の3つです。

```figure
  "root":{"label":"スライサーが効かない"},
```

## シンプソンのパラドックスに注意

フィルターコンテキストを理解すると、こういう現象が起きうることも分かります。

**全体では A店の利益率が高いのに、セグメント別に見ると全セグメントで B店が高い。**

| | 法人 利益率 | 個人 利益率 | 全体 利益率 |
|---|---|---|---|
| A店 | 20% | 40% | **32%** |
| B店 | 25% | 45% | **28%** |

A店は利益率の高い個人向けの構成比が大きく、B店は法人向けが大きい。
だから全体では逆転します。**どちらの数字も正しく、どちらもフィルターコンテキストの産物です。**

```figure
{ "type":"chart", "kind":"bar", "title":"シンプソンのパラドックス",
  "caption":"セグメント別ではB店が上、全体ではA店が上。構成比の違いが逆転を生む",
  "categories":["法人(A)","法人(B)","個人(A)","個人(B)","全体(A)","全体(B)"],
  "series":[{"name":"利益率","values":[20,25,40,45,32,28],"tone":"amber"}],
  "highlight":4, "unit":"%" }
```

> [!DS] シンプソンのパラドックス
> 部分集団ごとの傾向と、全体の傾向が逆転する現象を **シンプソンのパラドックス** と呼びます。
> 原因は、集団ごとの **構成比（重み）の違い** です。
> BIでは「合計行だけを見て意思決定する」ことがこの罠を踏む典型です。
> 対策は、比率指標を出すときに必ず **母数（分母）も並べて表示する**こと。
> フィルターコンテキストの理解は、この種の誤読を防ぐ武器になります。

> [!NOTE] 「見えている行」を数えて確かめる
> 効いている条件が分からなくなったら、`行数 = COUNTROWS( Fact_売上 )` という確認用メジャーを
> 一時的に作り、ビジュアルに並べてください。**条件が正しく効いていれば行数が減ります。**
> 金額ではなく行数で見ると、フィルターの効き方だけを純粋に観察できます。

## 理解度チェック

**問1.** レポートレベルフィルターで「2024年」、スライサーで「関東」、テーブルの行に「家電」があるセルには、いくつの条件が効いているか。またそれらはどう合成されるか。

<details><summary>答え</summary>
3つ。年=2024、Region=関東、Category=家電。異なる列なのですべてANDで合成され、3条件すべてを満たす行だけが集計対象になる。
</details>

**問2.** カテゴリ別の顧客数の合計行が各行の和より小さかった。この現象を利用者に説明せよ。

<details><summary>答え</summary>
合計行はカテゴリの条件を外して独立に再計算されるため。複数カテゴリで購入した顧客は、各行では重複して数えられるが、合計行では1人としてしか数えられない。重複除去カウントは非加法的な指標であり、正常な挙動である。
</details>

**問3.** 店舗別の利益率で、全社では A店 > B店 なのに、法人・個人のどちらのセグメントでも B店 > A店 になっている。これはデータの誤りか。

<details><summary>答え</summary>
誤りではない。シンプソンのパラドックスであり、店舗ごとのセグメント構成比が異なることが原因。比率を提示する際は分母（売上規模や構成比）も併せて示す必要がある。
</details>

## よくあるエラーと原因

| 症状 | 原因 | 対処 |
|---|---|---|
| 値がすべて空白になる | フィルターの重なりで該当行が0件 | フィルターペインを上から順に確認する |
| どの行も同じ値になる | ビジュアルの行にディメンション列を置いていない | 行に `Dim_商品[Category]` などを追加する |
| スライサーを動かしても値が変わらない | ビジュアルの相互作用がオフ | 「書式 → 相互作用の編集」で確認する |
| 合計行が各行の和と違う | 非加法的な指標 | 正常。説明を添える |
| ファクト側の列でスライスすると遅い | 高カーディナリティ列で絞っている | ディメンション側の列でスライスする |
| ディメンションを絞ってもファクトが減らない | リレーションが無い、または非アクティブ | モデルビューでリレーションを確認する |

> [!NOTE] このレッスンのまとめ
> フィルターコンテキストは「いまどの行が見えているか」を決める条件の集合で、発生源は
> **ビジュアルの座標・スライサー・フィルターペイン・CALCULATE** の4つです。
> 同じ列の複数値は OR、違う列どうしは AND。そして **合計行は独立した再計算** です。
> 次のレッスンで、もう1つの文脈である**行コンテキスト**を扱い、2つを完全に区別します。
