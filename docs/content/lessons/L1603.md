領域3・4は「知っていれば取れる」問題の宝庫です。DAXのように考える必要がなく、機能名と設定場所を覚えていれば即答できます。だからこそ、**知らない機能が1つあるだけで確実に1問落とします**。

このレッスンも確認表です。見出しだけを見て中身を思い出せるかを試してください。合わせて12スキル項目、ここを全部◎にすると、合計で200点前後を安定して確保できます。

## 3.1 レポートの作成

### 必ず言えるようにすること

- ビュー3種（レポート・テーブル・モデル）とペイン3種（データ・視覚化・フィルター）の役割
- ページレベル / ビジュアルレベル / レポートレベルのフィルターの適用範囲
- ブックマークは「フィルター・スライサー・表示状態・並べ替え」を保存する
- 選択ペインでビジュアルの表示/非表示とレイヤー順を管理する
- 個人用ブックマークとレポートのブックマークは別物
- ページネーション（ページ表示）とツールチップページの用途

| フィルターの種類 | 効く範囲 | 閲覧者が変更できるか |
|---|---|---|
| ビジュアルレベル | そのビジュアルのみ | フィルターペインで可（許可時） |
| ページレベル | そのページの全ビジュアル | 同上 |
| レポートレベル | 全ページの全ビジュアル | 同上 |
| ドリルスルーフィルター | 遷移先ページ | 遷移元の選択で決まる |
| スライサー | 同一ページ（同期設定で他ページも） | 常に可 |

> [!EXAM] PL-300で問われる
> 「フィルターペインを閲覧者から隠したい」→ フィルターペインの**非表示（目のアイコン）**、または**表示ペインでロック**。「特定のフィルターを変更させたくない」→ そのフィルターカードを**ロック**します。非表示とロックの違いは頻出です。

## 3.5 データの探索と分析

### 必ず言えるようにすること

- 分析ペイン（折れ線・散布図など）で追加できる線：定数・最小・最大・平均・中央値・パーセンタイル・傾向線・予測・異常検出
- 「増減の説明」（分析情報）で変化の要因を自動生成できる
- Q&A ビジュアルで自然言語の質問に答えさせる。用語集（同義語）を設定できる
- 上位N件フィルター、相対日付スライサー、相対時間スライサー
- クイックメジャーでよくある計算をGUIから作れる
- パーソナライズビジュアル（閲覧者が軸を変更できる）

| やりたいこと | 機能 |
|---|---|
| 売上上位10商品だけ表示 | 上位N件フィルター |
| 直近30日だけ表示 | 相対日付スライサー |
| なぜ今月が落ちたか自動で説明 | 増減の説明（分析情報） |

| 値を階層的に分解する | 分解ツリー |

## 3.6 AI ビジュアルの活用

### 必ず言えるようにすること

- キーインフルエンサー：目的の値に影響する要因をランク付け（**相関であって因果ではない**）
- 分解ツリー：値をディメンションで分解。「AI 分割」で高い値／低い値を自動探索
- Q&A：自然言語入力。同義語（シノニム）とフィールドの用語集で精度が上がる
- スマートナラティブ：テキスト要約を自動生成し、動的な値を差し込める
- Copilot などの生成AI機能はライセンス・容量の条件がある

## 4.1 ワークスペースの管理

### 必ず言えるようにすること

- ワークスペースの4ロールと権限差を即答できる
- マイワークスペースは個人用であり、共同作業には使わない
- ワークスペースにはライセンス（Pro / PPU / Fabric容量）が関わる

| ロール | 主にできること |
|---|---|
| **管理者** | ワークスペースの削除・更新、ユーザーの追加/削除を含むすべて |
| **メンバー** | コンテンツの発行・共有、他ユーザーの追加（管理者以外）、アプリの発行 |
| **共同作成者** | コンテンツの作成・編集・削除、スケジュール更新の設定。**アプリの発行はできない** |
| **ビューアー** | 閲覧のみ。RLSが適用される |

> [!EXAM] PL-300で問われる
> 「レポートを編集させたいが、アプリの発行はさせたくない」→ **共同作成者**。「RLSを効かせたい」→ 対象者は**ビューアー**でなければならない。この2つは頻出です。

- モデルの「ビルド」権限が、他ユーザーがそのモデルからレポートを作るために必要

## 4.4 アクセス権とセキュリティ

### 必ず言えるようにすること

- 配布の選択肢：**アプリ / ワークスペースへの追加 / レポートの直接共有 / 埋め込み / Teams**

## 領域3・4の迷いやすい論点

| 迷う場面 | 判断 |
|---|---|
| 非表示かロックか | 見せない＝非表示、見せるが変更させない＝ロック |
| ドリルダウンかドリルスルーか | 同じビジュアル内＝ダウン、別ページへ＝スルー |
| フィルターか強調か | 他ビジュアルを絞る＝フィルター、色で示す＝強調 |
| アプリか共有か | 人数が多い・管理が要る＝アプリ |
| 共同作成者かメンバーか | アプリを発行させるならメンバー以上 |
| ゲートウェイは要るか | データが社内にあるなら要る |
| 昇格済みか認定済みか | 自己申告＝昇格済み、公式承認＝認定済み |
| RLSかOLSか | 行を隠す＝RLS、列やメジャーを隠す＝OLS |
| Pro か Premium/PPU か | 無料ユーザーへの配布・大容量・パイプラインは Premium/PPU |

> [!TRAP] 「ダッシュボード」と「レポート」を混同しない
> Power BI の**ダッシュボード**は Service 上でタイルをピン留めして作る1ページのものです。レポート（複数ページ・Desktopで作る）とは別物で、ダッシュボードにはスライサーもドリルダウンもありません。日本語の日常語では両方「ダッシュボード」と呼ぶため、試験でも実務でも混乱の元になります。**問題文に「タイルをピン留め」とあればダッシュボードの話**です。

## まとめ

- 領域3・4は暗記で確実に取れる。取りこぼしが最も痛い
- フィルターは範囲（ビジュアル/ページ/レポート）で覚える。非表示とロックは別物
- 相互作用は フィルター / 強調 / なし の3択
- ドリルダウンは同じビジュアル、ドリルスルーは別ページ
- アクセシビリティは 代替テキスト・タブ順序・色以外の手がかり・テーブル表示
- ワークスペース4ロール。共同作成者はアプリを発行できない
- 社内データにはゲートウェイ。Pro の更新は1日8回が目安
- 100人配布はアプリ。RLS はビューアーに効く
- パイプラインとリネージ、影響分析はガバナンスの定番機能
