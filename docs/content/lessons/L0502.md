## 空白の3種類

「空白を消す」と一言で言いますが、消す対象は3種類あります。

| 種類 | 例 | 見た目 | 除去方法 |
|---|---|---|---|
| 半角スペース | `新宿本店 ` | ふつうの空白 | トリミング |
| 全角スペース（U+3000） | `　新宿本店` | 少し広い空白 | **トリミングでは消えない** |
| 制御文字 | 改行・タブ | 見えない | クリーン |

> [!TRAP]
> **「変換 → 書式 → トリミング」は全角スペースを削除しません。** これは日本語データで最も多いつまずきです。トリミングをかけたのに `　新宿本店 ` が残り、マージが一致しない、という事故が頻発します。M の `Text.Trim` は第2引数で削る文字を指定できるので、全角スペースを明示してください。

```m
// 全角スペースと半角スペースの両方を前後から削る
= Table.TransformColumns(
    前のステップ,
    {{"店舗名", each Text.Trim(_, {" ", "　"}), type text}}
  )
```

文字列の**内部**にある空白まで消したい場合は、置換を使います。

```m
// 内部も含めてすべての空白を除去する（キー照合用の正規化に使う）
= Table.TransformColumns(
    前のステップ,
    {{"店舗名", each Text.Remove(_, {" ", "　"}), type text}}
  )
```

改行やタブなどの制御文字は「変換 → 書式 → クリーン」（`Text.Clean`）で除去します。CSV に貼り付けられた Excel のセル内改行は、これで消えます。


## null とエラーは別物

初学者が最も混同するのがここです。

```figure
{ "type": "compare", "title": "null と エラー",
  "caption": "null は「値がない」。エラーは「変換に失敗した」。対処法が違う",
  "panels": [
    {"title": "null（空）", "tone": "neutral",
     "items": ["値が存在しないことを表す正当な値", "SUM では無視される（0として足されない）", "COUNT では数えられない", "そのまま残してよい場合が多い", "セルは空白で表示される"],
     "note": "情報がない、という情報"},
    {"title": "エラー", "tone": "bad",
     "items": ["型変換や計算に失敗した状態", "1つでも残るとビジュアルが表示できないことがある", "セルに Error と赤字で表示される", "必ず処理を決める必要がある", "原因は元の値にある"],
     "note": "放置してはいけない"} ] }
```

`sales_dirty.csv` の金額列を数値型に変換すると、`N/A` と `"2,279,016"` がエラーになります。前者は「値がないことを文字で書いたもの」、後者は「数値なのに桁区切りが入ったもの」で、原因も対処も違います。

| 元の値 | 型変換の結果 | 正しい対処 |
|---|---|---|
| `N/A` | エラー | 変換前に `null` へ置換する（欠測として扱う） |
| `2,279,016` | エラー | 変換前にカンマを空文字へ置換する（値は生きている） |
| 空セル | null | 業務判断。0 とみなすか欠測のままにするか |
| `確認中` | エラー | 別列（備考）に退避してから null にする |

> [!TRAP]
> エラーを見つけたとき、反射的に「**エラーの削除**」を押してはいけません。エラーの削除は**行ごと消します**。`2,279,016` のようにカンマが入っているだけの行を削除すれば、実在する 227 万円の売上が消えます。**まず原因を直し、それでも直らないものだけを削除または置換の対象にします**。

```m
// 桁区切りカンマを除去してから数値型へ変換する（この順序が重要）
let
    カンマ除去 = Table.TransformColumns(
        前のステップ,
        {{"金額", each Text.Replace(Text.From(_), ",", ""), type text}}
    ),
    NAをnullに = Table.ReplaceValue(カンマ除去, "N/A", null, Replacer.ReplaceValue, {"金額"}),
    数値化 = Table.TransformColumnTypes(NAをnullに, {{"金額", Int64.Type}})
in
    数値化
```

行を失いたくないが、どうしても変換できない値がある場合は `try ... otherwise` を使います。

```m
// 変換できない値は null にして、行は残す
= Table.AddColumn(
    前のステップ,
    "金額_数値",
    each try Number.FromText(Text.Replace([金額], ",", "")) otherwise null,
    type nullable number
  )
```

> [!EXAM]
> PL-300 では「エラーの削除」「エラーの置換」「行の削除」の使い分けが問われます。**エラーの削除＝エラーを含む行を消す**、**エラーの置換＝エラーの値を指定した値に差し替えて行は残す**。「データを失わずにエラーを処理したい」という設問なら、答えは置換または `try ... otherwise` です。

Excel の結合セルを CSV にすると、2行目以降が null になります。「変換 → フィル → 下」で直上の値を埋められます。

> フィルは「直前の値が正しい」という前提に立った操作です。**先に並べ替えを変えてしまうと、まったく違う値が埋まります**。フィルは、元ファイルの行順が意味を持っているうちに行ってください。

> [!DS]
> 欠測値（missing value）の扱いは統計学の主題の1つです。欠測には、完全にランダムに生じる MCAR、他の変数で説明できる MAR、値そのものに依存する MNAR の3種類があります。`sales_dirty.csv` の「確認中」の行が空になっているのは、**値が確定していないから空**という MNAR に近い構造で、これを 0 で埋めると売上を過小に見積もります。**欠測を 0 で埋める判断は、必ず業務側に確認してから行ってください**。BI では「0」と「データなし」を見た目で区別できるようにしておくのが誠実な設計です。

## クレンジングの完成形

最後に、クレンジング済みクエリが満たすべき条件を確認します。

| チェック項目 | 確認方法 |

## 理解度チェック

1. 「トリミング」を実行したのに、マージで店舗名が一致しませんでした。最初に疑うべき原因は何ですか。M でどう書けば解決しますか。
2. 金額列を数値型に変換したところ、42 行がエラーになりました。ここで「エラーの削除」を押してはいけない理由を、`sales_dirty.csv` の具体的な値を挙げて説明してください。
3. 「重複の削除」と「トリミング・置換による正規化」は、どちらを先に実行すべきですか。逆にすると何が起きますか。

## よくあるエラーと対処

| 症状 | 原因 | 対処 |
|---|---|---|
| トリミングしたのに一致しない | 全角スペースが残っている | `Text.Trim(_, {" ", "　"})` を使う。または全空白を `Text.Remove` で除去した照合用列を作る |
| 数値型に変換すると大量にエラー | 桁区切りカンマ、`N/A`、全角数字 | 変換前に置換で正規化してから型変換する |
| エラーの削除で売上が激減した | エラー行を丸ごと消した | ステップを取り消し、原因ごとに置換で対処する |
| 重複が消えない | 正規化前に重複の削除をした | 正規化ステップを重複の削除より前に移動する |
| フィルで変な値が埋まった | 並べ替えの後にフィルした | 並べ替えステップを後ろへ移す |
| 来月ファイルで全部壊れた | 上位の行を固定数で削除していた | 行位置ではなく内容（テキストフィルター）で除外する |
| 日付列が変換できない | ロケールが合っていない | 「データ型の変更 → ロケールを使用」で `ja-JP` などを明示する |
