ここからは実際に手を動かします。まず Power BI Desktop を自分のPCに用意します。

作業自体は10分で終わりますが、**入手経路と初期設定を間違えると、後の全レッスンで画面が食い違います。** 特に「自動日付/時刻」の設定は、放置すると数か月後にモデルが肥大化する原因になります。ここで正しく整えておきます。

## 動作環境

| 項目 | 要件 | 実務での推奨 |
|---|---|---|
| OS | Windows 10 / 11（64ビット） | 最新の更新を適用した状態 |
| メモリ | 最低2GB | **16GB以上**。データ量が増えると効いてくる |
| ディスク | 空き1GB以上 | SSD。読み込み速度が体感を大きく左右する |
| 画面解像度 | 1440×900以上 | フルHD以上。ペインが多いため狭いと辛い |
| .NET | 4.7.2以上 | 通常はWindows Updateで導入済み |

> [!TRAP] macOS には対応していない
> Power BI Desktop は Windows 専用アプリです。Mac ユーザーの選択肢は次の3つです。**① Parallels などの仮想環境でWindowsを動かす、② Windows 365 / Azure Virtual Desktop などのクラウドPCを使う、③ ブラウザ版の Power BI Service で作成する。** ③は無料ライセンスでも一部利用できますが、Power Query の全機能やモデリング機能に制限があるため、本格的な学習には①か②を推奨します。

## つまずいたときの対処

| 症状 | 原因 | 対処 |
|---|---|---|
| Storeでインストールできない | 組織ポリシーでStoreが無効 | ダウンロードセンター版を使う。IT部門に確認 |
| 起動が非常に遅い | 初回起動または低スペック | 2回目以降は速くなる。メモリ8GB未満なら増設を検討 |
| サインインできない | 組織アカウントがない | サインインしなくてもDesktopは使える。発行時のみ必要 |
| 画面が英語で表示される | 表示言語の設定 | オプション → 地域の設定 → アプリケーションの言語 |
| メニュー位置が教材と違う | バージョン差 | 更新して最新にする。リボンの検索ボックスで機能名を検索 |

> [!DS] 環境の再現性という考え方
> データ分析では、**同じ入力から同じ結果が得られること**が信頼の基礎です。ところが分析環境（ツールのバージョン、ロケール設定、地域設定）が違うと、同じCSVから違う結果が出ることがあります。典型例が日付の解釈です。`03/04/2025` はロケールによって3月4日にも4月3日にもなります。だからチームで作業するときは、**ツールのバージョンとロケール設定を揃える**ことが最初の合意事項になります。プログラミングの世界で仮想環境やコンテナが使われるのと同じ理由です。

## まとめ

- Power BI Desktop は無料。Windows専用で、Microsoft Store版が最も手軽（自動更新）
- macOS では仮想環境・クラウドPC・ブラウザ版Serviceのいずれかを使う
- メモリは16GB以上を推奨。データ量が増えると体感差が大きい
- 初期設定で**「自動の日付/時刻」を必ずオフ**にする。日付列ごとに隠しテーブルが作られモデルが肥大化する
- ロケール設定は日付や小数点の解釈を左右する。チームで揃えることが再現性の前提
- pbixはOneDrive / SharePointに置くと版履歴とバックアップが得られる
- 毎月更新される。学習中は最新を維持し、教材との画面の差を減らす

## 理解度チェック（自分に説明してみる）

1. 「自動の日付/時刻」をオフにする理由を、モデルサイズと会計年度の2つの観点から説明してください。
2. 同僚のPCで同じCSVを読み込んだのに、日付列の値が違っていました。考えられる原因を1つ挙げ、確認すべき設定を説明してください。
3. あなたの環境では、pbixファイルをどこに保存しますか。その選択の利点とリスクをそれぞれ挙げてください。
