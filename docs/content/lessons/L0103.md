コールセンターで「1件あたりの対応時間」を評価指標にすると、オペレーターは電話を早く切るようになります。問題が解決していなくてもです。すると顧客は再び電話をかけ、総対応件数は増え、顧客満足度は下がります。

これは作り話ではなく、世界中の組織で繰り返し起きてきたことです。**測った数字は必ず行動を変えます。** だから指標の設計は、レポートを作る技術よりはるかに重要です。悪い指標を置いた組織は、真面目に、全力で、間違った方向へ走ります。

## KGIとKPIと先行指標

まず言葉を整理します。実務では混同されがちですが、役割がまったく違います。

```figure
{ "type": "stack", "title": "指標の3層構造",
  "caption": "上から降ろして考え、下から積み上げて動かす",
  "layers": [
    {"label":"KGI（重要目標達成指標）","sub":"最終的に達成したいゴール — 年間売上高、営業利益率","tone":"pink"},
    {"label":"KPI（重要業績評価指標）","sub":"KGIを分解した、日々追いかける数字 — 新規顧客数、リピート率、客単価","tone":"violet"},
    {"label":"先行指標（Leading Indicator）","sub":"KPIより先に動く、行動に直結する数字 — 商談件数、来店客数、カート投入数","tone":"blue"} ] }
```

**KGI**（Key Goal Indicator）は「どこに着きたいか」、**KPI**（Key Performance Indicator）は「そこに向かって進んでいるか」を示します。そしてもう1つ重要な区別が、**先行指標**と**遅行指標**です。

```figure
{ "type": "compare", "title": "先行指標と遅行指標",
  "caption": "遅行指標だけを見る組織は、バックミラーだけで運転している",
  "panels": [
    {"title":"遅行指標 Lagging","tone":"amber","items":[
      "売上高、利益、解約率、顧客満足度",
      "結果が確定してから分かる",
      "正確だが、分かったときには手遅れ",
      "評価と報告に使う"],
     "note":"結果の確認"},
    {"title":"先行指標 Leading","tone":"good","items":[
      "商談件数、見積提出数、来店客数、問い合わせ件数",
      "結果より先に動く",
      "予測は不完全だが、まだ手が打てる",
      "日々の行動管理に使う"],
     "note":"行動の舵取り"} ] }
```

体重で例えると分かりやすくなります。体重計の数字は遅行指標です。今日食べた量と運動量が先行指標です。体重だけを毎日見ても痩せませんが、摂取カロリーと歩数を管理すれば体重は後からついてきます。**先行指標は操作でき、遅行指標は操作できない。** これが両者の決定的な違いです。

> [!NOTE] 両方が要る
> 先行指標だけでは、そもそも目標に近づいているかが分かりません。遅行指標だけでは、手を打つタイミングを逃します。**遅行指標を1つ置き、それを動かす先行指標を2〜3個置く**のが実務の基本構成です。

## 指標ツリー — KGIを分解する

KPIは思いつきで選ぶものではなく、KGIを**割り算で分解**して導きます。この分解図を**指標ツリー（KPIツリー）**といいます。

```figure
{ "type": "tree", "title": "小売業の指標ツリー",
  "caption": "掛け算で分解すると、どの数字を動かせば売上が動くかが一目でわかる",
  "root": {"label":"売上高（KGI）","sub":"= 客数 × 客単価"},
  "children": [
    {"label":"客数","sub":"= 来店数 × 購買率","tone":"blue",
     "children":[
       {"label":"来店数","sub":"販促・立地・天候","tone":"blue"},
       {"label":"購買率","sub":"接客・品揃え・在庫欠品","tone":"blue"} ]},
    {"label":"客単価","sub":"= 商品単価 × 買上点数","tone":"green",
     "children":[
       {"label":"商品単価","sub":"価格設定・値引き率","tone":"green"},
       {"label":"買上点数","sub":"クロスセル・売場配置","tone":"green"} ]},
    {"label":"リピート率","sub":"既存顧客の再購買","tone":"violet",
     "children":[
       {"label":"再来店期間","sub":"平均何日で戻るか","tone":"violet"},
       {"label":"離脱率","sub":"90日以上来ない顧客の割合","tone":"violet"} ]} ] }
```

このツリーの良いところは、**責任の分担が明確になる**ことです。来店数は販促担当、購買率は店舗運営、商品単価は商品部、というように、それぞれの数字に責任者を割り当てられます。「売上を上げろ」という指示は誰も動かせませんが、「買上点数を1.8から2.0にする」なら具体的な施策が出てきます。

```figure
{ "type": "formula", "lang": "text",
  "code": "売上 = 客数 × 客単価 = ( 来店数 × 購買率 ) × ( 商品単価 × 買上点数 )",
  "parts": [
    {"match":"来店数","label":"販促・立地。先行指標として日次で見る","tone":"blue"},
    {"match":"購買率","label":"接客と在庫の質。欠品があると即落ちる","tone":"green"},
    {"match":"商品単価","label":"値引き施策の影響が最も出る箇所","tone":"amber"},
    {"match":"買上点数","label":"売場配置とクロスセルで動かす","tone":"violet"} ] }
```

> [!TIP] 分解は「掛け算」で行う
> 足し算の分解（売上＝家電＋衣料＋食品）は内訳であって、指標ツリーではありません。**掛け算の分解**にすると、各要素が「率」や「単価」になり、施策と結びつきます。実務でKPIツリーを描くときは、まず掛け算で3段まで割ってみてください。

## 指標定義の5要素

「客単価」と言葉で決めても、人によって計算が違えば数字は合いません。指標は必ず次の5つを文書で固定します。

```figure
{ "type": "cards", "cols": 5, "title": "指標定義に必須の5要素",
  "caption": "これが書かれていない指標は、会議で必ず揉める",
  "items": [
    {"icon":"➗","title":"分子","text":"何を足すか。売上金額か、値引き前か、税込か","tone":"blue"},
    {"icon":"👥","title":"分母","text":"何で割るか。注文件数か、顧客数か、来店数か","tone":"green"},
    {"icon":"🔬","title":"粒度","text":"どの単位で見るか。店舗別か、全社か、日次か月次か","tone":"amber"},
    {"icon":"📅","title":"期間","text":"いつの日付基準か。受注日か出荷日か。月末締めか","tone":"violet"},
    {"icon":"🚫","title":"除外条件","text":"何を除くか。返品、テスト注文、社内販売、キャンセル","tone":"pink"} ] }
```

サンプルデータで「客単価」を定義してみます。同じ言葉から3つの違う数字が出ます。

```figure
{ "type": "tablediff", "arrowLabel": "定義を明示する",
  "before": {"title":"曖昧な指示","tone":"bad",
    "head":["依頼"],
    "rows":[["「客単価を出しておいて」"]]},
  "after": {"title":"定義次第で数字が変わる","tone":"good",
    "head":["定義","計算","2024-2025の値"],
    "rows":[
      ["注文あたり単価","売上合計 ÷ 注文件数","!39,728円"],
      ["顧客あたり売上","売上合計 ÷ 顧客数600","!460,050円"],
      ["顧客あたり年間売上","売上合計 ÷ 顧客数 ÷ 2年","!230,025円"]]} }
```

3つとも計算は正しく、3つとも「客単価」と呼ばれます。だから**定義文を書く**のです。実務では次の形式を推奨します。

```text
指標名：注文単価（Average Order Value）
定義　：SalesAmount の合計 ÷ OrderID の一意カウント
期間　：OrderDate 基準の暦月
粒度　：全社 / 店舗別 / カテゴリ別
除外　：Quantity が 0 以下の行、テスト店舗 S999 の注文
目標　：月次 40,000 円以上
責任者：営業企画部
```

> [!WARN] 定義はpbixの中に書く
> 定義を別のExcelやWikiに書くと、必ず本体と乖離します。Power BI ではメジャーの説明欄（プロパティの「説明」）や、レポート内のテキストボックスに定義を書けます。**数字と定義を同じ場所に置く**ことが、信頼されるレポートの条件です。

## SMARTで指標を点検する

指標が使えるかどうかを点検する定番のフレームが **SMART** です。

```figure
{ "type": "cards", "cols": 5, "title": "SMARTチェック",
  "items": [
    {"icon":"S","title":"Specific","text":"具体的か。「売上向上」ではなく「新規顧客の月次売上」","tone":"blue"},
    {"icon":"M","title":"Measurable","text":"実際に測れるか。データが取得できるか","tone":"green"},
    {"icon":"A","title":"Achievable","text":"達成可能か。前年比300%は指標ではなく願望","tone":"amber"},
    {"icon":"R","title":"Relevant","text":"KGIと繋がっているか。動かしてもゴールに効かない指標は捨てる","tone":"violet"},
    {"icon":"T","title":"Time-bound","text":"期限と測定頻度が決まっているか","tone":"pink"} ] }
```

このうち実務で最も見落とされるのが **R（Relevant）** です。「SNSのフォロワー数」は測りやすく、増やしやすく、達成感もあります。しかし売上と繋がっていなければ、それは活動指標であって業績指標ではありません。**測りやすさで指標を選ぶと、測りやすいだけの指標が集まります。**

## Goodhartの法則 — 指標が目標になると壊れる

> 指標が目標になったとき、それは良い指標ではなくなる。

これが **Goodhartの法則** です。冒頭のコールセンターの例がまさにこれでした。人間は評価される数字を最適化するため、指標が測ろうとしていた本質（顧客の問題解決）ではなく、指標そのもの（通話時間）を改善してしまいます。

```figure
{ "type": "matrix", "title": "指標が壊れるパターン",
  "caption": "右上の領域に置いた指標は、必ず数か月以内に歪む",
  "xLabel": "評価・報酬との結びつき", "yLabel": "抜け道の作りやすさ",
  "xLow": "弱い（参考値）", "xHigh": "強い（賞与に直結）",
  "yLow": "難しい", "yHigh": "簡単",
  "quadrants": [
    {"title":"要注意","text":"抜け道はあるが評価に響かないので実害は小さい","tone":"amber"},
    {"title":"危険領域","text":"通話時間・訪問件数・登録数。必ず数合わせが始まる","tone":"bad"},
    {"title":"安全","text":"参考指標として監視する分には健全","tone":"gray"},
    {"title":"比較的健全","text":"売上・粗利など、ごまかしにくく評価に使える指標","tone":"good"} ] }
```

対策は「指標を評価に使わない」ことではありません。実務的な解は**ペア指標（対になる指標を必ずセットで置く）**です。

```figure

  "caption": "片方だけを追うと必ず片方が犠牲になる。だから最初からセットで置く",
  "panels": [
    {"title":"単独で置くと壊れる指標","tone":"bad","items":[
      "通話対応時間の短縮 → 問題未解決のまま切る",
      "新規契約件数 → 質の低い契約を乱発",
      "在庫削減率 → 欠品による機会損失",
      "コスト削減額 → 必要な投資まで削る"],
     "note":"局所最適"},
    {"title":"ペアで置くと健全化する","tone":"good","items":[
      "通話対応時間 ＋ 一次解決率",
      "新規契約件数 ＋ 3か月後の継続率",
      "在庫削減率 ＋ 欠品率",
      "コスト削減額 ＋ 顧客満足度"],
     "note":"全体最適"} ] }
```

> [!DS] 代理指標のリスク
> 本当に測りたいもの（顧客の幸福、従業員のやる気、ブランド価値）は直接測れません。そこで測れる別の数字で代用します。これを**代理指標（プロキシ）**といいます。代理指標は必ず本来の目的からズレを含んでいるため、次の2つを習慣にします。第一に、**代理であることを忘れない**。第二に、**定期的に代理指標と本来の目的の関係を検証する**。「NPSが上がったのに解約が増えている」なら、その代理はもう機能していません。

## ノーススターメトリック — 全員が見る1つの数字

指標は増えすぎると機能しません。20個のKPIが並ぶダッシュボードは、優先順位がないのと同じです。

そこで多くの企業が、組織全体で共有する最重要指標を1つだけ決めます。これを**ノーススターメトリック（北極星指標）**といいます。条件は3つです。顧客が受け取る価値を表していること、事業の成長と連動していること、チームの行動で動かせること。

```figure
{ "type": "cards", "cols": 3, "title": "ノーススターメトリックの例",
  "caption": "いずれも「売上」そのものではなく、売上を生む顧客価値を測っている点が共通",
  "items": [
    {"icon":"🛒","title":"小売","text":"週次のアクティブ購買顧客数。単発の売上より継続的な価値を表す","tone":"blue"},
    {"icon":"📺","title":"動画サービス","text":"週あたりの視聴時間。課金より先に動く先行指標でもある","tone":"green"},
    {"icon":"🏨","title":"宿泊予約","text":"予約成立した宿泊数。供給側と需要側の両方の健全性を反映","tone":"amber"} ] }
```

> [!TIP] ダッシュボードの指標は5個まで
> 人間が同時に把握できる数字は多くありません。1画面のKPIカードは**3〜5個**に絞り、それ以外はドリルダウン先に置きます。「全部載せる」は「何も伝えない」と同義です。この原則はM03でレポートを作るときに実践します。

## 目標値をどう決めるか

指標を決めても、目標値がなければ良し悪しが判断できません。目標値の置き方には型があります。

```figure
{ "type": "steps", "title": "目標値の決め方",
  "items": [
    {"title":"1. ベースラインを測る","text":"まず現状値を3〜6か月分測る。現状を知らずに目標は置けない。ここを飛ばした目標は必ず形骸化する。","tone":"blue"},
    {"title":"2. ばらつきの幅を見る","text":"月ごとの変動幅を確認する。毎月±20%動く指標に「前月比+3%」の目標を置いても、達成/未達はほぼ偶然で決まる。","tone":"green"},
    {"title":"3. 達成水準を3段階で置く","text":"最低ライン（必達）・標準（計画値）・ストレッチ（挑戦）の3段。1本の線だけだと、超えた瞬間に努力が止まる。","tone":"amber"},
    {"title":"4. 見直し周期を決める","text":"四半期ごとに目標値そのものを点検する。環境が変われば目標も変わる。指標は固定、目標値は可変。","tone":"violet"} ] }
```

> [!DS] 平均への回帰に騙されない
> 極端に悪い数字を出した店舗に指導を入れると、翌月はたいてい改善します。しかしこれは指導の効果ではなく、**平均への回帰**（極端な値の次は平均に近い値が出やすいという統計的な性質）かもしれません。逆に、絶好調だった店舗を表彰した翌月に成績が落ちるのも同じ現象です。施策の効果を判定するには、**施策を打たなかった比較対象**と並べる必要があります。これが対照群という考え方です。KPIレビューでこの落とし穴を知っているかどうかで、判断の質が大きく変わります。

## 指標を運用に乗せる

最後に、作った指標を実際に回すための実務ルールを挙げます。

```figure
{ "type": "flow", "dir": "col", "title": "指標の運用サイクル",
  "items": [
    {"label":"週次","sub":"先行指標を確認し、その週の行動を決める","tone":"blue"},
    {"label":"月次","sub":"KPIの達成状況を確認し、施策の効果を検証する","tone":"green"},
    {"label":"四半期","sub":"指標そのものと目標値が妥当かを点検する","tone":"amber"},
    {"label":"年次","sub":"KGIとの整合を見直し、不要な指標を廃止する","tone":"violet"} ] }
```

最も忘れられがちなのが**指標の廃止**です。指標は増える一方で減りません。四半期ごとに「この3か月で、この指標を見て何か行動を変えたか」を問い、答えがノーなら廃止します。使われない指標を維持するコストは、集計の手間だけでなく、重要な指標から注意をそらすコストとしても効いてきます。

同じデータでも、見る人の階層によって必要な粒度と頻度が変わります。全員に同じ画面を見せるのは失敗の典型です。

```figure

    {"label":"部門長","sub":"週次・部門/地域粒度・KPI中心。目標達成率と要因分解","tone":"violet"},
    {"label":"現場マネージャ","sub":"日次・店舗/担当者粒度・先行指標中心。異常検知と行動指示","tone":"amber"},
```

> [!TRAP] 指標の追加は簡単、削除は政治
> 「この数字も出せますか」と言われて追加した指標は、誰も見なくなっても消せません。追加を依頼されたら「その数字を見て、どんな判断をしますか」と必ず聞いてください。答えが出ないなら、それは好奇心であって業務要件ではありません。この一言が、レポートの寿命を倍にします。

## まとめ

- KGI（ゴール）・KPI（進捗）・先行指標（行動）の3層で考える。先行指標は操作でき、遅行指標は操作できない
- KPIはKGIを**掛け算で分解**して導く。指標ツリーを描くと責任分担も同時に決まる
- 指標定義には分子・分母・粒度・期間・除外条件の5要素が必須。同じ「客単価」でも定義次第で数字は10倍変わる
- SMARTで点検する。特に Relevant（KGIと繋がっているか）が見落とされやすい
- Goodhartの法則により、評価に直結する指標は必ず歪む。**ペア指標**をセットで置いて防ぐ
- 全員が見る指標は3〜5個に絞る。ノーススターメトリックは1つ
- 目標値はベースライン測定→ばらつき確認→3段階設定→定期見直しの順で決める
- 平均への回帰に注意。施策の効果は比較対象と並べて判定する
