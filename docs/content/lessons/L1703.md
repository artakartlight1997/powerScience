「顧客マスタから休眠行を除き、法人格の表記ゆれを正規化し、都道府県コードを付ける」。この20行のMコードが組織にいくつあるでしょうか。

調べると、たいてい**モデルの数だけあり、中身が微妙に違います**。数字が合わない原因の多くはここに埋まっています。

## 設計チェックリスト

- [ ] 変換の配置候補5つを理解し、判断フローを文書化した
- [ ] 「全システムで正しくあるべき事実」は上流に起票する運用にした
- [ ] BI側の暫定対処に期限と起票番号を記録する運用を決めた
- [ ] ブロンズ層は加工しない、というルールを明文化した
- [ ] 取り込み処理を冪等（再実行可能）に設計した
- [ ] データフローのステージングと変換を分離した
- [ ] データフローのチェーンの深さに上限を設けた
- [ ] 上流と下流の更新順序をパイプラインで制御した
- [ ] 新規のデータフローは Gen2 を既定にすると決めた
- [ ] 重複変換を検出し、旧経路の削除まで完了させた

## 理解度チェック

1. 取引先マスタの重複を Power Query で名寄せするか、基幹側で統合するか。判断に必要な条件を挙げてください。
2. ブロンズ層で型変換もフィルターも行わない理由を述べてください。
3. データフローのチェーンを2段までに制限すべき理由を、更新時間と障害対応の2観点から説明してください。

> [!NOTE] このレッスンのまとめ
> 変換は「できるだけ下の層で、できるだけ一度だけ」。再利用範囲と変更速度の綱引きで決める。ブロンズは加工せず再処理可能性を残し、取り込みは冪等に作る。共通化は旧経路を閉じて初めて完了する。
