「10月に新しいレコメンド機能をリリースしました。11月の購入率は 3.2% から 3.9% に上昇。施策は成功です」。

この報告は、次のどれか1つが当てはまるだけで崩れます。11月は季節的に購入率が高い月だった。同時期にセールをやっていた。10月の購入率がたまたま低く、平均に戻っただけ。新機能を使ったのは、もともと積極的な顧客だけだった。

**「前後で数字が上がった」は、効果の証拠ではありません。** 効果を主張するには、「その施策がなかった場合に何が起きていたか」——反事実（counterfactual）——を用意する必要があります。

このレッスンでは、反事実を用意する2つの方法、ランダム化比較試験（A/Bテスト）と差分の差分法を扱います。

> [!DS]
> 因果推論の根本問題は、**同じ対象について「施策をした場合」と「しなかった場合」を同時に観測できない**ことにあります。だから私たちは、施策をしなかった別の集団で代用します。この代用が妥当であるためには、その集団が「施策をした集団と、施策以外の点で同じ」でなければなりません。ランダム化は、この条件を統計的に保証する唯一の一般的手段です。

## なぜランダム化が効くのか

```figure
{ "type": "compare", "title": "群の作り方で結論が変わる", "panels": [
  {"title":"自己選択（使いたい人が使う）","tone":"bad","items":[
    "新機能を使った人と使わなかった人を比較",
    "使った人はもともと積極的な顧客",
    "測っていない意欲の差が結果を作る",
    "効果は必ず過大評価される"],
   "note":"因果は主張できない"},
  {"title":"ランダム割当","tone":"good","items":[
    "コイン投げで対象を2群に分ける",
    "年齢・性別・購買履歴が平均的に揃う",
    "測っていない変数（意欲・所得）まで揃う",
    "差は施策の効果としか説明できない"],
   "note":"因果を主張できる"} ] }
```

ランダム化の真価は、**測っていない変数まで揃う**点にあります。層別（L1502）は、思いついた交絡変数しか調整できません。ランダム化は、思いつかなかった変数についても、群間の分布を平均的に等しくします。

> [!NOTE] 要点
> ランダム化は「1回のテストで完全に揃う」ことを保証しません。保証するのは「多数回繰り返せば平均的に揃う」ことです。サンプルサイズが小さいと、偶然の偏りが残ります。だから**割当後に主要な属性の分布が揃っているかを必ず確認する**（バランスチェック）のが実務の手順です。

| 押さえるべき関係 | 内容 |
|---|---|
| 効果が小さいほど | 必要サンプルは効果の2乗に反比例して増える |

> 各群1,000人で「有意差なし」という結果が出ても、それは「効果がない」ことの証明ではありません。**そのサイズでは10%の改善すら検出できない**だけかもしれません。「有意差なし」を報告するときは、必ず「このテストで検出できた最小の効果は何%か」を併記してください。検出力の低いテストを根拠に施策を却下するのは、最もよくある意思決定の誤りです。

## p値を正しく理解する

p値ほど誤解されている統計量はありません。定義を正確に述べます。

```figure
  {"icon":"❌","title":"誤解③ 0.05 が神聖な境界","text":"p = 0.049 と p = 0.051 の間に本質的な違いはない。0.05 は慣習にすぎない。","tone":"bad"} ] }
```

> [!DS]
> 2016年、アメリカ統計協会（ASA）は p値に関する声明を発表し、「p値は仮説が真である確率を測るものではない」「p値だけで科学的結論やビジネス上の意思決定を下すべきではない」と明示しました。実務での結論はシンプルです。**p値ではなく、効果量とその信頼区間で報告する。** 「購入率は +0.7ポイント（95%信頼区間 +0.2 〜 +1.2ポイント）改善した」——この一文には、大きさ・向き・不確実性のすべてが含まれています。

## 平均への回帰

```figure
{ "type": "chart", "kind": "line", "title": "平均への回帰：低調な店舗を選んでテコ入れすると必ず改善する",
  "categories": ["前々月","前月（選定）","当月","翌月","翌々月"],
  "series": [
    {"name":"テコ入れ対象（前月に成績下位20%）","values":[98,72,89,94,97,0],"tone":"amber"},
    {"name":"何もしていない全店平均","values":[100,100,100,100,100,0],"tone":"gray"} ],
  "unit": "指数",
  "caption": "施策を何もしなくても、極端に悪かった集団は次期に平均へ戻る。この回復を「施策の効果」と読むのが最大の誤り。" }
```

前月に成績が悪かった店舗を選んでテコ入れすると、**何をしても改善します**。前月の悪さの一部は偶然（悪天候、たまたま重なった休業）であり、偶然は繰り返さないからです。これが平均への回帰です。

> [!TRAP] 「下位グループを選んで施策」は必ず成功して見える
> 逆に「上位グループを選んで表彰し、その後を見る」と、必ず成績が落ちます。表彰が悪影響を与えたのではありません。これは教育や人事評価でも起きる現象で、「褒めると調子に乗る、叱ると伸びる」という誤った経験則の正体でもあります。**極端な値で対象を選んだ時点で、比較対照群がなければ効果は測れません。** 同じ基準で選んだ対象をランダムに2群に分け、片方だけにテコ入れしてください。

## 実験できないときの差分の差分法

価格改定、店舗改装、地域限定キャンペーン——ランダム化できない施策は多くあります。そこで使うのが **差分の差分法（DID: Difference in Differences）** です。

```figure
{ "type": "chart", "kind": "line", "title": "差分の差分法：施策を受けていない地域を反事実の代わりにする",
  "categories": ["1月","2月","3月","4月(施策)","5月","6月"],
  "series": [
    {"name":"施策地域（実績）","values":[100,104,102,118,124,127],"tone":"blue"},
    {"name":"対照地域（実績）","values":[98,101,100,106,109,110],"tone":"gray"},
    {"name":"施策地域（施策がなかった場合の推定）","values":[100,104,102,108,111,112],"tone":"amber"} ],
  "unit": "指数",
  "caption": "施策地域は +25 伸びたが、対照地域も +10 伸びている。差の差 = 25 − 10 = 15 が施策の効果。前後比較だけなら +25 と過大評価していた。" }
```

計算は引き算2回です。

```text
施策地域の変化 = 127 − 102 = +25
対照地域の変化 = 110 − 100 = +10
施策の効果 = (+25) − (+10) = +15
```

```dax
// 差分の差分（DID）メジャー
DID_効果 :=
VAR 施策後 = CALCULATE( [売上指数], Dim_期間[区分] = "施策後" )
VAR 施策前 = CALCULATE( [売上指数], Dim_期間[区分] = "施策前" )
VAR 対照後 = CALCULATE( [売上指数], Dim_期間[区分] = "施策後", Dim_地域[群] = "対照" )
VAR 対照前 = CALCULATE( [売上指数], Dim_期間[区分] = "施策前", Dim_地域[群] = "対照" )
RETURN
    ( 施策後 - 施策前 ) - ( 対照後 - 対照前 )
```

> [!NOTE] 要点
> 差分の差分法が成り立つ条件は **平行トレンド仮定** です。「施策がなければ、両群は同じ傾きで動いたはずだ」という前提です。これは検証できませんが、**施策前の期間で両群のトレンドが平行だったかを必ずグラフで確認**します。上の図では1〜3月に両群がほぼ平行に動いており、仮定は妥当だと判断できます。施策前から傾きが違うなら、DIDは使えません。

## どの検定を使うか

Power BI で検定統計量まで計算することは多くありませんが、**どの指標にどの検定が対応するか**は知っておく必要があります。分析チームや外部ベンダーの報告を読むときに必要になります。

| 比較したいもの | 代表的な手法 | 注意点 |
|---|---|---|
| 比率どうし（購入率・クリック率） | 2標本のz検定、カイ二乗検定 | 各群の期待件数が5未満だと近似が崩れる |
| 平均どうし（客単価・滞在時間） | 2標本のt検定（Welch法） | 分散が違ってよいWelch法を既定にする |
| 歪んだ分布の中心（購入金額） | マン・ホイットニーのU検定 | 順位に置き換えるので外れ値に強い |
| 継続期間（解約までの日数） | ログランク検定 | 打ち切りデータを正しく扱える |
| 3群以上 | 分散分析 + 多重比較補正 | 補正なしで総当たり比較をしない |

```figure
  "xLow": "対称・二値", "xHigh": "強く歪む", "yLow": "比率", "yHigh": "連続量",

```

> [!TRAP] 売上金額の平均で A/B テストを判定しない
> 購入金額は右に強く歪みます（L1501）。数万人のテストでも、片方の群にたまたま1件の超大型注文が入るだけで、平均が逆転します。**売上を主要指標にするなら、①購入率（比率）と②購入者あたり金額（中央値）に分解する**か、上位0.1%を一律の上限値で丸める（winsorize）処理を事前に決めておいてください。「事前に」が重要です。結果を見てから外れ値を除くと、それは分析ではなく作文です。

## 多重比較と事前登録

セグメントを10個作って結果を見れば、どこかの層で「有意な改善」が必ず見つかります。5%水準で10回比較すれば、本当は効果ゼロでも約40%の確率でどれかが有意になります。

```figure
{ "type": "chart", "kind": "bar", "title": "比較の回数と「偶然に有意が1つ以上出る確率」（真の効果がゼロのとき）",
  "categories": ["1回","3回","5回","10回","20回","50回"],
  "series": [{"name":"偽陽性が出る確率","values":[5,14,23,40,64,92],"tone":"bad"}],
  "unit": "%", "highlight": 3,
  "caption": "10セグメントを見れば4割の確率で「効いた層」が見つかる。それは発見ではなく偶然。" }
```

対策は3つです。

1. **事前登録**：見るセグメントと指標を、テスト開始前に文書化する
2. **補正**：ボンフェローニ補正（有意水準を比較回数で割る）などを適用する
3. **再現確認**：見つかった効果を、別期間・別セグメントで再テストする

> [!TIP] 実務のコツ
> 探索的にセグメントを掘ること自体は有益です。禁じられているのは、**掘って見つけたものを「検証済みの結論」として報告すること**です。「探索の結果、若年層で効果が大きい可能性が見えた。次のテストでこれを主要仮説として検証する」——この書き方なら誠実であり、次の行動にもつながります。

## 短期の勝ちと長期の負け

テスト期間中は指標が改善しても、長期では悪化する施策があります。

| 施策 | 短期に上がるもの | 長期に下がるもの |
|---|---|---|
| 通知の増加 | クリック率、当月の訪問数 | 通知オフ率、アンインストール率 |
| 強引なポップアップ | 会員登録数 | 離脱率、ブランド評価 |
| 大幅な値引き | 当月売上、購入率 | 粗利、定価での購入意欲 |
| おすすめの多様性削減 | 直近のクリック率 | 新商品の発見、長期の購入頻度 |

> [!WARN] 注意
> これを検出するには、**ホールドアウト群を長期間残す**しかありません。全体の1〜5%を「何の施策も受けない群」として数か月〜1年維持し、施策を受け続けた集団と比較します。短期テストの積み上げだけを続けると、個々のテストはすべて勝っているのに、事業全体の指標が下がっていく——という現象が起きます。

```dax
// 群別の指標とリフト
購入率 := DIVIDE( DISTINCTCOUNT( Fact_イベント[購入ユーザーID] ), DISTINCTCOUNT( Dim_割当[ユーザーID] ) )

購入率_対照群 := CALCULATE( [購入率], Dim_割当[群] = "A" )
購入率_処置群 := CALCULATE( [購入率], Dim_割当[群] = "B" )

絶対リフト := [購入率_処置群] - [購入率_対照群]
相対リフト := DIVIDE( [絶対リフト], [購入率_対照群] )

// 差の95%信頼区間（比率の差の標準誤差）
差の標準誤差 :=
VAR pA = [購入率_対照群]
VAR pB = [購入率_処置群]
VAR nA = CALCULATE( DISTINCTCOUNT( Dim_割当[ユーザーID] ), Dim_割当[群] = "A" )
VAR nB = CALCULATE( DISTINCTCOUNT( Dim_割当[ユーザーID] ), Dim_割当[群] = "B" )
RETURN
    SQRT( DIVIDE( pA * ( 1 - pA ), nA ) + DIVIDE( pB * ( 1 - pB ), nB ) )

差_下限95 := [絶対リフト] - 1.96 * [差の標準誤差]
差_上限95 := [絶対リフト] + 1.96 * [差の標準誤差]
```

> [!TIP] 実務のコツ
> 実験レポートの1ページ目には、**「割当比率」「サンプル数」「主要指標の差と信頼区間」「ガードレール指標」の4つだけ**を置きます。セグメント別の内訳は2ページ目以降にドリルスルーで用意してください。1ページ目にセグメント別の表を置くと、必ず誰かが「この層では効果が出ている」と言い出し、多重比較の罠にはまります。

## まとめ

- 前後比較は効果の証拠にならない。反事実を用意する
- ランダム化は、測っていない交絡変数まで揃える唯一の一般的手段
- テスト開始前に、主要指標・サンプル数・終了条件を決めて書く
- p値は「効果がない確率」ではない。効果量と信頼区間で報告する
- 統計的有意と実務的な意味は別。導入基準を事前に決める
- ピーキング・SRM・干渉・新奇性効果を点検する
- 極端な集団を選んだ施策は、平均への回帰で必ず成功して見える
- 実験できないときは差分の差分法。平行トレンドを図で確認する
- 実験レポートには健全性チェックを必ず載せる
