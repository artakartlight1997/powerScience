## 条件の合成

```dax
-- OR：同じ列の複数値
CALCULATE( [売上合計], Dim_商品[Category] IN { "家電", "食品" } )

-- AND：違う列（引数を分ける）
CALCULATE( [売上合計], Dim_商品[Category] = "家電", Dim_店舗[Region] = "関東" )

-- OR：違う列どうし（複数列の表を FILTER に渡す）
CALCULATE( [売上合計],
    FILTER( ALL( Dim_商品[Category], Dim_店舗[Region] ),
        Dim_商品[Category] = "家電" || Dim_店舗[Region] = "関東" ) )
```

    {"title":"難しい","tone":"amber","note":"実務では設計を見直す","items":[

> [!TIP] 反復対象は最小の表にする
> `FILTER( Fact_売上, … )` を書きそうになったら、ディメンション側で書けないか先に考えます。

> [!EXAM] PL-300で問われる
> 行の条件を保つ＝KEEPFILTERS、メジャー条件＝FILTER、単一列＝述語。`FILTER( Fact_売上, … )` は不適切選択肢。

## 理解度チェック

**問1.** `CALCULATE( [売上合計], Dim_商品[Category] = "家電" )` が全行52になる仕組みを述語の展開で説明せよ。

<details><summary>答え</summary>
述語は `FILTER( ALL( Dim_商品[Category] ), … = "家電" )` に展開される。`ALL` が行の条件を外すため、どの行も家電になる。
</details>

**問2.** 価格帯スライサーがあるのに「定価5万円以上の売上」が反応しない。原因と対処は。

<details><summary>答え</summary>
述語が ListPrice 列の既存フィルターを上書きしているため。`KEEPFILTERS( Dim_商品[ListPrice] >= 50000 )` で包むと選択と交差する。
</details>

**問3.** `FILTER( Fact_売上, RELATED( Dim_商品[Category] ) = "家電" )` の問題点は。

<details><summary>答え</summary>
ファクト全体を1行ずつ反復するため非常に遅い。同じ結果は述語 `Dim_商品[Category] = "家電"` で得られ、こちらは桁違いに速い。
</details>

## よくあるエラーと原因

| 症状・エラー | 原因 | 対処 |
|---|---|---|
| スライサーが効かないメジャー | 同じ列を述語で上書き | `KEEPFILTERS` で包む |
| 該当しない行にも値が出る | 上書きの既定動作 | 空白にしたければ `KEEPFILTERS` |
| 「単一の列を参照する必要があります」 | 述語に複数列を書いた | 引数を分けるか `FILTER` |
| ビジュアルが数十秒かかる | `FILTER( Fact_売上, … )` | 述語に書き換える／`VALUES( 列 )` |
| `FILTER` 内のメジャーが全体値 | 反復対象が1行の表 | `VALUES( 列 )` や `ALL( 列 )` を渡す |
| KEEPFILTERSで結果が変わらない | 別の列で衝突がない | 正常。衝突時のみ効果がある |
| 違う列どうしのORが書けない | 述語では表現できない | 複数列の表を `FILTER` に渡す |
