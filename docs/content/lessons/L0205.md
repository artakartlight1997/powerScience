「ダッシュボードを作ってください」と依頼されたとき、Power BI で何を作ればよいか即答できますか。Power BI において**ダッシュボードとレポートは別物**であり、作り方も置き場所も違います。

用語が曖昧なままだと、要件定義の段階で食い違い、作り直しになります。このレッスンでモジュール2の締めくくりとして、用語とファイル形式を確定させます。

## セマンティックモデルとは何か

**セマンティックモデル**は、以前は「データセット」と呼ばれていたものです。名称が変わったのは、単なるデータの集まりではなく**「意味（セマンティクス）を持つ層」**だからです。

```figure
{ "type": "cards", "cols": 4, "title": "セマンティックモデルが保持するもの",
  "caption": "データだけでなく「意味の定義」が入っている点が重要",
  "items": [
    {"icon":"🗄","title":"データ本体","text":"インポートの場合、圧縮されたテーブルの実データ","tone":"blue"},
    {"icon":"🔗","title":"リレーションシップ","text":"表どうしの繋がりと、フィルターが流れる向き","tone":"green"},
    {"icon":"🧮","title":"メジャー・計算列","text":"DAXで書かれた計算の定義。「売上とは何か」がここにある","tone":"amber"},
    {"icon":"🏷","title":"メタデータ","text":"表示名、書式、階層、非表示設定、説明文、RLSロール","tone":"violet"} ] }
```

このモデルが「共通言語」になります。1つのモデルに複数のレポートがぶら下がる構成にすれば、**どのレポートを見ても「売上」は同じ計算**になります。組織でBIを機能させる鍵はここにあります。

> [!NOTE] 名称変更の歴史を知っておく
> 公式ドキュメントや古い記事では「データセット(Dataset)」という語が使われています。**データセット＝セマンティックモデル**と読み替えてください。同様に「アプリのワークスペース」は現在の「ワークスペース」、「Power BI Premium」の一部は「Fabric容量」に整理されました。用語の変遷を知っていると、古い記事も読めるようになります。

## 3つのファイル形式

### pbix — 標準形式

保存すると自動的にこの形式になります。**データも一緒に入る**ため、100万行のデータを取り込んだpbixは数十MBになります。逆に言えば、pbixファイルを渡すことは**中のデータをすべて渡すこと**を意味します。

> [!WARN] pbixの受け渡しは情報漏えいのリスク
> 「レポートの作り方を見せてほしい」と言われてpbixを送ると、取り込んだ顧客データもすべて渡ることになります。フィルターで隠していても、モデルの中には全行が残っています。**構造だけを渡したいならpbitを使ってください。**

### pbit — テンプレート

「ファイル → 名前を付けて保存 → Power BI テンプレート(.pbit)」で作れます。データを含まないため軽量です。

```figure
{ "type": "steps", "title": "pbitが役立つ3つの場面",
  "items": [
    {"title":"店舗ごとに同じレポートを配る","text":"接続先のフォルダやサーバ名をパラメータにしておけば、開いた人が自分の環境の値を入れるだけで完成する。","tone":"blue"},

```

### pbip — プロジェクト形式（Git向け）

pbix はバイナリファイルのため、Git で管理しても「何が変わったか」が分かりません。**pbip 形式**で保存すると、レポート定義とモデル定義がテキストファイル群としてフォルダに展開されます。

> [!DS] 再現可能性とバージョン管理
> 分析の世界では、**「同じ入力から同じ結果が再現できること」**が品質の基礎です。ソフトウェア開発ではGitによるバージョン管理が当たり前ですが、BIやデータ分析の領域では長く「最終版_v3.pbix」文化が続いてきました。pbip形式やノートブックの普及は、分析作業をソフトウェア開発と同じ工学的な規律に乗せる動きの一部です。「誰が、いつ、なぜ、この指標定義を変えたか」が追跡できることは、数字への信頼そのものを支えます。

## ファイルサイズはどこから来るのか

pbix ファイルが大きくなる理由を理解すると、後の性能改善の土台になります。pbix の中身は、圧縮されたデータとメタデータのアーカイブです。

```figure
{ "type": "chart", "kind": "hbar", "title": "pbixのサイズを決める要素（典型例）",
  "caption": "サイズの大半は「値の種類が多い列」が占める。行数そのものより列の性質が効く",
  "categories": ["高カーディナリティ列","日時列（秒まで保持）","テキスト列","低カーディナリティ列","レポート定義"],
  "series": [{"name":"サイズ寄与","values":[45,25,18,8,4],"tone":"amber"}],
  "highlight": 0, "unit": "%" }
```

**カーディナリティ**とは、その列に含まれる値の種類の数です。OrderID のように全行で異なる値を持つ列はカーディナリティが最大で、圧縮がまったく効きません。逆に Category 列は3種類しかないため、極めて高い圧縮率になります。

```figure
{ "type": "compare", "title": "モデルを軽くする基本方針",
  "caption": "ティア3で本格的に扱うが、原則はティア1のうちに知っておく価値がある",
  "panels": [

     "note":"サイズと速度が悪化"},
    {"title":"軽くなる作り方","tone":"good","items":[

     "note":"推奨"} ] }
```

> [!TIP] 最初から全部取り込まない
> 「とりあえず全列を取り込んで、あとで考える」は最も高くつく判断です。**Power Queryの段階で不要な列を削除する**だけで、モデルサイズも更新時間も劇的に改善します。M04で列の削除を扱いますが、その操作にはこれだけの意味があります。

## まとめ

- Power BI は「データソース → セマンティックモデル → レポート → ダッシュボード」の4層構造
- レポートは複数ページで対話でき、探索が目的。ダッシュボードは1ページでService専用、監視が目的
- セマンティックモデル（旧データセット）はデータ・リレーションシップ・メジャー・メタデータを保持する「意味の層」
- pbix はデータ込みの標準形式。渡すとデータも渡ることになる
- pbit はテンプレート。データを含まないので雛形配布と構造共有に使う
- pbip はフォルダ形式でテキスト管理でき、Gitによるチーム開発に対応する
- 「ダッシュボードを作って」の依頼の多くは、実際にはレポートを指している。必ず用途を確認する

## 理解度チェック（自分に説明してみる）

1. レポートとダッシュボードの違いを4点挙げ、「毎朝、在庫切れの商品数を見張りたい」という要件にはどちらが適切か説明してください。
2. 作成したレポートの構造だけを社外のパートナーに共有したい。どのファイル形式で渡すべきか、その理由とともに説明してください。
3. セマンティックモデルには何が保持されているかを4つ挙げ、「1つのモデルに複数レポートをぶら下げる」構成の利点を説明してください。
