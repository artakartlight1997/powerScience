Power BI では**ダッシュボードとレポートは別物**です。作り方も置き場所も違います。

用語が曖昧なままだと要件定義で食い違い、作り直しになります。ここで用語とファイル形式を確定させます。

## 用語の対応表と、何を作るかの判断

| 用語 | 意味 | どこにある |
|---|---|---|
| レポート | 対話できる複数ページの分析画面 | Desktop / Service |
| ビジュアル | グラフやカード1つ | ページ内 |
| ダッシュボード | タイルを集めた1画面の監視盤 | Serviceのみ |
| タイル | ダッシュボードに貼られたパネル | ダッシュボード内 |
| セマンティックモデル | データ・関係・計算の定義（旧データセット） | Desktop / Service |
| ワークスペース | アイテムを置く場所であり権限の単位 | Serviceのみ |
| アプリ | ワークスペースの内容を整えて配る公開版 | Serviceのみ |

## まとめ

- 4層はデータソース→セマンティックモデル→レポート→ダッシュボード
- レポートは複数ページで対話でき探索が目的。ダッシュボードは1ページで監視が目的
- セマンティックモデルはデータ・関係・メジャー・メタデータを持つ意味の層
- pbixはデータ込みの標準形式。渡すとデータも渡る
- pbitはテンプレート。雛形配布と構造共有に使う
- pbipはフォルダ形式でテキスト。Gitによるチーム開発に対応する
- 「ダッシュボードを作って」の多くは実際にはレポート。必ず用途を確認する

## 理解度チェック

1. レポートとダッシュボードの違いを4点挙げ、「在庫切れ数を毎朝見張る」にはどちらが適切か。
2. 構造だけを社外に共有したい。どの形式で渡しますか。理由も述べてください。
3. セマンティックモデルが持つものを4つ挙げ、1モデル複数レポート構成の利点を説明してください。
