色は視覚属性のなかで最も注意を引きます。だからこそ、**最も誤用される属性**でもあります。

虹色に塗られたレポートは、色を使っているのに情報を一切伝えていません。色に意味を持たせるには、「どの色が何を意味するか」の対応表を先に決め、最後まで守る必要があります。このレッスンでは配色の理論、色覚多様性への対応、そしてテーマJSONによる組織全体への統一を扱います。

> 「きれいにするため」は色を使う理由になりません。**識別・量・強調**のどれにも当てはまらない色は、必ずグレーか単色に置き換えられます。

## 3種類のカラーパレット

データの尺度によって、使うべきパレットの型が決まります。ここを間違えると、色が嘘をつきます。

```figure
{ "type":"cards", "cols":3, "title":"パレットの3類型",
  "caption":"データの尺度に対応する。混同すると読み手が誤った量的関係を読み取る",
  "items":[
    {"icon":"🎨","title":"カテゴリカル（質的）","text":"順序のないカテゴリに。色相を変え、明度はそろえる。使うのは最大6色まで。部門・製品・地域など","tone":"blue"},
    {"icon":"🌡","title":"シーケンシャル（連続）","text":"0から大きくなる量に。1つの色相で明度・彩度を段階変化させる。売上金額、件数など","tone":"green"},
    {"icon":"↔","title":"ダイバージング（発散）","text":"中央値・目標値からの±に。2色相を両端に置き、中央を無彩色に。予算差異、前年比など","tone":"amber"} ] }
```

```figure
{ "type":"compare", "title":"パレットの誤用",
  "caption":"色の型はデータの型に従う。逆はない",
  "panels":[
    {"title":"連続量にカテゴリカル配色","tone":"bad",
     "items":["売上の大小を赤・青・緑・黄で塗る","色の間に順序がないため、大小関係が読めない","虹色（レインボー）カラーマップも同じ理由で不適切"],
     "note":"量が伝わらない"},
    {"title":"連続量にシーケンシャル配色","tone":"good",
     "items":["薄い青 → 濃い青 の一方向で塗る","明度の順序がそのまま量の順序として読める","印刷してグレースケールになっても順序が保たれる"],
     "note":"推奨"} ] }
```

> [!DS] データサイエンス視点：虹色カラーマップが批判される理由
> 気象図や科学論文で長く使われてきた虹色（jet / rainbow）カラーマップは、現在では推奨されません。理由は 3 つあります。(1) **知覚的に均等でない**：色の変化量と値の変化量が一致せず、黄色の付近だけ急に変わって見えるため、存在しない境界が生まれる。(2) **順序が直感的でない**：赤と青のどちらが大きいのか、凡例なしには判断できない。(3) **色覚多様性で崩壊する**：赤緑の判別が難しい人には、まったく別の分布に見える。
>
> 代替として、明度が単調に変化する**知覚的均等カラーマップ**（viridis、cividis、magma など）が使われます。Power BI の条件付き書式でも、**最小値を白または非常に薄い色、最大値を濃い単色**に設定すれば、同じ性質を得られます。

```figure
  "categories":["直営","EC","代理店","法人","海外","卸","その他"],
  "series":[{"name":"売上","values":[98,131,146,182,44,61,22]}],

```

```figure
{ "type":"chart", "kind":"bar", "title":"1色＋強調に減らした同じデータ",
  "caption":"注目させたい1本だけ色を変え、他はグレー。主張が一瞬で伝わる",
  "categories":["直営","EC","代理店","法人","海外","卸","その他"],
```

**カテゴリ名が軸ラベルに書いてあるなら、色でカテゴリを区別する必要はありません**。この単純な事実に気づくだけで、レポートの色数は半分以下になります。

> 棒グラフで特定の 1 本だけ色を変えるには、書式ペインの **「列」→「色」→ fx（条件付き書式）→ 書式スタイル「ルール」** を使います。「値が最大のとき青、それ以外グレー」といった DAX メジャーによる指定も可能で、データが変わっても自動的に最大値が強調されます。

## 色覚多様性 — 20人に1人は同じ色に見えていない

日本人男性の約 5%、白人男性では約 8% が何らかの色覚特性を持ちます。最も多いのは **赤と緑の区別が難しい型（1型・2型色覚）** です。100 人が見るレポートなら、2〜3 人は赤緑の対比を読めないと考えるべきです。

```figure
{ "type":"compare", "title":"色だけに頼る表現と、形も併用する表現",
  "caption":"色は補助。意味の本体は形・位置・ラベルに載せる",
  "panels":[
    {"title":"色だけで意味を表す","tone":"bad",
     "items":["赤＝未達、緑＝達成 のセル背景のみ","凡例に『赤：要対応』とだけ書く","折れ線を赤と緑の2本で描き分ける"],
     "note":"色覚特性のある読み手には判別不能"},
    {"title":"色＋形／記号／ラベル","tone":"good",
     "items":["背景色に加えて ▲▼ のアイコンを添える","数値そのもの（-12%）を必ず表示する","線種を実線と破線で分ける／直接ラベルを置く"],
     "note":"誰でも読める（冗長符号化）"} ] }
```

> [!DS] データサイエンス視点：冗長符号化（redundant encoding）
> 1 つの情報を **2 つ以上の視覚属性で同時に表す**ことを冗長符号化と呼びます。色＋形、色＋位置、色＋テキストラベル。冗長という語は無駄を連想させますが、可視化では**堅牢性**を意味します。片方の経路が使えない読み手（色覚特性、白黒印刷、プロジェクターの発色不良）でも情報が届くからです。アクセシビリティ対応は特別な配慮ではなく、単に壊れにくい設計です。

```figure
{ "type":"cards", "cols":2, "title":"色覚多様性に強い配色の作り方",
  "caption":"赤緑を対比に使わない、が最重要ルール",
  "items":[
    {"icon":"🔵","title":"青とオレンジを対比に使う","text":"最も安全な2色対比。1型・2型色覚でも明確に区別できる。予算＝グレー、実績＝青、警告＝オレンジが実務の定番","tone":"blue"},
    {"icon":"◐","title":"明度差を必ずつける","text":"色相が判別できなくても、明るさの差は全員が読み取れる。グレースケールに変換して区別できるかを確認する","tone":"gray"},
    {"icon":"🔺","title":"形・記号を併用する","text":"達成 ●／未達 ▲ のように記号を変える。Power BI の条件付き書式のアイコンセットで実現できる","tone":"green"},
    {"icon":"🖨","title":"白黒印刷で検証する","text":"印刷プレビューをグレースケールにして読めるか確認する。これが最も手軽な色覚チェックになる","tone":"amber"} ] }
```

> [!WARN] 注意
> 赤＝悪い、緑＝良い は文化的な慣習であり、金融の一部地域では逆の意味を持ちます。また色覚特性のある読み手には成立しません。**赤緑の意味づけは補助に留め、数値と記号を主役にする**のが安全です。

## コントラスト比 — 読めるかどうかは測れる

文字と背景の明るさの比を**コントラスト比**と呼びます。1:1（同色）から 21:1（黒と白）までの数値で表され、可読性の基準になります。

```figure
{ "type":"steps", "title":"コントラスト比の基準と確認",
  "caption":"WCAG（Webアクセシビリティ指針）の基準がそのまま使える",
  "items":[
    {"title":"通常サイズの文字：4.5:1 以上","text":"本文・軸ラベル・データラベル。薄いグレー文字は高確率でこの基準を割る","tone":"blue"},
    {"title":"大きい文字（18pt以上・太字14pt以上）：3:1 以上","text":"KPIカードの数字や見出しはこちらの基準","tone":"green"},
    {"title":"グラフの要素同士：3:1 以上","text":"隣接する2つの塗り色が近すぎると境界が見えない","tone":"amber"},
    {"title":"確認方法","text":"コントラスト比を計算するツールに16進カラーコードを2つ入れる。社内の標準色は一度測って表にしておく","tone":"violet"} ] }
```

> [!TRAP] つまずきポイント
> ブランドカラーが淡いパステル調の企業では、**そのまま使うとほぼすべての文字が基準を割ります**。対策は「ブランドカラーは面（背景・帯・アクセント）に使い、文字と細い線には濃い派生色を使う」ことです。ブランドガイドラインとアクセシビリティは、色を使う場所を分ければ両立します。

## テーマJSON — 組織全体で配色を固定する

レポートごとに色を選んでいると、部署間で同じ「売上」が別の色になります。Power BI では **テーマJSON** を読み込むことで、配色・フォント・既定の書式をまとめて固定できます。

## 色と意味の対応表を先に作る

配色で失敗する組織に共通するのは、「作りながら色を決めている」ことです。**色は先に決め、表にして共有します**。

```figure
{ "type":"tablediff", "arrowLabel":"対応表を決めてから作る",
  "before":{"title":"レポートごとに場当たりで決める","tone":"bad",
    "head":["レポート","予算","実績","前年"],
    "rows":[["営業ダッシュボード","青","オレンジ","緑"],["経営会議用","グレー","青","赤"],["店舗別分析","緑","紫","黄"]]},
  "after":{"title":"全社カラーマッピング表","tone":"good",
    "head":["意味","色","使う場所"],
    "rows":[["!実績","!#2E6FD9（青）","棒・線の主系列"],["予算・目標","#9AA3AE（グレー）","参照線・薄い棒"],["前年同期","#C9D2DB（薄グレー）","背景の比較系列"],["注意・未達","#C0492F（赤茶）","アイコンと数値のみ"],["良好・達成","#2E7D5B（緑）","アイコンと数値のみ"]]} }
```

この表を 1 枚作り、テーマJSON の `dataColors` の並び順と対応させておけば、誰が作っても同じ色になります。**色の意味は組織の共通言語**であり、レポート単位で決めるものではありません。

> [!TIP] 実務のコツ
> `dataColors` の**並び順が重要**です。Power BI は系列に対して配列の先頭から順に色を割り当てます。最も頻繁に使う「実績」の色を配列の先頭に置いておけば、単一系列のグラフは何も設定しなくても正しい色になります。

## 理解度チェック

1. 「売上金額の大きさ」をヒートマップで表す。カテゴリカルパレット（赤・青・緑・黄）を使ってはいけない理由を述べよ。
2. 達成／未達をセルの背景色（緑／赤）だけで表現した表がある。この設計の問題点と、具体的な改善案を 2 つ挙げよ。
3. 組織の全レポートで「予算はグレー、実績は青」を徹底したい。最も確実な方法と、その運用上のルールを述べよ。

<details>
<summary>解答の要点</summary>

1. 売上金額は**連続量**であり、大小の順序を持つ。カテゴリカルパレットは色相を変えるだけで**明度に順序がない**ため、赤と青のどちらが大きいのかを凡例なしに読み取れない。連続量には 1 つの色相で明度が単調に変化するシーケンシャルパレット（薄い青 → 濃い青）を使う。虹色カラーマップも知覚的に均等でないため同じ理由で不適切。
2. 問題点は**色だけに意味を載せている**こと。赤緑の判別が難しい読み手（男性の約 5%）、白黒印刷、投影時の発色不良で情報が完全に失われる。改善案：(1) 背景色に加えて ▲▼ などのアイコンを併記する（冗長符号化）。(2) 差異の数値そのもの（-12%）をセルに表示する。(3) 赤緑ではなく青とオレンジの対比に変える、も可。
3. **テーマJSON を作成して配布する**。`dataColors` の並び順と `good`/`bad`/`neutral` を定義し、`.pbit` テンプレートに読み込んだ状態で共有フォルダーに置く。運用ルールとして「レポート内で色を手動指定しない」を定め、レビュー時に手動指定を差し戻す。色を変えたい要求が出たらテーマ側を改訂する。

</details>
