正確なグラフを10枚並べても、人は動きません。動くのは「**だから、何をすべきか**」が腹落ちしたときだけです。

データストーリーテリングは、感情に訴える技術ではありません。**意思決定者の頭の中に、判断に必要な文脈を正しい順序で構築する技術**です。順序が違うだけで、同じデータが伝わらなくなります。

```figure
{ "type":"flow", "dir":"row", "title":"ストーリーアークの4要素", "caption":"この順序を崩すと、聞き手は「で？」と言う",
  "items":[
    {"label":"① 状況","sub":"共通認識。合意できる事実から始める","tone":"blue"},
    {"label":"② 変化","sub":"何が起きたか。緊張を作る","tone":"amber"},
    {"label":"③ 示唆","sub":"それが何を意味するか","tone":"violet"},
    {"label":"④ 行動","sub":"だから何をするか。判断を求める","tone":"good"} ] }
```

> [!NOTE] 要点
> ①で**必ず相手が同意できる事実**から始めてください。いきなり②の「売上が落ちています」から入ると、聞き手は防御的になり、数字の粗探しが始まります。「今期の目標は前年比+8%でした」という合意可能な前提から入ると、同じ話が協調的な議論になります。

## 報告型と物語型

```figure
{ "type":"compare", "title":"同じ分析、2つの伝え方", "caption":"情報は同じ。違うのは順序と、結論があるかどうか",
  "panels":[
    {"title":"報告型（データの羅列）","tone":"bad",
     "items":["「売上の月次推移です」","「カテゴリ別の内訳です」","「地域別も出しました」","「以上です。何かご質問は」"],
     "note":"聞き手が自分で結論を作る必要がある"},
    {"title":"物語型（結論への道筋）","tone":"good",
     "items":["「今期目標は+8%でした（状況）」","「実績は-6.2%。9月から急に落ちています（変化）」","「原因は国内直営の客数減で、ECは伸びています（示唆）」","「直営10店で来店施策を2週間テストしたい（行動）」"],
     "note":"判断を求められている"} ] }
```

物語型の決定的な違いは、**最後に判断を求めている**ことです。報告は聞き流せますが、判断を求められた人は考えます。

> [!TRAP] つまずきポイント
> 「事実をお伝えするのが分析者の仕事で、判断は経営がすること」——この態度は一見謙虚ですが、実際には**最も文脈を知る人が判断材料を作らずに丸投げしている**状態です。提案が間違っていても構いません。叩き台があれば議論が始まります。「私はこう考えます、根拠はこれです」まで言い切ってください。

## アクションタイトル — 1スライド1メッセージ

タイトルは分類名を書く場所ではありません。**そのページで最も伝えたい1文**を書く場所です。

```figure
{ "type":"compare", "title":"タイトルの書き換え例", "caption":"タイトルだけ読めば全体が分かる状態を目指す",
  "panels":[
    {"title":"分類ラベル","tone":"bad",
     "items":["「月次売上推移」","「カテゴリ別分析」","「地域別実績」","「顧客セグメント」"],
     "note":"読まないと分からない"},
    {"title":"アクションタイトル","tone":"good",
     "items":["「売上は9月から3か月連続で前年割れ」","「減少の8割は家電カテゴリに集中」","「西日本のみ増加、要因は新規出店」","「休眠顧客が前年比1.4倍に増加」"],
     "note":"タイトルだけで筋が通る"} ] }
```

各ページのタイトルを縦に並べて読んだとき、それが**そのまま報告の要約になっている**——これが良い構成のテストです。並べて意味が通らないなら、構成に問題があります。

```figure
{ "type":"steps", "title":"タイトルを書く4手順", "caption":"グラフを作ってからタイトルを考えるのではなく、逆にする",
  "items":[
    {"title":"1. 主張を1文で書く","text":"「何が」「どうなった」を含める。数字を1つ入れる","tone":"blue"},
    {"title":"2. その主張を支えるグラフを選ぶ","text":"主張が先、ビジュアルが後。主張が読めないグラフは差し替える","tone":"green"},
    {"title":"3. 主張に関係ない要素を消す","text":"グラフ内に主張と無関係な系列があるなら除く","tone":"amber"},
    {"title":"4. 主張の箇所を強調する","text":"該当する棒・期間だけを色付けし、注釈を添える","tone":"violet"} ] }
```

```figure
  "categories":["4月","5月","6月","7月","8月","9月","10月","11月","12月"],
  "series":[
    {"name":"当年","values":[108,112,109,115,111,96,92,89,91],"tone":"blue"},
    {"name":"前年","values":[102,105,104,106,103,104,107,105,108],"tone":"gray"} ],
  "highlight":5, "unit":"百万円" }
```

```figure
{ "type":"cards", "cols":2, "title":"視線を誘導する4つの手段", "caption":"Power BIの標準機能だけで全部実現できる",
  "items":[
    {"icon":"🎯","title":"色の限定","text":"注目箇所だけ濃色、他はグレー。条件付き書式のDAXで制御する","tone":"blue"},
    {"icon":"📝","title":"テキスト注釈","text":"グラフの上に直接「9月：主力商品の欠品」と書く。テキストボックスかシェイプ","tone":"green"},

    {"icon":"🔲","title":"領域の強調","text":"期間を薄い矩形で囲む。透明度を上げたシェイプを重ねる","tone":"violet"} ] }
```

> [!TIP] 実務のコツ
> 注釈は**必ずデータの近くに置く**こと。凡例の下や欄外に書くと読まれません。可能なら折れ線の該当ポイントの真横に配置します。近接のゲシュタルト原則が働き、「この注釈はこの点の説明だ」と説明抜きで伝わります。

## 構成のパターンを3つ持つ

状況によって使い分けます。

```figure
{ "type":"cards", "cols":3, "title":"3つの構成パターン", "caption":"聞き手の姿勢と時間で選ぶ",
  "items":[
    {"icon":"⏱","title":"時系列型","text":"「こうなって、こうなって、今こう」。経緯の共有が必要なときに有効。長くなりやすい","tone":"blue"},
```

日常の報告では**結論先出し型**が基本です。ただし、聞き手が強い先入観を持っていて結論から言うと反発される場合は、発見追体験型で「一緒に発見する」形にすると受け入れられやすくなります。

```figure
    {"title":"データに強い決裁者","text":"結論に加え、前提・限界・代替仮説を用意。突っ込まれる前に自分で示す","tone":"amber"},
    {"title":"現場担当","text":"「明日から何が変わるか」を具体的に。手順と対象リストを添える","tone":"green"},
    {"title":"分析担当・同業者","text":"手法と再現性を共有。データと計算式を開示する","tone":"blue"} ] }
```

## 数字を相手の単位に翻訳する

「粗利率が1.2ポイント低下」は、営業部長にとって実感を伴いません。翻訳が必要です。

```figure
{ "type":"formula", "lang":"text", "title":"数字の翻訳",
  "code":"粗利率 -1.2pt = 年間 -1億4400万円 = 営業所2つ分の年間利益 = 新規顧客480社分",
  "parts":[
    {"match":"粗利率 -1.2pt","label":"分析の言葉。正確だが実感がない","tone":"gray"},
    {"match":"年間 -1億4400万円","label":"金額への換算。まず金額にする","tone":"amber"},
    {"match":"営業所2つ分の年間利益","label":"相手が日常で扱う単位に翻訳","tone":"good"},
    {"match":"新規顧客480社分","label":"努力量への翻訳。行動につながる","tone":"pink"} ] }
```

> [!DS] データサイエンス視点：ナラティブは強力であり、危険でもある
> 人は物語を通してしか複雑な情報を記憶できません。しかし同時に、物語は**確証バイアス**（自分の仮説に合う証拠だけを集める傾向）と**アンカリング**（最初に見た数字に判断が引きずられる現象）を強力に増幅します。「筋の通った物語」ほど、反証データが無視されやすくなります。だからこそ、ストーリーを組んだ後には必ず**「この物語に反する証拠は何か」を自分で探す工程**を入れてください。反証を1つも見つけられない分析は、探し方が甘いだけです。

## Power BI での実装手段

ストーリーテリングは、資料作成の技術であると同時にレポート実装の技術でもあります。

| やりたいこと | Power BI での実装 |
|---|---|
| ページを順に見せる | ページナビゲーションボタン、ブックマークナビゲーター |
| 段階的に要素を出す | ブックマークで表示/非表示を切り替え、ボタンで進める |
| 主張をタイトルに書く | DAXメジャーを作り、タイトルの「fx」から条件付き書式で適用 |
| 注釈を添える | テキストボックス、シェイプ。ブックマークで表示制御も可能 |
| 強調を動的にする | 条件付き書式（データの色）にDAXメジャーを指定 |
| 深掘りを促す | ドリルスルー、ツールチップページ |

```dax
-- 主張を自動生成するタイトル用メジャー
分析タイトル =
VAR 当年 = [売上合計]
VAR 前年 = [売上合計_前年同期]
VAR 差率 = DIVIDE( 当年 - 前年, 前年 )
VAR 連続月数 = [前年割れ連続月数]
RETURN
SWITCH(
    TRUE(),
    ISBLANK( 前年 ), "比較対象期間のデータがありません",
    連続月数 >= 3,
        "売上は" & 連続月数 & "か月連続で前年割れ（直近 " & FORMAT( 差率, "+0.0%;-0.0%" ) & "）",
    差率 < 0, "売上は前年比 " & FORMAT( 差率, "-0.0%" ) & "。単月の落ち込み",
    "売上は前年比 " & FORMAT( 差率, "+0.0%" ) & "で推移"
)
```

> [!EXAM] PL-300で問われる
> ストーリーテリング関連では、**ブックマークとボタンによるナビゲーション**、**選択ウィンドウによる表示制御**、**条件付き書式によるタイトルの動的変更**が出題されます。また **Power BI のプレゼンテーションモード**や、**PowerPoint への埋め込み**についても問われます。「同じページで異なるビジュアルを切り替えて見せたい」→ブックマーク＋ボタン、が定番の対応です。

## ストーリーを資産にする

一度作った物語は、繰り返し使えます。組織の中で同じ問いが何度も発生するからです。

```figure
{ "type":"timeline", "title":"分析ストーリーの再利用サイクル", "caption":"毎月ゼロから作らない。型を育てる",
  "items":[
    {"label":"初回","title":"手作業で組み立てる","text":"構成、タイトル、注釈をすべて手で作る","tone":"blue"},
    {"label":"2回目","title":"型を抽出する","text":"どの構成が刺さったかを記録し、テンプレート化する","tone":"green"},
    {"label":"3回目以降","title":"動的化する","text":"タイトル・コメントをDAXで自動生成し、数字だけ入れ替える","tone":"amber"},
    {"label":"半年後","title":"配布形態を変える","text":"定例レポートとして自動配信。会議は例外時のみに","tone":"violet"},
    {"label":"1年後","title":"問いを更新する","text":"組織の関心が変わったかを確認し、構成を作り直す","tone":"good"} ] }
```

> [!TRAP] つまずきポイント
> 型の再利用は効率的ですが、**同じ構成を1年続けると誰も読まなくなります**。人は繰り返される刺激に慣れます（馴化）。定期的に「この構成はまだ意思決定に使われているか」を確認し、使われていない要素を入れ替えてください。読まれ方が変わったこと自体が、組織の関心の変化を示す情報です。

> [!NOTE] 要点
> データストーリーテリングの本質は、**聞き手の認知の負担を、語り手が引き受けること**です。分析者が10時間かけて理解した構造を、聞き手が5分で理解できる形に圧縮する。その圧縮作業こそが、この技術の中身です。

## 練習：3行で語る

日々のトレーニングとして、どんな分析も**3行に圧縮する**練習をしてください。書けないなら、まだ理解していません。

```text
【3行フォーマット】
1行目（事実）: ______ が ______ になった（数字を1つ）
2行目（意味）: それは ______ を意味する（金額または業務影響）
3行目（行動）: だから ______ を ______ までに実施したい

【記入例】
1. 国内直営店の客数が前年比 -16% になった。
2. 通期では約 3.2 億円の売上機会損失に相当する。
3. だから駅遠38店のうち10店で来店促進をテストし、7/15 に結果を報告したい。
```

この3行が書けていれば、資料は後からいくらでも作れます。逆に3行が曖昧なまま作った資料は、何ページあっても伝わりません。

次のレッスンでは、こうして作ったレポートを**公開した後**——実際に使われているかを測り、改善し続ける仕組みを扱います。

### 語彙を揃える

最後に、報告で使う言葉自体も設計対象です。同じ意味の言葉が混ざると、聞き手は毎回変換します。

| 避ける表現 | 使う表現 | 理由 |
|---|---|---|
| 「かなり増えた」 | 「前年比 +18%（+2.1億円）」 | 主観語は人によって幅が違う |
