1 ページにすべてを載せようとすると、必ず破綻します。読み手が知りたい粒度は人によって違い、同じ人でも場面によって変わるからです。

解決策は「載せない情報を、操作で取り出せるようにする」ことです。Power BI の相互作用・ドリルダウン・ドリルスルー・ブックマークは、そのための道具です。このレッスンでは、それぞれの役割と使い分けを設計として扱います。

## 情報探索の原則

> [!DS] データサイエンス視点：Shneiderman の情報探索マントラ
> Ben Shneiderman は 1996 年、対話的な可視化の設計原則を 1 文にまとめました。**「Overview first, zoom and filter, then details-on-demand（まず全体像、次に拡大と絞り込み、そして必要に応じて詳細）」**。
>
> この順序が重要です。最初に詳細を見せると、読み手は文脈を失って迷子になります。まず全体を見せて「どこを見るべきか」を判断させ、そこから絞り込ませ、最後に詳細を要求に応じて出す。Power BI の機能はこの 3 段階にきれいに対応します。全体像＝サマリーページ、拡大と絞り込み＝スライサーと相互作用とドリルダウン、詳細＝ツールチップとドリルスルー。**機能から設計を考えるのではなく、この 3 段階から機能を割り当てます**。

```figure
{ "type":"flow", "dir":"row", "title":"情報探索の3段階と対応機能",
  "caption":"レポート設計はこの順序で行う。詳細から作ると必ず破綻する",
  "items":[
    {"label":"① 全体像","sub":"KPIカード・サマリーページ","tone":"pink","icon":"👁"},
    {"label":"② 絞り込み","sub":"スライサー・相互作用・ドリルダウン","tone":"blue","icon":"🔍"},
    {"label":"③ 要求時の詳細","sub":"ツールチップ・ドリルスルー・明細ページ","tone":"green","icon":"📋"} ] }
```

## 相互作用の編集 — 既定のままにしない

Power BI では、1 つのビジュアルをクリックすると同じページの他のビジュアルが自動的に反応します。この挙動は **書式 → 相互作用を編集** で個別に制御できます。

```figure
{ "type":"cards", "cols":3, "title":"相互作用の3つのモード",
  "caption":"ビジュアルの組み合わせごとに1つを選ぶ。既定は棒＝強調表示、スライサー＝フィルター",
  "items":[
    {"icon":"🔽","title":"フィルター","text":"対象のビジュアルが選択値だけに絞り込まれる。他の値は消える。内訳を掘るときに使う","tone":"blue"},
    {"icon":"🔦","title":"強調表示","text":"全体は薄く残したまま、該当部分だけ濃く描かれる。全体に対する割合が見えるのが利点","tone":"amber"},
    {"icon":"🚫","title":"なし","text":"クリックしても反応しない。常に全社合計を表示したいKPIカードなどに設定する","tone":"gray"} ] }
```

```figure
{ "type":"matrix", "title":"どの相互作用を選ぶか",
  "xLabel":"対象ビジュアルの役割", "yLabel":"全体との比較の必要性",
  "xLow":"文脈を示す（合計・基準）","xHigh":"詳細を示す（内訳・明細）","yLow":"不要","yHigh":"必要",
  "quadrants":[
    {"title":"強調表示","text":"全体の棒の中で選択分がどれだけかを見せる","tone":"amber"},
    {"title":"フィルター","text":"選択したセグメントの内訳だけを見たい","tone":"good"},
    {"title":"なし","text":"全社KPIカードは常に全体を表示し続ける","tone":"gray"},
    {"title":"フィルター","text":"明細テーブルは常に絞り込む。全件表示は無意味","tone":"good"} ] }
```

> [!TRAP] つまずきポイント
> 相互作用を既定のままにすると、**KPI カードが選択のたびに変化します**。読み手は「全社売上 182」が「32」に変わったのを見て、全社の数字が変わったと誤解します。ヘッダーの全社 KPI は原則「なし」に設定し、常に全体を示し続けるようにします。逆に、内訳グラフと明細テーブルは必ず「フィルター」にします。

> [!TIP] 実務のコツ
> 相互作用の編集は**ビジュアルを選択した状態**でリボンの「書式」タブ →「相互作用を編集」を押すと、他の全ビジュアルの右上に 3 つのアイコンが出ます。ここで 1 つずつ設定します。設定はビジュアルのペアごとに保存されるため、ビジュアルを追加したら再度確認が必要です。

## ドリルダウン — 同じページで階層を掘る

ドリルダウンは、**1 つのビジュアルの中で粒度を下げる**機能です。年 → 四半期 → 月 → 日、あるいは 地域 → 都道府県 → 店舗 のような階層を軸に設定すると使えます。

```figure
{ "type":"tree", "title":"ドリルダウンの階層設計",
  "caption":"軸フィールドに複数の列を上から順に入れると階層になる",
  "root":{"label":"地域別 売上（最上位）"},
  "children":[
    {"label":"地域（東日本／西日本）","sub":"最初に表示される粒度","tone":"blue",
     "children":[
       {"label":"都道府県","sub":"ドリルダウン1回","tone":"green",
        "children":[{"label":"店舗","sub":"ドリルダウン2回。ここが最下層","tone":"amber"}]}]} ] }
```

```figure
{ "type":"steps", "title":"ドリルダウンの操作と設定",
  "caption":"読み手が使い方を知らないと機能は存在しないのと同じ。案内を必ず添える",
  "items":[
    {"title":"1. 軸に階層を積む","text":"視覚化ペインの『X軸』または『軸』に、上位から順に列をドラッグする","tone":"blue"},
    {"title":"2. ビジュアル右上のアイコンを確認する","text":"下向き矢印（1階層下へ）／二重矢印（全展開）／上向き矢印（戻る）の3つが出る","tone":"green"},
    {"title":"3. ドリルモードのオン／オフを理解する","text":"下向き矢印を押した状態でデータ点をクリックすると、その項目だけを掘る","tone":"amber"},
    {"title":"4. 読み手に使い方を伝える","text":"『棒をクリックすると店舗別に展開します』とテキストで明記する","tone":"violet"},
    {"title":"5. 階層は3段まで","text":"4段以上は読み手が現在位置を見失う。深い探索はドリルスルーに逃がす","tone":"pink"} ] }
```

> [!TRAP] つまずきポイント
> ドリルダウンは**発見されにくい機能**です。右上の小さな矢印に気づく読み手はごく一部です。対策は 3 つ。(1) ビジュアルのタイトルに「（クリックで店舗別に展開）」と書く。(2) 現在の階層をタイトルに動的に表示する。(3) 階層が浅いなら、ドリルダウンをやめてスライサーやボタンによるページ切り替えにする。**操作を要求する設計は、案内とセットでなければ機能しません**。

## ドリルスルー — 別ページの詳細へ飛ぶ

ドリルスルーは、**選択したコンテキストを持って別のページに移動する**機能です。「この店舗を右クリック → 店舗詳細ページへ」という動きになります。

```figure
{ "type":"compare", "title":"ドリルダウンとドリルスルーの違い",
  "caption":"同じ『掘る』でも、粒度を下げるのか、別の観点に移るのかが違う",
  "panels":[
    {"title":"ドリルダウン","tone":"blue",
     "items":["同じビジュアル・同じページの中で粒度が下がる","見せる指標は変わらない（売上のまま）","階層関係にある列が必要"],
     "note":"縦に掘る"},
    {"title":"ドリルスルー","tone":"violet",
     "items":["別ページへ移動し、そのエンティティの全情報を見せる","指標も構成も自由に変えられる（売上＋在庫＋顧客一覧）","階層である必要はない"],
     "note":"横に展開する"} ] }
```

```figure
{ "type":"steps", "title":"ドリルスルーページの作り方",
  "caption":"詳細ページは単体で開かせない。必ずドリルスルー専用にする",
  "items":[
    {"title":"1. 新しいページを作る","text":"『店舗詳細』のような名前にする","tone":"blue"},
    {"title":"2. 視覚化ペインの『ドリルスルー』にフィールドを追加","text":"Dim_店舗[店舗名] をドラッグする。これがコンテキストの受け口になる","tone":"green"},
    {"title":"3. 戻るボタンが自動生成される","text":"左上に矢印ボタンが自動で置かれる。位置だけ整える","tone":"amber"},
    {"title":"4. すべてのフィルターを保持するを設定","text":"元ページの期間などのフィルターを引き継ぐかを選ぶ","tone":"violet"},
    {"title":"5. ページを非表示にする","text":"ページタブを右クリック →『ページの非表示』。読み手のタブ一覧から消える","tone":"pink"},
    {"title":"6. 元ページで右クリックして確認する","text":"データ点を右クリック →『ドリルスルー』→ ページ名 で遷移する","tone":"cyan"} ] }
```

> [!WARN] 注意
> ドリルスルーページを**非表示にしないと**、読み手がタブから直接開けてしまいます。その場合はコンテキストが渡されていないため、全店舗の合計が「店舗詳細」というタイトルで表示され、誤読の原因になります。非表示は必須の手順です。

> [!EXAM] PL-300で問われる
> 「特定の製品を選んで、その製品だけの詳細分析ページに移動させたい」→ **ドリルスルー**。「年から月へ粒度を下げたい」→ **ドリルダウン**。「1つのビジュアルの選択で他のビジュアルを絞りたい」→ **相互作用の編集（フィルター）**。この 3 つの区別は頻出します。ドリルスルーの受け口が「ドリルスルー」フィールドウェルであることも問われます。

## フィルターペインの設計

キャンバス上のスライサーだけでなく、右側の**フィルターペイン**も読み手が操作できる領域です。放置すると、内部の作業用フィルターまで読み手に見えてしまいます。

```figure
{ "type":"stack", "title":"フィルターの3つの階層",
  "caption":"下位ほど適用範囲が広い。どの階層に置くかで影響範囲が決まる",
  "layers":[
    {"label":"このビジュアルのフィルター","sub":"選択中のビジュアルだけに効く。上位N件の指定などに使う","tone":"pink"},
    {"label":"このページのフィルター","sub":"ページ内の全ビジュアルに効く。ページ固有の前提条件を置く","tone":"blue"},
    {"label":"すべてのページのフィルター","sub":"レポート全体に効く。『テストデータを除外』などの恒久条件","tone":"amber"} ] }
```

> [!TIP] 実務のコツ
> 読み手に触らせたくないフィルターは、フィルターペインで**「フィルターを非表示にする」（目のアイコン）**、または**「ロック」**を設定します。非表示は読み手から見えなくなり、ロックは見えるが変更できません。「テストデータ除外」のような前提条件はロックにして、条件が効いていることを見せるほうが誠実です。

> [!WARN] 注意
> フィルターペイン自体を書式ペインの「フィルターウィンドウ」で消すこともできますが、**消すと読み手はビジュアルに何のフィルターが効いているか確認できなくなります**。消すのではなく、不要な項目を非表示にして整理するのが正解です。

## スライサーの同期

複数ページで同じ期間を選ばせたいとき、ページごとにスライサーを操作させるのは不親切です。

```figure
{ "type":"steps", "title":"スライサーの同期設定",
  "caption":"『表示 → スライサーの同期』で、ページごとに同期と表示を独立に制御する",
  "items":[
    {"title":"1. スライサーを選択する","text":"同期させたい期間スライサーなどを選ぶ","tone":"blue"},
    {"title":"2. 表示 → スライサーの同期 を開く","text":"ページ一覧と2列のチェックボックスが出る","tone":"green"},
    {"title":"3. 『同期』列で連動させるページを選ぶ","text":"チェックしたページでは選択状態が共有される","tone":"amber"},
    {"title":"4. 『表示』列で見せるページを選ぶ","text":"同期はするが表示はしない、という設定もできる","tone":"violet"} ] }
```

同期と表示が独立している点が重要です。**サマリーページだけにスライサーを置き、詳細ページには置かないが同じ期間が効いている**、という設計ができます。

> [!EXAM] PL-300で問われる
> 「複数ページで同じスライサー選択を保ちたいが、スライサー自体は 1 ページだけに表示したい」→ **スライサーの同期で「同期」だけチェックし「表示」は外す**。この設定が問われます。

## 理解度チェック

1. ヘッダーの「全社売上」KPI カードが、部門別グラフをクリックするたびに変化してしまう。原因と対処を述べよ。
2. ドリルダウンとドリルスルーの違いを、使う場面を挙げて説明せよ。またドリルスルーページで必ず行うべき設定を 1 つ挙げよ。
3. ボタンでグラフを切り替えるブックマークを作ったところ、押すたびに読み手のスライサー選択が初期化される。原因と対処を述べよ。

<details>
<summary>解答の要点</summary>

1. 原因は**相互作用が既定の「フィルター」または「強調表示」のまま**であること。部門を選択するとカードにもフィルターが伝播している。対処は、部門別グラフを選択した状態で「書式 → 相互作用を編集」を開き、全社 KPI カードに対して **「なし」** を設定する。これで全体値を常に表示し続けられる。
2. **ドリルダウン**は同一ビジュアル内で粒度を下げる（年→月、地域→店舗）。階層関係にある列が必要で、見せる指標は変わらない。**ドリルスルー**は選択したコンテキストを持って別ページへ移動し、そのエンティティについて指標も構成も自由に組んだ詳細を見せる。必須設定は、**ドリルスルーページを「ページの非表示」にする**こと。非表示にしないと読み手が直接開き、コンテキストのない合計値を詳細と誤解する。
3. 原因はブックマークが**「データ」（フィルター状態）も保存している**こと。対処はブックマークペインで各ブックマークを右クリックし、**「データ」のチェックを外す**。あわせて「選択したビジュアル」に限定すると、影響範囲を切り替え対象だけに絞れる。

</details>
