売上レポートを開くと、まず目に入るのはカードビジュアルに並んだ「平均単価 ¥4,200」「平均滞在時間 12.4分」という数字です。この数字は、多くの場合、**何も語っていません**。

平均は、分布という豊かな情報を1つの数字に潰した結果です。潰す前に何があったかを見ないまま平均だけを報告するのは、本を1冊読んで「文字数は8万字でした」と報告するようなものです。

このレッスンでは、記述統計 — つまり手元のデータそのものを要約して説明する技術 — を、Power BI での実装まで含めて身につけます。

> [!DS]
> **記述統計（descriptive statistics）** は、手元のデータの特徴を要約する統計です。対して **推測統計（inferential statistics）** は、手元のデータから背後の母集団を推測します。L1501〜L1504 は記述統計、L1505〜L1506 は推測統計の入り口にあたります。この2つを混同すると、「うちの顧客の平均購入額は3,200円だった」（記述）と「うちの顧客の平均購入額は3,200円である」（推測）の違いが分からなくなります。

## 3つの代表値

データの中心を表す代表値は3つあります。どれを使うかは、分布の形で決まります。

```figure
{ "type": "cards", "cols": 3, "title": "3つの代表値", "items": [
  {"icon":"⚖","title":"平均値 (Mean)","text":"合計 ÷ 個数。すべての値を使うが、外れ値1つで大きく動く。","tone":"blue"},
  {"icon":"🎯","title":"中央値 (Median)","text":"小さい順に並べて真ん中。外れ値に強い。分布が歪むときの主役。","tone":"green"},
  {"icon":"🔝","title":"最頻値 (Mode)","text":"最も多く現れる値。カテゴリや離散値、二峰性の把握に使う。","tone":"violet"} ] }
```

具体例で違いを見ます。ある部署10人の年収（万円）です。

```text
420, 450, 460, 480, 500, 520, 540, 560, 600, 4,200
```

- 平均値 = 873万円
- 中央値 = (500 + 520) ÷ 2 = 510万円
- 最頻値 = なし（すべて異なる値）

平均873万円と報告すると、10人中9人が「そんなにもらっていない」と感じます。1人の役員（4,200万円）が平均を363万円押し上げているからです。この部署の「典型的な年収」は中央値510万円です。

> [!TRAP] 平均が使えない代表的な場面
> 次の指標は、ほぼ必ず右に大きく歪みます。平均ではなく**中央値やパーセンタイル**で報告してください。
> - 顧客あたり購入金額（一部の大口が全体を引っ張る）
> - Webページの滞在時間（タブを開きっぱなしの人が混じる）
> - 問い合わせの対応時間（放置された1件が数千分になる）
> - 世帯所得・資産（上位が桁で違う）
> - サーバーの応答時間（95パーセンタイル・99パーセンタイルで見るのが業界標準）


| 分布の形 | 平均と中央値の関係 | 報告に使うべき値 | 疑うべきこと |
|---|---|---|---|
| 左右対称 | 平均 ≒ 中央値 | 平均 ± 標準偏差 | 特になし |

> 二峰性を見つけたら、それは「隠れたセグメントの発見」です。B店の例なら「平日客」と「週末客」という2つの顧客像があるということ。分布を分けた瞬間、施策が具体的になります。ヒストグラムは分析の終点ではなく**セグメント発見の起点**です。

## ばらつきを数字にする

中心だけでは足りません。「どれくらい散らばっているか」を数字にします。

```figure
{ "type": "flow", "dir": "row", "title": "ばらつきの指標（左ほど単純、右ほど頑健）", "items": [
  {"label":"範囲","sub":"最大 − 最小","tone":"gray"},
  {"label":"分散","sub":"偏差の2乗の平均","tone":"blue"},

  {"label":"四分位範囲","sub":"Q3 − Q1。外れ値に強い","tone":"violet"} ],
  "caption": "外れ値がある／分布が歪むときは、標準偏差ではなく四分位範囲を使う。" }
```

### 標準偏差を手で計算する

5日間の来客数：`96, 104, 100, 92, 108`。平均は100人です。

| 値 | 偏差（値−平均） | 偏差の2乗 |
|---|---|---|
| 96 | −4 | 16 |
| 104 | +4 | 16 |
| 100 | 0 | 0 |
| 92 | −8 | 64 |
| 108 | +8 | 64 |
| **合計** | **0** | **160** |

偏差をそのまま足すと必ず0になります。だから2乗して符号を消します。

- 分散 = 160 ÷ 5 = 32（母分散。データが全体なら n で割る）
- 標準偏差 = √32 ≒ **5.7人**

「平均100人、標準偏差5.7人」。これで初めて「だいたい94〜106人の間に収まる日が多い」と言えます。

> [!NOTE] 要点
> 標準偏差は**元のデータと同じ単位**を持ちます（人・円・分）。分散は単位が2乗になるので（人²）、報告には向きません。分散は計算の途中経過、標準偏差が報告用、と覚えてください。

### 標本標準偏差と母標準偏差

n で割るか n−1 で割るかは、そのデータが**全体そのもの**か、**全体から取り出した一部**かで決まります。

| | 割る数 | Excel/DAX | 使う場面 |
|---|---|---|---|
| 母標準偏差 | n | `STDEV.P` | 全店舗・全期間など、データが全体そのもの |
| 標本標準偏差 | n − 1 | `STDEV.S` | アンケート回答など、母集団の一部を測った |

実務では n が大きければ差は無視できます。迷ったら `STDEV.S`（標本）が安全側です。

### 変動係数 — 単位が違うものを比べる

売上（万円）の標準偏差120と、来客数（人）の標準偏差18は比べられません。**変動係数（CV）= 標準偏差 ÷ 平均** を使うと、単位が消えて比較できます。

```dax
変動係数 :=
DIVIDE(
    STDEV.S( Fact_売上[金額] ),
    AVERAGE( Fact_売上[金額] )
)
```

CV が 0.1 なら「平均の10%ぶれる」。店舗別に CV を並べると、**売上が大きい店ではなく、読みにくい店**が特定できます。

## 四分位・パーセンタイル・箱ひげ

データを小さい順に並べ、4等分する境目が四分位です。

```figure
{ "type": "chart", "kind": "hbar", "title": "顧客1人あたり年間購入額（円）の分位点",
  "categories": ["最小","Q1(25%)","中央値(50%)","Q3(75%)","P90","P99","最大"],
  "series": [{"name":"金額","values":[800,4200,9600,21000,48000,180000,1240000],"tone":"blue"}],
  "highlight": 6, "unit": "円",
  "caption": "平均は18,400円。だが中央値は9,600円で、平均を超える顧客は全体の27%しかいない。最大値は中央値の129倍。" }
```

- **Q1（第1四分位）**：下から25%の位置の値
- **Q3（第3四分位）**：下から75%の位置の値
- **IQR（四分位範囲）= Q3 − Q1**：真ん中50%が収まる幅

箱ひげ図の「ひげ」は、慣習的に **Q1 − 1.5×IQR** から **Q3 + 1.5×IQR** まで伸ばし、そこから外れた点を外れ値として個別に描きます。上の例なら IQR = 21,000 − 4,200 = 16,800、上限は 21,000 + 25,200 = **46,200円**。P90 の48,000円より上の顧客は、統計的には外れ値扱いになります。

> [!DS]
> 1.5 という係数に理論的な必然性はありません。正規分布なら約0.7%が外れ値として拾われる、という経験則から Tukey が定めた値です。**外れ値の定義は分析者が選ぶもの**であり、データが自動的に教えてくれるものではない、と理解してください。3σ法（平均±3標準偏差）も同様に、正規分布を仮定した1つの選択肢にすぎません。

## Power BI で記述統計を出す

### DAX：代表値とばらつきの一式

```dax
売上_平均 := AVERAGE( Fact_売上[金額] )
売上_中央値 := MEDIAN( Fact_売上[金額] )
売上_標準偏差 := STDEV.S( Fact_売上[金額] )
売上_Q1 := PERCENTILE.INC( Fact_売上[金額], 0.25 )
売上_Q3 := PERCENTILE.INC( Fact_売上[金額], 0.75 )
売上_IQR := [売上_Q3] - [売上_Q1]
売上_P95 := PERCENTILE.INC( Fact_売上[金額], 0.95 )
```

`PERCENTILE.INC` は境界を含む（0〜1）、`PERCENTILE.EXC` は境界を含まない（0と1を許さない）版です。Excel と同じ挙動なので、**Excel の集計と数字を合わせたいときは `.INC` を選びます**。

### 顧客単位の中央値 — イテレータが必要な場面

「顧客1人あたり購入額の中央値」は、`MEDIAN` では出せません。明細行の中央値になってしまうからです。**一度顧客単位に集約してから中央値を取る**必要があります。

```figure
{ "type": "formula", "lang": "dax",
  "code": "MEDIANX( VALUES( Dim_顧客[顧客ID] ), CALCULATE( SUM( Fact_売上[金額] ) ) )",
  "parts": [
    {"match":"MEDIANX","label":"表を1行ずつ回って式を評価し、その結果の中央値を返す","tone":"violet"},
```

> [!TRAP] 平均の平均を取ってはいけない
> 店舗別の平均単価を求め、それをさらに平均して「全社平均単価」とするのは誤りです。店舗ごとの取引件数が違うからです。件数10件で平均1,000円の店と、件数1,000件で平均5,000円の店の全社平均単価は 3,000円ではなく、`(10×1000 + 1000×5000) ÷ 1010 = 4,960円` です。**平均は必ず「合計 ÷ 件数」に戻して計算する**か、件数で重み付けしてください。DAX で `AVERAGE([平均単価])` のようなメジャーを書いた時点で間違いです。

## 歪みを数字にする — 歪度と尖度

「右に歪んでいる」を目視ではなく数字で判定できると、レポートの自動チェックに組み込めます。

- **歪度（skewness）**：分布の非対称さ。0で左右対称、正なら右に長い裾、負なら左に長い裾
- **尖度（kurtosis）**：裾の重さ。正規分布より裾が重い（極端な値が出やすい）ほど大きい

DAX に歪度の組み込み関数はないので、定義どおり書きます。

```dax
歪度 :=
VAR N = COUNTROWS( Fact_売上 )
VAR Mean = AVERAGE( Fact_売上[金額] )
VAR SD = STDEV.P( Fact_売上[金額] )
VAR Sum3 = SUMX( Fact_売上, ( Fact_売上[金額] - Mean ) ^ 3 )
RETURN
    DIVIDE( Sum3, N * SD ^ 3 )
```

実務では次の目安で十分です。

| 歪度の値 | 判定 | 報告に使う代表値 |
|---|---|---|
| −0.5 〜 0.5 | ほぼ対称 | 平均 |
| 0.5 〜 1.0 | 中程度に右へ歪む | 平均と中央値を併記 |
| 1.0 超 | 強く右へ歪む | 中央値・パーセンタイル |

```figure
  "quadrants": [

  "caption": "順序は左上→右上→左下→右下。外れ値か歪みのどちらかがあれば、平均単独での報告をやめる。" }
```

## n が小さいときの作法

30件のデータで「A支店のほうが平均が高い」と言えるでしょうか。件数が少ないと、平均は偶然で大きく動きます。

```figure
{ "type": "chart", "kind": "line", "title": "サンプル件数と平均のブレ幅（同一母集団から繰り返し抽出）",
  "categories": ["n=5","n=10","n=30","n=100","n=300","n=1000"],
  "series": [{"name":"平均の標準誤差（相対）","values":[44.7,31.6,18.3,10.0,5.8,3.2],"tone":"blue"}],
  "unit": "%",
  "caption": "標準誤差は √n に反比例する。精度を2倍にするには件数を4倍必要とする。n=5 の平均は±45%動く。" }
```

**標準誤差 = 標準偏差 ÷ √n**。これが「平均という値そのもののブレ幅」です。n=5 の平均を小数第1位まで報告しても、その桁には意味がありません。

> [!WARN] 注意
> 件数が少ないセルを含むマトリックスを配布すると、「n=2 で構成比100%」のようなセルが独り歩きします。件数の少ないセルは条件付き書式でグレーアウトするか、`IF( [件数] < 10, BLANK(), [構成比] )` のように意図的に非表示にしてください。

```figure
{ "type": "stack", "title": "数字を報告する前の3層チェック", "layers": [
  {"label":"第3層：文脈","sub":"比較対象は？ 前年は？ 目標は？ この数字は良いのか悪いのか","tone":"pink"},
  {"label":"第2層：ばらつき","sub":"標準偏差／IQR は？ 分布の形は？ 外れ値はあるか","tone":"amber"},
  {"label":"第1層：代表値","sub":"平均か中央値か。件数（n）はいくつか","tone":"blue"} ],
  "caption": "下から積み上げる。第1層だけで報告すると、必ずどこかで判断を誤る。" }
```

- [ ] 平均を出したら、必ず中央値も並べて差を見た
- [ ] 件数（n）を明記した。n が30未満なら、その旨を添えた
- [ ] ヒストグラムを1枚は描いた。二峰性がないか確認した
- [ ] 歪んだ分布に対して平均を使っていない
- [ ] 外れ値を除外したなら、条件と件数をレポートに書いた
- [ ] 平均の平均を取っていない
- [ ] 「このデータから消えた集団はいないか」を確認した

> [!EXAM] PL-300で問われる
> PL-300 では統計そのものは深く問われません。しかし **3.5 データの探索と分析** で「分布を確認するために適切なビジュアルはどれか」「四分位を表示するには」といった形で出ます。具体的には次を押さえてください。
> - ヒストグラムは**グループ化（ビン）＋棒グラフ**で作る
> - 分布の中央値や四分位を1つのビジュアルで見るなら**箱ひげ図（カスタムビジュアル）**
> - 「上位N件」の絞り込みは**上位N件フィルター**、割合の把握は**リボングラフやパレート**
> - Q&A や主要なインフルエンサー（キーインフルエンサー）は探索の補助であり、統計的な検定ではない

## まとめ

- 平均は「典型」ではなく「合計÷個数」。分布を見ずに平均を語らない
- 歪んだ分布では中央値とパーセンタイル。右に歪むデータは実務に溢れている
- ばらつきは標準偏差（対称な分布）か IQR（歪む分布・外れ値あり）で表す
- 単位が違うものを比べるときは変動係数
- Power BI では `MEDIAN` / `PERCENTILE.INC` / `STDEV.S`、粒度を変えるときは `MEDIANX` + `VALUES`
- ヒストグラムはビン列＋棒グラフ。二峰性を見つけたらセグメント発見のチャンス
- 外れ値は消す前に原因を調べる。消したなら必ず記録する
