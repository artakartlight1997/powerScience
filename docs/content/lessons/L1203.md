1件の受注には受注日・出荷日・請求日があります。3部門とも自分の日付で見たい。

日付テーブルを3つ作るとスライサーが3つ並びます。1つで役割を切り替えます。

## `USERELATIONSHIP` の書き方

```figure
{ "type":"formula", "lang":"dax", "title":"USERELATIONSHIP の構造", "caption":"CALCULATE の修飾子。その計算の間だけ関係を切り替える",
  "code":"CALCULATE( SUM( Fact_受注[金額] ), USERELATIONSHIP( Fact_受注[出荷日], Dim_日付[日付] ) )", "parts":[
  {"match":"CALCULATE","label":"この中でしか USERELATIONSHIP は使えない","tone":"violet"},
  {"match":"SUM( Fact_受注[金額] )","label":"評価したい式","tone":"blue"},
  {"match":"USERELATIONSHIP","label":"非アクティブな関係をこの計算の間だけ有効にする","tone":"amber"},
  {"match":"Fact_受注[出荷日], Dim_日付[日付]","label":"多側の列, 1側の列 の順","tone":"green"}] }
```

```dax
-- 受注日ベース（アクティブなので指定不要）
売上_受注ベース = SUM( Fact_受注[金額] )

売上_出荷ベース =
CALCULATE( SUM( Fact_受注[金額] ),
    USERELATIONSHIP( Fact_受注[出荷日], Dim_日付[日付] ) )

売上_請求ベース =
CALCULATE( SUM( Fact_受注[金額] ),
    USERELATIONSHIP( Fact_受注[請求日], Dim_日付[日付] ) )

-- タイムインテリジェンスは切替済みのベースメジャーを参照する
売上_出荷ベース_前年 = CALCULATE( [売上_出荷ベース], DATEADD( Dim_日付[日付], -1, YEAR ) )
売上_出荷ベース_YTD  = CALCULATE( [売上_出荷ベース], DATESYTD( Dim_日付[日付], "3/31" ) )
```

```figure
  {"icon":"📍","title":"CALCULATE の中だけ","text":"SUMX の中に直接書くとエラーになる","tone":"violet"},
```

> [!TIP] 実務のコツ
> メジャー名に基準日付を明記する（`売上_出荷ベース`）。
> 経理と営業で数字が食い違う原因の多くは、この命名の曖昧さ。

```figure
    "rows":[["S-001","2026-02-01","2026-02-03","!2","出荷済"],["S-002","2026-02-01","2026-02-09","!8","出荷済"],["S-003","2026-02-02","(未出荷)","!null","!未出荷"]]} }
```

```m
// Power Query で計算する（更新時に1度だけ。推奨）
let
    LT = Table.AddColumn(Fact_受注, "リードタイム日数",
        each if [出荷日] = null then null else Duration.Days([出荷日] - [受注日]), Int64.Type)
in
    Table.AddColumn(LT, "出荷状態", each if [出荷日] = null then "未出荷" else "出荷済", type text)
```

```dax
-- 未出荷を除外した平均。件数と必ずセットで表示する
平均リードタイム =
AVERAGEX( FILTER( Fact_受注, NOT ISBLANK( Fact_受注[リードタイム日数] ) ), Fact_受注[リードタイム日数] )

-- 5日以内出荷率（SLA達成率）
SLA達成率 =
VAR 出荷済 = CALCULATE( COUNTROWS( Fact_受注 ), Fact_受注[出荷状態] = "出荷済" )
VAR 期限内 = CALCULATE( COUNTROWS( Fact_受注 ), Fact_受注[リードタイム日数] <= 5 )
RETURN DIVIDE( 期限内, 出荷済 )
```

```dax
-- 予算はカテゴリ×年月の粒度だけ。細かい粒度では BLANK を返す
予算額_安全 =
IF( ISINSCOPE( Dim_商品[商品名] ), BLANK(),
    CALCULATE( SUM( Fact_予算[予算金額] ),
        TREATAS( VALUES( Dim_商品[カテゴリ] ), Fact_予算[カテゴリ名] ),
        TREATAS( VALUES( Dim_日付[年月] ), Fact_予算[年月] ) ) )

予算達成率 = DIVIDE( [売上_受注ベース], [予算額_安全] )
```

> [!TIP] 実務のコツ
> `ISINSCOPE( 列 )` はその行が実際に列でグループ化されているかを判定する。
> スライサーの単一選択と区別できるので、粒度判定はこちらを使う。

```dax
-- 切断テーブル（どのテーブルとも関係を持たない）で基準を選ばせる
-- Dim_日付基準 = DATATABLE("基準", STRING, {{"受注日"},{"出荷日"},{"請求日"}})
売上_基準切替 =
SWITCH(
    SELECTEDVALUE( Dim_日付基準[基準], "受注日" ),   -- 第2引数の既定値は必須
    "受注日", [売上_受注ベース],
    "出荷日", [売上_出荷ベース],
    "請求日", [売上_請求ベース]
)
```

> [!EXAM] PL-300で問われる
> 「1つのファクトに複数の日付列」は頻出。正解は非アクティブ関係＋`USERELATIONSHIP`。
> 日付テーブルの複製は通常、誤答か次善として扱われる。

## 設計判断チェックリスト

- [ ] 日付テーブルは1つに統一されているか
- [ ] 非アクティブな関係をモデル図（破線）で確認したか
- [ ] メジャー名に基準日付を明記したか
- [ ] タイムインテリジェンスは切替済みベースメジャーを参照しているか
- [ ] リードタイムで null の扱いを決め、件数も表示するか
- [ ] 複数ファクトは共有ディメンション経由でのみ結んでいるか
- [ ] `ISINSCOPE` で存在しない粒度を BLANK にしたか
- [ ] `SELECTEDVALUE` に既定値を指定したか

## 理解度チェック

1. 受注・出荷・請求の売上を同じマトリクスに並べる実装をメジャー定義込みで説明せよ。
2. `USERELATIONSHIP` を `SUMX` に直接書くとエラーになる。正しい形に直し理由を述べよ。
3. 月次・カテゴリ別予算を商品単品まで展開すると何が起きるか。防ぐDAXを書け。
