「更新に3時間」の原因はほぼ1つ。1億行を全部転送してから Power Query で絞っているからです。

**クエリ フォールディング**は、変換ステップをSQLに翻訳してソース側で実行させる仕組みです。

## Table.Buffer とネイティブSQL

```m
let
    Fact = Sql.Database(pServer, pDatabase){[Schema="dbo", Item="FactSales"]}[Data],
    絞り込み = Table.SelectRows(Fact, each [売上日] >= #date(2026,1,1)),
    固定 = Table.Buffer(絞り込み),   // ここで折りたたみが切れる
    追加 = Table.AddColumn(固定, "四半期", each "Q" & Text.From(Date.QuarterOfYear([売上日])), type text)
in
    追加
```

```figure
{ "type":"cards", "cols":2, "title":"Table.Buffer が有効な場面",
  "caption":"小さく、繰り返し参照されるテーブルにだけ使う",
  "items":[
    {"icon":"📇","title":"小さなマスタの反復参照","text":"参照のたびのソースアクセスを防ぎ劇的に速くなる","tone":"good"},{"icon":"🔁","title":"同じ中間結果を複数が参照","text":"再計算を防げることがある","tone":"green"},
    {"icon":"📸","title":"結果を固定したい","text":"更新中のソースでも一貫した断面を取れる","tone":"cyan"},{"icon":"🚫","title":"速くなりそうだから","text":"逆効果。折りたたみが切れて全件転送になる","tone":"bad"} ] }
```

> [!TRAP] Buffer を先頭に置かない
> 先頭の Buffer は「全件をメモリへ読み込む」宣言。小さいテーブルに限って使う。

```m
let
    Src = Sql.Database(pServer, pDatabase),
    // EnableFolding=true で後続ステップも折りたたまれる。条件はパラメータで渡す
    Q = Value.NativeQuery(Src,
        "SELECT 商品ID, CAST(売上日 AS date) AS 売上日, SUM(金額) AS 金額 FROM dbo.FactSales " &
        "WHERE 売上日 >= @from AND 売上日 < @to GROUP BY 商品ID, CAST(売上日 AS date)",
        [from = RangeStart, to = RangeEnd], [EnableFolding = true])
in
    Q
```

> [!WARN] 接続時にSQLを埋め込まない
> `Sql.Database(..., [Query=...])` は以降の折りたたみを止め、増分更新も動かない。

| 阻害要因 | なぜ切れるか | 対処 |
|---|---|---|
| 異なるソースのマージ | ソースをまたぐ翻訳ができない | 片方を先にDBへ取り込む |
| プライバシー レベル | 結合が禁止され内部でバッファされる | ポリシーに従いレベルを揃える |
| 特殊な型への変更 | 翻訳先の型が存在しない | ソース側でCASTしておく |
| 列名に依存する動的処理 | 実行時まで列が確定しない | 列構成を固定してから処理する |

## 理解度チェック

1. 2番目でインデックス列、3番目で年フィルター。何行転送されるか。改善策は。
2. 全ステップで「ネイティブ クエリの表示」がグレー。原因2つと対処は。
3. `Table.Buffer` を使うべき場面と、使ってはいけない場面を1つずつ挙げよ。
