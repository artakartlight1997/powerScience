## 列を直接書けるのは行コンテキストがある場所だけ

```dax
-- 計算列：行コンテキストがあるので OK
利益額 = Fact_売上[SalesAmount] - Fact_売上[原価額]

-- メジャー：行コンテキストが無いので エラー
利益額NG = Fact_売上[SalesAmount] - Fact_売上[原価額]

-- メジャー：反復関数が行コンテキストを作るので OK
利益額合計 = SUMX( Fact_売上, Fact_売上[SalesAmount] - Fact_売上[原価額] )
```

## 理解度チェック

**問1.** `Dim_商品` の計算列に `SUM( Fact_売上[SalesAmount] )` と書いたら全商品が同じ値。理由と対処は。

<details><summary>答え</summary>
行コンテキストは Fact_売上 を絞らないため全社合計が返る。対処は `CALCULATE` で包むか `RELATEDTABLE` を使う。
</details>

**問2.** `SUMX( VALUES( Dim_商品[ProductName] ), [売上合計] )` が商品ごとの合計になる理由は。

<details><summary>答え</summary>
メジャー参照は暗黙的に `CALCULATE` で包まれるため、SUMX が作った行コンテキストがフィルターコンテキストに変換される。これがコンテキスト遷移。
</details>

**問3.** `Dim_商品` の計算列で `RELATED( Fact_売上[SalesAmount] )` がエラーになるのはなぜか。

<details><summary>答え</summary>
`RELATED` は多側から1側を参照する関数で、対応行が1つに定まる場合しか使えない。1側から多側は対応行が複数あるため `RELATEDTABLE` ＋ 集計関数を使う。
</details>

## よくあるエラーと原因

| 症状・エラー | 原因 | 対処 |
|---|---|---|
| 計算列の値が全行同じ | 行コンテキストが変換されていない | `CALCULATE` で包む／`RELATEDTABLE` |
| 「1つの値が必要ですが…」 | メジャーで列を直接参照した | 集計関数か反復関数を使う |
| `RELATED` がエラー | 1側から多側を参照している | `RELATEDTABLE` ＋ 集計関数 |
| `RELATED` が空を返す | リレーションが無い／非アクティブ | モデルビューで関係を確認 |
| 反復の中の集計が全体値 | 式を直接書いた | メジャー参照にする |
| 計算列が非常に遅い | 行ごとに遷移が発生 | メジャー化／Power Query で処理 |

> [!EXAM] PL-300で問われる
> 「計算列の SUM が全行同じ」の原因＝行コンテキストは自動変換されない。対処は CALCULATE か RELATEDTABLE。
