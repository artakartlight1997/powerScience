## ユーザーストーリーと受け入れ基準

```figure
{ "type":"formula", "lang":"text", "title":"ユーザーストーリーの形式", "caption":"3要素で1行に収める",
  "code":"[誰として] [何をしたい] [なぜなら]",
  "parts":[

    {"match":"[なぜなら]","label":"週次で訪問先を決める必要があるから","tone":"amber"} ] }
```

```text
受け入れ基準（誰が見ても判定できる形にする）
  □ 自分の担当エリアの店舗のみ表示される（RLS適用）
  □ 達成率の低い順に並ぶ
  □ 達成率／未達額／前週からの変化が見える
  □ 月曜8:00時点で前週日曜までの実績が反映される
  □ スマートフォンで文字が読める
  □ 表示完了まで3秒以内

完了の定義
  所長3名がテスト環境で訪問先を選定でき、
  現行のExcel作業（週2時間）が不要になったことを確認できた状態
```

> [!TIP] 実務のコツ
> 性能要件（3秒）と鮮度要件（月曜8:00）は必ず入れる。後付けはモデル再設計になる。

## 理解度チェック

1. 役員の「全社売上ダッシュボードが欲しい」に、最初に投げる質問を3つ挙げてください。
2. 依頼者（部長）と利用者（現場40名）が異なる案件で、進め方をどう変えますか。
3. 要件合意後に業種データの60%欠損が判明。防ぐべき工程と、今取るべき対応は。
