モデルを開いた利用者の最初の質問はいつも同じです。「**どの列を使えばいいんですか**」。

`金額` `金額2` `売上金額` `SalesAmount` が並べば必然です。100人が使うモデルでは、この質問が100回来ます。

標準化とは、その質問が発生しない状態を作る作業です。センスではなく規約の問題です。

## 設計チェックリスト

- [ ] テーブル命名を接頭辞方式か業務語方式に統一した
- [ ] 列名がテーブル名なしで意味が確定する形になっている
- [ ] メジャー名を業務語・単位明示・修飾後置・略語禁止で統一した
- [ ] キー列・作業列・ファクトの数値列を非表示にした
- [ ] 暗黙のメジャーを封じ、指標はメジャー経由に一本化した
- [ ] メジャーを表示フォルダーで分類し、番号接頭辞で順序を制御した
- [ ] テーブル・列・メジャー・モデルの説明をモデル内に書いた
- [ ] pbit テンプレート、テーマJSON、共有日付テーブルを配布した
- [ ] BPA規則を配布し、必須規則を段階的に設定した
- [ ] 品質6次元それぞれに測定式と目標値を定め、メジャーを常設した
- [ ] 規約書を1〜2ページに収め、必須／推奨／任意を明示した
- [ ] レポート標準（色の意味・ビジュアル選択規則・注記）を配布した
- [ ] 規約の四半期見直しを予定に組み込んだ

## 理解度チェック

1. 共有モデルでファクトの数値列を非表示にする理由を、暗黙のメジャーという語を使って説明してください。
2. 品質6次元のうち「一貫性」と「正確性」の違いを、測定方法を挙げて説明してください。
3. モデル仕様書を別文書ではなくモデル内の説明プロパティに書くべき理由を述べてください。

> [!NOTE] このレッスンのまとめ
> 標準化の目的は利用者の判断回数を減らすこと。列名はテーブル名なしで意味が確定させ、ファクトの数値列を隠して暗黙のメジャーを封じる。規約は文書ではなくテンプレートとBPAで配る。
