スタースキーマは1対多を前提にします。現実にはこの前提が崩れる関係が多くあります。

無理に1対多で組むと、合計が静かに水増しされます。

```m
// パターン1: 明細に両方のキーがある → 組み合わせを一意化する
let
    キーのみ = Table.SelectColumns(Fact_口座明細, {"口座ID", "顧客ID"}),
    null除去 = Table.SelectRows(キーのみ, each [口座ID] <> null and [顧客ID] <> null)
in
    Table.Distinct(null除去)

// パターン2: タグがカンマ区切りの1列 → 分割して縦持ちにする
let
    分割 = Table.TransformColumns(Dim_商品生データ, {{"タグ", each Text.Split(_, ","), type list}}),
    展開 = Table.ExpandListColumn(分割, "タグ"),
    トリム = Table.TransformColumns(展開, {{"タグ", Text.Trim, type text}}),
    キーのみ = Table.SelectColumns(トリム, {"商品ID", "タグ"})
in
    Table.Distinct(Table.SelectRows(キーのみ, each [タグ] <> null and [タグ] <> ""))
```

## `TREATAS` と `CROSSFILTER`

```figure
{ "type":"formula", "lang":"dax", "title":"TREATAS の構造", "caption":"列の順序と個数を一致させる",
  "code":"TREATAS( VALUES( Dim_商品[カテゴリ] ), Fact_予算[カテゴリ名] )", "parts":[
  {"match":"TREATAS","label":"テーブルの値を、別の列のフィルターとして扱う","tone":"violet"},
  {"match":"VALUES( Dim_商品[カテゴリ] )","label":"いま見えている値の一覧","tone":"blue"},
  {"match":"Fact_予算[カテゴリ名] ","label":"フィルターを適用する先の列","tone":"amber"}] }
```

```dax
-- 予算はカテゴリ×年月の粒度しかない。関係を張らずフィルターを渡す
予算額 =
CALCULATE( SUM( Fact_予算[予算金額] ),
    TREATAS( VALUES( Dim_商品[カテゴリ] ), Fact_予算[カテゴリ名] ),
    TREATAS( VALUES( Dim_日付[年月] ), Fact_予算[年月] ) )

-- 予算のない粒度では BLANK。誤った按分表示を防ぐ
予実差異 =
VAR 予算 = [予算額]
RETURN IF( NOT ISBLANK( 予算 ), [売上合計] - 予算 )

-- ブリッジ経由。方法1: メジャー内だけ双方向にする
顧客別残高 =
CALCULATE( SUM( Fact_残高[残高] ),
    CROSSFILTER( Bridge_口座保有[口座ID], Dim_口座[口座ID], BOTH ) )

-- 方法2: ブリッジの口座IDをファクトへ直接適用する
顧客別残高2 =
CALCULATE( SUM( Fact_残高[残高] ),
    TREATAS( VALUES( Bridge_口座保有[口座ID] ), Fact_残高[口座ID] ) )
```

## 実装後の検証と設計判断

| 検証項目 | 方法 | 期待される結果 |
|---|---|---|
| 総計の一致 | ブリッジ非経由と経由の合計を比較 | 按分なら完全一致 |
| 内訳の合計 = 総計 | 顧客別合計と全体総計を比較 | 共有分があり一致しないのが正しい。仕様として説明する |
| 孤児レコード | `LeftAnti` でブリッジにないキーを検出 | 0件 |
| 比率の健全性 | 案件ごとの比率合計 | すべて 1.0 |
| 空白メンバー | スライサーの「（空白）」 | 出るなら不一致あり |

- [ ] 粒度を変えて1対多にできないか検討したか
- [ ] 多対多の型（タグ／共有／粒度差／配分）を特定したか
- [ ] ブリッジのキーを一意化し、null を除いたか
- [ ] ディメンションのキーはサロゲートキーか
- [ ] 双方向に頼らない方法（CROSSFILTER / TREATAS）を検討したか
- [ ] 比率合計が 1.0 であることを検証したか

## 理解度チェック

1. 商談↔製品タグのモデルに必要なテーブルと関係の向き・カーディナリティを挙げよ。
2. 多対多で内訳合計が総計より小さい。原因と確認方法は。
3. 日次売上とカテゴリ×月次予算を比べる `TREATAS` メジャーを書け。
