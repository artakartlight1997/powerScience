整形のゴールには名前があります。**整然データ（tidy data）** です。
統計学者 Hadley Wickham が定義した、分析しやすいデータの標準形です。

> [!NOTE]
> 3ルールは覚えるものではなく、判定に使う道具です。
> 「列名に値が入っていないか」「1行は何の1件か」を順に聞きます。

```dax
-- 横持ち：5月が来たら書き換えが必要
売上合計_横持ち = SUM( 売上[2025年1月] ) + SUM( 売上[2025年2月] ) + SUM( 売上[2025年3月] )

-- 縦持ち：何月が増えても書き換えは不要
売上合計 = SUM( Fact_売上[SalesAmount] )
```

式の短さは、設計の正しさの副産物です。

| チェック | 違反していたら |
|---|---|
| 列名に月・年・支店名が入っていないか | 列のピボット解除（L0504） |
| 小計・合計・注釈の行が混ざっていないか | テキストフィルターで除外（L0502） |
| 1セルに2つの意味が入っていないか | 列の分割（L0502） |
| 1行が何を表すか1文で言えるか | 粒度を決めてグループ化（L0506） |
| 同じ値が何百万回も繰り返されていないか | マスタに切り出す（L0601） |

> [!TRAP]
> 整然データにすると行数は必ず増えます。これは成功の証拠です。
> 列指向エンジンは縦に長い表を強く圧縮するので、性能面でも有利です。

> [!EXAM]
> 「月ごとの列が横に並んだデータを分析可能にする変換は」の答えは**列のピボット解除**。
> 選択肢の「列のピボット」「転置」「グループ化」との区別は L0504 で扱います。

## よくあるエラーと対処

| 症状 | 原因 | 対処 |
|---|---|---|
| 毎月フィールドを追加している | データが横持ちのまま | 列のピボット解除で縦持ちにする |
| 合計が実際の2倍になる | 小計行が混ざっている | 「小計」を含む行を除外する |
| 同じ商品名が数万行続く | 観測単位が混ざっている | 商品マスタに切り出して関係で結ぶ |
| DAXが長大な足し算になる | 変数が列名に散っている | ピボット解除して1列にまとめる |
| 送料の合計が3倍になる | 粒度の違う数値が同居 | 粒度ごとにテーブルを分ける |
| 1行が何なのか説明できない | 粒度が未定義 | グループ化で粒度を決め直す |
