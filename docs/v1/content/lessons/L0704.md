> [!TRAP] 第3引数に安易に 0 を入れない
> `DIVIDE( [実績], [目標], 0 )` は「目標未設定」を「達成率0%」に化けさせます。
> 頑張っていない店に見え、誤った意思決定を招きます。

> [!DS] 0 と欠測は違う
> **0は「測った結果ゼロ」、欠測は「測っていない」。** 混ぜると平均も比率も歪みます。
> DAXでは BLANK が欠測を表す手段です。意識的に使い分けてください。

> [!EXAM] PL-300で問われる
> ゼロ除算の対処は答えが `DIVIDE`。`IFERROR` や `IF([分母]=0,…)` は不適切です。
> 「未設定を0と表示すべきでない」という設計判断も出題されます。

## 理解度チェック

**問1.** `IF` を4段ネストした式は、どう書き換えるべきか。

<details><summary>答え</summary>
`SWITCH( TRUE(), 条件, 値, …, 既定値 )`。条件が整列し、追加が1行の差分で済むため。
</details>

**問2.** `DIVIDE( [実績], [目標], 0 )` の何が問題か。

<details><summary>答え</summary>
目標未設定と達成率0%が同じ表示になる。第3引数を省略しBLANKのままにする。
</details>

**問3.** 売上0の商品も表に出したい。どうするか、副作用は。

<details><summary>答え</summary>
`+ 0` か `COALESCE(…,0)`。全商品が行として現れ、行数が増えて重くなる。
</details>

## よくあるエラーと原因

| 症状・エラー | 原因 | 対処 |
|---|---|---|
| ビジュアル全体がエラー表示 | `/` によるゼロ除算 | `DIVIDE` に置き換える |
| 分岐の結果が全部文字列になる | `IF` の各分岐で型が混在 | 全分岐の戻り値の型をそろえる |
| `SWITCH` で下の条件に到達しない | 緩い条件を上に書いた | 厳しい条件から順に並べ替える |
| 達成率が0%と表示される | `DIVIDE` の第3引数に0を指定 | 第3引数を省略しBLANKにする |
| 売上0の商品が表から消える | メジャーがBLANKを返し行が除外 | `+ 0` または `COALESCE` を使う |
| `AND()` で3条件を書いてエラー | `AND` は2引数まで | `&&` 演算子でつなぐ |
