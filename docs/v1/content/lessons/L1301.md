DAX の集計関数は2種類。表をまとめて集計する関数と、行を1つずつ見る関数。
後者が**イテレータ関数**。名前の末尾の `X` が目印です。

> [!NOTE] 要点
> `SUM(列)` は列を足すだけ。`SUMX(表,式)` は1行ずつ式を評価してから集計する。

## 理解度チェック

**問1.** 行ごとに割引率 `Fact_売上[DiscountRate]` が違います。割引後売上の合計を返すメジャーは。

<details>
<summary>解答</summary>

`SUMX( Fact_売上, [UnitPrice] * [Quantity] * ( 1 - [DiscountRate] ) )`。3列を行ごとに掛けるため SUM では書けません。
</details>

**問2.** `RANKX( ALL( Dim_商品 ), … )` と `RANKX( ALL( Dim_商品[ProductName] ), … )` の違いは。

<details>
<summary>解答</summary>

前者はテーブル全体を解放し、カテゴリスライサーの選択まで無視します。後者は家電の中での順位。欲しいのは後者です。
</details>

**問3.** `AVERAGEX( VALUES( Dim_顧客[CustomerID] ), [売上合計] )` が想定より高く出る原因は。

<details>
<summary>解答</summary>

売上ゼロの顧客が BLANK になり分母から外れています。`[売上合計] + 0` で含められますが、まず要件を確認します。
</details>

## 実務チェックリスト

- [ ] 列同士の演算を含む集計を SUM で書いていないか確認した
- [ ] 単一列の単純な集計に無意味な SUMX を使っていないか確認した
- [ ] RANKX の第1引数に、順位を競わせたい列だけを ALL で渡した
- [ ] AVERAGEX の分母に BLANK 行を含めるかを要件として確認した
- [ ] RELATED を使う箇所に行コンテキストが存在することを確認した
- [ ] ネストしたイテレータの評価回数を見積もり、1万回以下に収めた
