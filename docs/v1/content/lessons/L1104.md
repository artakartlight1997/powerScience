5年分1億行でも、毎日変わるのは直近数日だけ。全件を読み直せば毎日3時間かかります。

**増分更新**はテーブルを期間で分割し、変わり得る範囲だけを取り直す仕組みです。

## 境界は半開区間で切る

```m
let
    Fact = Sql.Database(pServer, pDatabase){[Schema="dbo", Item="FactSales"]}[Data],
    // 開始は「以上」、終了は「より小さい」。この非対称が重要
    増分フィルター = Table.SelectRows(Fact, each [売上日] >= RangeStart and [売上日] < RangeEnd)
in
    増分フィルター
```

-- ソース側のビューに検出列を用意しておく
CREATE VIEW dbo.vw_FactSales AS
SELECT 伝票番号, 売上日, 商品ID, 金額,
       ISNULL(更新日時, 登録日時) AS 最終更新日時   -- 訂正でも必ず更新される

検出列は物理削除に反応しません。論理削除の運用にするか、定期的に全体更新を挟みます。

## まとめ

- 前提は折りたたみ。効いていなければ増分更新は無意味
- 境界は `>= RangeStart and < RangeEnd`。半開区間で切る
- 増分範囲は訂正が入る期間から決める。技術者の推測で決めない
- サービスは UTC。ソースが現地時間だと境界がずれて伝票が抜ける
- 更新履歴で所要時間の推移を見る。伸びていれば見直しの合図

> [!EXAM] 増分更新の頻出4点
> 名前と日付/時刻型が必須。折りたたみが前提。アーカイブと増分の違い。初回は全期間。

## 理解度チェック

1. 設定したのに更新時間が変わらない。最初に確認すべきことと確認方法は。
2. `<= RangeEnd` にすると何が起きるか。境界を例に説明せよ。
3. ソースで物理削除が起きる。増分10日ならどんな不整合が出るか。対処2つは。
