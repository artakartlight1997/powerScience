同じ式が2回書かれたメジャーは、読めず・遅く・直すと壊れます。

`VAR` はこの3つを一度に解決します。DAXで最初に覚えるべき作法です。

> [!TRAP] 「VARが再評価されない罠」の見分け方
> 変数を `CALCULATE` `SUMX` `AVERAGEX` の引数に渡していたら、ほぼこの罠です。
> **文脈を変えたい計算には、変数ではなくメジャーや式そのものを渡す。**

> [!TIP] 入れ子とコメント
> 変数の中でさらに `VAR … RETURN` を書けます。名前が外に漏れず衝突しません。
> `ADDCOLUMNS` の追加列名は `"@売上"` と `@` を付け、実在の列と区別します。

> [!DS] 中間結果に名前をつける意味
> 読みやすさはそのまま **検証可能性** です。名前がなければ壊れた箇所を切り分けられません。
> SQLのCTE、Pythonの一時変数と同じ役割。名前をつける行為が仕様の記述になります。

## 理解度チェック

**問1.** `VAR 当年 = [売上合計]` を `CALCULATE( 当年, … )` に渡すとどうなるか。

<details><summary>答え</summary>
当年は評価済みの定数なので値が変わらず、前年比は常に0%になる。式を渡すこと。
</details>

**問2.** 3番目の変数の中身を確認したい。どうするか。

<details><summary>答え</summary>
`RETURN` の後ろを一時的にその変数名に差し替え、ビジュアルで値を確認する。
</details>

**問3.** `VAR 対象 = FILTER(…) RETURN 対象` がエラーになる理由は。

<details><summary>答え</summary>
FILTER はテーブルを返すが、メジャーの戻り値はスカラーでなければならないため。
</details>

## よくあるエラーと原因

| 症状・エラー | 原因 | 対処 |
|---|---|---|
| フィルターを変えても値が変わらない | 変数を `CALCULATE` に渡した | 変数ではなくメジャー・式を渡す |
| テーブル式は…変換できません | テーブル変数を `RETURN` した | `COUNTROWS` などでスカラー化する |
| 名前 'X' が認識されません | 後ろの変数を前から参照した | 宣言順を入れ替える（参照は上から下） |
| RETURN が必要です | 書き忘れた／2つ書いた | `RETURN` は最後に1つだけ |
| 変数名が列名と衝突して混乱 | `Sales` など汎用語を使った | 「当年売上」など役割が分かる名前に |
| 期待より遅い | 重い計算を何度も呼んでいる | 共通部分をさらに変数へ切り出す |
