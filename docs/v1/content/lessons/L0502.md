## 値を切り出す

1つの列から必要な部分だけを取り出す操作です。

```figure
{ "type": "cards", "cols": 3, "title": "切り出しの3つの道具", "caption": "区切り文字で足りるなら、それが一番壊れにくい",

    {"icon": "🔎", "title": "抽出", "text": "区切り記号の前／後／間、最初のN文字を取り出す。列を増やさずに済む。", "tone": "green"},
    {"icon": "🔀", "title": "条件列", "text": "if 〜 then 〜 else を GUI で組む。分岐が3つを超えるならカスタム列に直接書く。", "tone": "amber"} ] }
```
```m
= Table.AddColumn(前のステップ, "ドメイン", each Text.AfterDelimiter([ManagerEmail], "@"), type text)

= Table.AddColumn(前のステップ, "割引区分",
    each if [Discount] = 0 then "なし" else if [Discount] < 0.1 then "小"
         else if [Discount] < 0.2 then "中" else "大", type text)
```

クレンジング済みクエリは、次を満たしていれば完成です。

- 全列に明示的な型がある（アイコンが ABC123 でない）
- 列の品質でエラー 0%、マスタ側のキーは個別の値＝一意の値
- ステップ名を上から読むと仕様が分かる
- 固定の行番号・列位置に依存していない

> [!TIP]
> 「例からの列」は推測なので、想定外のデータで壊れます。
> 生成された M を必ず読み、意図と一致しているか確認してください。

## 理解度チェック

1. トリミング後もマージが一致しません。最初に疑う原因と、M での書き方は。
2. 金額列の型変換で42行がエラー。「エラーの削除」を押してはいけない理由は。
3. 「重複の削除」と「正規化」はどちらが先ですか。逆にすると何が起きますか。

## よくあるエラーと対処

| 症状 | 原因 | 対処 |
|---|---|---|
| トリミングしても一致しない | 全角スペースが残っている | `Text.Trim(_, {" ", "　"})` を使う |
| 数値型で大量にエラー | 桁区切り、`N/A`、全角数字 | 変換前に置換で正規化してから型変換する |
| エラー削除で売上が激減 | エラー行を丸ごと消した | 取り消して、原因ごとに置換で対処する |
| 重複が消えない | 正規化の前に削除した | 正規化ステップを前に移動する |
| 来月ファイルで全部壊れた | 上位の行を固定数で削除した | 内容（テキストフィルター）で除外する |
| 日付列が変換できない | ロケールが合っていない | 「ロケールを使用」で `ja-JP` を明示する |
