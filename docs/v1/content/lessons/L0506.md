L0503 で宣言した「1行が何を表すか」を、実装に落とします。

> グループ化は必ず情報を捨てます。何を捨てるかを意識して実行してください。

    グループ化 = Table.Group(売上, {"CustomerID"}, {{"明細", each _, type table}}),
    最新受注 = Table.AddColumn(グループ化, "最新", each Table.Max([明細], "OrderDate")),
    展開 = Table.ExpandRecordColumn(最新, "最新", {"OrderID", "OrderDate", "SalesAmount"}, {"最新受注ID", "最終受注日", "最新受注金額"})

```m
let
    列を絞る = Table.SelectColumns(売上, {"StoreID", "OrderDate", "OrderID", "Quantity", "SalesAmount"}),
    月キー = Table.AddColumn(列を絞る, "月初日", each Date.StartOfMonth([OrderDate]), type date),
    サマリー = Table.Group(月キー, {"StoreID", "月初日"},
        { {"売上計", each List.Sum([SalesAmount]), Int64.Type},
          {"受注件数", each List.Count( List.Distinct([OrderID]) ), Int64.Type} })
in
    サマリー
```

Power Query のグループ化が正当化されるのは、次の場面だけです。

- ソースが巨大で、明細を取り込むと更新が終わらない（粒度を文書化して畳む）
- 月次予算のように、そもそも明細が存在しない
- ディメンションを作るための一意化。モデルに載せない検査クエリ

> [!TRAP]
> 「すべての行」は明細をメモリに保持するため、大きな表では非常に重くなります。
> 先に不要な列を削除してからグループ化してください。

> [!EXAM]
> 更新時間とモデルサイズの削減策は、(1) 不要な列の削除、(2) 粒度の集計、
> (3) 日時の分割でカーディナリティ低減、(4) 期間のフィルター、の4つです。

## よくあるエラーと対処

| 症状 | 原因 | 対処 |
|---|---|---|
| 必要な列が消えた | キーにも集計にも指定していない | キー列に加えるか `List.Max` で取り出す |
| 件数が実際より多い | 行数のカウントを使っている | 個別の行数のカウントに変更する |
| グループ化が終わらない | 「すべての行」で巨大な入れ子を作った | 先に不要な列を削除する／集計に置き換える |
| 平均が想定より高い | null が無視され分母が小さい | 0 と null の扱いを決めてから平均する |
| 新しい列が勝手に入る | 「列の削除」で列挙していた | 「他の列の削除」に置き換える |
| 集計値の平均が合わない | 平均の平均は全体平均と一致しない | 合計と件数を保持し、割り算はメジャーで |
| 折りたたみが切れた | カスタムの集計式を使っている | 標準の集計関数だけで書き直す |
