GUIで押したボタンは、すべてMのコードに翻訳されています。あなたはすでにMを書いています。

目的は関数の暗記ではなく、**どういう文法の言語かを掴む**ことです。

```m
// 各行で「日付が自分以下の行の金額」を合計する（累計）
let
    T = #table(type table[日付=date, 金額=number],
        {{#date(2026,1,1), 100}, {#date(2026,1,2), 200}, {#date(2026,1,3), 50}}),
    累計付き = Table.AddColumn(T, "累計", (outer) =>
        List.Sum( Table.SelectRows(T, each [日付] <= outer[日付])[金額] ), type number)
in
    累計付き
```

> [!TRAP] 入れ子の each は外側を見失う
> 内側の `_` は内側の行を指す。外側に `(outer) =>` と名前を付けるのが唯一の確実な解決策。

```m
let
    試行 = Table.AddColumn(T, "試行", each try Number.From([金額])),
    金額 = Table.AddColumn(試行, "変換後", each if [試行][HasError] then null else [試行][Value], type number),
    理由 = Table.AddColumn(金額, "エラー理由", each if [試行][HasError] then [試行][Error][Message] else null, type text)
in
    Table.RemoveColumns(理由, {"試行"})
```

> [!TRAP] try ... otherwise 0 は事故のもと
> 変換失敗と本当に0円が区別できなくなる。`otherwise null` にして件数を必ず数える。

## まとめ

| 症状 | 確認する場所 | 対処 |
|---|---|---|
| トークン 'in' が必要です | 直前の行の末尾カンマ | カンマの過不足を直す |
| ステップ 'xxx' が見つかりません | 参照しているステップ名 | 削除・改名を特定して繋ぎ直す |
| 列 'xxx' が見つかりません | ソース側の列名変更 | ハードコードを可変にする |
| 途中結果が見たい | `in` の値 | 一時的に `in 途中のステップ名` に書く |

> [!EXAM] 読めれば足りる
> `let ... in` の構造、ステップ間の参照、`each` の意味、主要な Table 関数の役割まで。暗記は不要。

## 理解度チェック

1. `in` が3つ目のステップを指すとき、4・5番目は実行されるか。理由も。
2. `each [金額] > 0` を each なしで書け。書き換えが必要な場面は。
3. 型変換の失敗を消さずに理由を残す構成は。try の返り値にも触れよ。
