## 理解度チェック

**問1.** 3カテゴリ中2つを選択中。構成比の合計行を100%にしたい。どの関数を使うか。

<details><summary>答え</summary>
`ALLSELECTED`。スライサーの選択を分母に残しつつ、行の条件だけを外すため合計が100%になる。`ALL` では分母が全データになり70%になる。
</details>

**問2.** `RANKX( VALUES( Dim_商品[ProductName] ), [売上合計] )` が全行1位になる理由は。

<details><summary>答え</summary>
各セルでは商品が1つに絞られており、`VALUES` はその1行を返す。比較相手が自分だけなので常に1位になる。`ALL` で外して全商品を比較集合にする。
</details>

**問3.** 「同じカテゴリの中での商品構成比」はどう書くか。

<details><summary>答え</summary>
`DIVIDE( [売上合計], CALCULATE( [売上合計], ALLEXCEPT( Dim_商品, Dim_商品[Category] ) ) )` と書く。
Category だけ残して他を外すため、分母がそのカテゴリ全体になる。
</details>

## よくあるエラーと原因

| 症状 | 原因 | 対処 |
|---|---|---|
| 順位が全行1になる | 比較集合のフィルターを外していない | `RANKX( ALL( 列 ), … )` |
| 構成比の合計が100%にならない | `ALL` の分母＋スライサーで一部選択 | 要件次第で `ALLSELECTED` |
| 構成比が全行100% | 分母のフィルター除去が効いていない | `CALCULATE` で包む |
| `ALLSELECTED` の結果が読めない | ネストや反復の中で使っている | `REMOVEFILTERS` で書けないか再検討 |
| メジャーが極端に遅い | `ALL( Fact_売上 )` で全体を展開 | 必要な列だけ `ALL( 表[列] )` |
| `ALLEXCEPT` が効かない | 残す列が別テーブルの列 | 第1引数の表に属する列を指定 |
| 同順位の次が飛ぶ | 既定の `Skip` 方式 | 第5引数に `Dense` |
