「キーが同じに見えるのに一致しない」原因は、ほぼこの4つです。

| 原因 | 症状 | 対処 |
|---|---|---|
| 型が違う | `text` の `"1001"` と `number` の `1001` | 同じ型に揃える。IDは text 推奨 |
| 前後の空白 | `"P0027 "` と `"P0027"` | 両側にトリミング（全角に注意） |
| 大文字小文字 | `"p0027"` と `"P0027"` | 両側を大文字に統一 |
| 見えない文字 | 改行、BOM、ゼロ幅スペース | クリーンを適用する |

結合の前に、次を必ず確認します。

- 左の行数を控える（左外部結合なら結合後も同じはず）
- 右のキーが一意か。列の分布で個別の値＝一意の値を確認する
- 左反結合が0行か、0行でないなら内容を説明できるか
- ダイアログの「n 行のうち m 行が一致します」を読んでから OK を押す

> [!TRAP]
> 内部結合は48,000円の売上を警告なしに消します。既定は左外部結合。
> ファジーマッチは候補出しに使い、確定分は変換テーブルで完全一致に戻します。

> [!EXAM]
> 「一致しない行を特定したい」の答えは**左反結合**。
> 「両方に存在する行だけ」は内部結合、「1つ目の全行を保持」は左外部結合です。

## 理解度チェック

1. 6,948 行が内部結合で 5,120 行になりました。行を失わず原因を調べる手順は。
2. マージ後に売上が正確に2倍。疑う原因と、事前に検出する方法を2つ挙げてください。
3. 売上に商品名を付けるとき、マージとリレーションシップのどちらを選びますか。

## よくあるエラーと対処

| 症状 | 原因 | 対処 |
|---|---|---|
| マージしても全部 null | キーの型が違う | 両側のキー列を同じ型に揃える |
| 一致件数が想定より少ない | 空白・大文字小文字・不可視文字 | トリミング・クリーン・大文字統一を両側に |
| マージ後に行数が増えた | 右キーの重複（ファンアウト） | 右側で重複を削除、または粒度を見直す |
| 内部結合で売上が減った | 一致しないファクト行が消えた | 左外部結合にし、左反結合で欠落を調査 |
| 追加したら列が2倍 | 列名が一致していない | 追加前に列名を完全に揃える |
| 更新が急に遅くなった | 異なるソース間で折りたたみが切れた | 同一ソース内で結合する／先に絞る |
