支店ごとにレポートを複製すると、支店が20個になった時点で運用が崩壊します。

行レベルセキュリティ（RLS）は、1つのモデルのまま見える行だけを変えます。

```dax
-- 静的RLS。ロール「東京支店」を Dim_支店 に設定
[支店名] = "東京"

-- ロール「西日本」。複数条件も書ける
[地域] IN { "近畿", "中国", "四国", "九州" }

-- 動的RLS。ロールは1つだけ、Dim_ユーザー支店 に設定する
-- USERNAME() は Desktop で DOMAIN\名 を返すので使わない
[メール] = USERPRINCIPALNAME()
```

> [!TRAP] つまずきポイント
> 静的RLSは支店20個ならロール20個。増えるたび再発行が必要。
> 適するのは「社内／社外」のような数が増えない大分類だけ。

```dax
-- 計算列。E007 なら "E001|E002|E004|E007"
社員パス = PATH( Dim_社員[社員ID], Dim_社員[上司ID] )
レベル1 = PATHITEM( Dim_社員[社員パス], 1 )
階層の深さ = PATHLENGTH( Dim_社員[社員パス] )

-- 検証ページのカード。問い合わせ時に画面を送ってもらう
ログインID = USERPRINCIPALNAME()
見える支店数 = COUNTROWS( ALLSELECTED( Dim_支店 ) )
見える行数 = COUNTROWS( Fact_売上 )
```

## 設計判断チェックリスト

- [ ] フィルターをディメンション側に書いたか
- [ ] ロールが増え続ける設計になっていないか
- [ ] `USERNAME()` ではなく `USERPRINCIPALNAME()` を使ったか
- [ ] 対応表のメールが実際のログインIDと完全一致しているか
- [ ] 対応表に存在しないユーザーを検出する仕組みがあるか
- [ ] 階層RLSで循環参照・自己参照を事前に検出したか
- [ ] Desktop・Serviceの両方で検証したか
- [ ] 対象ユーザーのワークスペース ロールは「閲覧者」か
- [ ] 全社合計などをレポートにハードコードしていないか
- [ ] RLS導入前後で応答時間を計測したか

## 理解度チェック

1. 支店が50あり毎月増減する。静的と動的のどちらを選ぶか。理由と必要な構成を述べよ。
2. `Dim_社員` の `社員ID`・`上司ID` から「自分と配下すべて」を見せるRLSを説明せよ。
3. RLS設定済みなのに管理職が全支店を見られた。原因を3つ挙げ確認方法を述べよ。
