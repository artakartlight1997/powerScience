# ユーザーマニュアル — Integral Prism PoC

投資プロ向け。**やることは「フォルダに資料を置いて1コマンド」だけ**である。
システムが固定の物差し(箱0〜10 × 業態別ドライバーツリー)に突き合わせ、
どこが**検証済みで厚く、どこが薄く、どこが未知か**を機械判定して4つの成果物を返す。

## 0. 初回セットアップ(1回だけ)

```bash
cd poc
cp .env.example .env      # OPENROUTER_API_KEY を記入。モデルは既定のままで良い
docker compose build
```

> 生成モデルと検証モデルは**別ベンダ**が必須(同一ベンダだと起動を拒否する)。
> これは仕様であってバグではない — 同じモデルに自分の答えを採点させないための構え。

## 1. ケースを作る

```bash
docker compose run --rm prism init-case yamada2026 \
  --name "株式会社サンプルテック" --archetype ses_jutaku --industry "ITサービス"
```

- `yamada2026` はケースID(フォルダ名になる。半角英数)
- `--archetype` は業態テンプレ。現状 `ses_jutaku`(SES×受託)。
  追加は `templates/archetypes/` に YAML を1枚置くだけ(コード変更不要)
- 実行すると `inbox/yamada2026/` に3つの投入フォルダができる

## 2. 資料を置く(ドロップフォルダ規約)

```
inbox/<ケースID>/
  seller/       ← ティーザー・IM・売り手提供資料(「売り手の主張」として扱われる)
  consultant/   ← コンサル成果物(検収QCの対象になる)
  general/      ← 業界レポート・記事・開示など自分で拾った外部資料
```

- 対応形式: **PDF / txt / md**
- **ファイル名の先頭に `YYYY-MM-DD_` を付ける**(例 `2026-01-15_im.pdf`)。
  これがその情報の as_of(入手時点)になる。付けなければファイル更新日時を使う
- 同じ内容のファイルを二度置いても二重登録されない(内容ハッシュで冪等)
- **seller に置いた資料だけでは項目は filled にならない**(外部証拠との突合が必須)

## 3. 回す

```bash
docker compose run --rm prism run yamada2026            # 手持ち資料のみ
docker compose run --rm prism run yamada2026 --online   # Web収集も有効化
```

- 停止条件(ラウンド上限 / LLM呼び出し上限 / 収穫逓減 / 公開経路の完了)まで
  自動で回り、**必ず停止理由を表示して**終わる。放置してよい
- `--online` は `templates/fund/standards.yaml` の `allowed_hosts` で制限できる
  (空なら全ホスト許可)。取得したページは必ずスナップショット保存され、
  原文照合に通らない Web 情報は判定に使われない

## 4. 成果物を読む(`out/<ケースID>/`)

| ファイル | 何か | いつ使うか |
|---|---|---|
| `sakusenban.md` | **作戦盤**: 箱×状態の全景、見張り台帳(論点依存度highの項目)、未解消の矛盾 | 検討会の前に5分で眺める |
| `order_spec.md` | **発注仕様書**: 公開情報で埋まらなかった項目+取得経路(vdr/expert)。filled は「発注不要」リスト | コンサル発注・マネジメントインタビューの設計 |
| `qc.md` | **検収QC**: コンサル成果物のうち公開情報で再現できた割合 | 納品物の検収 |
| `ledger.md` | **証拠台帳**: 全証拠の出所・原文照合結果・独立性クラスタ | 数字の出典を確かめたいとき |
| `status.md` | 現況サマリと改竄検知の結果 | 途中経過の確認 |

### 状態の読み方

- ✅ **filled** — 独立した2系統以上の証拠が原文照合を通過(売り手のみは不可)
- 🟡 **thin** — 証拠はあるが、独立性不足/売り手のみ/矛盾が未解消
- 🔴 **missing** — 公開経路で取れるはずだが未取得
- ⚫ **unknown** — 公開では到達不能。**取得手段(vdr/expert)つきで発注仕様書へ**

> unknown が多いのは初期は**正常**(対象の大半は非上場)。
> unknown を「取得手段つきリスト」に変換することがこの段階の価値である。

### 矛盾について

売り手が「稼働率95%」、外部記事が「80%」なら、システムは**どちらも保存して並記**し、
その項目を filled にせず、確認タスクに変換する。平均したり片方を捨てたりは**しない**。

## 5. その他のコマンド

```bash
docker compose run --rm prism status yamada2026        # 現況
docker compose run --rm prism report yamada2026        # 成果物の再生成のみ
docker compose run --rm prism verify-chain yamada2026  # 台帳の改竄検知
```

## 6. 不具合が起きたら

**何が起きたか説明する必要はない。** `data/logs/prism.log` を開発者に渡すだけでよい。

- 全ての処理・スキップ・失敗・エラーの詳細(トレースバック含む)がこのファイルに残る
- 画面には「内部エラーが発生した。詳細な記録は …/prism.log にある」とだけ出る
- ログには資料の本文・引用は記録されない(ID・件数・URL・エラーのみ)。
  案件資料ごと送る必要はない

## 7. よくある質問

- **Q. 資料を追加したら?** → もう一度 `run`。追加分だけ取り込まれ、判定が更新される
- **Q. 物差し(必須項目)を変えたい** → `templates/boxes.yaml` /
  `templates/fund/standards.yaml` を編集(**変更は承認者を通すこと** — 判定基準そのものなので)
- **Q. 新しい業態が来た** → `templates/archetypes/` に YAML を1枚追加。
  ドライバーツリーは `templates/drivers/` に置く
- **Q. Docker なしで動かせる?** → `pip install -e .` して `prism ...` で同じ
